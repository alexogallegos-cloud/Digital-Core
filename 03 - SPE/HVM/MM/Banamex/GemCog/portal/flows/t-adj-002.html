  participant GLOps as GL_Operaciones

  GLOps->>P312: Invoca P312 — ejecución batch manual

  LIBCTRL-->>P312: ESTATUS=3 (sistema activo)

  loop Por cada instrucción en ENTRADA
    P312->>P312: T-ADJ-P312-003 Lee instrucción TIPO+KEY+CAMPO+ESPERADO+NUEVO
    P312->>P312: T-ADJ-P312-004 Valida TIPO-ESTRUCTURA en conjunto B20/B21/B70/B71/B72

    alt TIPO desconocido
      Note over P312,LISTADO: Escribe REJECT a LISTADO — CONTINUE sin detener proceso
    else TIPO válido
      P312->>P312: T-ADJ-P312-005 Construye clave DMSII según routing TIPO
      P312->>DMSII: T-ADJ-P312-006 FIND UPDATE FIRST — lock exclusivo
      alt NOT FOUND
        DMSII-->>P312: Registro no encontrado
        P312->>LISTADO: Escribe REJECT "NO ENCONTRADO" — CONTINUE
      else Lock obtenido
        DMSII-->>P312: Registro con lock de escritura
        P312->>P312: T-ADJ-P312-007 Verifica VALOR-ESPERADO vs valor actual DMSII
        alt Mismatch — pre-check falla
          Note over P312,LISTADO: REJECT VALOR-ESPERADO INCORRECTO — SIN ROLLBACK de previos
        else Match
          P312->>P312: T-ADJ-P312-008 Calcula WKS-DELTA = VALOR-NUEVO minus VALOR-ACTUAL
          P312->>DMSII: T-ADJ-P312-009 MODIFY UPDATE — commit inmediato persistente
          DMSII-->>P312: Confirma commit (sin batch rollback disponible)
          P312->>LISTADO: Escribe OK para esta instrucción
          P312->>P312: T-ADJ-P312-010 WKS-COUNT-OK++ acumula WKS-TOTAL-DELTA
        end
      end
    end
  end

  P312->>LISTADO: T-ADJ-P312-015 Genera footer — contadores + WKS-TOTAL-DELTA neto
  P312-->>GLOps: STOP RUN
  LISTADO->>GLOps: Entrega listado a equipo auditoria GL post-ajuste

Reglas de negocio

RN-S151-707 — CRÍTICO: Sin rollback multi-registro en ajuste directo DMSII
P312_ADJUSALDO T-ADJ-P312-007 🔴 CRÍTICO ajuste parcial · CNBV
Cuando el pre-check falla en la instrucción N (VALOR-ACTUAL ≠ VALOR-ESPERADO), las instrucciones 1..N-1 ya están committed en DMSII. P312 escribe rechazo a LISTADO y continúa con la siguiente instrucción sin hacer rollback de las anteriores. El GL entra en un estado parcialmente ajustado sin mecanismo de recuperación automática. Corrección requiere nueva ejecución manual con instrucciones inversas para 1..N-1.
* T-ADJ-P312-007 — Pre-check VALOR-ESPERADO IF DMSII-VALOR-ACTUAL(CAMPO-AJUSTE) NOT = VALOR-ESPERADO PERFORM WRITE-REJECT-LISTADO *> razón: VALOR-ESPERADO INCORRECTO GO TO NEXT-INSTRUCTION *> CONTINUE — sin rollback de previos * * Instrucciones 1..N-1 ya committed en DMSII * GL en estado parcialmente ajustado * No existe mecanismo de rollback multi-registro en DMSII END-IF
Impacto migración: El sistema destino debe implementar ajustes GL como transacciones atómicas multi-registro. Si el conjunto de instrucciones no puede garantizarse atómico, el sistema debe rechazar todo-o-nada — nunca comprometer un subconjunto. El patrón de ajuste parcial del legado no debe replicarse en el sistema moderno bajo ninguna circunstancia.
RN-S151-706 — CRÍTICO: FIND UPDATE DMSII sin timeout configurado
P312_ADJUSALDO T-ADJ-P312-006 🔴 CRÍTICO DMSII lock · operaciones
FIND UPDATE obtiene un lock de escritura exclusivo sobre el registro DMSII objetivo. No hay timeout configurado en P312 para este lock. Si el proceso se interrumpe entre el FIND UPDATE y el MODIFY UPDATE correspondiente — caída del sistema, kill manual del job — el lock puede mantenerse indefinidamente. El registro queda bloqueado para cualquier otro proceso hasta que un DBA libere el lock manualmente.
* T-ADJ-P312-006 — FIND UPDATE DMSII FIND UPDATE FIRST <TIPO-ESTRUCTURA> KEY IS <clave-construida-por-TIPO> * * Lock exclusivo obtenido — sin timeout configurado * Si P312 se interrumpe entre FIND y MODIFY: * → lock mantenido hasta liberación manual por DBA * Liberación normal: MODIFY UPDATE (éxito) o KEEP/FREE (rechazo) * Sin timeout → bloqueo indefinido si P312 falla mid-record
Impacto migración: El sistema destino debe implementar locks de escritura con timeout explícito y manejo de deadlock. Si un ajuste no puede obtenerse en N segundos (recomendado: 30s), debe rechazar la instrucción y reportar al operador. El lock sin timeout de P312 es un patrón de operación frágil que no debe heredarse en arquitectura moderna.
RN-S151-712 — B72POSCONTA: actualización simultánea SDOACT + NATCTA
P312_ADJUSALDO T-ADJ-P312-012 B72POSCONTA · CNBV
B72POSCONTA requiere coherencia entre SDOACT (saldo actual) y NATCTA (naturaleza de la cuenta: 1=deudora, 2=acreedora). Si un ajuste cambia el signo de SDOACT — de positivo a negativo o de negativo a positivo — P312 debe actualizar NATCTA simultáneamente en el mismo MODIFY UPDATE. La incoherencia entre SDOACT y NATCTA produce reportes CNBV con naturaleza de cuenta incorrecta y puede constituir un hallazgo regulatorio.
* T-ADJ-P312-012 — B72POSCONTA NATCTA simultáneo IF TIPO-ESTRUCTURA = 'B72' COMPUTE B72-SDOACT-NUEVO = B72-SDOACT-ACTUAL + WKS-DELTA *> Detectar cambio de signo en SDOACT IF (B72-SDOACT-ACTUAL > 0 AND B72-SDOACT-NUEVO < 0) OR (B72-SDOACT-ACTUAL < 0 AND B72-SDOACT-NUEVO > 0) IF B72-SDOACT-NUEVO > 0 MOVE 1 TO B72-NATCTA *> 1 = deudora ELSE MOVE 2 TO B72-NATCTA *> 2 = acreedora END-IF END-IF MODIFY UPDATE B72POSCONTA *> SDOACT + NATCTA en una sola operación END-IF
Impacto migración: El sistema destino debe implementar la invariante SDOACT↔NATCTA como constraint de dominio en la entidad de posición contable. Cualquier ajuste que actualice SDOACT debe evaluar y actualizar NATCTA atómicamente. Agregar validación en la capa de servicio y en la base de datos para garantizar consistencia antes del reporte CNBV.
RN-S151-709 — Ejecución manual sin control de autorización embebido en el código
P312_ADJUSALDO T-ADJ-P312-001 segregación de funciones · auditoría
P312 es invocado directamente por el equipo de operaciones GL sin firma dual ni flujo de aprobación embebido en el programa. El archivo ENTRADA es preparado manualmente y no tiene firma digital ni hash de integridad. El control de autorización es puramente operativo — un procedimiento externo al código — sin evidencia programática en el LISTADO de que las instrucciones fueron autorizadas antes de aplicarse.
* T-ADJ-P312-001 — Init ADJUSALDO * WKS-PARAM-SIS recibido como parámetro (3 dígitos) * ENTRADA abierto directamente — sin validación de firma digital * LISTADO abierto para resultado * * No existe verificación de autorización en código: * — Sin firma digital del archivo ENTRADA * — Sin registro de quién preparó las instrucciones * — Sin doble firma antes de MODIFY UPDATE * — Sin hash de integridad del conjunto de instrucciones * Control de autorización: procedimiento operativo externo al programa
Impacto migración: El sistema de ajuste GL destino debe implementar flujo de aprobación dual — el analista prepara las instrucciones y un segundo autorizante las valida antes de ejecutarlas. El LISTADO de auditoría debe incluir identidad del preparador, identidad del autorizante, timestamp de autorización y hash de integridad del conjunto de instrucciones aplicadas.

Vocabulario

ENTRADA
Archivo secuencial S151 · input de instrucciones
Archivo de instrucciones de ajuste preparado manualmente por operaciones GL. Campos: TIPO-ESTRUCTURA, clave DMSII completa, CAMPO-AJUSTE, VALOR-ESPERADO, VALOR-NUEVO. Sin validación de integridad interna — errores de captura solo se detectan durante la ejecución de P312.
VALOR-ESPERADO
PIC S9(15)V9(02) · pre-check optimistic lock
Valor actual esperado del campo en DMSII. P312 lo compara contra el valor real como pre-check de optimistic lock. Si no coincide, la instrucción se rechaza sin rollback de instrucciones previas ya aplicadas en DMSII.
WKS-DELTA
PIC S9(15)V9(02) · delta de ajuste
Delta calculado como VALOR-NUEVO - VALOR-ACTUAL. Aplicado con ROUNDED al campo objetivo. Acumulado en WKS-TOTAL-DELTA para el footer del LISTADO de reconciliación. ROUNDED evita truncación pero no previene pérdida de precisión por diferencias de escala entre VALOR-NUEVO y el campo DMSII.
TIPO-ESTRUCTURA
PIC X(03) · código de estructura DMSII
Código de la estructura DMSII objetivo del ajuste. Valores válidos: B20, B21, B70, B71, B72. Determina el layout de clave y los campos ajustables. Tipo desconocido produce rechazo con CONTINUE — el proceso no se detiene.
NATCTA
PIC 9(01) · naturaleza de la cuenta B72
Naturaleza de la cuenta en B72POSCONTA: 1=deudora, 2=acreedora. Debe ser consistente con el signo de SDOACT. P312 actualiza NATCTA cuando un ajuste cambia el signo del saldo — ambos campos en un solo MODIFY UPDATE atómico.
LISTADO
Archivo de impresión S151 · auditoría post-ajuste
Resultado de auditoría de P312. Un registro por instrucción (OK/REJECT/ERROR) más footer con WKS-COUNT-OK, WKS-COUNT-REJECT, WKS-COUNT-ERROR y WKS-TOTAL-DELTA neto. Entregado al equipo de auditoría GL post-ajuste. No incluye identidad del autorizante.

Hallazgos de migración — P312 ADJUSALDO

Tarea Hallazgo Severidad Acción requerida
T-ADJ-P312-007 GL parcialmente ajustado sin rollback. Pre-check falla en instrucción N → 1..N-1 committed en DMSII sin recuperación automática. 🔴 CRÍTICO Implementar ajustes GL como transacciones atómicas multi-registro en el sistema destino. Todo-o-nada: si cualquier instrucción falla, revertir el conjunto completo. El patrón de parcial del legado no debe heredarse.
T-ADJ-P312-006 FIND UPDATE sin timeout configurado. Lock DMSII mantenido indefinidamente si P312 se interrumpe entre FIND y MODIFY — bloqueo manual por DBA necesario. 🔴 CRÍTICO Implementar locks de escritura con timeout explícito (recomendado 30s) y manejo de deadlock en el sistema destino. Rechazo con notificación al operador si el lock no puede obtenerse en el tiempo límite.
T-ADJ-P312-001 Sin firma dual embebida en el código. Autorización de ajustes GL es puramente operativa — sin control programático de aprobación ni hash del conjunto de instrucciones. 🟡 ALTO Implementar flujo de aprobación dual en el sistema destino: analista prepara instrucciones, segundo autorizante valida antes de ejecución. LISTADO debe incluir identidad de preparador, autorizante y timestamp de autorización.
T-ADJ-P312-012 NATCTA asimetría en B72. Ajuste que cambia signo de SDOACT sin actualizar NATCTA simultáneamente produce inconsistencia contable en reportes CNBV. MEDIO Implementar invariante SDOACT↔NATCTA como constraint de dominio en la entidad de posición contable. Cualquier servicio de ajuste debe evaluar y actualizar NATCTA atómicamente con SDOACT.
T-ADJ-P312-003 ENTRADA sin validación de integridad. Archivo preparado manualmente — errores de captura en CAMPO-AJUSTE o VALOR-ESPERADO no se detectan hasta FIND NOT FOUND o pre-check fallo. MEDIO El sistema destino debe validar el conjunto de instrucciones antes de iniciar ajustes: verificar formato de campos, existencia de registros objetivo y consistencia del VALOR-ESPERADO en una fase de pre-validación sin modificar datos.

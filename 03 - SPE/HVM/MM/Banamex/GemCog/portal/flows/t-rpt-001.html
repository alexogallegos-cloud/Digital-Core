Flujo de tarea (L5) — P677 gate-keeper + P610 dispatcher

  P677->>CSISDIA: T-RPT-026 CONSISDIA F01 — gate inicial del ciclo
  alt CONSISDIA F01 falla
    CSISDIA-->>P677: STATUS=-1
    Note over P677: TEXTO-LJ + CALL LJ IN LIB-DISP
CHANGE ATTRIBUTE STATUS = -1 — fail-fast sin recovery
    P677-->>WFL: STOP STATUS=-1 (batch completo bloqueado — T-RPT-031)
  else CONSISDIA F01 OK
    CSISDIA-->>P677: gate superado
  end

  P677->>THECAL: T-RPT-027 THECALENDAR F18 — validar día hábil bancario
  alt Fecha inhábil (00000001)
    THECAL-->>P677: 00000001 inhábil Banxico
    P677-->>WFL: STOP STATUS=-1 (día inhábil — Circular 14/2017)
  else Día hábil
    THECAL-->>P677: hábil
    P677->>THECAL: F06 — obtener día de semana
    THECAL-->>P677: día de semana
    loop Reconstruir días hábiles del ciclo
      P677->>THECAL: F08 — restar 1 día hábil
      THECAL-->>P677: fecha anterior ajustada
    end
  end

  P677->>B01B03: T-RPT-028 MANTSISDIA F37 — FECPRO + FECCON + FECPRO151
  B01B03-->>P677: fechas actualizadas en B01SISDIA

  P677->>B01B03: T-RPT-029 CONSISMEN — buscar AAMM actual en B03SISMEN
  alt AAMM existe
    B01B03-->>P677: update registro existente
  else AAMM no existe y tabla llena
    B01B03-->>P677: reemplaza menor AAMM (buffer circular silencioso)
  end

  P677->>B04: T-RPT-030 leer ESTATUS de B04SISTEM
  B04-->>P677: ESTATUS actual

  alt ESTATUS=3 (cierre mensual)
    P677->>LIBL002: cargar LIB-L002
    P677->>LIBL002: CONTROLES F025 — F10..F(10+dias_habiles)
    LIBL002-->>P677: archivos de control del período generados
    Note over P677: LIB-L002 solo se carga en cierre mensual ESTATUS=3
  else ESTATUS!=3 (día ordinario)
    Note over P677: LIB-L002 NO se carga
  end

  P677->>P610: T-RPT-014 dispatch (W77-FUNCION, W77-SISTEMA, W77-NUMREG)

  P610->>B01B03: T-RPT-015 F01 — CONSISMEN F11 graba SECOKHI en B03SISMEN
  B01B03-->>P610: tamaño de ciclo persistido

  P610->>B04: T-RPT-016 F02 — STABDSAL=99 (base desactivada)
  P610->>B04: T-RPT-016 F04 — STABDSAL=1 (ciclo activo período AAMM)

  P610->>L002R: T-RPT-017 F03 — señal CNBV FUNCION=98
  Note over L002R: {84,87,335,336,408,703,711} → 6DIG
Todos los demás sistemas → 8DIG
  L002R-->>P610: señal enviada — ciclo GL del día cerrado

  P610->>B04: T-RPT-018 F05 — actualizar STABDSAL validando {1,3,5,99}
  P610->>B04: T-RPT-018 F06 — actualizar ESTATUS validando 2-4 (ESTATUS=3 dispara cadena en P677)
  B04-->>P610: estados intermedios actualizados

  P610->>P610: T-RPT-019 F07 — inicializar E01 vacío (HEADER sistema+fecha + TRAILER TOTREG=0)

  P610->>INFOICA: T-RPT-020 F09 — TANDEM ICA (APL-ORI=0236 APL-DES=0264 hardcoded IMP=1.1)

  P610-->>P677: T-RPT-021 CANCEL CTLVER — libera memoria task MCP
  P677-->>WFL: STOP RUN

Reglas de negocio

RN-S151-476 — P677 gate-keeper absoluto del ciclo batch S151
COBOL_P677.txt párrafo INICIO-PROCESO 🔴 CRÍTICO T-RPT-026 · T-RPT-031
P677 es el primer programa en ejecutarse cada día hábil en el batch S151. Si CONSISDIA F01 falla, todos los programas downstream del día no pueden ejecutarse — el batch completo queda bloqueado. No existe recovery ni retry: el comportamiento es fail-fast con STATUS=-1 inmediato. Cualquier fallo en cualquier punto de P677 sigue el mismo patrón: TEXTO-LJ + CALL "LJ IN LIB-DISP" + CHANGE ATTRIBUTE STATUS = -1.
* P677 — Gate-keeper del ciclo batch S151 * Primer programa ejecutado cada día hábil * Patrón fail-fast universal (T-RPT-031): sin recovery, sin retry CALL "CONSISDIA" USING SOPORTECOMS LIB-LINK *> W77-FUNCION = 1 (gate inicial) IF STATUS NOT = 0 MOVE "ERROR CONSISDIA F01 GATE FALLIDO" TO TEXTO-LJ CALL "LJ IN LIB-DISP" USING SOPORTECOMS *> registro en bitácora CHANGE ATTRIBUTE MYSELF STATUS = -1 *> fail-fast — batch bloqueado STOP RUN END-IF
Impacto migración: El patrón fail-fast total no es aceptable en un sistema bancario de alta disponibilidad en cloud. En el sistema destino reemplazar con circuit-breaker granular: si el gate falla, activar alerta P1 y modo degradado controlado — no bloqueo total del batch. Separar el gate de inicio del orquestador de jobs downstream para que un fallo de P677 no bloquee automáticamente toda la cadena.
RN-S151-477 — Validación de calendario bancario Banxico mediante THECALENDAR F18
COBOL_P677.txt párrafo VALIDA-CALENDARIO 🔴 CRÍTICO T-RPT-027 Banxico Circular 14/2017
P677 valida si la fecha de proceso es día hábil bancario mediante THECALENDAR F18. Si la función retorna "00000001", la fecha es inhábil → P677 termina con STATUS=-1 sin procesar ese día. THECALENDAR es una librería propietaria Unisys MCP sin equivalente directo en Linux o cloud. El loop F08+F06 reconstruye los días hábiles del ciclo — base para computar el número de archivos de control mensual. Base regulatoria: Banxico Circular 14/2017.
* THECALENDAR F18 — Validar día hábil bancario Banxico MOVE W77-FECHA-PROCESO TO THECAL-FECHA CALL "THECALENDAR" USING THECAL-FECHA THECAL-FUNCION=18 THECAL-RESULTADO IF THECAL-RESULTADO = "00000001" MOVE "DIA INHABIL BANXICO — SIN PROCESAMIENTO" TO TEXTO-LJ CALL "LJ IN LIB-DISP" USING SOPORTECOMS CHANGE ATTRIBUTE MYSELF STATUS = -1 *> día inhábil — Circular 14/2017 STOP RUN END-IF *> F06: obtener día de semana (0=lunes..6=domingo) *> F08: restar 1 día con ajuste de días hábiles *> loop F08+F06 → reconstruir días hábiles del ciclo → WKS-DIAS-HABILES
Impacto migración: THECALENDAR es propietario Unisys MCP — sin equivalente en Linux ni cloud. Debe reemplazarse con un servicio de calendario bancario Banxico (API REST o tabla de referencia con datos del calendario oficial Banxico publicado anualmente). Las funciones F06 (día de semana) y F08 (restar 1 día hábil) deben reimplementarse como utilidades de fecha estándar. Validar cobertura mínima de 5 años futuros antes del cutover.
RN-S151-455 — F03 señal fin de día CNBV: el ciclo GL queda abierto sin esta señal
COBOL_P610.txt función F03 🔴 CRÍTICO T-RPT-017 CNBV · cierre contable diario
P610 F03 envía la señal de fin de día CNBV a L002 REGISTRA con FUNCION=98. Sin esta señal el ciclo GL de S151 queda abierto — ningún posting adicional puede registrarse hasta que la señal llegue. Impacto regulatorio directo en el cierre contable diario CNBV. Los sistemas {84, 87, 335, 336, 408, 703, 711} usan formato 6DIG; todos los demás usan 8DIG. La lista está hardcodeada en el código fuente.
* P610 F03 — Señal fin de día CNBV a L002 REGISTRA * Sin esta señal: ciclo GL queda abierto — impacto regulatorio CNBV MOVE 98 TO W77-FUNCION-L002 *> FUNCION=98 = señal fin de ciclo GL del día *> Selección de formato por sistema (hardcodeado): EVALUATE W77-SISTEMA WHEN 84 WHEN 87 WHEN 335 WHEN 336 WHEN 408 WHEN 703 WHEN 711 SET W77-FORMATO TO 6DIG *> sistemas específicos: 6 dígitos WHEN OTHER SET W77-FORMATO TO 8DIG *> todos los demás: 8 dígitos END-EVALUATE CALL "L002 REGISTRA" USING SOPORTECOMS W77-FUNCION-L002 W77-FORMATO
Impacto migración: La señal CNBV fin de día debe convertirse en un evento explícito en la arquitectura cloud (mensaje a un topic/queue de cierre de ciclo GL). La lista de sistemas con formato 6DIG debe externalizarse a tabla de configuración — no código fuente. El formato 8DIG vs 6DIG debe validarse contra el esquema CNBV vigente en el corte. Si F03 no se ejecuta, la deuda regulatoria es inmediata.
RN-S151-485 — B04SISTEM ESTATUS=3 dispara generación de archivos de ciclo mensual en cadena
COBOL_P677.txt · COBOL_P610.txt T-RPT-030 · T-RPT-018 🟠 amber · cierre mensual
Cuando B04SISTEM.ESTATUS=3 (cierre mensual), P677 carga LIB-L002 y llama CONTROLES F025 para generar los archivos de control F10..F(10+días_hábiles). El número de archivos se computa dinámicamente: WKS-DEL-FUNCION = W77-IND + 9. En días ordinarios (ESTATUS≠3), LIB-L002 NO se carga. Es P610 F06 quien activa ESTATUS=3, desencadenando la cadena en P677 — acoplamiento implícito entre ambos programas.
* P677 — Cierre mensual: ESTATUS=3 activa generación de archivos de control IF B04-ESTATUS = 3 LOAD LIBRARY "LIB-L002" *> solo en cierre mensual CALL "CONTROLES" USING LIB-LINK FUNCION=025 PERFORM VARYING W77-IND FROM 1 BY 1 UNTIL W77-IND > WKS-DIAS-HABILES COMPUTE WKS-DEL-FUNCION = W77-IND + 9 *> F10..F(10+N) CALL "CONTROLES" USING LIB-LINK WKS-DEL-FUNCION END-PERFORM END-IF *> P610 F06 actualiza ESTATUS en B04SISTEM (validando 2-4) *> ESTATUS=3 aquí dispara la cadena anterior en P677
Impacto migración: La lógica de cierre mensual debe aislarse como workflow separado del gate diario. En cloud: evento de cierre mensual dispara un workflow orquestado dedicado que genera los archivos de control. El número de archivos (WKS-DIAS-HABILES) debe obtenerse del servicio de calendario bancario destino. El acoplamiento implícito P610→P677 vía B04SISTEM.ESTATUS debe convertirse en dependencia explícita declarada en el orquestador.
RN-S151-484 — B03SISMEN buffer circular: ciclos históricos pueden sobrescribirse silenciosamente
COBOL_P677.txt T-RPT-029 🟠 amber · auditoría histórica
B03SISMEN es un buffer circular de ciclos mensuales. Cuando la tabla está llena y llega un nuevo AAMM, P677 identifica el registro con el menor AAMM (el ciclo más antiguo) y lo reemplaza. Este reemplazo ocurre silenciosamente — sin notificación al operador, sin archivo de respaldo, sin log del ciclo eliminado. Si hay ciclos históricos relevantes para auditoría CNBV o Banxico, pueden perderse sin traza.
* P677 — T-RPT-029 Gestión B03SISMEN: buffer circular de ciclos mensuales PERFORM CONSISMEN USING W77-AAMM-ACTUAL VARYING ... AT END *> AAMM actual no existe en B03SISMEN IF B03-TABLA-LLENA FIND MINIMUM B03-AAMM GIVING WKS-MENOR-AAMM *> reemplaza el ciclo más antiguo — SIN ALERTA, SIN LOG, SIN RESPALDO MODIFY B03SISMEN (WKS-MENOR-AAMM) WITH CURRENT-AAMM-DATA ELSE STORE NEW RECORD B03SISMEN WITH CURRENT-AAMM-DATA END-IF
Impacto migración: B03SISMEN debe migrarse a una tabla con retención configurable — mínimo 13 meses para cubrir ciclos de auditoría CNBV. La eliminación de ciclos debe generar un evento de log y alerta al operador. El patrón de buffer circular silencioso no es aceptable en un entorno regulatorio bancario sujeto a revisiones de Banxico y CNBV.
RN-S151-462 — F09 TANDEM ICA: valores hardcodeados en P610 para CECOBAN Banxico
COBOL_P610.txt función F09 T-RPT-020 Banxico · ICA · CECOBAN
P610 F09 genera el archivo TANDEM para la red interbancaria ICA (CECOBAN Banxico) con valores hardcodeados directamente en el código fuente: APL-ORI=0236 (identificador Banamex origen), APL-DES=0264 (identificador Banamex destino), COD-SER=20 (tipo de servicio abono), IMP=1.1 (importe). Si Banamex cambia su identificador en CECOBAN post-separación Citi, o el tipo de servicio cambia, P610 requiere modificación directa del código fuente.
* P610 F09 — TANDEM ICA para CECOBAN Banxico * Valores hardcodeados en código fuente — sin externalización MOVE 0236 TO ICA-APL-ORI *> identificador Banamex origen (hardcoded) MOVE 0264 TO ICA-APL-DES *> identificador Banamex destino (hardcoded) MOVE 20 TO ICA-COD-SER *> tipo de servicio abono (hardcoded) MOVE 1.1 TO ICA-IMPORTE *> importe (hardcoded) CALL "INFOICA" USING ICA-APL-ORI ICA-APL-DES ICA-COD-SER ICA-IMPORTE *> genera archivo TANDEM para red ICA/CECOBAN bajo supervisión Banxico
Impacto migración: Los valores APL-ORI, APL-DES, COD-SER e IMP deben externalizarse a tabla de configuración. Verificar con el área de operaciones bancarias si el identificador CECOBAN de Banamex (0236/0264) sigue vigente post-separación de Citi — es posible que el registro en CECOBAN haya cambiado o esté en proceso de actualización durante la transición. Cualquier cambio en el registro CECOBAN debe poder aplicarse sin tocar código fuente.

Vocabulario

THECALENDAR
Librería MCP · propietaria Unisys
Librería propietaria Unisys MCP para cálculo de fechas bancarias. F18=validar si la fecha es día hábil bancario Banxico (retorna "00000001" si es inhábil), F06=obtener día de semana, F08=restar 1 día con ajuste de días hábiles. Sin equivalente directo en Linux ni cloud — requiere reimplementación como servicio de calendario. Base regulatoria: Banxico Circular 14/2017.
CONSISDIA
Entry point · control del día S151
Función de control del día en S151. F01=gate inicial del ciclo batch — si falla, P677 termina con STATUS=-1 inmediato bloqueando todo el batch del día. F11=graba el tamaño del ciclo (SECOKHI, conteo de registros OK) en B03SISMEN. Es el primer punto de control de S151 cada día hábil bancario.
MANTSISDIA
Entry point · mantenimiento B01SISDIA
Función de mantenimiento de B01SISDIA. F37=actualizar las tres fechas de proceso del sistema: FECPRO (fecha de proceso), FECCON (fecha de contabilización) y FECPRO151 (fecha de proceso específica de S151). Las tres fechas son normalmente iguales pero pueden diferir en escenarios de recuperación de ciclo — condición importante para trazabilidad contable.
CONSISMEN
Entry point · control ciclos mensuales
Control de ciclos mensuales en B03SISMEN. Busca el AAMM actual en el buffer circular; si existe actualiza el registro; si no existe y la tabla está llena, reemplaza silenciosamente el menor AAMM. F11 persiste el tamaño del ciclo (conteo de registros OK = SECOKHI). Gestiona el estado de cada período mensual procesado por S151.
B01SISDIA
Dataset DMSII · registro de fechas del sistema
Registro maestro de fechas del sistema S151. Almacena FECPRO (fecha de proceso), FECCON (fecha de contabilización) y FECPRO151 (fecha de proceso S151). Actualizado por P677 cada día hábil mediante MANTSISDIA F37. Las tres fechas pueden diferir en recuperaciones de ciclo — condición relevante para trazabilidad contable y auditoría.
B03SISMEN
Dataset DMSII · buffer circular mensual
Tabla de ciclos mensuales organizada como buffer circular. Almacena el estado de cada período AAMM procesado, incluyendo el conteo de registros OK (SECOKHI). Cuando la tabla está llena y llega un nuevo AAMM, P677 reemplaza el ciclo con el menor AAMM sin alerta ni respaldo — riesgo de pérdida silenciosa de datos históricos de auditoría CNBV.
B04SISTEM
Dataset DMSII · estado global S151
Estado global del sistema S151. ESTATUS=3 indica cierre mensual — activa la carga de LIB-L002 y la generación de archivos de control en P677. También almacena STABDSAL (estado de base de saldos mensual). Controlado por P610 F02/F04/F05/F06 y leído por P677. El campo ESTATUS debe estar en rango 2-4 para ser modificado por P610 F06.
STABDSAL
Campo de estado · base de saldos mensual
Estado de la base de saldos mensual: 1=activa (ciclo activo para el período AAMM actual), 99=desactivada (base fuera de ciclo). Controlado por P610: F02 establece STABDSAL=99 (desactiva la base), F04 establece STABDSAL=1 (activa el ciclo). F05 valida que el valor esté en {1, 3, 5, 99} antes de actualizar.
CTLVERS
Catálogo central · versiones de programas
Registro central de versiones de programas y títulos de librerías en MCP. P610 lo carga al inicio para resolver las rutas físicas de LIBCTL (vía CTLVER). Al finalizar el ciclo, P610 ejecuta CANCEL CTLVER para liberar la memoria de la task MCP asociada. Equivale a un service registry en arquitecturas modernas — mapea nombre lógico a ruta física de librería.
ICA/CECOBAN
Red interbancaria · Banxico compensación
Red de compensación interbancaria de Banxico para movimientos entre instituciones financieras. P610 F09 genera el archivo TANDEM para ICA con los identificadores de Banamex hardcodeados: APL-ORI=0236 y APL-DES=0264. CECOBAN (Centro de Compensación Bancaria) opera la red ICA bajo supervisión Banxico. La vigencia del identificador 0236/0264 debe verificarse post-separación Citi.

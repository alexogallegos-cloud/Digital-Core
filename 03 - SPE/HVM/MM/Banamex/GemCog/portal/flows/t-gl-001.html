Diagrama de secuencia

sequenceDiagram
  participant WFL as WFL LOTE (Orquestador)
  participant P109 as P109 GL POSTING ENGINE
  participant S080 as S080 Parámetros
  participant LOG151 as LOG151 (movimientos día)
  participant CAT7 as ARCH-CAT7 (catálogo)
  participant ESQCON as ARCH-ESQCON (esquemas)
  participant MOVCON as MOVCONTABLES (salida GL)
  participant PUNTEO as Archivo PUNTEO
  participant CUADRE as Archivo CUADRE (CNBV)
  participant POSICION as BD POSICION (DMSII)
  participant LAKE as DATALAKE (solo S264)

  WFL->>P109: INITIATE (W77-SISTEMA-PARAMETRO, WKS-B03-TIPBD)

  P109->>S080: T-GL-001 Cargar parámetros + resolver CSI (12→10)
  S080-->>P109: Parámetros del sistema
  P109->>P109: T-GL-002 Cargar tabla INDS250 en memoria
  P109->>P109: T-GL-003 Decidir estrategia acceso S016

  P109->>LOG151: T-GL-004 Leer cabecera (HDR-HD="HD" y fecha)
  alt Cabecera inválida — DEFECTO-PRODUCCIÓN
    LOG151-->>P109: Discrepancia de fecha en header
    Note over P109: PERFORM 000-030-IMPRIME-MENSAJE
SET MYSELF(STATUS) TO -1 — COMENTADO en ln 10009
NO aborta — continúa con fecha potencialmente incorrecta
  else Cabecera OK
    LOG151-->>P109: Cabecera válida
  end

  loop Por cada registro LOG151
    P109->>LOG151: T-GL-005 Leer siguiente registro
    LOG151-->>P109: Registro (FUNCION, STATUS, CVETRANn, IMPORTEn)

    alt FUNCION=99 (centinela EOF)
      Note over P109: W77-EOF=1 → salir del ciclo
    else FUNCION≠1 o STATUS≠1/2
      Note over P109: T-GL-006 → Movimiento descartado
    else FUNCION=1 y STATUS=1 o 2
      P109->>P109: T-GL-006 Filtro aprobado

      loop Por cada CVETRANn mayor que 0 (hasta 5)
        P109->>P109: T-GL-007 Extraer CVETRANn/IMPORTEn/ESQCONn
        P109->>CAT7: T-GL-008 Lookup AGR-CONT → W77-IND3
        CAT7-->>P109: Índice de esquema (0=no existe)

        alt W77-IND3 = 0
          Note over P109: Error ESQUEMA NO EXISTE
movimiento descartado silenciosamente — gap GL
        else W77-IND3 mayor que 0
          P109->>ESQCON: T-GL-008 Lookup (IND3, IND4) → NAT-MOV + CUENTA
          ESQCON-->>P109: NAT-MOV (1=débito/2=crédito) + CUENTA + CAUSA

          P109->>P109: T-GL-009 Enrutar por sistema origen
          P109->>P109: T-GL-010 Generar asiento partida doble
          Note over P109: T-GL-012 solo si STATUS=1 AND ORIGEN=1 o 3
          P109->>P109: T-GL-012 Acumular clave 11-dimensional
        end
      end

      alt STATUS=1
        P109->>PUNTEO: T-GL-011 Grabar PUNTEO → sistema origen
      end
    end
  end

  P109->>MOVCON: T-GL-013 Write último registro acumulado
  P109->>CUADRE: T-GL-014 Cuadre contable (cargos×−1, excluir cta 1503)
  P109->>POSICION: T-GL-015 Actualizar BD POSICION (si TIPBD=1/2/5/6)
  P109->>LAKE: T-GL-016 Escribir DATALAKE (solo S264/SPEI)
  P109-->>WFL: STOP RUN

Reglas de negocio

RN-S151-025 — Cadena de resolución ESQCON (corazón del motor GL)
COBOL_P109.txt párrafos 21120 / 21122 🔴 CRÍTICO T-GL-008
P109 resuelve la cuenta GL de cada CVETRANn mediante 3 lookups encadenados: primero en INDS250 (tabla en memoria) para obtener AGR-CONT y W77-IND3; si IND3>0, segundo en CAT7 (disco) para obtener IND4; tercero en ESQCON (disco) para obtener NAT-MOV + CUENTA + CAUSA. Si cualquier lookup falla (IND3=0 o NAT-MOV≠1/2), el movimiento se descarta silenciosamente — sin asiento GL y sin alerta al operador.
* Párrafo 21120-GRABA-MOV-CONTABLE PERFORM 21122-MUEVE-ESQUEMA VARYING W77-IND2 FROM 1 BY 1 UNTIL W77-IND2 > W77-NUM-CVETRANS * Párrafo 21122-MUEVE-ESQUEMA MOVE INDS250-AGR-CONT(CVETRANn) TO W77-AGR-CONT MOVE INDS250-IND3(CVETRANn) TO W77-IND3 IF W77-IND3 = 0 PERFORM 000-030-IMPRIME-MENSAJE *> "ESQUEMA NO EXISTE" GO TO 21122-EXIT END-IF MOVE CAT7-IND4(W77-IND3) TO W77-IND4 MOVE ESQCON-NAT-MOV(IND3, IND4) TO RMS-NAT-MOV MOVE ESQCON-CUENTA(IND3, IND4) TO RMS-CUENTA MOVE ESQCON-CAUSA(IND3, IND4) TO RMS-CAUSA
Impacto migración: La cadena de 3 catálogos debe migrarse como servicio de resolución de cuentas con validación de integridad. Los catálogos INDS250, CAT7 y ESQCON deben cargarse completos y validarse contra el catálogo CNBV vigente antes del cutover. El gap silencioso (ESQUEMA NO EXISTE sin abortar) debe convertirse en fallo explícito con alerta P1 en el sistema destino.
RN-S151-026 — Partida doble: NAT-MOV=1 (débito) / NAT-MOV=2 (crédito)
COBOL_P109.txt T-GL-010 partida doble · CNBV
P109 determina la naturaleza del asiento en MOVCONTABLES a partir de NAT-MOV devuelto por ESQCON. NAT-MOV=1 genera un asiento débito (CARGO), NAT-MOV=2 genera un asiento crédito (ABONO). Cualquier valor distinto de 1 o 2 descarta el asiento silenciosamente — creando un gap contable sin registro de error. La partida doble queda garantizada solo si ESQCON tiene NAT-MOV válidos para todos los CVETRANs del catálogo vigente.
* Párrafo 21120 — T-GL-010 EVALUATE RMS-NAT-MOV WHEN 1 MOVE RMS-IMPORTE TO RMS-DEBITO *> asiento débito (CARGO) WRITE REG-MOVCONTABLES WHEN 2 MOVE RMS-IMPORTE TO RMS-CREDITO *> asiento crédito (ABONO) WRITE REG-MOVCONTABLES WHEN OTHER *> descartado silenciosamente — sin asiento GL, sin error explícito END-EVALUATE
Impacto migración: Antes de migrar ESQCON, auditar que todos los CVETRANs vigentes tienen NAT-MOV=1 o 2. Entradas con NAT-MOV=0 o fuera de rango representan gaps actuales en el GL que pasan silenciosamente en producción. El sistema destino debe implementar alerta explícita para NAT-MOV inválido (RN-S151-051).
RN-S151-031 — Clave de acumulación 11-dimensional en MOVCONTASORT
COBOL_P109.txt T-GL-012 granularidad GL · CNBV
P109 acumula cada asiento en SMOVCONTASORT por una clave compuesta de 11 dimensiones. Esta granularidad es la mínima canónica del GL de Banamex — cualquier sistema destino debe replicarla exactamente. Solo los movimientos con STATUS=1 AND (ORIGEN=1 OR 3) se acumulan; movimientos STATUS=2 son excluidos de MOVCONTASORT.
* Clave 11-dimensional SMOVCONTASORT (SORT key): * 1. FILIAL — entidad legal * 2. ORIGEN — sistema origen (1=caja, 3=batch, etc.) * 3. MONEDA — código de moneda ISO * 4. BANCO — código de banco/entidad * 5. SUC-PROM — sucursal promotora * 6. FECVEN — fecha valor/vencimiento * 7. PRODUCTO — código de producto bancario * 8. INSTRUMENTO — instrumento financiero * 9. SECTOR — sector CNBV (Anexo 33 CUB) * 10. CVETRAN — clave de transacción * 11. ESQCON — esquema contable * Condición de inclusión (T-GL-012): IF A00-R01-STATUS = 1 AND (A00-R01-ORIGEN = 1 OR 3) ADD RMS-IMPORTE TO SMOVCONTASORT(clave-11D) END-IF
Impacto migración: El sistema destino (GL moderno) debe soportar exactamente esta clave 11-dimensional como granularidad mínima de acumulación. Reducir dimensiones rompe la equivalencia con el GL actual y constituye un defecto de migración. Implementar como índice compuesto en la tabla de movimientos contables del target.
RN-S151-021 — Validación de cabecera LOG151 — [DEFECTO-PRODUCCIÓN]
COBOL_P109.txt T-GL-004 línea 10009 🔴 DEFECTO-PROD
P109 valida la cabecera de LOG151 verificando HDR-HD="HD" y WKS-FECHA-PROCESO = HDR-FCH. Si la validación falla, emite un mensaje de aviso mediante PERFORM 000-030-IMPRIME-MENSAJE, pero NO aborta el proceso — la instrucción SET MYSELF(STATUS) TO -1 que debería abortar está COMENTADA en el código fuente (línea 10009). P109 continúa el procesamiento con la fecha potencialmente incorrecta, generando asientos GL con fecha errónea sin notificación al operador.
* T-GL-004 — Párrafo validación de cabecera LOG151 IF HDR-HD NOT = "HD" OR WKS-FECHA-PROCESO NOT = HDR-FCH PERFORM 000-030-IMPRIME-MENSAJE *> aviso impreso * SET MYSELF(STATUS) TO -1 *> INSTRUCCIÓN COMENTADA — ln 10009 * *> proceso NO aborta * *> continúa con fecha potencialmente incorrecta END-IF
Impacto migración: El sistema destino debe implementar esta validación de cabecera como fallo fatal con abort inmediato y alerta P1. No replicar el comportamiento de "aviso sin abort" del legado. Verificar con operaciones si esta condición se ha disparado alguna vez en producción para evaluar la magnitud del riesgo histórico.

Vocabulario

LOG151
Archivo secuencial · input principal
Archivo de movimientos del día que P109 lee como input. Contiene registros con FUNCION, STATUS, hasta 5 CVETRANs e importes. El header (HDR-HD + HDR-FCH) debe coincidir con la fecha de proceso. Es el input principal del motor GL — leído en T-GL-004 y T-GL-005.
INDS250
Tabla en memoria · índice CVETRAN
Tabla cargada en memoria al inicio de P109 (T-GL-002). Primer lookup de la cadena de resolución: mapea cada CVETRAN a su agrupación contable (AGR-CONT) y al índice de esquema (W77-IND3). Si un CVETRAN no tiene entrada, W77-IND3=0 y el movimiento queda sin asiento GL.
ESQCON
ARCH-ESQCON · archivo en disco
Archivo de esquemas contables. Tercer y último lookup de la cadena: dado el par (IND3, IND4), entrega NAT-MOV (1=débito/2=crédito), CUENTA (número de cuenta GL) y CAUSA. Es el catálogo maestro del GL de Banamex — su integridad determina la calidad de todos los asientos contables.
NAT-MOV
PIC 9(1) · naturaleza del movimiento
Código que determina si el asiento es débito (1) o crédito (2). Proviene de ESQCON. Un valor distinto de 1 o 2 hace que el asiento sea descartado silenciosamente, creando un gap contable sin registro de error. Determina si el importe va a WS-TOT-CARGOS o WS-TOT-ABONOS en el cuadre.
MOVCONTABLES
Archivo secuencial · output GL
Output canónico del motor GL. Contiene el contrato de equivalencia de la migración: FILIAL + CTA-CONT(12) + IMPORTE(14V99) + TIPO-MOV + NAT-MOV + FOLIO + CVETRAN + BANCO + CAUSA. Una diferencia en cualquier campo respecto al legado constituye un defecto de migración.
SMOVCONTASORT
Sort en memoria · acumulador 11D
Estructura de acumulación en memoria donde P109 agrega importes por clave 11-dimensional durante el ciclo principal. Al detectar cambio de clave (T-GL-013), escribe el registro acumulado a MOVCONTABLES. Solo STATUS=1 AND ORIGEN=1 o 3 contribuyen a la acumulación.
PUNTEO
Archivo de retroalimentación · T-GL-011
Archivo de confirmación que P109 escribe al sistema origen para cada movimiento procesado con STATUS=1. Confirma que el asiento GL fue generado exitosamente. Los movimientos STATUS=2 no reciben PUNTEO — el sistema origen los mantiene en estado "en tránsito" hasta el siguiente ciclo.
W77-SISTEMA-PARAMETRO
PIC 9(3) · parámetro de sistema
Identifica el sistema origen de los movimientos que procesa este batch de P109. Ejemplos: 500=caja S500, 264=SPEI, 084=tarjetas, 087=cheques, 502=nómina, 702=CBII, 703=SWIFT, 711=MICR. Determina el enrutamiento específico en T-GL-009 y los outputs adicionales (DATALAKE para 264).
HDR-FCH
PIC 9(8) · fecha en header LOG151
Fecha de proceso inscrita en el header de LOG151 por el sistema que lo generó. T-GL-004 verifica que coincida con WKS-FECHA-PROCESO (fecha del job batch). Una discrepancia activa el aviso sin abort — DEFECTO de producción documentado.
CAT7
ARCH-CAT7 · catálogo en disco
Archivo de catálogo de agrupación contable. Segundo lookup de la cadena de resolución: dado W77-IND3 (obtenido de INDS250), entrega IND4 (subíndice) necesario para el lookup final en ESQCON. Intermediario entre la agrupación de negocio y el esquema contable formal.

Hallazgos de migración — P109 GL Posting Engine

Tarea Hallazgo Severidad Acción requerida
T-GL-001 P109 es un binario multi-sistema (15+ sistemas origen con el mismo ejecutable parametrizado). Equivalencia debe probarse independientemente por cada sistema. 🟠 CRÍTICO Descomponer en microservicio por sistema origen o parametrizar vía configuración externa. Suite de pruebas de equivalencia separada por sistema.
T-GL-004 [DEFECTO-PROD] Validación de cabecera LOG151 no aborta el proceso aunque la fecha sea incorrecta — SET MYSELF(STATUS) TO -1 está comentado (ln 10009). 🟠 CRÍTICO Implementar validación de cabecera como fallo fatal con abort y alerta P1 en el sistema destino. No replicar el comportamiento de "aviso sin abort".
T-GL-008 Cadena ESQCON en 3 catálogos (INDS250+CAT7+ESQCON). "ESQUEMA NO EXISTE" es un gap silencioso en GL — sin asiento y sin alerta al operador. 🟠 CRÍTICO Migrar como servicio de resolución de cuentas con validación de integridad. Convertir gap silencioso en fallo explícito con alerta P1. Validar 100% de CVETRANs activos contra ESQCON antes del cutover.
T-GL-010 Partida doble solo garantizada si ESQCON es correcto. NAT-MOV ≠ 1/2 descarta el asiento silenciosamente — gap invisible hasta el cuadre del día. 🟠 CRÍTICO Auditar calidad del catálogo ESQCON antes de migrar. Implementar alerta explícita para NAT-MOV inválido. Validar cuadre cargos=créditos en ambiente de QA antes del cutover.
T-GL-012 Clave 11-dimensional (FILIAL·ORIGEN·MONEDA·BANCO·SUC-PROM·FECVEN·PRODUCTO·INSTRUMENTO·SECTOR·CVETRAN·ESQCON) es la granularidad mínima canónica del GL. 🟡 ALTO El sistema GL destino debe soportar exactamente esta clave como índice compuesto. Reducir dimensiones rompe la equivalencia de reconciliación CNBV.
T-GL-010 CTA1-CONT=0 en ESQCON activa fallback con prefijo "5" hardcodeado. El prefijo 5 puede no existir en el plan de cuentas CNBV del sistema destino. 🟡 ALTO Auditar ESQCON para eliminar entradas con CTA=0. Convertir el fallback en fallo explícito en el sistema destino con notificación al área contable.
T-GL-016 Output DATALAKE generado exclusivamente para S264/SPEI en modo batch. Si se migra a streaming SPEI, este path batch queda obsoleto. 🟡 MEDIO Definir destino del data lake en arquitectura target. Si SPEI migra a streaming, rediseñar el canal DATALAKE como evento en tiempo real en lugar de archivo batch diario.
T-GL-001 CSI=12 → CSI=10 hardcodeado (mapeo histórico). Puede ser un artefacto de migración antigua que ya no aplica. 🟢 BAJO Verificar con el área de sistemas si CSI 12 sigue activo. Si no, eliminar el mapeo; si sí, externalizar a configuración.

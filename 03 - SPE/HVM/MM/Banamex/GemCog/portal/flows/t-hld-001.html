Reglas de negocio

RN-S151-292 — TC=10 fallback en P052: tipo de cambio efectivo USD/MXN = 1.0
COBOL_P052.txt T-HLD-012 🔴 CRÍTICO L700_RAF_TAR · S080
P052 obtiene el tipo de cambio USD/MXN consultando L700_RAF_TAR desde S080. Si la consulta falla o retorna cero, P052 asigna TC=10 como fallback. Este valor produce un tipo de cambio efectivo de 1.0 porque el sistema multiplica el importe en USD por TC y luego divide por 10 internamente. Todas las transacciones USD procesadas en un día de falla de S080 quedan con error contable grave. La conversión se realiza con MULTIPLY sin ROUNDED, lo que añade truncación (no redondeo) al error.
* T-HLD-012 — Consulta TC USD/MXN en L700_RAF_TAR (S080) CALL L700_RAF_TAR USING W77-TC-PARAMS IF L700-TC = 0 OR L700-RETURN-CODE NOT = 0 MOVE 10 TO W77-TCAMBIO-VTA *> FALLBACK PELIGROSO *> TC efectivo = 1.0 (divide/multiplica ×10) END-IF *> Conversión posterior SIN ROUNDED — truncación en lugar de redondeo MULTIPLY W77-IMPORTE-USD BY W77-TCAMBIO-VTA GIVING W77-IMPORTE-MXN
Impacto migración: Eliminar el fallback silencioso. El sistema moderno debe fallar explícitamente con alerta P1 si S080 no responde — nunca asumir un TC por defecto. Implementar circuit breaker hacia S080 con alerta operativa. Cambiar MULTIPLY sin ROUNDED por operación con redondeo bancario (ROUNDED MODE NEAREST-EVEN) conforme a la norma CNBV de tratamiento de fracciones.
RN-S151-291 — Eliminación irreversible de saldo BD02ADSALDO sin audit trail
COBOL_P050.txt T-HLD-011 🔴 CRÍTICO LIB-L006 FUN=06 · BD02ADSALDO
Cuando P050 recibe un mensaje COMS con WKS-HI=500, invoca LIB-L006 FUNCION=06 que elimina el registro correspondiente de BD02ADSALDO de forma irreversible. El código AS-IS no genera ningún registro de auditoría previo a la eliminación. No existe mecanismo de recuperación dentro del programa. Esta ruta de código es un vector de fraude interno: un actor con acceso a la interfaz COMS puede eliminar saldos de tesorería sin dejar rastro auditable.
* T-HLD-011 — Disparado cuando WKS-HI = 500 * No hay WRITE de audit record antes de invocar la eliminación CALL LIB-L006 USING FUNCION = 06 BD02-KEY = WKS-CLAVE-SALDO *> Operación irreversible — BD02ADSALDO record eliminado *> Sin log de auditoría previo en el código fuente AS-IS
Impacto migración: En el sistema moderno, cualquier eliminación de saldo debe: (1) escribir registro de auditoría inmutable antes de la operación, (2) requerir autorización dual para WKS-HI=500, (3) implementar soft delete con retención mínima de 7 años conforme a Ley IC. Registrar en el sistema de observabilidad como evento de seguridad nivel P2 o superior.
RN-S151-283 — Dispatcher COMS P050: evaluación secuencial de 93 ramas EVALUATE
COBOL_P050.txt T-HLD-003 240-MANEJA-MSG modernización
El párrafo 240-MANEJA-MSG de P050 despacha cada mensaje COMS evaluando WKS-HI de forma secuencial sobre 93 ramas EVALUATE. La complejidad es O(n) por mensaje: en el peor caso el dispatcher recorre las 93 comparaciones antes de encontrar la rama. No hay índice ni tabla de salto. En modernización, este dispatcher debe convertirse en un router REST/gRPC documentado con OpenAPI. Las 93 funciones deben tener contrato de API individual, y se requiere un mínimo de 93 casos de prueba de equivalencia funcional para validar la migración.
* 240-MANEJA-MSG — Dispatcher P050 (93 ramas secuenciales) EVALUATE WKS-HI WHEN 001 PERFORM 001-CONSULTA-SALDO-GLOBAL WHEN 002 PERFORM 002-CONSULTA-SALDO-CLIENTE WHEN 003 PERFORM 003-ACTUALIZA-SALDO *> ... 90 ramas adicionales ... WHEN 093 PERFORM 093-GENERA-REPORTE WHEN OTHER PERFORM 000-030-IMPRIME-MENSAJE END-EVALUATE
Impacto migración: Reemplazar el EVALUATE secuencial por un router de microservicio con dispatch table (O(1)). Documentar las 93 funciones en un contrato OpenAPI 3.1 con schema de request/response para cada WKS-HI. La suite de pruebas de equivalencia debe cubrir los 93 casos con datos reales de producción anonimizados y validar bit-a-bit las respuestas COMS.
RN-S151-288 — Ventana SECORE hardcoded 08:00-14:05 en P050
COBOL_P050.txt T-HLD-008/009 Banxico MRA 032 08-MAY-2002 NATURALEZA=2
P050 genera cápsulas SECORE exclusivamente para abonos (NATURALEZA=2, conforme a Banxico MRA 032 del 08-MAY-2002) y solo dentro de la ventana horaria 08:00:00:00-14:05:00:00 hardcoded en el código fuente. El umbral de dormancia se obtiene de S080 ID=802 LLAVE2=98; si S080 no responde, el fallback es 180 días (Ley IC Art. 61). La exclusión de las 32 sucursales de concentración MEX se aplica antes de generar la cápsula (T-HLD-010). Un cambio regulatorio en el horario SECORE de Banxico requiere recompilación y redespliegue de P050.
* T-HLD-008 — Control de ventana SECORE (hardcoded) IF WKS-HORA >= 080000 AND WKS-HORA <= 140500 *> Dentro de ventana: evaluar calificación IF WKS-NATURALEZA = 2 AND (WKS-ORIGEN = 1 OR WKS-ORIGEN = 2) PERFORM 009-GENERA-CAPSULA-SECORE END-IF END-IF *> Banxico MRA 032 08-MAY-2002: solo NATURALEZA=2 (abonos) califican *> Umbral dormancia: S080 ID=802 LLAVE2=98 (fallback 180 días — Ley IC Art. 61)
Impacto migración: Externalizar la ventana horaria SECORE a configuración gestionada (feature flag o tabla de parámetros en S080 modernizado). Cualquier ajuste regulatorio de Banxico debe aplicarse en caliente sin recompilación. Implementar alerta operativa cuando la ventana esté por cerrar y haya cápsulas pendientes de envío. Mantener el filtro NATURALEZA=2 como invariante de negocio en el sistema destino.

Vocabulario

BD02ADSALDO
DMSII BD02 · ~500K registros en B03SDOCTE
Base de datos DMSII de saldos de tesorería gestionada exclusivamente por P050 (ADSALDOS). Contiene aproximadamente 500,000 registros en el dataset B03SDOCTE. Es la fuente única de verdad de saldos consolidados en S151. Los saldos MXN se almacenan multiplicados por 1,000 para conservar precisión decimal — P050 aplica la escala ÷1000 en las respuestas COMS (MONEDA=1). LIB-L006 es la única vía de acceso.
LIB-L006
Librería propietaria Unisys MCP · acceso DMSII BD02
Librería propietaria de Unisys ClearPath MCP que encapsula todo el acceso a BD02ADSALDO. FUNCION=10 inicializa el contexto al arranque de P050. FUNCION=06 elimina registros de forma irreversible (T-HLD-011). No existe equivalente directo en plataformas modernas (cloud, Linux, Windows). Toda la lógica de acceso DMSII debe reimplementarse desde cero en la migración — riesgo crítico de equivalencia.
WKS-HI
PIC 9(03) · identificador de función COMS
Campo de trabajo de tres dígitos que identifica la función solicitada al servidor P050 en cada mensaje COMS. El párrafo 240-MANEJA-MSG evalúa WKS-HI secuencialmente sobre 93 ramas EVALUATE para enrutar al procedimiento correspondiente. En modernización, cada valor de WKS-HI se convierte en un endpoint REST/gRPC individual con contrato OpenAPI. El valor 500 dispara la eliminación irreversible de un saldo (T-HLD-011).
L422
Entry point S016 · gestión de clientes
Biblioteca del sistema S016 de gestión de clientes. P050 la invoca con Entry 84 (índice B01SXCTE) para obtener saldos del cliente con 4 opciones de búsqueda. OPCION=2 retorna el nombre del cliente. Un error en R422-84-CTR-ERROR es FATAL y termina la atención del mensaje. Un error en R422-XX-CTR-ERROR durante la consulta de nombre es no-fatal: el proceso continúa con el nombre en SPACES — anti-patrón de falla silenciosa documentado.
SECORE
Hub Banxico · liquidación créditos tiempo real
Sistema de Entregas Contra Recepción de Banxico para liquidación de créditos en tiempo real. P050 genera cápsulas SECORE exclusivamente para abonos (NATURALEZA=2, conforme a MRA 032 08-MAY-2002) dentro de la ventana 08:00:00:00-14:05:00:00. Las 32 sucursales de concentración MEX (WKS-SUCS-EXCLUIDAS) quedan excluidas. P052 también genera cápsulas SECORE en la ruta de distribución (T-HLD-016), con exclusión de CVETRAN=3002 y 4001.
TABLA-FRAUD
PIC 9(01) OCCURS 5000 COMP · array detección fraude
Array binario de 5,000 entradas de tipo COMP cargado en memoria al inicio de P052. El CVETRAN de cada movimiento actúa como índice directo. Si WKS-TABLA-FRAUD(CVETRAN)=1, P052 escribe el movimiento en el archivo A10-FRAUD-ARCHIVO (MAXRECSIZE=211 caracteres). Módulo MARL-FRAUDES 2020: primera implementación de detección de fraude en P052. El array no se recarga en caliente — requiere reinicio de P052 para incorporar nuevos CVETRANs marcados.

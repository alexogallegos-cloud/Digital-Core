Reglas de negocio

RN-S151-382 — Auto-submisión WFL: P158 genera su propio job de continuación
COBOL_P158.txt T-STA-011 🔴 CRÍTICO Patrón MCP propietario
P158 genera dinámicamente un WFL job al final del procesamiento para invocar P170. El propio programa construye el texto del job en memoria y lo envía mediante CALL SYSTEM WFL. Este patrón es exclusivo del Work Flow Language de Unisys MCP y no tiene equivalente directo en plataformas modernas — ninguna arquitectura cloud o on-prem estándar soporta que un proceso genere y submita su propio job de continuación como primitiva nativa del sistema operativo.
* T-STA-011 — Auto-submisión WFL MOVE "BEGIN JOB;" TO WKS-WFL-JOB STRING WKS-WFL-JOB DELIMITED SIZE " RUN " WKS-WFL-PROG DELIMITED SIZE " (""" WKS-WFL-SIS WKS-WFL-NOM """);" DELIMITED SIZE " VALUE = " WKS-WFL-FP170 ";" DELIMITED SIZE " END JOB." DELIMITED SIZE INTO WKS-WFL-COMPLETE CALL SYSTEM WFL USING WKS-WFL-COMPLETE *> Resultado: "BEGIN JOB; RUN {PROG} ("{SIS}{NOM}"); VALUE = {FP170}; END JOB." *> P158 genera y lanza su propio job de continuación en tiempo de ejecución
Impacto migración: Rediseño completo obligatorio. El patrón debe reimplementarse como disparador de pipeline (Step Functions, Azure Logic Apps, Airflow) activado al completar P158 exitosamente. La cadena P158 → P170 debe modelarse como dependencia explícita en el orquestador de pipelines del sistema destino, no como auto-submisión interna del proceso.
RN-S151-375 — Y2K expirante 2049: A2K-BRIDGE-EDOCTA
COBOL_P158.txt T-STA-005 Deuda técnica activa Expira 2049
Las fechas del período del estado de cuenta (FECINI, FECFIN, HDR-FEC-BASE, HDR-FEC-PROC) usan el puente Y2K A2K-BRIDGE-EDOCTA con pivote A2K-BASE-YEAR VALUE 50. El fix funciona hasta el 31 de diciembre de 2049 — después, años 50..99 serán interpretados como 1950..1999 en lugar de 2050..2099. El sistema moderno debe eliminar esta deuda explícitamente.
* A2K-BRIDGE-EDOCTA — Conversión Y2K de fechas (formato CCAAMMDD) 01 A2K-BRIDGE-EDOCTA. 05 A2K-BASE-YEAR PIC 99 VALUE 50. *> pivote: expira 2049 05 A2K-CC PIC 99. 05 A2K-YY PIC 99. 05 A2K-MM PIC 99. 05 A2K-DD PIC 99. IF A2K-YY < A2K-BASE-YEAR MOVE 20 TO A2K-CC *> 2000+AA → años 00..49 ELSE MOVE 19 TO A2K-CC *> 1900+AA → años 50..99 END-IF *> HDR-FEC-BASE, HDR-FEC-PROC, FECINI, FECFIN procesadas con este bridge
Impacto migración: El sistema moderno debe usar fechas ISO 8601 completas (YYYY-MM-DD o timestamp UTC) para todas las fechas del período del estado de cuenta. No replicar el A2K bridge — eliminarlo y validar que todos los procesos aguas abajo (S050, S502, S701) acepten el formato moderno antes del cutover.
RN-S151-363 — Sort de 9 campos ARCH-ORD con detección de ruptura de contrato
COBOL_P158.txt T-STA-003 · T-STA-006 Sort batch COBOL-MCP
P158 ordena todos los registros de movimiento por una clave compuesta de 9 campos (ARCH-ORD REDEFINES). El primer campo KEY-SUBNODO segrega por nodo (permite instancias paralelas de P158 sin colisión). El último campo KEY-AUTS151 garantiza orden cronológico dentro del contrato. Cuando WKS-LLAVE-ACTUAL (primeros 8 campos) cambia respecto al registro anterior, todos los movimientos del contrato anterior se consolidan y escriben como un único registro MOVSXCONT.
* ARCH-ORD REDEFINES — 9 claves de sort (T-STA-006) 01 WKS-SORT-KEY. 05 KEY-SUBNODO PIC X(2). *> 1° — segrega por nodo (paralelismo) 05 KEY-SUCPROM PIC X(4). *> sucursal promotora 05 KEY-TIPO-PROD PIC X(2). *> tipo de producto 05 KEY-CONTRATO PIC X(10). *> número de contrato 05 KEY-PROD PIC X(3). *> producto 05 KEY-INSTRUM PIC X(3). *> instrumento financiero 05 KEY-SUCOPER PIC X(4). *> sucursal operadora 05 KEY-CAJAOPER PIC X(4). *> caja operadora 05 KEY-AUTS151 PIC X(8). *> 9° — orden cronológico dentro del contrato *> Detección de ruptura (T-STA-003): IF WKS-LLAVE-ACTUAL (1:32) NOT = WKS-LLAVE-ANTERIOR (1:32) PERFORM FLUSH-MOVSXCONT *> consolida y escribe registro completo END-IF
Impacto migración: El sort de 9 campos debe reimplementarse como ORDER BY compuesto en el sistema destino. La detección de ruptura equivale a una operación de GROUP BY sobre los primeros 8 campos. El sistema moderno debe garantizar que todos los movimientos de un contrato lleguen al mismo worker (particionamiento por KEY-SUBNODO+KEY-CONTRATO) antes de la agregación.
RN-S151-370 — WKS-SORT-HORA mislabeled: “DD” contiene probablemente segundos
COBOL_P158.txt T-STA-006 Mislabeling desde 1995
El campo de hora en el registro de sort WKS-SORT-HORA usa un REDEFINES con subcampos HH(2)+MM(2)+DD(2). El subcampo nombrado “DD” casi con certeza contiene segundos (SS) — el nombre es un error de nomenclatura en el código fuente original de 1995. No tiene impacto funcional conocido (el valor se ordena correctamente), pero genera confusión al analizar logs de auditoría y al documentar el sistema.
* WKS-SORT-HORA — mislabeled desde 1995 01 WKS-SORT-HORA PIC 9(6). 01 WKS-SORT-HORA-R REDEFINES WKS-SORT-HORA. 05 WKS-HORA-HH PIC 9(2). *> horas (correcto) 05 WKS-HORA-MM PIC 9(2). *> minutos (correcto) 05 WKS-HORA-DD PIC 9(2). *> MISLABEL: nombre "DD" = probable SS (segundos) *> Nomenclatura incorrecta en código fuente de 1995 *> Sin impacto funcional — el ordenamiento cronológico funciona correctamente *> Confunde análisis de logs y auditoría de tiempos de procesamiento
Impacto migración: Al migrar este campo, documentar explícitamente que el subcampo “DD” contiene segundos. Renombrar a SS en el sistema destino para eliminar la ambigüedad. Verificar con análisis de datos reales (valores observados en logs) si efectivamente contiene 00..59 (segundos) y no 01..31 (días) antes de definir el mapping final.

Vocabulario

MOVSXCONT
PIC: X(840)/registro
Archivo principal de movimientos por contrato para S050. Nombre externo incluye NODO-ORIGEN y NODO-DESTINO para particionamiento paralelo sin colisión. Formato: S{SIS}/FILE/S050/{NO}/{ND}/MOV{PROD}/{FEC}. Un registro por contrato — consolida todos los movimientos del período.
ARCH-ORD
PIC: Sort buffer
Buffer de ordenamiento de 9 campos. Garantiza que todos los movimientos del mismo contrato lleguen consecutivos al loop de escritura. Sin equivalente directo en sort SQL moderno — la clave compuesta de 9 campos debe reimplementarse como ORDER BY en el sistema destino.
A2K-BRIDGE-EDOCTA
PIC: PIC 9(08) CCAAMMDD
Fechas de período del estado de cuenta en formato de 8 dígitos post-Y2K. Pivote A2K-BASE-YEAR=50 expira 2049. Aplica a FECINI, FECFIN, HDR-FEC-BASE y HDR-FEC-PROC. El sistema moderno debe eliminar este bridge y usar fechas ISO completas.
NOMPACMOV
PIC: X(12)
Nombre del pack de movimientos activo. Leído de BD99 vía CONSISDIA al inicio. LOG151 y LOG151-COMP (audit trails) se escriben en este pack. Determina qué volumen físico de disco contiene los movimientos del ciclo activo.
LOG151
PIC: DISK X(450)/450 bytes
Audit trail principal de cada movimiento procesado por P158. Archivo secuencial en pack NOMPACMOV. Su contraparte aleatoria es LOG151-COMP X(540 bytes) — ambos registran trazabilidad completa del procesamiento de estados de cuenta.
MOVSXCONTESOF
PIC: X(581)/registro
Subset reducido del MOVSXCONT para S502 (impuestos SAT/CFDI). El sufijo “ON IMPUESTOS” en el nombre externo identifica el pack de destino. Formato: (S502)S{SIS}/FILE/S502/{NO}/{ND}/MOV{PROD}/{FEC} ON IMPUESTOS.
WKS-SORT-HORA
PIC: PIC 9(06) HH+MM+DD
Campo de hora en el registro de sort. El subcampo “DD” es probable mislabeling de segundos — error de nomenclatura en código fuente de 1995 sin impacto funcional conocido. Al migrar, renombrar a SS y verificar con datos reales antes del mapping definitivo.

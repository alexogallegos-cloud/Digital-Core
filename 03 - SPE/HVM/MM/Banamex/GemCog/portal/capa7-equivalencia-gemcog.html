Arquitectura de Performance · Prerequisito DoD-SPE-MM-05
8 patrones para que el SLA del target ≤ SLA del mainframe

La transpilación 1:1 preserva semántica pero hereda el modelo de ejecución secuencial del mainframe. Sin estos patrones el servicio Java puede correr funcionalmente correcto pero 3–10× más lento que el legacy — lo que bloquea DoD-SPE-MM-05 en el parallel-run antes de llegar al 99.99%.

P1I/O de archivos secuenciales
READ NEXT RECORD → syscall por registro
Spring Batch FlatFileItemReader con chunk-size entre 500–2000 registros. BufferedWriter con flush solo al cierre del chunk.
Regla: chunk-size = (TPS legacy × latencia P95 ms) / 1000. Partir de 1000.
P2Cursor COBOL → JDBC row-by-row
FETCH loop 1-a-1 sobre 500K registros
stmt.setFetchSize(1000) obligatorio en cualquier cursor > 10K filas. Procesar en chunks de memoria, no registro a registro.
Regla: el default de JDBC es 1 fila — principal causante de regresión vs. mainframe.
P3BigDecimal en hot path
new BigDecimal(String) en loops de alto volumen
Constantes estáticas fuera del loop para ZERO y valores frecuentes. Usar rs.getBigDecimal(col) directo — el driver JDBC construye BigDecimal sin parseo extra.
Regla: nunca parsear String→BigDecimal dentro del loop de cursor o batch.
P4WORKING-STORAGE → scope de thread
Campo de instancia en @Singleton compartido entre threads
COBOL es single-threaded por invocación. Variables que acumulan estado → locales al método o @StepScope en Spring Batch. Nunca campo de instancia acumulador en bean @Singleton.
Regla: race condition bajo carga produce corrupción silenciosa — no error detectable en QA con un thread.
P5Batch single-threaded → particionado
JCL step de 10M registros traducido como loop Java
Spring Batch PartitionedStep dividiendo el dataset por rango de ID, fecha o BC. Número de particiones = cores × 0.75 (headroom para GC e I/O).
Activar cuando el job procesa > 1M registros o debe completar en < 60% del tiempo del legacy.
P6CALL dentro de loop → HTTP call
CALL 'SUBPROG' en COBOL = salto en memoria ≈ 0ms
Subprogramas llamados dentro de un loop van internalizados como método privado o módulo Maven. Nunca como HTTP call — la latencia de red × iteraciones destruye el SLA.
Solo puede ser microservicio separado si el CALL cruza bounded context y ocurre fuera del hot path.
P7Sin connection pooling
COBOL mantiene una conexión DB por instancia de job
HikariCP con maximum-pool-size calibrado al TPS peak del mainframe (dato de Fase 1 · metrics-report). Nunca dejar el default de 10 conexiones en producción bancaria.
Fórmula: maximum-pool-size = TPS_peak × 1.2 · minimum-idle = TPS_peak × 0.3
P8Strings COBOL fixed-length
PIC X(N) rellena con espacios — trim en cada comparación
El trim se hace una sola vez en el mapper de entrada (al leer del archivo o ResultSet), nunca en la lógica de negocio. La lógica trabaja con Strings ya limpios.
String.equals() con trailing spaces devuelve false — divergencia silenciosa que aparece en el comparator.

Regla de test obligatoria para todos los programas CRONOS2K

Para cada campo de fecha en estos programas, el dataset de golden-master debe incluir tres clases de equivalencia: fecha anterior a 2000-01-01, fecha exactamente 2000-01-01, y fecha posterior a 2000-01-01. Los campos resultantes se anotan @LegacyY2kPatch(reviewRequired=true) — ningún test automatizado sustituye la revisión humana de la lógica de conversión.

Plan de Parallel-Run · ≥ 3 Meses por Wave
Legacy procesa · target observa · comparator valida

El parallel-run corre el legacy en producción y el target en shadow. El comparator contrasta cada output campo a campo y registra divergencias. Finance/Risk firma la reconciliación mensualmente — sin firma, no hay cutover.

Taxonomía de Divergencias
4 tiers · del bloqueo al informativo

No toda divergencia es igual. El tier determina si bloquea el cutover, requiere aprobación regulatoria, o puede documentarse y cerrar.

Tier-1 · 277 campos
CRÍTICO
Campo monetario que afecta balance o posteo GL. Cualquier diferencia en un campo COMP-3 de BC-01 saldo, BC-05 GL, BC-06 movimiento o BC-09 ajuste genera un asiento de ajuste auditable CNBV.
→ P1 inmediato · block cutover · corrección obligatoria antes de continuar
Tier-2 · regulatorio
REGULATORIO
Campo que aparece en reporte CNBV pero no afecta directamente el balance. Incluye campos de fecha en reportes, claves de trayectoria en reportería, indicadores de estado en archivos regulatorios.
→ CR de aceptación firmado por Regulatory + Risk antes de cutover
Tier-3 · operacional
OPERACIONAL
Campo que afecta el procesamiento interno pero no es visible al regulador ni impacta balances. Campos de control de flujo batch, contadores de proceso, indicadores de módulo activo.
→ Bug en backlog · aceptable con justificación documentada por arquitecto
Tier-4 · informativo
INFORMATIVO
Campo de display, código de estado, mensaje de texto. No afecta lógica de negocio ni cómputo. Incluye labels, textos de error, códigos de módulo.
→ Puede cerrar sin corrección si stakeholder acepta formalmente

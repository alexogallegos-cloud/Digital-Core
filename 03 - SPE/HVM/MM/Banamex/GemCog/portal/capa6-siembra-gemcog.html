ADRs Pendientes
Decisiones que desbloquean implementación

Tres ADRs identificados en Capa 6. Los dos marcados como bloqueantes impiden avanzar a transpilación en los BCs afectados.

🟡
ADR-SPE-MM-002
Stack Java · COBOL→Java Types · BigDecimal Strategy
Java 21 + Spring Boot 3 / Quarkus como stack target. Mapeo de tipos COBOL→Java: COMP-3 / PIC S9 → BigDecimal(4, HALF_EVEN) serializado como String en JSON. Fechas 9(8) → LocalDate con validación explícita de era (CRONOS2K). Ratio de review humano por dominio.
⚡ En progreso — Specialist Transpilation
🔴
ADR-SPE-MM-003
DISEÑO-GENERICO S151 — Factory vs Strategy para 19 Instancias
L030 y P015 (ASINCRONO GL) son un solo componente genérico instanciado 19 veces en S151 — una por cada sistema externo (S500, C402, C600, S804, S707, S203 Tandem, Citibank, etc.). El target debe decidir: Factory Method (una clase por sistema) vs Strategy Pattern (comportamiento inyectable). La decisión impacta el diseño de package, los tests de equivalencia por instancia y la configuración de Kafka consumers.
🚫 BLOCKING — BC-06 Movimientos Service no puede implementarse sin este ADR
🔴
ADR-SPE-MM-004
L039 ALGOL RETAIN — Adapter Strategy durante Coexistencia
L039 (ACCESOBD04, 11.7K LOC ALGOL) es la librería más grande de S500 — gestiona acceso a BD04TARJETAS. Está en el pool RETAIN de Unisys ClearPath. En Wave 1 la lógica COBOL que la invoca se transpila, pero L039 sigue ejecutándose en el mainframe. Opciones: JNI adapter (latencia baja, complejidad alta), HTTP microservice wrapper (latencia media, desacoplamiento claro), REWRITE total (riesgo alto, sin parallel-run para L039 ALGOL). La elección define el plan de coexistencia BC-03.
🚫 BLOCKING — BC-03 Tarjetas Service Wave 1 requiere este ADR antes de implementar

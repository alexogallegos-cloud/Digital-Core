CORE-DEP · P191 a Java 21 Spring Boot

P191 lee de CORE-DEPB02CONTROL la fecha de línea, el CSI y la fecha del último archivo aplicado, y decide si procesa todas las fechas pendientes o solo la fecha que llega por TASKVALUE. Por cada fecha espera a que estén residentes los archivos de punteo de S054 (uno por cada día inhábil anterior), concentra los seis archivos de CORE-DEP en un temporal y ordena ambos lados por número de tarjeta e importe. Un recorrido de mezcla clasifica cada movimiento en aplicado o en diferencia y emite dos listados con totales. Al terminar cada fecha en modo normal, o en reproceso válido, calcula el siguiente día hábil y lo graba en B02CONTROL dentro de una transacción.

enum TipoProceso { NEUTRALIZADO, NORMAL, REPROCESO }   // WKS-TIPO-PROCESO 0, 8, 9

record VentanaPunteo(TipoProceso tipo, LocalDate inicio, LocalDate fin) {

    /** 30010000-DECIDE-TIPO-PROCESO. fechaParametro viene de TASKVALUE (W77-VAL-191). */
    static VentanaPunteo decide(Optional<LocalDate> fechaParametro, FechasControl c) {
        if (fechaParametro.isEmpty()) {
            return new VentanaPunteo(TipoProceso.NORMAL, c.ultimoArchivoAplicado(), c.fechaLote());
        }
        LocalDate f = fechaParametro.get();
        TipoProceso tipo = f.isAfter(c.ultimoArchivoAplicado())
                ? TipoProceso.REPROCESO           // W77-REPROCESO-VAL = 1
                : TipoProceso.NEUTRALIZADO;       // tipo 0: procesa la fecha pero no mueve B02
        return new VentanaPunteo(tipo, f, f);
    }

    boolean actualizaControl() { return tipo != TipoProceso.NEUTRALIZADO; }
}

@Component
@StepScope
@RequiredArgsConstructor
class EsperaArchivoS054Tasklet implements Tasklet {

    private final ArchivosS054 archivos;            // un archivo por día natural (incluye inhábiles previos)
    private final VentanaHoraria ventana;
    private final P191Properties props;             // p191.s054.reintento: PT20S

    @Override
    public RepeatStatus execute(StepContribution c, ChunkContext ctx) throws InterruptedException {
        for (Path p : archivos.requeridos()) {      // 60070000-OBTEN-NUM-ARC-S054
            while (!Files.exists(p)) {               // ATTRIBUTE RESIDENT = 0
                ventana.verificaCorte(p, archivos.fechaLinea());   // 60074000-VERIFICA-CAMBIO
                Thread.sleep(props.s054().reintento().toMillis());   // WAIT (20)
            }
            archivos.validaHeader(p);               // 50032000-ABRE-Y-VAL-ARC-S054
        }
        return RepeatStatus.FINISHED;
    }
}
@Component
@RequiredArgsConstructor
class VentanaHoraria {
    private final Clock reloj;
    private final P191Properties props;        // p191.s054.hora-limite: 09:00:00, aviso-cada: 90 (30 min con reintento de 20 s)
    private int ciclos;                          // WKS-CON-TIME

    /** 60074000-VERIFICA-CAMBIO + 60075000-LEYENDA. */
    void verificaCorte(Path faltante, LocalDate fechaLinea) {
        ciclos++;
        boolean mismoDia = LocalDate.now(reloj).equals(fechaLinea);   // B02-FECHA-LINEA = fecha de máquina
        if (mismoDia && LocalTime.now(reloj).isAfter(props.s054().horaLimite())) {
            log.warn("ARCHIVO {} NO EXISTE, ESTOY FUERA DE HORARIO TERMINO SIN PUNTEO", faltante);
            throw new JobInterruptedException("SIN PUNTEO");   // hoy: 90000000-FIN, STOP RUN normal
        }
        if (ciclos % props.s054().avisoCada() == 0) {
            log.warn("ARCHIVO {} NO EXISTE, HORARIO LIMITE {} FAVOR DE PONERLO RESIDENTE",
                     faltante, props.s054().horaLimite());
        }
    }
}

/** Resultado de comparar la cabeza de cada archivo. */
sealed interface Punteo permits Punteo.Aplicado, Punteo.SoloCORE-DEP, Punteo.SoloS054 {
    record Aplicado(MovimientoCORE-DEP core-dep, MovimientoS054 s054) implements Punteo {}
    record SoloCORE-DEP(MovimientoCORE-DEP core-dep) implements Punteo {}
    record SoloS054(MovimientoS054 s054) implements Punteo {}

/** 20015100-EFECTUA-MATCH sobre dos PeekableItemReader ordenados por (tarjeta, importe). */
@Component
@StepScope
@RequiredArgsConstructor
class ConciliacionReader implements ItemReader<Punteo> {
    private final SingleItemPeekableItemReader<MovimientoCORE-DEP> core-dep;
    private final SingleItemPeekableItemReader<MovimientoS054> s054;

    private static final Comparator<Llave> ORDEN =
            Comparator.comparing(Llave::tarjeta).thenComparing(Llave::importe);

    @Override
    public Punteo read() throws Exception {
        var a = core-dep.peek();
        var b = s054.peek();
        if (a == null && b == null) return null;                 // ambos EOF
        if (a == null) return new Punteo.SoloS054(s054.read());
        if (b == null) return new Punteo.SoloCORE-DEP(core-dep.read());
        int cmp = ORDEN.compare(a.llave(), b.llave());
        if (cmp == 0) return new Punteo.Aplicado(core-dep.read(), s054.read());
        return cmp > 0 ? new Punteo.SoloS054(s054.read())        // el menor avanza
                       : new Punteo.SoloCORE-DEP(core-dep.read());
    }
}

Riesgos de migración
Números de tarjeta en archivos públicos y reportes

El temporal CORE-DEP-I01-TEMP se declara SECURITYTYPE IS PUBLIC (línea 170) y ambos temporales se cierran WITH SAVE porque el WITH PURGE está comentado (líneas 1576-1580). Los listados de aplicados y diferencias imprimen el campo NUMTC de 16 dígitos completo. Es un hallazgo de cumplimiento PCI DSS si el campo es el PAN.

Llave de conciliación débil

El SORT y la mezcla usan solo número de tarjeta e importe (líneas 1549-1551 y 1589-1592). Movimientos distintos con la misma tarjeta e importe, o un cargo contra un abono, se dan por aplicados.

Reproceso que salta fechas pendientes

Un reproceso válido exige una fecha posterior al último aplicado (línea 1974) y al terminar graba el día hábil siguiente a esa fecha. Las fechas intermedias quedan sin punteo en modo normal.

Fin normal sin conciliación

Después de las 09:00 sin archivo de S054, 60074000-VERIFICA-CAMBIO termina con STOP RUN (líneas 3023-3039) sin actualizar B02 y sin estado de error.

Hardcodes

La fecha de arranque 20061231, la clave de abono 3047, la hora límite 09:00:00, la semana de calendario 65, el reintento de 20 segundos, el aviso cada 90 ciclos y el tope de 90 posiciones para días inhábiles hacia atrás están compilados. Se trasladan a application.yml.

Pendiente de revisión SME
  • Confirmar que el campo NUMTC de CORE-DEP y S054 es el número de tarjeta completo (PAN) y no un número de contrato o cuenta de 16 dígitos.
  • RN-CORE-DEP-267 dice que el tipo 0 neutraliza el reproceso; en el fuente la fecha sí se procesa y se generan los reportes (rama ELSE de las líneas 1238-1239), solo que no se actualiza B02. Revisar la redacción.
  • Los archivos de S054 traen la fecha del detalle en 6 dígitos (E01-REG-S054-DET-FEC PIC 9(06), línea 249); no se revisó qué pivote de siglo aplica el formateo del reporte.
  • La condición de B02-NUM-CSI = 10 que limitaba el proceso a Valle de México está comentada (líneas 1980-1984); confirmar si P191 corre hoy en ambos CSI.
  • No se revisaron los párrafos 50021100 a 50021600 de apertura y validación de header de los seis archivos de CORE-DEP.

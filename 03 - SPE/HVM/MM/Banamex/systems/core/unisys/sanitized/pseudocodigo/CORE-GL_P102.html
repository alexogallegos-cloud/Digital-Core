P102 · Transferencia de Archivos entre Equipos Unisys (CORE-GL)

CORE-GLProgramaCOBOL

Fuente: COBOL_P102.cbl (856 LOC)

Rol en batch: Utilitario de transferencia inter-nodo — posición WFL_LOTE: P021 → P102 → P104

Convenciones: nombres traducidos (Unisys→legible); [P102 Lnnnn] = origen en fuente; (BR: RN-...) = regla de negocio.

1. Resumen funcional

P102 (PROGRAM-ID: CALLLIBCTL) es el utilitario de transferencia de archivos físicos entre equipos Unisys del ecosistema CORE-GL. Su función es resolver qué par de nodos (origen ↔ destino) corresponde al host donde corre el batch, construir el comando de transferencia y ejecutarlo mediante la librería XFER. El programa recibe cuatro parámetros de ejecución: usercode del solicitante (WKS-USER), nombre del archivo a transferir (WKS-ARCHIVO), pack de origen y pack de destino.

La topología de enrutamiento está hardcodeada: ocho hosts formando cuatro pares fijos (ACYPGAMA↔MONALFA, VDMALFA↔MONBETA, ACYPBETA↔VDMBETA, ACYPOMEGA↔VDMKAPPA). Dos excepciones sobreescriben el ruteo estándar: archivos contables CORE-DEP/S701 con CSI 10 ó 12 se redirigen al usercode S702; el archivo de movimientos por terminal (S711/FILE/MOVSXTERM) se redirige al usercode S028. Si la librería XFER falla, el programa no aborta — degrada de forma controlada emitiendo un mensaje al operador para copia manual.

2. Datos y archivos

2.1 FILE-CONTROL / FD

Ninguno. P102 no tiene archivos propios (no FILE-CONTROL, no FD). Toda E/S se realiza a través de llamadas a librerías externas (XFER, SOPORTECOMS).

```
PROCEDIMIENTO Cargar_Librerias():
    // Configuración de atributos de la librería XFER (motor de transferencia inter-nodo)
    CAMBIAR ATRIBUTO LIBACCESS    DE "XFER"       A BYFUNCTION  // P102 L727
    CAMBIAR ATRIBUTO FUNCTIONNAME DE "XFER"       A "XFER"      // P102 L728

    // Configuración de CTLVER (validador de versión de librerías)
    // Vocab: CTLVERS = módulo de control de versiones; punto de fallo si hay desalineación
    CAMBIAR ATRIBUTO LIBACCESS    DE "CTLVER"     A BYFUNCTION  // P102 L730
    CAMBIAR ATRIBUTO FUNCTIONNAME DE "CTLVER"     A "CTLVERS"   // P102 L731

    // Configuración de SOPORTECOMS (librería de identificación de host/CSI)
    CAMBIAR ATRIBUTO LIBACCESS    DE "SOPORTECOMS" A BYFUNCTION // P102 L733-L735
    CAMBIAR ATRIBUTO FUNCTIONNAME DE "SOPORTECOMS" A "SOPORTECOMS"

    // Configuración de LIB-DISP (librería de despliegue de mensajes al operador)
    CAMBIAR ATRIBUTO TITLE DE "LIB-DISP"
        A "(S000)S000/UTILITY/DESPLIEGA/OBJ/LIB ON PACK"       // P102 L737-L738  ⚠ [HARDCODE]

    // Obtener identificación del host donde corre el batch
    // → Puebla WKS-HOST: WKS-NUMCSI (CSI activo), WKS-NOM-HOST (nombre de máquina), etc.
    LLAMAR "CSIID OF SOPORTECOMS" CON WKS-HOST                  // P102 L740

    // Liberar librerías que ya no se necesitan en esta inicialización
    LIBERAR "SOPORTECOMS"                                        // P102 L742
    LIBERAR "CTLVER"                                             // P102 L743
```

```
PROCEDIMIENTO Enviar_Archivo():
    // Armar el buffer del comando XFER desde el área de título construida en §3
    // WKS-TITULO-ARCH-CAP contiene el comando ADD completo con todos los campos
    // ya resueltos: usercode origen/destino, nombre de archivo, pack y nodo origen/destino
    MOVER WKS-TITULO-ARCH-CAP  A WS-TRF-COMANDO                  // P102 L818
    MOVER 193                  A WS-TRF-TAMACOM                   // P102 L819  ⚠ [HARDCODE]

    // Ejecutar la transferencia vía librería XFER
    // ENVIA_XFER: función de transferencia inter-nodo de la librería XFER de Unisys
    // Retorna: WS-TRF-RESULT = 0 → éxito; > 0 → error de transferencia
    LLAMAR "ENVIA_XFER IN XFER"
        CON WS-TRF-COMANDO, WS-TRF-TAMACOM
        DEVOLVIENDO WS-TRF-RESULT                                 // P102 L820-L822

    // Manejo de error con degradación controlada (sin ABORT)
    SI WS-TRF-RESULT > 0 ENTONCES                                 // P102 L824
        // Tipo de mensaje = "O" (operador)
        // Código de error fijo: 020101
        MOVER "O"          A TIPO-LJ                              // P102 L825
        MOVER 020101       A CODIGO-LJ                            // P102 L826  ⚠ [HARDCODE]
        CONCATENAR
            "ERROR AL LLAMAR LIBRARY XRAPID PARA ARCHIVO ",
            WKS-ARCHIVO,
            " FAVOR DE COPIAR MANUALMENTE EL ARCHIVO ",
            WKS-TITULO-ARCH-CAP
            EN TEXTO-LJ                                           // P102 L827-L830
        LLAMAR "LJ IN LIB-DISP"
            CON CONTADOR-LJ, MENSAJE-LJ                           // P102 L831-L832
        // El programa NO aborta — continúa con STOP RUN ⚠ [DESCARTE-SILENCIOSO]
    FIN-SI
    « [P102 L816-L832] · BR: RN-CORE-GL-909 »
```

5.1 Notas de cobertura

  • RN-CORE-GL-775 (rules-core-gl-contabilidad-a.md — "Ruteo especial de correspondencia sólo al paso P102 para S264"): esta regla describe una dependencia batch en WFL (literal "CORRESOLO P102 S264") — no se materializa en código COBOL de P102 sino en la orquestación WFL; no tiene sección en este pseudocódigo.
  • Hardcodes de negocio identificados: topología de 8 nodos (L747-L777), rutas de archivo CORE-DEP/S701/S711 (L780-L812), CSI 10/12 (L785), longitud de comando XFER 193 (L819), código de error 020101 (L826), ruta de librería de despliegue (L738).
  • Código muerto: 5 sentencias DISPLAY comentadas (L707-L710, L722) — trazas de depuración desactivadas en producción.
  • Antipatrón: dos ramas ELSE faltantes en los IFs anidados de nodos (L747-L777 y L833-L856): un host no reconocido no genera error explícito — el nodo destino queda con el valor previo.

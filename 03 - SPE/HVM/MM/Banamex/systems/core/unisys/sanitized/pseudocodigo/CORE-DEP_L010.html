1. Resumen funcional

CORE-DEPL010CTRL es la librería de control central (single point of control) del sistema de captación CORE-DEP. Es el proceso residente que arranca antes que los programas de aplicación, se congela como librería MCP (FREEZE(TEMPORARY) [L010 L13804]) y queda enlazada por todas las copias de los programas anfitriones (P010 gateway de línea, P014, P020, P050, P008, P015…). Concentra, en un único espacio de direcciones compartido, el estado global del sistema: qué copias están vivas y en qué mezcla (MIX) corren, qué contrato tiene bloqueado cada copia, en qué fase del día está el sistema (línea / prebatch / prelínea / fin-prelínea / batch / fin-batch / restablece-24hrs / recuperación), el último folio/autorización/secuencial asignado, el tipo de cambio vigente, el status de contingencia de 20+ sistemas satélite y los catálogos de control cargados en memoria.

Expone 68 puntos de entrada (EXPORT [L010 L13728-L13802]) que los clientes invocan como procedimientos de librería. La fachada COBOL lib010 (copybook CORE-DEP/INC/L010/lib010.cbl) consume 44 de esos 68 mediante 53 párrafos wrapper 0000-CALL-CORE-DEPL010xxx; los 24 restantes los consumen clientes ALGOL/COBOL distintos (familia …P020, AVIFINDIA/AVIINIDIA, BAJAESCALON, CONSTRZOS, GENERALOG, FECGENMDA, SDOPEND, CIERRAMOV, SOLSECDIA, SINCRHI163, INICIOXPGM…). Ver §5.2 para el cruce completo.

Funcionalmente hace cinco cosas que ningún programa de aplicación puede hacer por sí solo:

  1. Serializar el acceso concurrente entre las 14 copias del P010 (DF_NUMCOPIAS_P010 = 14 [L010 L319]) y las copias de P014/P020/P050, usando 34 INTERLOCK globales [L010 L392-L428] y 40+ EVENT de sincronización [L010 L378-L464].
  2. Orquestar el ciclo de día del sistema (prebatch → prelínea → fin-prelínea → batch → fin-batch → restablece-24hrs), con la mecánica "una copia dispara la fase, las demás esperan el evento y confirman" (PREBATCH/ESPREBTCH/CONFIRMHI).
  3. Administrar la bitácora transaccional (LOG) — un DIRECT FILE de acceso aleatorio por número de registro [L010 L81] — que es a la vez log de movimientos, mecanismo de recuperación (LEELOG) y sede del header de contingencias de los sistemas satélite [L010 L1141-L1258].
  4. Ser el semáforo operativo (HI): mantiene tareas hijas (HIS, HISP014, HISP020, MONIP010, MONIP050, MONINEW) que escuchan comandos HI <taskvalue> del operador de consola y traducen ese número a una acción sobre el estado global (activar/desactivar contingencias, forzar cierres, disparar WFL, pedir sucursal a monitorear…).
  5. Ser el único cliente de las bases DMSII de control (CORE-DEPBD01CAPTACION, CORE-DEPBD02AUXILIAR, CORE-DEPBD03MSGAAPLI) para los datasets de control B01/B02/B00, dejando a los programas el acceso a datasets de negocio.

(BR: RN-CORE-DEP-893) — el pack describe la librería como "administra parámetros, banderas de control y estado global del sistema (capa 10.1.1) … transversal a los flujos de aplicación (P010)". La fuente confirma y amplía: además de parametría, la librería implementa el motor de fases del día, la bitácora/recuperación, la asignación de folios y el bus de comandos HI. La fórmula del pack (LEE_PARAMETRO(clave) / EVALUA_CONTROL(bandera)) es una simplificación: no existe un entry point genérico de lectura de parámetro; cada parámetro tiene su propio entry point tipado. Ver « divergencia KB: RN-CORE-DEP-893 » en §5.3.

        ⚠ `[RIESGO-BLOQUEO]` ciclo sin salida: si una copia nunca se levanta, el arranque **no termina nunca**.
        Finalmente: contador de recuperados := 0; propagar el indicador de saldo pendiente; limpiar `BA_COP_PUEDO_REC[*]`.
      **(6)** `B_NOCHECO_RECOVER := VERDADERO`; cerrar LOG con LOCK y releer su header; si hay recuperación, reabrir `LOG2`.
      « ⚠ [CÓDIGO-MUERTO] bloque de `ACCEPT` de depuración `"<L010> DS DS?"` comentado [L010 L6985-L6989];

@Component
@RequiredArgsConstructor
public class CambioEstadoSistemaTasklet implements Tasklet {   // PROGRAM-ID CALLLIBCTL (P602)

    private final LibreriaControl libCtl;
    private final ReporteOperador operador;     // LJ IN LIB-DISP: S0151/P602/002

    @Override
    public RepeatStatus execute(StepContribution contribution, ChunkContext ctx) {
        var p = CambioEstadoParams.de(ctx.getStepContext().getStepExecution().getJobParameters());
        var consulta = libCtl.consultaSistema(p.sistema(), 0, 0);       // 000300, primera parte
        if (!consulta.ok()) operador.info(51001, "ERROR AL CONSULTAR B04");
        var cambio = libCtl.cambiaSistema(base(consulta, p).conEstatus(p.estatus()));
        if (!cambio.ok()) operador.info(51001, "ERROR AL ACTUALIZAR B04");
        // STOP RUN: el fuente termina normal aunque ambas llamadas fallen.
        contribution.setExitStatus(cambio.ok() ? ExitStatus.COMPLETED
                                               : new ExitStatus("COMPLETED_WITH_ERRORS"));
        return RepeatStatus.FINISHED;
    }
}

@Configuration
public class LibreriaControlConfig {

    /** 000200-LIBRERIAS: DAME_TIT IN CTLVER; si falla, título fijo. */
    @Bean
    LibreriaControl libreriaControl(CatalogoVersiones ctlvers, LibCtlProperties props,
                                    LibreriaControlFactory factory) {
        String titulo = ctlvers.dameTitulo(props.idCatalogo())
                .filter(r -> r.codigo() == 0)
                .map(CatalogoVersiones.Resultado::titulo)
                .orElseGet(() -> {
                    log.warn("CTLVERS sin título para {}; se usa respaldo", props.idCatalogo());
                    return props.tituloRespaldo();
                });
        return factory.para(titulo);       // versión de la librería elegida al arrancar
    }
}

CambioEstadoSistemaTasklet.java · LibreriaControlJpa.javaJPA · @TransactionalJava 21
    /** 000300-LLAMA-LIBCTL, primera parte: función 1 de B04SISTEM. */
    private SistemaControl base(ResultadoLibCtl consulta, CambioEstadoParams p) {
        // Solo se informa WKS-B04-SISTEMA; producto e instrumento conservan el contenido
        // inicial de WORKING-STORAGE (no tienen VALUE). Aquí se envían en cero explícito.
        if (consulta.ok()) {
            return consulta.registro();
        }
        // El fuente no detiene el flujo: el cambio se envía con lo que haya en el bloque.
        log.warn("ERROR AL CONSULTAR B04 sistema={} codigo={}", p.sistema(), consulta.codigo());
        return new SistemaControl(37, p.sistema(), 0, 0, "", "", p.estatus());
    }
@Service
@RequiredArgsConstructor
public class LibreriaControlJpa implements LibreriaControl {

    private final SistemaControlRepository b04;          // CORE-GLBD99CONTROL.B04SISTEM

    /** MANTB04SISTEM función 37: la validación del estatus vive aquí, no en P602. */
    @Override
    @Transactional
    public ResultadoLibCtl cambiaSistema(SistemaControl r) {
        return b04.findBySistema(r.sistema())
                .map(e -> {
                    e.setEstatus(r.estatus());            // p. ej. 3 = cierre del día
                    return new ResultadoLibCtl(0, r);
                })
                .orElseGet(() -> new ResultadoLibCtl(1, r));
    }
}

Riesgos de migración
Fallo silencioso hacia la WFL

Las dos llamadas a la librería (líneas 728 y 743) solo informan el error al operador y el programa siempre termina con STOP RUN normal (línea 696). La WFL que invoca P602 no puede saber que el estatus no cambió.

Resultados negativos ignorados

W77-RESULT-LIBCON es PIC S9(11) BINARY pero solo se evalúa > 0 (líneas 730 y 745); un código negativo de la librería se trata como éxito.

Campos de consulta sin inicializar

Antes de la función 1 solo se mueve WKS-B04-SISTEMA; producto e instrumento, que el copy documenta como requeridos (líneas 371-373), conservan su contenido inicial.

Cambio aplicado aun si la consulta falló

El cambio con función 37 se ejecuta aunque la consulta haya fallado, con el bloque en el estado que dejó la llamada anterior.

Mensajes de error con tipo informativo

Los errores se emiten con TIPO-LJ 'I' y código 051001 (líneas 691-692), igual que un mensaje informativo.

Título de respaldo compilado

El título '(CORE-GL)CORE-GL/OBJECT/L001/CONTROL ON CMEMP' (línea 713) está en el código y se usa sin aviso cuando CTLVERS falla.

Pendiente de revisión SME
  • La lógica real de validación y actualización del estatus está en MANTB04SISTEM dentro de CORE-GLL001CTL, que no forma parte de este fuente; la implementación LibreriaControlJpa es ilustrativa.
  • Confirmar si la librería devuelve códigos negativos y qué significan, para decidir si la condición > 0 debe ampliarse.
  • Confirmar qué contenido tienen WKS-B04-PRODUCTO y WKS-B04-INSTRUM al ejecutar la consulta y si B04SISTEM los usa para localizar el registro.
  • RN-CORE-GL-557 atribuye el catálogo 1, 19, 22 y 37 a B04SISTEM; el fuente lo documenta para B05PROCESOS y para B04SISTEMA solo lista las funciones 1 y 2. Validar con el SME.
  • Confirmar con el SME el catálogo de valores de ESTATUS (RN-CORE-GL-558 menciona 3 = cierre según P677) para documentarlo en la validación.

Obtiene la fecha de proceso del sistema 264 con CONSISDIA (o del VALUE del WFL si viene informado) y abre el archivo diario CORE-GL/FILE/MOVS264/AAMMDD. En el INPUT PROCEDURE de un SORT filtra los movimientos activos y aprobados de origen local o foráneo y libera un registro por cada una de sus cinco claves de transacción menores a 2000. En el OUTPUT PROCEDURE agrupa por referencia, moneda y sucursal inicial, separa las claves 1 a 999 como envíos a S028 y las 1000 a 2998 como envíos a S115, y cuando los totales no cuadran imprime el detalle de ambos lados. Al final escribe la suma de diferencias por sistema y la de importes correctos.

public record MovimientoS264(

    /** Llave de agrupación real del OUTPUT PROCEDURE (la CVETRAN solo ordena dentro del grupo). */
    public record Grupo(int moneda, int sucInic, BigInteger refNum) {}

    public Grupo grupo(int moneda) { return new Grupo(moneda, sucInic, refNum); }

    public Destino destino() {
        if (cveTran > 0 && cveTran < 1000) return Destino.S028;
        if (cveTran > 999 && cveTran < 2999) return Destino.S115;

    }
}

@Configuration
public class DiferenciasS264JobConfig {

    /** 20000-GEN-BITACORA: SORT ... INPUT PROCEDURE 30000 ... OUTPUT PROCEDURE 40000. */
    @Bean
    Job diferenciasS264(JobRepository repo, Step seleccionaMovimientos, Step reportaDiferencias) {
        return new JobBuilder("CORE-GLP128", repo)
                .start(seleccionaMovimientos)   // INPUT PROCEDURE: filtra y explota a staging
                .next(reportaDiferencias)       // OUTPUT PROCEDURE: lee ordenado y compara
                .build();
    }

    /** El orden ASCENDING KEY del SORT pasa al ORDER BY del lector del segundo step. */
    static final Map<String, Order> ORDEN = new LinkedHashMap<>() {{
        put("MONEDA", Order.ASCENDING);
        put("SUC_INIC", Order.ASCENDING);
        put("REFNUM", Order.ASCENDING);
        put("CVETRAN", Order.ASCENDING);
        put("ID", Order.ASCENDING);         // desempate estable; el SORT de MCP no lo garantiza
    }};
    // 70000-CALCULA-ESPACIO (MEMORY SIZE y DISK SIZE en palabras de 48 bits) no tiene
    // equivalente: el motor de base de datos dimensiona el ordenamiento.
}
/** 30200-LEE-MOVS264 + 30300-ALSORT: un registro de entrada genera de 0 a 5 registros. */
@Component
public class ExplotaClavesProcessor implements ItemProcessor<RegistroMovs264, List<MovimientoS264>> {

    private static final int TOPE_CLAVE = 2000;

    @Override
    public List<MovimientoS264> process(RegistroMovs264 r) {
        // El registro con FUNCION = 99 lo trata el lector como fin lógico de archivo.
        boolean califica = r.funcion() == 1 && r.status() == 1
                && (r.origen() == 1 || r.origen() == 2);
        if (!califica) return null;                          // filtrado
        List<MovimientoS264> salida = new ArrayList<>(5);
        for (ClaveImporte ci : r.clavesImporte()) {          // CVETRAN1..5 / IMPORTE1..5
            if (ci.clave() < TOPE_CLAVE) {                   // incluye la clave 0 de posiciones vacías
                salida.add(MovimientoS264.de(r, ci.clave(), ci.importe()));
            }
        }
        return salida;
    }
}

/** Acumulado de un grupo (referencia, moneda, sucursal inicial). */
final class GrupoAcumulado {
    final MovimientoS264.Grupo llave;
    final List<ClaveImporte> s028 = new ArrayList<>();   // WKS-TABLA-P028 OCCURS 5000
    final List<ClaveImporte> s115 = new ArrayList<>();   // WKS-TABLA-P115 OCCURS 5000
    BigDecimal total028 = BigDecimal.ZERO.setScale(2);  // W77-TOT-IMP028 9(16)V99
    BigDecimal total115 = BigDecimal.ZERO.setScale(2);

    GrupoAcumulado(MovimientoS264.Grupo llave) { this.llave = llave; }

    /** 46420-ACUMULA. */
    void acumula(MovimientoS264 m) {
        switch (m.destino()) {
            case S028 -> { s028.add(new ClaveImporte(m.cveTran(), m.importe())); total028 = total028.add(m.importe()); }
            case S115 -> { s115.add(new ClaveImporte(m.cveTran(), m.importe())); total115 = total115.add(m.importe()); }
            case NINGUNO -> { }                         // clave 0: se ignora
        }
    }
}

/** 41000-GEN-BITACORA: si cambia la llave, se evalúa el grupo anterior y se abre uno nuevo. */
void procesa(MovimientoS264 m, int moneda) {
    var llave = m.grupo(moneda);
    if (actual == null || !actual.llave.equals(llave)) {
        if (actual != null) evaluaGrupo(actual);        // 46430-IMPRIME
        actual = new GrupoAcumulado(llave);
    }
    actual.acumula(m);
}
/** 46430-IMPRIME. */
void evaluaGrupo(GrupoAcumulado g) {
    if (g.total028.compareTo(g.total115) == 0) {
        totalCorrectas = totalCorrectas.add(g.total028);     // W77-TOT-BIEN
        return;
    }
    // Comportamiento del fuente: solo se reporta si hubo al menos un envío a S028.
    if (!g.s028.isEmpty() || props.reportarSoloS115()) {      // p128.reportar-solo-s115: false
        g.s028.forEach(ci -> reporte.detalle(g, ci, g.llave.sucInic()));   // 26450-IMP-028
        g.s115.forEach(ci -> reporte.detalle(g, ci, sucProm));              // 26460-IMP-115
        reporte.lineaEnBlanco();
        malS028 = malS028.add(g.total028);                     // W77-MAL-028
        malS115 = malS115.add(g.total115);                     // W77-MAL-115
    } else {
        log.warn("Grupo {} con S115={} y sin envío a S028: el fuente no lo reporta", g.llave, g.total115);
    }
}

Riesgos de migración
Último grupo sin comparar

42000-IMPRIMIR termina el bucle de 41000-GEN-BITACORA con el fin del SORT y pasa directo a 42000-TOTALES (líneas 1955-1956) sin evaluar el grupo en curso. La diferencia del último grupo se pierde.

Grupos solo con S115 no se reportan

En 46430-IMPRIME el detalle y la suma a W77-MAL-115 están dentro de IF W77-028 > ZEROS (líneas 1988-1997). Un grupo descuadrado sin envíos a S028 no aparece en el reporte.

Tablas de 5000 sin control de límite

WKS-TABLA-P028 y WKS-TABLA-P115 tienen OCCURS 5000 (líneas 1477 y 1482) y se llenan sin validar el índice.

Resultado de CONSISDIA ignorado

El CALL de la línea 1728 recibe W77-RESULT pero no se evalúa; una falla de la librería deja la fecha de proceso y el pack del archivo sin validar.

Rango de claves inconsistente

30300-ALSORT solo libera claves menores a 2000 y 46420-ACUMULA define S115 como 1000 a 2998. Las claves 2000 a 2998 nunca llegan al reporte.

Hardcodes

Sistema 264 fijo en CONSISDIA, redirección del CSI 12 al 10, título de librería de respaldo (CORE-GL)CORE-GL/OBJECT/L001/CONTROL ON CMEMP y nombre de reporte 001CORE-GLDIFS264. Se trasladan a application.yml.

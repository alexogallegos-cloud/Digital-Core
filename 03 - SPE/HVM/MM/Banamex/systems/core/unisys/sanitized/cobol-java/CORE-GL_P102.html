CORE-GL · P102 a Java 21 Spring Boot

P102 recibe cuatro parámetros: el usercode, el título del archivo y los packs de origen y destino. Pregunta a SOPORTECOMS en qué equipo corre y, con una tabla fija de ocho equipos agrupados en pares, decide el nodo origen y el nodo destino. Algunos archivos cambian de usercode destino: PROTCOB y cuatro archivos E01 de CORE-DEP y S701 van a S702 (estos últimos solo en CSI 10 o 12) y MOVSXTERM de S711 va a S028, con su propio nodo destino. Arma un comando ADD ... AS ... FROM ... TO ... de 193 posiciones y lo entrega a ENVIA_XFER; si falla, solo avisa al operador para que copie el archivo a mano.

/** WKS-TITULO-ARCH-CAP: 192 posiciones; se entrega a XFER con longitud 193. */
public record ComandoXfer(String usercodeOrigen, String archivo, String usercodeDestino,
                          String archivoDestino, String packOrigen, String nodoOrigen,
                          String packDestino, String nodoDestino) {

    public String texto() {
        return "ADD " + fijo("(" + usercodeOrigen + ")", 6) + fijo(archivo, 55)
             + " AS (" + fijo(usercodeDestino, 4) + ")" + fijo(archivoDestino, 55)
             + " FROM " + fijo(packOrigen, 16) + "," + fijo(nodoOrigen, 9)
             + " TO " + fijo(packDestino, 16) + "," + fijo(nodoDestino, 9);
    }

    /** Igual que un MOVE alfanumérico: trunca a la derecha y rellena con espacios. */
    private static String fijo(String s, int n) {
        String v = (s == null) ? "" : s;
        if (v.length() > n) {
            throw new TituloTruncadoException(v, n);    // el COBOL truncaría en silencio
        }
        return String.format("%-" + n + "s", v);
    }
}

/** VL38112 2020: PROTCOB siempre; los cuatro E01 de CORE-DEP/S701 solo en CSI 10 o 12. */
private static final List<String> E01_S702 = List.of(
        "CORE-GL/FILE/E01/CORE-DEPALRCD/", "CORE-GL/FILE/E01/S701OCMCD/",
        "CORE-GL/FILE/E01/CORE-DEPAHRCD/", "CORE-GL/FILE/E01/CORE-DEPACCCD/");

boolean vaAS702(SolicitudTransferencia s, Equipo eq) {
    return s.archivo().startsWith("CORE-GL/FILE/PROTCOB/")                 // WKS-NOM-S015 X(18)
        || (E01_S702.stream().anyMatch(s.archivo()::startsWith)          // WKS-NOM-CORE-GL X(24)
            && (eq.csi() == 10 || eq.csi() == 12));
}

// destinoS702 en application.yml: VDMALFA y MONBETA -> VDMALFA; ACYPGAMA y MONALFA -> ACYPGAMA;
// ACYPOMEGA y VDMKAPPA -> ACYPOMEGA; VDMBETA y ACYPBETA -> VDMBETA.
String nodoDestinoS702(Equipo eq) {
    return props.destinoS702().getOrDefault(eq.host(), props.par(eq.host()).destino());
}
/** S711/FILE/MOVSXTERM/ (WKS-NOM-S028 X(20)): usercode S028 y destino = el propio equipo. */
public ComandoXfer resuelve(SolicitudTransferencia s) {
    Equipo eq = equipo.identifica();
    var par = props.par(eq.host());
    String usercodeDestino = s.usercode();
    String nodoDestino = par.destino();

    if (vaAS702(s, eq)) {
        usercodeDestino = "S702";
        nodoDestino = nodoDestinoS702(eq);
    }
    if (s.archivo().startsWith("S711/FILE/MOVSXTERM/")) {       // se evalúa después y prevalece
        usercodeDestino = "S028";
        nodoDestino = par.origen();                             // 000400-VALIDA-NODO: mismo equipo
    }
    return new ComandoXfer(s.usercode(), s.archivo(), usercodeDestino, s.archivo(),
                           s.packOrigen(), par.origen(), s.packDestino(), nodoDestino);
}

XferAdapter.java@ServiceActivator · adaptador de salidaJava 21
@Component
@RequiredArgsConstructor
public class XferAdapter {

    private final XferClient xfer;                  // CALL "ENVIA_XFER IN XFER"
    private final ApplicationEventPublisher eventos;

    @ServiceActivator
    public ResultadoTransferencia envia(ComandoXfer cmd) {
        String texto = String.format("%-193s", cmd.texto());     // MOVE 193 TO WS-TRF-TAMACOM
        long resultado = xfer.envia(texto, 193);
        if (resultado > 0) {
            // Mismo criterio que el COBOL: no aborta, pide copia manual. Además se publica
            // un evento para que el orquestador o la mesa de operación lo vean.
            eventos.publishEvent(new TransferenciaFallida(cmd, resultado,
                    "FAVOR DE COPIAR MANUALMENTE EL ARCHIVO " + texto.strip()));
            return ResultadoTransferencia.manual(resultado);
        }
        return ResultadoTransferencia.ok();
    }
}

Riesgos de migración
Topología de equipos compilada en el programa

Los ocho nombres de host y sus pares (líneas 745-777), el destino especial de S702 (líneas 788-810) y el de S028 (líneas 833-856) están escritos como cadenas de IF anidados. Agregar, renombrar o retirar un equipo exige recompilar P102, y un host que no esté en la lista deja WKS-NODO-ORI y WKS-NODO-DES con su contenido inicial.

Falla de transferencia sin aborto

Si ENVIA_XFER regresa un resultado mayor a cero, P102 solo envía un mensaje al operador (líneas 824-832) y termina normalmente. El paso que lo invocó no se entera y el archivo puede no llegar al equipo destino hasta que alguien lo copie a mano.

Reconocimiento de archivos por truncamiento

La comparación por prefijo se logra moviendo el título de 80 posiciones a campos de 18, 20 y 24 posiciones (líneas 665-668 y 711-717). Funciona porque cada literal mide exactamente lo mismo que su campo; cambiar un PIC o un literal rompe el ruteo sin error de compilación.

El título recibido es X(80) pero WKS-NOMB-ARCH y WKS-NOMB-ARTG son X(55), y el pack de origen y destino X(17) se mueve a campos X(16). Un título de más de 55 caracteres o un pack de 17 se envía truncado.

P655 · CALLLIBCTL — Control de Estatus de Sistema (CORE-GL)

CORE-GLProgramaCOBOL

Fuente: COBOL_P655.cbl (770 LOC)

Rol en batch: utilitario de control operativo; invocado en inicio y fin de jornada batch · BC-16

Convenciones: nombres traducidos (Unisys → legible); [P655 Lnnnn] = línea fuente; (BR: RN-CORE-GL-NNN) = regla.

Nota: COBOL_P650.txt no existe en el directorio fuente; P655 ocupa el slot P650 en el WFL.

1. Resumen funcional

P655 (PROGRAM-ID: CALLLIBCTL) es un utilitario de control operativo que cambia el valor del campo ESTATUS en el dataset DMSII CORE-GLB04SISTEM para un sistema CORE-GL dado. Se invoca desde el WFL en dos momentos críticos del ciclo batch: inicio de jornada (W77-FUNCION=2) y fin de jornada (W77-FUNCION=3); para cualquier otro valor de función el programa ejecuta solo las consultas informativas y termina sin modificar nada. Antes de actualizar B04, P655 resuelve dinámicamente el nombre del pack de movimientos consultando B01SISDIA y el nombre de la base de datos de saldo consultando B03SISMEN, ambos a través de la librería de control LIBCTL. La inicialización de LIBCTL es también dinámica: usa el catálogo CTLVER para obtener el path físico real, con fallback hardcodeado a (CORE-GL)CORE-GL/OBJECT/L001/CONTROL ON CMEMP si CTLVER falla.

4.2 · Inicializar_Librerias

PROCEDIMIENTO Inicializar_Librerias():    // 000200-LIBRERIAS · [P655 L693]
```
FUNCIÓN Inicializar_Librerias():

    // Configurar CTLVER para acceso por función
    CHANGE ATTRIBUTE LIBACCESS    OF "CTLVER" → BYFUNCTION    // [P655 L695]
    CHANGE ATTRIBUTE FUNCTIONNAME OF "CTLVER" → "CTLVERS"     // [P655 L696]

    // Configurar librería de display de mensajes al operador
    CHANGE ATTRIBUTE TITLE OF "LIB-DISP" →
        "(S000)S000/UTILITY/DESPLIEGA/OBJ/LIB ON PACK"        // [P655 L698-699]

    // Obtener path físico dinámico de LIBCTL desde catálogo de versiones
    MOVER "CORE-GLL001CTL"  → wks_libid          // ID lógico de la librería [P655 L701]
    LLAMAR "DAME_TIT IN CTLVER"
           USANDO wks_libid, wks_nomlib
           DANDO resultado_ctlver             // W77-ERR-CTLVER [P655 L702-703]

    SI resultado_ctlver = 0 ENTONCES
        // Resolución dinámica exitosa — usar path del catálogo
        CHANGE ATTRIBUTE TITLE OF "LIBCTL" → wks_nomlib       // [P655 L705] (BR: RN-CORE-GL-597)
    SINO
        // Fallback hardcodeado: path fijo en pack CMEMP
        CHANGE ATTRIBUTE TITLE OF "LIBCTL" →
            "(CORE-GL)CORE-GL/OBJECT/L001/CONTROL  ON CMEMP"        // [P655 L707-708]
        // ⚠ [HARDCODE-SOSPECHOSO]: si el pack CMEMP no está disponible, fallo no manejado
        // (BR: RN-CORE-GL-597)
    FIN-SI

    // Liberar CTLVER — ya no se necesita en memoria
    CANCEL "CTLVER"                                            // [P655 L710]
```

4.7 · Cambiar_Estatus_B04

PROCEDIMIENTO Cambiar_Estatus_B04():    // 000320-CAMBIA-B04 · [P655 L758]
```
FUNCIÓN Cambiar_Estatus_B04():
    // PRE-CONDICIÓN: se ejecuta SOLO si W77-FUNCION = 2 OR 3; siempre después de Consultar_SistemaB04

    // Mapeado de función a estatus: el código de función ES el nuevo valor de estado
    MOVER codigo_funcion → wks_b04_estatus         // W77-FUNCION → WKS-B04-ESTATUS [P655 L760]
    // ⚠ IDENTIDAD FUNCIÓN=ESTATUS: no hay tabla de conversión — el número de función
    //   se escribe directamente como valor de estado en B04SISTEM.
    //   FUNCION=2 → ESTATUS=2 (inicio jornada: habilita procesamiento batch)
    //   FUNCION=3 → ESTATUS=3 (fin jornada: bloquea nuevas operaciones)
    // (BR: RN-CORE-GL-593, RN-CORE-GL-599)

    // Reiniciar código de retorno
    MOVER 0  → resultado_libcon                    // W77-RESULT-LIBCON [P655 L761]

    // Preparar operación de cambio en B04SISTEM
    MOVER 37 → wks_b04_funcion                     // FUNCION=37 = cambio genérico [P655 L762]
                                                   // ⚠ [HARDCODE-SOSPECHOSO]
    MOVER codigo_sistema → wks_b04_sistema         // W77-SISTEMA [P655 L763]

    // Invocar entry-point de actualización de B04SISTEM en LIBCTL
    LLAMAR "MANTB04SISTEM IN LIBCTL"
           USANDO wks_b04sistema
           DANDO resultado_libcon                  // W77-RESULT-LIBCON [P655 L764-765]
    // (BR: RN-CORE-GL-592 — escritura activada solo por FUNCION=2 OR 3)

    SI resultado_libcon > 0 ENTONCES
        // Error al actualizar B04 — log al operador pero no aborta (no-fatal)
        MOVER "ERROR AL ACTUALIZAR B04" → texto_log // TEXTO-LJ [P655 L767] ⚠ [HARDCODE-SOSPECHOSO]
        LLAMAR "LJ IN LIB-DISP"
               USANDO contador_lj, mensaje_lj      // [P655 L768-769]
        // NOTA: si la actualización falla, el estatus de B04 queda inconsistente
        // sin abortar el job — riesgo de coherencia en ciclos posteriores
    FIN-SI
    // Retorna implícitamente al llamador (000300-PROCESO)
```

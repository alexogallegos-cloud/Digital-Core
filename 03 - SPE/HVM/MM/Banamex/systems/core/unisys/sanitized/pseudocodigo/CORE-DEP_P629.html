P629 · Inicialización de la Base BD06 TELETON y Preformateo de Archivos LOG (CORE-DEP)

CORE-DEPProgramaCOBOL

Fuente: P629CARGABD06.cbl (656 LOC) · Paso batch de arranque/preparación del ciclo (paso CORE-DEP/0629) · BC-XX [NO-DETERMINADO]

Convenciones: nombres traducidos (Unisys COBOL→legible); [P629 Lnnnn] = línea física del fuente; (BR: RN-CORE-DEP-...) = regla de negocio.

1. Resumen funcional

P629 (CORE-DEPP629, autor Autor 01, OCT/2000, migrado del S501 al CORE-DEP en JUN/2016 [P629 L6-L8]) es el programa de inicialización / carga en frío de la base DMSII CORE-DEPBD06TELETON y de preformateo de los archivos de bitácora (LOG) del sistema. No procesa movimientos de negocio: siembra las estructuras de control que el resto del batch consumirá durante el día.

Su comportamiento se bifurca por el TASKVALUE recibido de la WFL [P629 L242]: con valor 1 o 2 ejecuta la carga completa (crea el registro global CORE-DEPB00TGLOBAL con la fecha de línea hábil y el CSI, crea cuatro registros CORE-DEPB01TCONTROL —uno por copia 1..4— y genera cuatro archivos LOG preasignados con 20,000 registros en ambiente beta o 250,000 en producción); con valor 3 solo apaga el interruptor B02-ACT-TELETON en la base CORE-DEPBD01CAPTACION (desactivación del proceso TELETON); con valor 0 no hace absolutamente nada y termina normal ⚠. Cualquier otro valor aborta con STATUS = -1.

El programa es sensible al host: distingue producción de beta comparando el atributo HOSTNAME contra la constante "ACYPBETA." [P629 L218], y de esa comparación dependen tres decisiones: si se valida la versión contra CTLVERS, qué CSI se graba (04 vs 10) y cuántos registros LOG se preasignan (20,000 vs 250,000).

4. Lógica por sección

4.1 Control del programa y ruteo por TASKVALUE

PROCEDIMIENTO Controlar_Programa():                    // 0000-CONTROL-PROGRAM · [P629 L209]

    // Enlace dinámico por función a la librería de control de versiones
    CAMBIAR ATRIBUTO LIBACCESS    DE "CTLVERS" A BYFUNCTION      « [P629 L211] »
    CAMBIAR ATRIBUTO FUNCTIONNAME DE "CTLVERS" A "CTLVERS"       « [P629 L212] »

    EJECUTAR Enlazar_Libreria_Bitacora()                         // 70000010-LINK-LIBLJ · [P629 L214]

    MOVER ATRIBUTO HOSTNAME DE MYSELF A nombre_host   // W77-MY-HOST X(9)   « [P629 L216] »

    // --- Discriminación de ambiente ---
    SI nombre_host = "ACYPBETA."          ⚠ [HARDCODE-SOSPECHOSO]  « [P629 L218] »
        // ⚠ segundo host beta DESACTIVADO por comentario: OR nombre_host = "VDMBETA. "  [P629 L219]
        MOVER 0 A es_produccion            // WS-HOST-PROD = 0 → BETA
    SINO
        MOVER 1 A es_produccion            // WS-HOST-PROD = 1 → PRODUCCIÓN
    FIN-SI                                                        « [P629 L218-L222] »

    // --- Autochequeo de versión ---
    MOVER "CORE-DEPP629" A id_programa         // W77-S000-MY-ID       « [P629 L225] »
    MOVER "25MTP004" A version_programa    // W77-S000-MY-VERSION  « [P629 L226] »

    SI es_produccion = 0                                          // BETA: se omite la validación
        MOVER CERO A estatus_version
    SINO
        LLAMAR "CHECAME IN CTLVERS" USANDO (id_programa, version_programa)
               DEVOLVIENDO estatus_version                        « [P629 L232-L235] »
    FIN-SI

    SI estatus_version < 0
        MOVER "ERROR EN VERSIONES CORE-DEPP629" A texto_bitacora
        EJECUTAR Escribir_Bitacora()
        CAMBIAR ATRIBUTO STATUS DE MYSELF A -1        // aborta la WFL con error
    FIN-SI                                                        « [P629 L237-L240] »

    // --- Parámetro de ejecución recibido de la WFL ---
    MOVER ATRIBUTO TASKVALUE DE MYSELF A parametro_tarea          « [P629 L242] »

    SI parametro_tarea EN (0,1,2,3)                   // W88-TASK-OK
        SIGUIENTE SENTENCIA
    SINO
        CONCATENAR "ERROR TASKVALUE RECIBIDO =" + parametro_tarea EN texto_bitacora
        EJECUTAR Escribir_Bitacora()
        CAMBIAR ATRIBUTO STATUS DE MYSELF A -1                    « [P629 L244-L250] »
    FIN-SI

    SI parametro_tarea = 3                            // W88-TASK-TRES
        EJECUTAR Desactivar_Teleton_En_BD01()                     « [P629 L252-L253] »
    FIN-SI

    SI parametro_tarea = 0 O parametro_tarea = 3
        SIGUIENTE SENTENCIA                           // ⚠ TASK=0 ⇒ el programa NO hace nada y termina OK
    SINO                                              // TASK = 1 ó 2
        EJECUTAR Ejecutar_Carga_BD06()                            « [P629 L255-L258] »
    FIN-SI

    PARAR EJECUCIÓN                                               « [P629 L260] »

⚠ H-1 · Fallback silencioso. TASKVALUE = 0 es el valor por defecto cuando la WFL no pasa parámetro (WKS-TASK-PARAMETRO VALUE 0, [P629 L47]). En ese caso el programa termina con status normal sin haber cargado nada y sin emitir mensaje alguno, lo que es indistinguible de una carga exitosa desde la WFL. ⚠ [DESCARTE-SILENCIOSO]

⚠ H-2 · Validación de versión desactivada en beta. Con WS-HOST-PROD = 0 no se invoca CHECAME y se fuerza estatus_version = 0 [P629 L229-L230]: en beta puede correr cualquier versión del objeto sin control.

4.2 Flujo principal de carga (TASKVALUE 1 ó 2)

PROCEDIMIENTO Ejecutar_Carga_BD06():                   // 0000-CONT-PROCESO · [P629 L263]

    EJECUTAR Resolver_Libreria_Fechas()                // 1000-FECHAS-TIT   « [P629 L265] »

    ABRIR EN ACTUALIZACIÓN base_teleton[CORE-DEPBD06TELETON]           « [P629 L267] »

    EJECUTAR Iniciar_Transaccion_BD06()                // 999-OL-BEGIN-TRANSACTION « [P629 L269] »

    EJECUTAR Sembrar_Registro_Global()                 // 10000-ACTUALIZA-FECHAS   « [P629 L271] »

    PARA numero_copia = 1 HASTA 4 HACER                // W77-NUM-COPIA
        EJECUTAR Crear_Control_Por_Copia()             // 12000-CREA-B01CONTROL
    FIN-PARA                                                       « [P629 L273-L275] »

    EJECUTAR Cerrar_Transaccion_BD06_Sincrona()        // 999-OL-END-TRANSACTION-SYNC « [P629 L277] »

    CERRAR base_teleton[CORE-DEPBD06TELETON]                           « [P629 L279] »

    MOVER fecha_proceso A etiqueta_fecha_log           // WS-FECHA-PROC → WKS-ETIL-FECHA « [P629 L281] »
    MOVER 0 A numero_copia_log                         // W77-NCOPIA     « [P629 L283] »

    PARA numero_copia_log = 1 HASTA 4 HACER
        EJECUTAR Preformatear_Archivo_Log()            // 100-PARAM-GENARCH
    FIN-PARA                                                       « [P629 L285-L286] »

    PARAR EJECUCIÓN                                                « [P629 L288] »

⚠ H-3 · Punto faltante en el PERFORM VARYING. La sentencia PERFORM 100-PARAM-GENARCH VARYING ... UNTIL W77-NCOPIA > 4 no termina en punto [P629 L285-L286]; el punto aparece recién en STOP RUN. [P629 L288]. En este caso concreto no altera la semántica (ambas son sentencias imperativas consecutivas del mismo párrafo), pero es un defecto de puntuación real del legacy que debe preservarse tal cual en cualquier migración.

Orden transaccional: toda la escritura DMSII de la BD06 (registro global + 4 controles) ocurre dentro de una única transacción NO-AUDIT anclada en CORE-DEPB91TREINICIO, cerrada con SYNC. Los archivos LOG se generan fuera de la transacción y después de cerrar la base.

4.4 Resolución de la fecha de proceso (día hábil)

    EJECUTAR Verificar_Si_Es_Habil()                   // 9999-VERIFICA-HABIL « [P629 L380] »

            SIGUIENTE SENTENCIA                        // conserva la fecha de hoy

Semántica de la fecha de línea: en producción P629 siempre siembra la BD06 con el siguiente día hábil respecto de la fecha del sistema, sin excepción. En beta solo avanza si CHECA_HABIL2K devolvió 0; en cualquier otro retorno se queda con la fecha de hoy. El significado exacto de estatus_habil = 0 (¿"es hábil" o "sin error"?) no se puede determinar desde este fuente — depende del contrato de S000LIBFEC. [NO-DETERMINADO]

⚠ H-6 · Llamada sin captura de estatus.

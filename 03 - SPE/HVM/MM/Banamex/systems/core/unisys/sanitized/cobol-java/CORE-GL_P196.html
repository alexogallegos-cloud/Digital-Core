Recibe sistema, fecha, número de proceso, registro inicial y registro final como parámetro, y un modo en el TASKVALUE de la tarea. Consulta B01SISDIA del sistema (y lo crea con una fecha fija si falta el de CORE-GL). Con fecha de parámetro elimina o actualiza un B05 puntual mediante B05PROCESOS. Sin fecha calcula con THECALENDAR la fecha anterior a la de proceso y borra, en transacción no auditada, los B05 más antiguos de cada proceso de una tabla fija (cuatro procesos para CORE-GL y nueve para el resto), con tratamiento especial para los procesos 196 y 197. El modo 1 regresa la fecha de proceso de CORE-GL y el modo 2 copia a CORE-GL la fecha contable de CORE-DEP.

@Configuration
public class DepuracionJobConfig {

    /** 000100-INICIO: un solo programa con tres comportamientos según TASKVALUE. */
    @Bean
    Job depuraControl(JobRepository repo, Step inicializa, JobExecutionDecider porModo,
                      Step regresaFecha, Step sincronizaCORE-DEP, Step depura) {
        return new JobBuilder("CORE-GLP196", repo)
                .start(inicializa)                                   // 000100-INICIALIZACION
                .next(porModo)
                    .on("REGRESA_FECHA").to(regresaFecha)            // 000150-REGRESO-FECHA
                .from(porModo).on("SINCRONIZA_CORE-DEP").to(sincronizaCORE-DEP)  // 000140-MANTEN-FECHA-CORE-DEP
                .from(porModo).on("*").to(depura)                    // 000200-PROCESO
                .end()
                .build();
    }

    @Bean
    JobExecutionDecider porModo() {
        return (job, step) -> new FlowExecutionStatus(
                ModoDepuracion.de(job.getJobParameters().getLong("taskValue", 0L)).name());
    }
}
@Service
@RequiredArgsConstructor
public class FechaProcesoService {

    private final LibreriaControl libCtl;            // CONSISDIA / MANTSISDIA IN LIBCTL
    private final P196Properties props;

    /** 000100-INICIALIZACION: fecha de proceso 151 del sistema; si CORE-GL no tiene B01, se crea. */
    @Transactional
    public LocalDate fechaProceso151(int sistema, int csi) {
        var r = libCtl.consisdia(sistema, csi);
        if (r.ok()) return r.fecPro151();
        if (sistema == 151 && r.resultado() == 1) {                 // registro no existe
            var semilla = props.fechaSemillaB01();                 // p196.fecha-semilla-b01: 2015-05-25
            var alta = libCtl.mantsisdia(19, sistema, csi, semilla, semilla, semilla);
            if (!alta.ok()) throw new ProcesoAbortadoException("ERROR AL CREAR B01SISDIA");  // cambio deliberado
            return semilla;    // el COBOL no copia la semilla a WKS-FECPRO151 (ver riesgo)
        }
        throw new ProcesoAbortadoException("ERROR EN LLAMADO EN L001");  // STATUS OF MYSELF = -1
    }
}

        if (r.funcion() > 0) {

/** 000200-PROCESO con fecha > 0 + 000230-ELIMINA-ACTUALIZA. */
public void puntual(ParametrosDepuracion p) {
    // 196 y 197 se eliminan (función 22); cualquier otro proceso se actualiza (función 37) con REGFIN
    boolean elimina = p.numProceso() == 196 || p.numProceso() == 197;   // p196.procesos-eliminables
    var r = libCtl.b05Procesos(elimina ? 22 : 37,
                               p.sistema(), p.fecha(), p.numProceso(), p.numRegIni(),
                               elimina ? null : p.numRegFin());
    if (r.ok()) {
        bitacora.info("SE ELIMINO/ACT CORRECTAMENTE B05 CON FECHA: %s SISTEMA: %d Y NUM. PROC : %d"
                .formatted(p.fecha(), p.sistema(), p.numProceso()));
    } else {
        bitacora.info("NO SE ELIMINO/ACT B05 CON FECHA: %s SISTEMA: %d NUM. PROC : %d"
                .formatted(p.fecha(), p.sistema(), p.numProceso()));   // no aborta: solo informa
    }
}
/** 000200-PROCESO sin fecha: depuración masiva. */
public void masiva(ParametrosDepuracion p, LocalDate fechaProceso151) {
    LocalDate umbral = calendario.fechaAnterior(fechaProceso151);       // 000210
    if (p.sistema() == 151) {
        props.procesos().core-gl().forEach(proc -> depuraProceso(p.sistema(), proc, umbral));
        eliminaPrelinea500(umbral);                                     // 000220-ELI-B05-PRELIN500
        marcaP196Prelinea();                                            // 000230-ACT-B05-P196-PRELINEA
    } else {
        props.procesos().otros().forEach(proc -> depuraProceso(p.sistema(), proc, umbral));
    }
}

    log.info("Proceso {}: {} B05 depurados", proceso, borrados);
    if (proceso == props.procesoMarcaReinicio()) {                       // 197: se conserva el del umbral
        repo.findFirstBySistemaAndFchProAndNumProceso(sistema, umbral, proceso)
            .ifPresent(b -> b.setFchIni(1));                             // STORE
    }
}

/** 000140-MANTEN-FECHA-CORE-DEP: solo si aún no existe el B05 196 de CORE-GL con registro inicial 0. */
@Component

public class SincronizaFechaCORE-DEPTasklet implements Tasklet {

    private final ProcesoB05Repository repo;
    private final LibreriaControl libCtl;

    @Override
    @Transactional
    public RepeatStatus execute(StepContribution c, ChunkContext ctx) {

        int csi = csiDelHost();

        libCtl.consisdia(151, csi).orElseThrow("ERROR EN CONSULTA 151");

        libCtl.mantsisdia(37, 151, csi, fecConCORE-DEP, fecConCORE-DEP, fecConCORE-DEP)
              .orElseThrow("ERROR AL GRABAR FECHA 151");
        libCtl.b05Procesos(19, 151, fecConCORE-DEP, 196, 0, null)           // alta del B05 196
              .orElseThrow("ERROR AL CREAR REG B05 196");
        return RepeatStatus.FINISHED;
    }

Riesgos de migración
El proceso 197 sí se depura

El 197 está en la tabla NNN y pasa por el mismo ciclo de LOCK y DELETE que los demás procesos (líneas 879-881); solo el registro con fecha igual al umbral se conserva y se marca. Esto matiza la regla RN-CORE-GL-904, que dice que el 197 no se elimina.

Mensajes de error que no se emiten

En 000210-PROYFEC-ANTHAB (líneas 953-965) el texto del error de calendario se arma pero no se envía a LIB-DISP antes de STATUS -1. La tarea aborta sin dejar la causa en bitácora.

Alta de B01 con fecha de 2015 y sin propagar

Si falta el B01 de CORE-GL, se crea con 20150525 en sus tres fechas (líneas 799-801) sin revisar el resultado de MANTSISDIA, y WKS-FECPRO151 queda sin asignar para el cálculo del umbral.

Borrado sin auditoría y con errores silenciosos

Los DELETE se hacen dentro de BEGIN-TRANSACTION NO-AUDIT y un error solo se informa. No hay forma de reconstruir desde DMSII qué registros de control se eliminaron.

Resultados de librería sin revisar

B05PROCESOS en 000220-ELI-B05-PRELIN500 y la eliminación puntual con parámetro no abortan si fallan; el job que lanza a P196 termina en estado normal.

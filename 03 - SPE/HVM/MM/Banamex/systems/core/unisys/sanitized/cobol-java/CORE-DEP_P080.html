CORE-DEP · P080 a Java 21 Spring Boot

P080 corre en dos copias: la copia 1 atiende mensajes COMS y la copia 2 procesa los archivos masivos ARCHMASIV y, tras el aviso de cambio de día, ejecuta la sincronización entre el nodo de Monterrey (04) y el de Valle de México (10). La lógica de contrato vive en las librerías L080 y L081, que P080 invoca por entry points; el programa solo orquesta, valida agrupadores y lleva bitácora en ARCH-PROB. La sincronización es una máquina de seis fases con checkpoint en L081: genera ARCHSINC local, lo envía al nodo foráneo con el WFL de P197, espera el archivo del otro nodo, lo procesa y deriva al archivo ARCH-SINC-B03 una marca de cuenta ordenante por cada contrato del propio nodo. El operador gobierna el comportamiento en caliente mediante Handle Interrupts (TASKVALUE 4001 a 4196).

@Component
@RequiredArgsConstructor
@Slf4j
public class P080Server implements SmartLifecycle {

    private final ControlVersiones ctlvers;      // CHECAME contra CTLVERS
    private final ArranqueP080 arranque;         // 20000000-VALIDA-INICIO
    private final DespachadorActividades despacho; // 50000000-PROCESO-PGM
    private final FinP080 fin;                   // 70000000-FIN-PGM
    private volatile boolean eoj;                // WKS-EOJ
    private Thread bucle;

    @Override
    public void start() {
        if (!ctlvers.versionValida("CORE-DEPP080")) {          // S000-CTR-CVEERROR < 0
            log.error("VERSION INCORRECTA CORE-DEPP080");
            throw new IllegalStateException("VERSION INCORRECTA CORE-DEPP080");
        }
        EstadoTarea estado = arranque.ejecuta();
        bucle = Thread.ofVirtual().name("P080-copia-" + estado.copia()).start(() -> {
            while (!eoj) {
                despacho.obtieneTransaccion(estado);
            }
            fin.ejecuta(estado);
        });
    }

    @Override public void stop()        { eoj = true; }
    @Override public boolean isRunning() { return bucle != null && bucle.isAlive(); }
}

@Service
@RequiredArgsConstructor
public class ArranqueP080 {

    private final Host host;
    private final L080Client l080;
    private final L081Client l081;
    private final P080Properties props;
    private final RecuperacionSincronizacion recuperacion;

    public EstadoTarea ejecuta() {
        int csi = host.esPruebas()
                ? (host.numCsi() == props.csiPruebas().hostCsi() ? props.csiPruebas().mapeaA()
                                                                : props.csiPruebas().resto())
                : host.numCsi();

        InicioPgm ini = l080.inicioPorPrograma(80, host.mixNumber());   // L080INICIOXPGM
        Actividad actividad = switch (ini.copia()) {
            case 1 -> Actividad.COMS;
            case 2 -> Actividad.ARCHIVOS;
            default -> throw new ArranqueException("NUMERO DE COPIA NO RECONOCIDO: " + ini.copia());
        };

        int result = 99;
        for (int i = 1; i <= props.l081IntentosInicio() && result != 0; i++) {
            result = l081.inicio();
        }
        if (result != 0) {
            throw new ArranqueException("IMPOSIBLE INICIAR L081, RESULT " + result);
        }
        var estado = new EstadoTarea(csi, ini.copia(), ini.fechaLinea(), actividad);
        if (actividad == Actividad.ARCHIVOS) {
            recuperacion.validaRecSinc(estado);      // 50500000-VALIDA-REC-SINC
        }
        return estado;
    }
}

@Service

public class MonitoreoMapli {

    private final MeterRegistry meters;          // Micrometer: registro de tareas activas
    private final MapliClient mapli;             // adaptador mientras MAPLI siga vivo
    private Long idPrograma;                     // WS-S038L035-01-ID-PROG-S PIC 9(08)
    private boolean enError;                     // W77-ID-ERR-LIB-MAPLI

    public void alta(int copia) {
        try {
            idPrograma = mapli.inicioPrograma(new AltaMapli(copia, 2, 2, 2,
                    "LINEA ATRIBUTO EN APERTURA DE CUENTA"));
            meters.gauge("core-dep.p080.activo", Tags.of("copia", String.valueOf(copia)), 1);
        } catch (MapliException e) {
            enError = true;                         // el monitoreo nunca baja la tarea
            log.warn("(PROGRAMA INICIO) ERROR CALL MAPLI RESULT: {}", e.result());
        }
    }

    public void baja() {
        if (enError || idPrograma == null) return;
        try {
            mapli.finPrograma(idPrograma);
        } catch (MapliException e) {
            log.warn("(PROGRAMA FIN) ERROR CALL MAPLI RESULT: {}", e.result());
        }
    }
}
public enum Actividad { COMS, ARCHIVOS, SINCRONIZACION }   // WS-ACTIVIDAD 1, 2, 3

@Service
@RequiredArgsConstructor
public class DespachadorActividades {

    private final ActividadComs coms;                 // 50300000: listener de mensajes en línea
    private final ActividadArchivos archivos;         // 5040000: Job de masivos ARCHMASIV
    private final ActividadSincronizacion sinc;       // 50500000: máquina de 6 fases

    /** 50200000-OBTIENE-TRANSACCION. La actividad la cambian los HI y las propias actividades. */
    public void obtieneTransaccion(EstadoTarea e) {
        switch (e.actividad()) {
            case COMS -> coms.atiendeSiguienteMensaje(e);
            case ARCHIVOS -> {
                archivos.verificaRecuperacion(e);
                while (archivos.hayTrabajo(e) && !e.hayCambioDia()
                        && e.actividad() == Actividad.ARCHIVOS) {
                    archivos.procesa(e);
                }
            }
            case SINCRONIZACION -> {
                while (e.actividad() == Actividad.SINCRONIZACION && e.hayCambioDia()) {
                    sinc.ejecuta(e);
                }
            }
        }
    }
}

OperacionP080Endpoint.java · CambioDiaService.javaSpring Boot Actuator @Endpoint · @WriteOperationJava 21
@Component
@Endpoint(id = "p080")
@RequiredArgsConstructor
public class OperacionP080Endpoint {

    private final Map<Integer, OperacionHi> operaciones;   // 4001..4196, un bean por HI
    private final L080Client l080;
    private final ReentrantLock disallowInterrupt = new ReentrantLock();

    /** POST /actuator/p080/{hi}: reemplaza el HI con TASKVALUE sobre la tarea MCP. */
    @WriteOperation
    public String ejecuta(@Selector int hi) {
        disallowInterrupt.lock();                         // DISALLOW INTERRUPT
        try {
            var op = operaciones.get(hi);
            String r = (op == null) ? "HI SIN ACCION" : op.ejecuta();   // NEXT SENTENCE
            l080.procesaHi(1);                             // 20000000-CALL-L080-PROCHI
            return r;
        } finally {
            disallowInterrupt.unlock();                    // ALLOW INTERRUPT
        }
    }
}

@Component("hi4030")
@RequiredArgsConstructor
public class Hi4030CambioDia implements OperacionHi {

    private final EstadoTarea estado;
    private final MonitoreoMapli mapli;
    private final L080Client l080;
    private final L081Client l081;
    private final BitacoraProblemas archProb;
    private final ApplicationContext ctx;

    @Override public int numero() { return 4030; }

    @Override
    public String ejecuta() {
        mapli.baja();
        mapli.alta(estado.copia());                         // reinicia el registro de monitoreo
        l080.confirmaHi(80, estado.copia(), 2, estado.mix());

        estado.avisoCambioDia(true);                        // WS-AVISO-CAMBIO-DIA = 1
        estado.actividad(estado.copia() == 2 ? Actividad.SINCRONIZACION : Actividad.COMS);
        l081.religa();                                      // CANCEL + LIGA + INICIA

        EsBatch r = l080.esBatch(80, estado.copia(), estado.mix());
        if (r.result() != 0) {
            // CHANGE ATTRIBUTE STATUS OF MYSELF TO -1: la tarea se baja
            SpringApplication.exit(ctx, () -> 1);
            return "ERROR L080ESBATCH RESULT: " + r.result() + " SE BAJA EL P080";
        }
        estado.fechaProceso(r.fechaLinea());
        archProb.rota(estado);                              // nuevo título con la nueva fecha
        return "FIN CAMBIO DE DIA, NUEVA FECHA PROCESO: " + r.fechaLinea();
    }
}

@Service
@RequiredArgsConstructor
public class ActividadSincronizacion {

    private final ControlSincRepository control;   // L081 ACTUALIZACTRL: "aC0n" + fecha
    private final CalendarioBancario calendario;    // LOCSUP formato 12, función 15
    private final Map<FaseSinc, PasoSinc> pasos;    // un bean por fase

    public void ejecuta(EstadoTarea e) {
        if (!e.enRecuperacion()) {
            e.fechaSinc(calendario.proyecta(e.fechaProceso()));       // 00000000-PROYECTA-T-1
            control.registra(e.fechaSinc(), FaseSinc.GENERA_LOCAL);  // "aC01"
            e.fase(FaseSinc.GENERA_LOCAL);
        }
        e.tipoSinc(calendario.esFinDeSemana(e.fechaProceso()) ? TipoSinc.SEMANAL : TipoSinc.DIARIA);

        while (e.fase() != FaseSinc.TERMINADA && e.actividad() != Actividad.COMS) {
            // cada paso persiste su checkpoint y avanza e.fase(); si se interrumpe,
            // VALIDA-REC-SINC reanuda en la fase registrada
            pasos.get(e.fase()).ejecuta(e);
        }
        if (e.fase() == FaseSinc.TERMINADA) {
            e.avisoCambioDia(false);
            e.actividad(Actividad.ARCHIVOS);
        }
    }
}

Riesgos de migración
Validación de número de copia inoperante

En 20000000-VALIDA-INICIO (línea 3346) la condición WS-NO-COPIA < 1 AND WS-NO-COPIA > 2 no puede cumplirse. Una copia con número distinto de 1 o 2 arranca sin actividad asignada y sin aviso.

Reintentos de L081 menores a lo documentado

PERFORM 20000000-INICIA-L081 VARYING WS-CONT-TEMP FROM 1 BY 1 UNTIL WS-CONT-TEMP = 3 (líneas 3356 y 3465) ejecuta dos intentos. El comentario y el mensaje hablan de tres.

Archivo B03 incompleto en baja

Si la copia COMS ordena la baja durante 50500000-GENERA-ARCH-B03, el archivo se cierra WITH SAVE sin trailer (línea 6748). Un consumidor que no valide el trailer podría tomarlo como completo.

Excepciones DMSII no contempladas en el barrido

El barrido de CORE-DEPB01CONTRATOS para B03 solo termina con la categoría 01; deadlock u otras categorías no se tratan y pueden duplicar el último detalle o prolongar el ciclo.

Truncamiento de fecha en el header B03

WS-FEC-SINC es PIC 9(08) y WS-ARCHSINCB03-HDR-FECPRO es PIC 9(06); el MOVE numérico conserva los seis dígitos de la derecha. Si la fecha está en AAAAMMDD, el header lleva AAMMDD sin siglo.

Hardcodes de nodo y asiento

Nodos 04 y 10, CSI 32 del host de pruebas, sucursal 0511, caja 05, clave 0935, sucursales promotoras 0366 y 0432, sistema 500 y número de archivo 08 están compilados. Se trasladan a application.yml.

Pendiente de revisión SME
  • Confirmar el formato de WS-FEC-SINC que devuelve LOCSUP formato 12 función 15 (AAAAMMDD o AAMMDD) para fijar el patrón del header B03.
  • Confirmar qué sistema consume ARCH-SINC-B03 y si valida el trailer; RN-CORE-DEP-724 indica el amarre con CORE-GL, pero el fuente solo muestra la generación.
  • Confirmar si un contrato con B01-CSI-CONTRATO distinto de 04 y 10 puede existir; la sucursal promotora 0432 se asigna por omisión a cualquier CSI que no sea 04.
  • RN-CORE-DEP-723 dice que la copia se codifica 1 para programa y 2 para librería; en 60000000-PROGRAMA-MAPLI-INI la copia que se envía es WS-NO-COPIA y los campos fijos en 2 son tipo de despliegue, inicio de grupo y número de grupo. Revisar la redacción de la regla.
  • La lógica de alta y actualización de atributos de contrato vive en L080 y L081, que no forman parte de este fuente.

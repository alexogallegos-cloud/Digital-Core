CORE-GL · P001 a Java 21 Spring Boot

Recibe por LINKAGE la función a ejecutar, el sistema y un juego de fechas que devuelve proyectadas. Con las funciones 0 y 2 calcula mañana, pasado mañana y el tercer día hábil, el día natural siguiente y el día anterior con la librería de calendario THECALENDAR de LOCSUP; con la función 0 además graba la nueva fecha en CORE-GLBD99CONTROL vía MANTSISDIA, limpia tres niveles del arreglo circular de 10 archivos y borra los totales por clave vencidos de la base semanal BASESEM. La función 1 genera los archivos L01-MOVTOS, L02-DESCRIP, L03-CBII y L04-CTDR dimensionados por sistema y calendario; la 3 proyecta la fecha de consulta y, para el sistema 500, enlaza L009 y L012; las 4 y 5 delegan borrados en L002 y la 6 solo consulta. Desde 2015 un control de alta disponibilidad en B05 evita reproyectar un sistema ya procesado.

public enum FuncionProyeccion {
    PROYECTA_Y_GRABA(0), GENERA_ARCHIVOS(1), PROYECTA_SIN_GRABAR(2),
    PROYECTA_CONSULTA(3), BORRA_L002_22(4), BORRA_L002_23(5), CONSULTA(6);
    final int codigo;
    FuncionProyeccion(int c) { codigo = c; }
    static FuncionProyeccion of(int c) {
        return Arrays.stream(values()).filter(f -> f.codigo == c).findFirst()
                .orElseThrow(() -> new ProcesoAbortadoException("NUMERO DE FUNCION INVALIDA"));
    }
}

@Component
@RequiredArgsConstructor
public class FuncionProyeccionDecider implements JobExecutionDecider {

    private final ProyFechaProperties props;   // sistema-global: 999

    @Override
    public FlowExecutionStatus decide(JobExecution job, StepExecution step) {
        var f = FuncionProyeccion.valueOf(job.getJobParameters().getString("funcion"));
        long sistema = job.getJobParameters().getLong("sistema");
        if (sistema == props.sistemaGlobal() && f != FuncionProyeccion.PROYECTA_SIN_GRABAR) {
            return new FlowExecutionStatus("FUNCION_INVALIDA");   // solo se registra, no aborta
        }
        return new FlowExecutionStatus(f.name());
    }
}

    }

    LocalDate sumaHabiles(LocalDate f, int n) {
        LocalDate d = f;
        for (int i = 0; i < n; ) {
            d = d.plusDays(1);
            if (esHabil(d)) i++;
        }
        return d;
    }

    boolean esHabil(LocalDate d) {
        return d.getDayOfWeek() != DayOfWeek.SATURDAY
                && d.getDayOfWeek() != DayOfWeek.SUNDAY
                && !inhabiles.existsByFecha(d);
    }

    LocalDate restaUno(LocalDate f) {
        return f.minusDays(1);   // ajustar a hábil si el SME confirma que la función 15 es hábil
    }
}

@Component

public class DimensionamientoArchivos {

    private final ArchivosProperties p;

    Volumenes calcula(int sistema, long base, boolean cambiaMesOInhabil, boolean mismoMes,
                      String equipo, int diaArchivo) {
        long mov = base, des = base, cbii = 0, ctdr = 0;
        if (cambiaMesOInhabil && p.sistemasConFactor().contains(sistema)) {
            mov = des = BigDecimal.valueOf(base).multiply(p.factorCambioMes())
                    .setScale(0, RoundingMode.DOWN).longValueExact();   // COMPUTE sin ROUNDED trunca
        }
        if (p.equiposPruebas().contains(equipo)) {

Riesgos de migración
Purga antes de validar el grabado

En 01-0140-GRABA-FECHAS (líneas 2670-2676) se llama a MANTSISDIA y se ejecutan BORRA-NIVELES y BORRA-TOTXCVES antes de revisar el resultado; un fallo de grabado deja la fecha sin mover y los totales por clave ya borrados.

Reintento sin fin al abrir BASESEM

01-0116-ABRE-BASE (líneas 2203-2216) reinicia el contador al pasar de 5 intentos y no aborta; el PERFORM UNTIL W88-BASE-OPEN de la línea 2016 sigue esperando de 20 en 20 segundos.

Terminaciones normales ante errores

La función 1 con fecha inhábil hace DISPLAY y STOP RUN (líneas 1714-1715) y el sistema 999 con función distinta de 2 solo registra el mensaje; en ambos casos el programa termina sin estado de error.

Hardcodes operativos

Sistemas con lógica especial (999, 500, 264, 404, 403, 711, 335), nombres de equipos de pruebas, volúmenes de archivo, factor 1.1, espera de 20 segundos y 5 intentos, y códigos de función de LOCSUP están compilados.

Pivote Y2K

El copybook CRONOS2K usa A2K-BASE-YEAR = 50; las fechas internas son de 8 dígitos, pero los nombres de archivo se arman con la conversión CAMD a AMD de 6 dígitos (líneas 2896-2903).

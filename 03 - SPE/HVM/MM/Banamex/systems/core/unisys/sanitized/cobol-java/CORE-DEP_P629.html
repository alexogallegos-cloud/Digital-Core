CORE-DEP · P629 a Java 21 Spring Boot

P629 identifica el equipo por HOSTNAME para distinguir pruebas (ACYPBETA) de producción y lee el TASKVALUE. Con 1 o 2 crea en CORE-DEPBD06TELETON un registro global CORE-DEPB00TGLOBAL con la fecha del siguiente día hábil, el CSI y un importe de supervisión fijo, y cuatro registros CORE-DEPB01TCONTROL, uno por copia; después crea cuatro archivos CORE-DEP/FILE/LOG/P045 de 540 bytes con 250,000 registros llenos de nueves y espacios (20,000 en pruebas). Con 3 solo pone en cero B02-ACT-TELETON en CORE-DEPBD01CAPTACION, y con 0 no hace nada.

/** TASKVALUE: 0 = nada, 1 o 2 = inicializa BD06 y preformatea, 3 = apaga B02-ACT-TELETON. */
@Component
public class OpcionTeletonDecider implements JobExecutionDecider {

    @Override
    public FlowExecutionStatus decide(JobExecution job, StepExecution step) {
        long opcion = job.getJobParameters().getLong("opcion");
        return switch ((int) opcion) {
            case 0    -> new FlowExecutionStatus("NADA");
            case 1, 2 -> new FlowExecutionStatus("INICIALIZA");   // el fuente no distingue 1 de 2
            case 3    -> new FlowExecutionStatus("APAGA_TELETON");
            default   -> throw new ParametroInvalidoException("ERROR TASKVALUE RECIBIDO =" + opcion);
        };
    }
}
@Bean
Job inicializaTeleton(JobRepository repo, OpcionTeletonDecider decider,
                      Step inicializaBd06, Step preformateaLogs, Step apagaTeleton) {
    return new JobBuilder("CORE-DEPP629", repo)
            .start(decider)
                .on("INICIALIZA").to(inicializaBd06).next(preformateaLogs)
            .from(decider)
                .on("APAGA_TELETON").to(apagaTeleton)
            .from(decider)
                .on("NADA").end()
            .end()
            .build();
}

@Bean
Step inicializaBd06(JobRepository repo, PlatformTransactionManager tx, InicializacionBd06 servicio) {
    // OPEN UPDATE + BEGIN-TRANSACTION ... END-TRANSACTION SYNC: un solo commit
    return new StepBuilder("inicializaBd06", repo)
            .tasklet((c, ctx) -> { servicio.inicializa(); return RepeatStatus.FINISHED; }, tx)
            .build();
}

InicializacionBd06.java · FechaProcesoTeleton.java · ApagaTeletonTasklet.java@Service @Transactional · JPAJava 21
@Service
@RequiredArgsConstructor
public class InicializacionBd06 {

    private final GlobalTeletonRepository globales;    // CORE-DEPB00TGLOBAL
    private final ControlTeletonRepository controles;  // CORE-DEPB01TCONTROL
    private final FechaProcesoTeleton fechas;
    private final TeletonProperties props;

    @Transactional
    public void inicializa() {
        if (globales.existsByFechaLinea(fechas.siguienteHabil())) {
            // El COBOL no lo verifica y duplicaría; aquí se hace idempotente.
            throw new YaInicializadoException(fechas.siguienteHabil());
        }
        var g = new GlobalTeleton();
        g.setFechaLinea(fechas.siguienteHabil());              // B00T-FEC-LINEA
        g.setNumCsi(props.csi());                              // 04 o 10
        g.setImporteSupervision(BigDecimal.valueOf(props.importeSupervision()));  // 10000
        g.setImporteAutorizado(BigDecimal.ZERO);               // B00T-IMP-AUTORI y demás en cero
        g.setNumCopias(new int[5]);                            // B00T-NUM-COPIAS(1..5)
        globales.save(g);
        IntStream.rangeClosed(1, 4)                            // 12000-CREA-B01CONTROL VARYING 1..4
                 .mapToObj(ControlTeleton::nuevaCopia)
                 .forEach(controles::save);
    }
}
@Component
@RequiredArgsConstructor
public class FechaProcesoTeleton {

    private final CalendarioBancario calendario;   // S000LIBFEC: CHECA_HABIL2K / DAME_SIGHAB2K
    private final TeletonProperties props;
    private final Clock reloj;                     // ACCEPT ... FROM DATE, inyectable para pruebas

    /** Clave de semana 65 y clave de festivos 01, tal como las pasa el COBOL a la librería. */
    public LocalDate siguienteHabil() {
        LocalDate hoy = LocalDate.now(reloj);      // NUMERIC-DATE MM/DD/AAAA, ya con siglo
        if (props.productivo()) {
            return calendario.siguienteHabil(hoy, 65, 1);
        }
        // Pruebas: solo avanza si hoy es hábil; un día inhábil se queda como está.
        return calendario.esHabil(hoy, 65, 1) ? calendario.siguienteHabil(hoy, 65, 1) : hoy;
    }
}

/** I01-R-00-REGISTRO: 10 nueves y 530 espacios; la posición es W77-LLAVE-LOG (ACTUAL KEY). */
static final byte[] REGISTRO_VACIO = ("9".repeat(10) + " ".repeat(530))
        .getBytes(StandardCharsets.US_ASCII);
@Component
@RequiredArgsConstructor
public class PreformateaLogsTasklet implements Tasklet {

    private final TeletonProperties props;          // registros-log: 250000 o 20000

    @Override
    public RepeatStatus execute(StepContribution c, ChunkContext ctx) throws IOException {
        LocalDate fecha = (LocalDate) ctx.getStepContext().getJobExecutionContext().get("fechaProceso");
        for (int copia = 1; copia <= props.log().copias(); copia++) {          // W77-NCOPIA 1..4
            Path p = props.log().ruta(fecha, copia);
            try (FileChannel ch = FileChannel.open(p, CREATE, TRUNCATE_EXISTING, WRITE)) {  // OPEN OUTPUT
                ByteBuffer buf = ByteBuffer.wrap(REGISTRO_VACIO);
                for (long llave = 1; llave <= props.registrosLog(); llave++) {  // W77-LLAVE-LOG
                    buf.rewind();
                    ch.write(buf, (llave - 1) * REGISTRO_VACIO.length);         // WRITE ... INVALID KEY
                }
            }                                                                   // CLOSE WITH SAVE
        }
        return RepeatStatus.FINISHED;
    }
}
Riesgos de migración
Reejecución crea registros de control duplicados

La búsqueda que impedía crear de nuevo CORE-DEPB01TCONTROL está comentada (líneas 396-400) y 10000-ACTUALIZA-FECHAS hace CREATE de CORE-DEPB00TGLOBAL sin buscarlo antes. Si el paso se relanza con TASKVALUE 1 o 2, la base queda con un segundo registro global y cuatro controles más.

Ambiente decidido por nombre de equipo

Solo ACYPBETA se trata como no productivo (línea 218; VDMBETA está comentado). En ese equipo se omite la validación de versión con CTLVERS, se asigna CSI 04 en lugar de 10, se preformatean 20,000 registros en vez de 250,000 y cambia la regla de la fecha de proceso. Cualquier equipo nuevo se considera producción.

Importe de supervisión compilado

B00T-IMP-SUPERV se fija en 10000 (línea 305) sin parámetro ni catálogo. Es un umbral operativo de la base Teletón y debe moverse a configuración con control de cambios.

TASKVALUE 1 y 2 hacen lo mismo

El nivel 88 distingue 0, 1, 2 y 3, pero el programa solo pregunta por 0 y 3 (líneas 252-258): 1 y 2 ejecutan el mismo proceso completo.

Archivos de otro programa

Los archivos preformateados se titulan CORE-DEP/FILE/LOG/P045/{fecha}/{copia}: P629 prepara el log de acceso directo que usa P045, y el tamaño de 250,000 registros es un tope implícito para ese programa.

Pendiente de revisión SME
  • Confirmar el significado de WS-LIBFEC-ESTATUS que regresa CHECA_HABIL2K: en pruebas, con estatus 0 se toma el siguiente hábil y con otro valor se conserva la fecha del día (líneas 382-388); en producción siempre se toma el siguiente hábil.
  • Confirmar qué consume CORE-DEPB00TGLOBAL.B00T-IMP-SUPERV y si el valor 10000 está expresado en pesos o en otra unidad.
  • El inventario no asigna reglas del brain a P629; se recomienda registrar al menos la regla de inicialización por día hábil siguiente y la de preformateo de logs de P045.
  • Confirmar si P045 sigue requiriendo el preformateo con nueves o si es un remanente de la migración desde S501 (comentario de la línea 8).

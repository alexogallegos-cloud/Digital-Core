CORE-GL · P021 a Java 21 Spring Boot

Obtiene de la librería de control de versiones CTLVERS el título vigente de CORE-GLL001 y lo asigna a la librería. Para cada paso de CORE-DEP consulta con B05PROCESOS el número de mix del proceso y, si la consulta es exitosa, arma el comando de consola "{mix} HI 1" y lo envía con DCKEYIN. Repite la secuencia 9, 12 y 2 después de una espera fija de 300 segundos. No revisa la respuesta del sistema ni el resultado de cada envío.

/** APLICA_HI, primera parte: función 1, sistema, fecha 0 y paso. */
private Optional<Long> mixDelPaso(int sistema, int paso) {
    Optional<ProcesoB05> p = control.consultaProceso(sistema, paso);   // B05PROCESOS(EA_ARR_B05)
    if (p.isEmpty()) {
        log.warn("Paso {} de S{} sin proceso activo en B05: no se envía HI", paso, sistema);
    }
    return p.map(ProcesoB05::mix);                                      // IDFB05MIX
}
/** APLICA_HI, segunda parte: "{mix} HI {n}" por la consola del sistema. */
private void enviaHi(long mix, int valor) {
    if (mix > 9999) {
        // REPLACE ... I_MEZCLA FOR 4 DIGITS conserva solo los cuatro dígitos de menor orden
        throw new MixFueraDeRangoException(mix);
    }
    String comando = "%04d HI %04d".formatted(mix, valor);
    RespuestaConsola r = consola.ejecuta(comando);   // DCKEYIN(POINTER(A_COMANDO), A_RESPUESTA)
    log.info("{} -> {}", comando, r.texto());        // el fuente no lee A_RESPUESTA
}
@Component
@RequiredArgsConstructor
public class CierreCORE-DEPTasklet implements Tasklet {

    private final P021Properties props;     // sistema 500, pasos [9, 12, 2], espera PT300S

    @Override
    public RepeatStatus execute(StepContribution sc, ChunkContext cc) throws InterruptedException {
        resuelveLibreriaControl();                          // VERSIONES
        for (int ronda = 1; ronda <= 2; ronda++) {
            for (int paso : props.pasos()) {                // orden fijo: 9, 12, 2
                mixDelPaso(props.sistema(), paso).ifPresent(mix -> enviaHi(mix, 1));
            }
            if (ronda == 1) {
                Thread.sleep(props.espera().toMillis());    // WAIT((300)): sin verificar respuesta
            }
        }
        return RepeatStatus.FINISHED;
    }
}

Riesgos de migración
Número de mix truncado a cuatro dígitos

En APLICA_HI el mix se escribe FOR 4 DIGITS (línea 72) aunque IDFB05MIX ocupa 8 posiciones. Con un mix mayor que 9999 el comando HI se dirige a un número equivocado.

Fallas sin rastro

Un resultado distinto de 0 en B05PROCESOS omite el envío sin mensaje, y la respuesta de DCKEYIN (A_RESPUESTA) nunca se revisa.

Versión de librería no garantizada

Si CTLVERS no encuentra CORE-GLL001CTL, el programa solo despliega un mensaje y continúa con el título por omisión de CORE-GLL001.

Espera fija y segunda ronda incondicional

El WAIT((300)) y la repetición de los tres HI no dependen de ningún estado de CORE-DEP; son una suposición de tiempos codificada en el programa.

Pendiente de revisión SME
  • RN-CORE-GL-182 describe HI como Halt/Initialize. En MCP el comando HI provoca el EXCEPTIONEVENT de la tarea con un TASKVALUE; el efecto real depende del manejador de interrupción de cada paso. Confirmar con el SME qué hacen los pasos 9, 12 y 2 al recibir HI 1.
  • Identificar qué programas de CORE-DEP corresponden a los pasos 9, 12 y 2 en el registro B05 para mapearlos a los jobs o servicios destino.
  • Confirmar el rango real de números de mix en producción para dimensionar el riesgo de truncamiento a cuatro dígitos.
  • La consola de MCP no existe en el destino; definir con arquitectura el mecanismo de señal que sustituye a DCKEYIN.

P197 · Transferencia de Archivos entre Hosts Unisys (CORE-DEP)

CORE-DEPProgramaCOBOL

Fuente: P197.cbl (4117 LOC) · Programa BATCH utilitario de reconciliación — mueve archivos entre los hosts Unisys de la plataforma (Monterrey ⟷ México) y hacia la capa ETL/Genesis vía librería INTELAR, con fallback a WFL DUMPALL · BC-XX

Convenciones: nombres traducidos (Unisys→legible); [P197 Lnnnn] = número de secuencia COBOL (cols 1–6); (BR: RN-CORE-DEP-nnn) = regla de negocio verificada en KB.

1. Resumen funcional

P197 es un programa batch utilitario de la plataforma CORE-DEP (LegacyCore, Unisys ClearPath MCP) cuya responsabilidad es transferir un archivo entre los hosts físicos de la plataforma o hacia la capa de integración ETL/Genesis. Recibe por contenido un parámetro de dos campos ("NN AAAAMMDD" — número de opción de archivo + fecha) desde el WFL que lo arranca, resuelve dinámicamente el host origen/destino a partir del hostname de la máquina donde corre, y ejecuta la copia por uno de tres mecanismos: la librería propietaria XFER (ENVIA_XFER IN XFER), la librería INTELAR (INTELARSND IN ADMONXFERS) para envío hacia ETL/Genesis, o una invocación WFL DUMPALL del MCP como copia física inter-host.

El flujo es: (1) enlazar librerías y validar versión en el catálogo central CTLVERS; (2) abrir la base DMSII CORE-DEPBD01CAPTACION y leer del dataset de control CORE-DEPB02CONTROL el flag B02-NVOHOST-S274 que indica si además hay que enviar al sistema S274; (3) leer ATTRIBUTE HOSTNAME OF MYSELF para clasificar el ambiente (PRODUCCION/UAT/SIT/DESARROLLO) y derivar el CSI de origen (04 = Monterrey, 10 = México) junto con el host destino (BR: RN-CORE-DEP-734); (4) validar el parámetro recibido contra las decenas de opciones válidas; (5) según la opción, poblar la estructura de transferencia WKS-PARAM-XFER-XX (usuario/archivo/pack origen y destino, fechas, hosts) o el nombre del archivo INTELAR; (6) despachar a la rutina de envío correspondiente y verificar el resultado.

Punto crítico de comportamiento: P197 no aborta el job ante un fallo de transferencia. Cada rutina de envío INTELAR reintenta una o dos veces (con WAIT intermedio) y, si persiste el fallo, escribe al log un mensaje operativo "ERROR AL ENVIAR ... TRANSFERIR MANUAL OPC=nn AAAAMMDD" con instrucciones para que un operador reprocese manualmente — evidenciando una dependencia estructural de intervención humana (BR: RN-CORE-DEP-735). El único caso que aborta la transferencia es un hostname no reconocido (W77-SIN-TRANSF = 1), que salta directamente a devolver W77-SAL-RESULT = 9. El resultado se devuelve al orquestador vía SET MYSELF (TASKVALUE).

Naturaleza del programa: es esencialmente un gran despachador tabla-dirigido. La mayor parte de sus 4117 líneas son (a) ~100 estructuras WKS-DATO-ARCH-nn en Working-Storage que codifican rutas de archivo fijas, y (b) dos cadenas IF ... ELSE IF gigantes (1000400-PARAM-FIJO y 7003000-ENVIA-S022) que mapean cada código de opción a su estructura y a su rutina de envío. La lógica de negocio real es delgada; el volumen proviene de la enumeración de ~90 tipos de archivo transferibles.

4.5 Rutinas de envío INTELAR — patrones

Todas las rutinas de envío comparten el mismo núcleo (BR: RN-CORE-DEP-735):

PATRÓN A — envío simple con 1 reintento:
    limpiar buffer · resultado_intelar = 0 · MOVER nombre_archivo A buffer
    LLAMAR "INTELARSND IN ADMONXFERS" USING buffer GIVING resultado_intelar
    SI resultado_intelar ≠ 0
        WAIT (30 ó 60 seg) · reintentar UNA vez
        SI sigue ≠ 0 → registrar "ERROR AL ENVIAR <arch> RS=... TRANSFERIR MANUAL OPC=nn AAAAMMDD"  ⚠
        SINO → registrar "ARCHIVO <arch> ENVIADO"
    SINO → registrar "ARCHIVO <arch> ENVIADO"

PATRÓN B — multi-copia 1×1 (archivos particionados _01.._NN):
    rutina cabecera: fija número de copia (de Q-OPC-2D o incrementando), resetea intento/ok,
        PERFORM <rutina>-1X1 UNTIL trf_ok=1 ; al alcanzar copia máx (5, 9 ó 14) → trf_times=1
    rutina -1X1: ADD 1 a intento · enviar copia
        SI falla: SI intento=1 → WAIT(05) y reintenta ; SINO registrar error + comando de
                  reproceso (WKS-PARAM-REPROC) y marca trf_ok=1 (deja de reintentar esa copia)
        SINO registrar "ENVIADO" y trf_ok=1

PATRÓN C — genérico nuevo (9000000-ENVIA-INTELAR):
    intentos=0 · MOVER archivo A buffer · PERFORM 9000001-CALL-INTELARSND UNTIL intentos=2
    9000001-CALL-INTELARSND: enviar ; si falla ADD 1 a intentos, si llega a 2 registra error
        "TRANSFERIR MANUAL OPC=..." ; si intentos<2 WAIT(60) ; si OK intentos=2 y registra "ENVIADO"

5.1 Hardcodes y código muerto detectados

  • Hostnames y CSI hardcodeados: la matriz completa host→CSI→host-destino ("MONBETA"/"VDMALFA"/"ACYPGAMA"/... y CSI 04/10) está incrustada en Inicio [P197 L153800–L156840]. Agregar un host exige modificar el fuente. ⚠ material operativo — no limpiar.
  • 9 variantes DUMPALL fijas (WKS-COPY-DUMPALL-81..89): cada par host-origen/destino es una constante; ampliar la topología exige una nueva variante. [P197 L182600–L184234]
  • Ventana de año 2016–2061 validada inline [P197 L161000], mientras el 88-nivel W88-PAR-AAAA-OK (2000–2060) queda declarado sin uso [P197 L110700].
  • Tamaño de comando XFER fijo = 192 [P197 L179520].
  • FD CTOCHE / CTOCMA y sus chequeos de residencia: comentados (cambio R4-COPIAS-2011) — código muerto reemplazado por envío INTELAR. [P197 L108806–L108860, L188405–L188445, L191905–L191945]
  • Copy-paste en logs de error: Envia_Motor reporta "OPC=60" en lugar de "OPC=66" [P197 L215681]; MoniP014-1X1/ProbP014-1X1 nombran WKS-ARCH-93-PROB en su mensaje de error [P197 L216600, L219300].
  • Sentencia huérfana MOVE "O" TO TIPO-LJ. entre párrafos [P197 L244620].
  • Numeración de párrafo duplicada (mismo número, distinto sufijo): 5002000, 7004680(×5), 7004690(×2), 7006100(×2), 7006300(×2), 7006700(×3), 9000001(×2), 1000100(×2).

CORE-GL · P104 a Java 21 Spring Boot

P104 recibe el número de sistema y lee dos archivos: CVETRAN, con los movimientos que reporta el sistema origen, y CVETRANCORE-GL, con lo que registró CORE-GL. De cada uno toma solo los detalles, los ordena por libro, moneda, producto, instrumento, clave y tipo de movimiento, y compara importes totales por esa llave. Los grupos que no cuadran se escriben en CVESNNNDIF o CVECORE-GLDIF según el lado, y si hubo diferencias se ordenan por contrato y se aparean a detalle para listar los movimientos que solo existen en un lado. Emite dos listados, purga los archivos de trabajo y, para los sistemas 804 y 203, controla el reproceso en la bitácora B05.

@Configuration
public class PunteoJobConfig {

    /** 000000-PROGRAMA. El parámetro de sistema llega como JobParameter (USING W77-SISTEMA-PARAM). */
    @Bean
    Job punteoCORE-GL(JobRepository repo, Step inicio, Step ordenaTotales, Step comparaTotales,
                   Step ordenaPorContrato, Step comparaDetalle, Step purgaTrabajo,
                   Step actualizaB05, JobExecutionDecider hayDiferencias, JobExecutionDecider esAltaDisponibilidad) {
        return new JobBuilder("CORE-GLP104", repo)
                .start(inicio).next(ordenaTotales).next(comparaTotales)
                .next(hayDiferencias)                                  // W77-BAN-DIFSNNN = 1 OR W77-BAN-DIFCORE-GL = 1
                    .on("CON_DIFERENCIAS").to(ordenaPorContrato).next(comparaDetalle)
                .from(hayDiferencias)
                    .on("*").to(comparaDetalle)                        // el detalle corre aunque no haya diferencias
                .next(purgaTrabajo)                                    // CLOSE A00-SPUNTEO1/2 WITH PURGE
                .next(esAltaDisponibilidad)                            // sistema 804 o 203 y VALUE OF MYSELF = 0
                    .on("SI").to(actualizaB05)
                .from(esAltaDisponibilidad).on("*").end()
                .end()
                .build();
    }
}
@Bean
Step ordenaTotales(JobRepository repo, PlatformTransactionManager tx,
                   @Qualifier("cvetran") FlatFileItemReader<DetallePunteo> origen,
                   SortedWorkFileWriter<DetallePunteo> spunteo1) {
    // 20010-GENERA-ARCHIVO1 + SORT SCVETRAN ... USING A00-SPUNTEO1 GIVING A00-SPUNTEO1
    return new StepBuilder("ordenaTotales", repo)
            .<DetallePunteo, DetallePunteo>chunk(1000, tx)
            .reader(origen)
            .processor(d -> d.cveReg() == 2 ? d : null)        // IF A00-R01-PUN-CVEREG = 2: header y trailer se descartan
            .writer(spunteo1.ordenadoPor(Comparator.comparing(DetallePunteo::llaveTotales)))
            .build();
}

/** 30300-COMPARA-GLOBAL: merge de dos secuencias de totales ya agrupadas por LlaveTotales. */
public ResultadoPunteo comparaTotales(PeekingIterator<GrupoTotales> snnn,
                                      PeekingIterator<GrupoTotales> core-gl) {
    var r = new ResultadoPunteo();
    while (snnn.hasNext() || core-gl.hasNext()) {
        if (!core-gl.hasNext()) { r.soloOrigen(snnn.next()); continue; }          // DET4
        if (!snnn.hasNext()) { r.soloCORE-GL(core-gl.next());   continue; }          // DET3

        int cmp = snnn.peek().llave().compareTo(core-gl.peek().llave());
        if (cmp == 0) {
            GrupoTotales a = snnn.next(), b = core-gl.next();
            if (a.importe().compareTo(b.importe()) == 0) r.cuadra(a, b);        // DET1
            else { r.descuadre(a, b); }                                          // DET2: graba en ambos archivos
        } else if (cmp > 0) {
            r.soloCORE-GL(core-gl.next());                                            // DET3 -> CVECORE-GLDIF
        } else {
            r.soloOrigen(snnn.next());                                          // DET4 -> CVESNNNDIF
        }
    }
    return r;   // r.hayDiferenciaOrigen() = W77-BAN-DIFSNNN; r.hayDiferenciaCORE-GL() = W77-BAN-DIFCORE-GL
}

Riesgos de migración
Caja incorrecta en diferencias de CORE-GL

En 30900-GRABA-DIFCORE-GL2 (línea 2703) la caja inicial se toma de A00-R01-PUN-CAJAINI, el buffer del archivo origen, aunque el registro de CORE-GL trae su propia R00-CORE-GL-CAJAINI (línea 93). El listado a detalle muestra una caja que no corresponde al movimiento de CORE-GL.

Condición siempre verdadera

IF W77-EOF = 0 OR 1 (línea 2666) e IF W77-EOF2 = 0 OR 1 (línea 2704) se cumplen siempre. Si la relectura del grupo llegara a fin de archivo, se escribiría otra vez el registro que quedó en el buffer.

Cuadre solo por importe

En 30300-COMPARA-GLOBAL una clave cuadra si el importe total coincide, aunque el número de movimientos sea distinto entre el origen y CORE-GL.

Archivo vacío y aviso de sin información

El aviso NO HUBO INFORMACION del punteo por totales (líneas 2377-2389) exige que ambos lados hayan llegado a fin de archivo con un contador de 1 en el grupo leído. Según la lectura del fuente, con archivos completamente vacíos el contador queda en 0 y el programa entra a 30300-COMPARA-GLOBAL con llaves tomadas de un buffer no leído.

Fallback de librería que cambia el título equivocado

Si CTLVERS no encuentra S080BD01CON (líneas 1760-1768), el programa cambia el TITLE de CORE-GLLIBCONTROL a la librería de catálogos de S080 en lugar de cambiar el de CATALOGOS, con lo que la librería de control de CORE-GL queda apuntando a otro objeto.

Sistemas compilados

Los sistemas 804 y 203 de alta disponibilidad (líneas 1719 y 1814), la lista 804, 404, 707 y 203 (líneas 1666 y 2048), la plataforma C para 402 y 600 (línea 1775) y los números de respaldo 31 y 32 para el sistema 500 están en el código. Se trasladan a application.yml.

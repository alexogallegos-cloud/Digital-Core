CORE-GL · P013 a Java 21 Spring Boot

P013 arranca con la fecha contable de CORE-DEP obtenida de L001, carga del catálogo S080 las claves de transacción que pertenecen al servicio de domiciliación y entra a un ciclo que no termina hasta que COMS lo indica. En cada vuelta envía los registros pendientes y los reintentos de B10DOMI, lee un lote de hasta W77-LIMITE-ENVIOS movimientos nuevos de MOVCORE-DEP y, por cada importe con clave de domiciliación, da de alta un registro en B10DOMI y lo envía a S702; las funciones 2, 21 y 22 de CORE-DEP cancelan registros ya dados de alta. Si el servicio hacia S702 está inactivo los registros se guardan como pendientes. Desde la corrección del incidente INC0013018473 una orden de activación de S702 solo se acepta si su fecha SA2 coincide con la fecha contable de P013.

@Service
@RequiredArgsConstructor
class CicloDomiciliacion {

    private final ControlDomiciliacionRepository control;
    private final DomiciliacionProperties props;     // hora-fin-servicio: "22:00", limites
    private final PendientesService pendientes;      // 021200 / 021300
    private final JobLauncher launcher;
    private final Job movimientosCORE-DEP;               // 021600-MOVCORE-DEP
    private final Clock clock;
    private boolean preguntaMatutinaHecha;           // WKS-BAN-HR, se limpia en 022100-CAMBIO-DIA

    @Transactional
    void ejecutar() {
        ControlDomiciliacion ctl = control.findById(1).orElseThrow();
        if (!preguntaMatutinaHecha) {                // WKS-BAN-HR = 0 (solo en memoria)
            activacionMatutina(ctl);                 // 021222-VALIDA-SERV
        }
        if (ctl.isServicioActivo()) {
            pendientes.enviaPendientes(props.limitePendientes());   // status 0 y 5, máx. W77-LIMITE-PENDIENTES
            pendientes.enviaReintentos(LocalTime.now(clock));
        }
        launcher.run(movimientosCORE-DEP, new JobParametersBuilder()
                .addLong("desde", ctl.getAutCORE-DEP() + 1)
                .addLong("limite", (long) props.limiteEnvios())       // W77-LIMITE-ENVIOS VALUE 300
                .toJobParameters());

        // 021700-VALIDA-HORARIO: después de las 22:00 se apaga el servicio hacia S702
        if (LocalTime.now(clock).isAfter(props.horaFinServicio()) && ctl.isServicioActivo()) {
            ctl.setServicioActivo(false);
            log.info("SE ACTIVO EL FIN DE SERVICIO DEL PROGRAMA X HORARIO");
        }
    }
}

@Component
@StepScope
@RequiredArgsConstructor
public class DomiciliacionProcessor implements ItemProcessor<MovimientoCORE-DEP, MovimientoCORE-DEP> {

    private final AltaDomiciliacion alta;           // 021640-ALTA-MOVS
    private final CancelacionDomiciliacion cancela; // 021621 / 021630

    @Override
    public MovimientoCORE-DEP process(MovimientoCORE-DEP m) {
        // El avance (W77-AUT-ENVIO500) se incrementa para todos los registros leídos.
        if (m.tipoProc() >= 40 && m.tipoProc() <= 43) {
            return m;                               // Teletón: no participa en domiciliación
        }
        switch (m.funcion()) {
            case 21, 22 -> cancela.porProceso(m);   // cancelación masiva por proceso
            case 2      -> cancela.porCadena(m);    // cancelación siguiendo AUT-AELIM-CORE-GL
            case 1      -> alta.registra(m);
            default     -> { }                      // cualquier otra función se ignora
        }
        return m;
    }
}
@Service
@RequiredArgsConstructor
class AltaDomiciliacion {

    private final CatalogoDomiciliacion catalogo;   // WKS-CVETRAN-DOMI OCCURS 10000, servicio 3
    private final B10DomiRepository b10;
    private final ControlDomiciliacionRepository control;
    private final S702Gateway s702;

    void registra(MovimientoCORE-DEP m) {
        boolean activo = control.servicioActivo();
        for (int occ = 1; occ <= 5; occ++) {
            int cveTran = m.cveTran(occ);
            if (cveTran == 0) break;                         // MOVE 6 TO WKS-NUM-OCCURS
            if (!catalogo.esDomiciliacion(cveTran)) continue;

            B10Domi reg = B10Domi.desde(m, occ);             // 021643-MUVE-DATOS-DOMI, status 1, num-env 1
            if (!activo) {
                reg.marcaPendiente();                        // 021643-ALTA-DOMI-PEN: status 0, num-env 0
            }
            Optional<B10Domi> guardado = b10.guardaSiNoExiste(reg);   // STORE ... DMSTATUS(DUPLICATES)
            if (activo && guardado.isPresent()) {
                s702.envia(MensajeDomiciliacion.de(guardado.get()));   // 021236-ARMAREST-ENV-DIALOGO
            }
        }
    }
}

@Service
@RequiredArgsConstructor
class CancelacionDomiciliacion {

    private final B10DomiRepository b10;
    private final ControlDomiciliacionRepository control;
    private final S702Gateway s702;

    /** 021621/021623: FUNCION 21 cancela todo el proceso; 22 solo lo posterior a AUT-AELIM-CORE-GL. */
    void porProceso(MovimientoCORE-DEP m) {
        long desde = (m.funcion() == 21) ? 0 : m.autAelimCORE-GL();
        boolean activo = control.servicioActivo();
        for (B10Domi r : b10.paraCancelar(m.fecCargo(), m.tipoProc(), desde)) {   // LOCK B10SXPROC
            r.setTipoMov(2);
            if (activo) {
                if (r.getStatus() == 1 || r.getStatus() == 2) {
                    r.setStatus(3);                                  // cancelado y enviado
                    b10.save(r);
                    s702.envia(MensajeDomiciliacion.de(r));
                }
            } else {
                switch (r.getStatus()) {                             // 021624-ALMACENA-PENDIENTE

                    default -> { }                                   // otros estados no se tocan
                }
            }
        }
    }

        if (msg.destino() != 15113 || msg.sistemaDestino() != 151 || msg.direccion() != 1) {
            monitor.eco(msg);                                     // 022220-GUARDA-ECO
            return;
        }
        boolean ordenServicio = (msg.dcod() == 1 || msg.dcod() == 2) && msg.dscod() == 3;
        if (!ordenServicio) {
            monitor.eco(msg);
            return;
        }
        if (!msg.sa2().fecha().equals(fechaContable.actual())) {
            monitor.registra("RECEPCION MENSAJE  S702-CORE-GL", msg); // se ignora la orden, sin respuesta
            return;
        }
        control.fijaServicio(msg.dcod() == 1);                    // 022210-ACT-DEACT-SERV
        monitor.registra("RECEPCION MENSAJE  S702-CORE-GL", msg);
        s702.responde(msg.respuesta());                           // 022220-ENVIA-RES
    }

    void activacionMatutina(ControlDomiciliacion ctl) {
        if (LocalTime.now(clock).getHour() == 6 && !ctl.isServicioActivo()) {

                          + "DESEA ACTIVAR EL SERVICIO: S/N");
        }
    }

    public void respuestaOperador(String resp) {
        if ("S".equals(resp)) {
            control.fijaServicio(true);            // MOVE 1 TO W77-STATUS-SERV
        }

Riesgos de migración
Proceso detenido esperando al operador

021222-VALIDA-SERV (líneas 3614-3626) hace ACCEPT WKS-RESP-OPE a las 06 horas si el servicio está inactivo. Mientras no hay respuesta no se leen movimientos ni se envían domiciliaciones.

Orden de S702 descartada sin respuesta

Con la validación del INC0013018473 (línea 3369), una orden con fecha SA2 distinta a la fecha contable solo se anota en el monitor; S702 no recibe respuesta y puede asumir que el servicio cambió de estado.

Reintentos de DEADLOCK sin límite

Los LOCK FIRST y LOCK NEXT sobre B10SXPROC y B10SXFECAUT151 se repiten sin pausa mientras haya DEADLOCK (líneas 2981-2986, 3033 y 3089).

Fallas de REWRITE del control ignoradas

Los REWRITE de A02-CTL-DM llevan INVALID KEY NEXT SENTENCE (líneas 3427, 3434 y 3441). Un avance no guardado provoca reprocesar movimientos al reiniciar; los duplicados se detectan en el STORE, pero las cancelaciones se volverían a aplicar.

Hardcodes de horario y límites

Fin de servicio a las 22:00 (79200 segundos), pregunta al operador a las 06 horas, W77-LIMITE-ENVIOS 300 con mínimo 80, W77-LIMITE-PENDIENTES 150 con mínimo 40, reintento a los 120 segundos (línea 2621) y destino COMS 015113. Se trasladan a application.yml.

Pendiente de revisión SME
  • Confirmar el formato de WKS-SA2-FECHA en los mensajes que llegan de S702 (AAMMDD o DDMMAA). P013 la compara con WKS-FECPRO-6D, que es AAMMDD por la REDEFINES de las líneas 1463-1470; si S702 usa otro formato la orden nunca se aceptaría.
  • RN-CORE-GL-1026 dice que BAN-HR activa una validación de ventana horaria de Banxico. En el fuente R01-REG-BAN-HR (WKS-RESET-HORA) solo marca que ya se reiniciaron las horas de envío de los reintentos del día anterior (líneas 2935 y 3596), y WKS-BAN-HR en memoria controla que la pregunta de las 06 horas se haga una vez (líneas 2470-2471 y 3618-3619). No se encontró una ventana horaria de Banxico en P013. Revisar la redacción de la regla en el brain.
  • RN-CORE-GL-1029 indica que SER discrimina subtipos de servicio; en el fuente R01-REG-SER se carga en W77-STATUS-SERV y solo se usa como activo (1) o inactivo (0) mediante W88-SER-ACT. Validar con SME.

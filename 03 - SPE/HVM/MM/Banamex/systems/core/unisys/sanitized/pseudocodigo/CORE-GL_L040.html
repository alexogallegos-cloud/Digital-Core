L040 · TOTXCVETRA — Consulta de Totales por Clave de Transacción (CORE-GL · LegacyCore · Unisys ClearPath MCP)

CORE-GLLibreríaCOBOL

Fuente: COBOL_L040.cbl (4110 LOC) · Librería SHARED BY ALL / TARGET=LEVEL2 · rol: servicio de consulta de totales intraday del GL · BC-XX

Convenciones: nombres traducidos (Unisys→legible); [L040 Lnnnn] = línea origen en la fuente; (BR: RN-...) = regla de negocio. Marcas: ⚠ [HARDCODE], ⚠ [CODIGO-MUERTO], ⚠ [DIVERGENCIA-KB].

1. Resumen funcional

L040 (PROGRAM-ID TOTXCVETRA) es una librería MCP SHARED BY ALL con TARGET=LEVEL2 (BR: RN-CORE-GL-990): se carga una sola vez en memoria compartida de nivel 2 y atiende, sin recargas, a todas las tareas del sistema CORE-GL. Su función es calcular y devolver totales de movimientos del día (número de movimientos NUMMOV e importe IMPMOV) agregados según distintas combinaciones de clave: sistema, proceso, producto, instrumento, moneda, bancos origen/destino y clave de transacción (CVETRA) / esquema contable (ESQCON).

Se invoca vía CALL "...TOTXCVETRA..." pasando dos parámetros LINKAGE: la estructura WKS-L40-CVES (función + criterios de filtro + arreglo de hasta 100 renglones de resultado) y W77-RESULT-CORE-GL (código de resultado). El número de función (WKS-L40-FUN-L040) selecciona la operación (BR: RN-CORE-GL-991):

  • 0 = abrir la base del sistema · 40 = cerrar base · 41 = (re)abrir base.
  • 1–14 = consulta a nivel clave de transacción (agrupa/acumula por CVETRA).
  • 21–34 = consulta a nivel esquema (agregado por sistema; reutiliza los mismos párrafos 1–14 pero toma la rama sin agrupación por CVETRA).
  • 15–20 = rango reservado → error (BR: RN-CORE-GL-991, RN-CORE-GL-992).

Accede al dataset DMSII B50SXTOTXCVE de la base CORE-GLBD10MOVDIA151 bajo el alias BASEMOVDIA (BR: RN-CORE-GL-993), fuente de verdad de los totales intraday. Integra la librería CTLVER (control de versiones, BR: RN-CORE-GL-994), DESPLIEGA (mensajería al operador, BR: RN-CORE-GL-995) y LIB-CONTROL/CONSISDIA (estado del día del sistema, BR: RN-CORE-GL-996). Devuelve códigos de resultado estandarizados 0–8 y 99=EOF (BR: RN-CORE-GL-992, RN-CORE-GL-997, RN-CORE-GL-999).

2. Datos y archivos

Base de datos DMSII (DATA-BASE SECTION) [L040 L0073]

  • BASEMOVDIA = CORE-GLBD10MOVDIA151 — alias local de la base de movimientos del día (BR: RN-CORE-GL-993).
  • Dataset/SET accedido: B50SXTOTXCVE (totales por clave). Campos de registro leídos (prefijo B50-MOV-): FEC (fecha), PROCESO, PRD (producto), INS (instrumento), MONEDA, CVETRA (clave transacción), ESQCON (esquema contable), BANCOS (empaquetado 6D: BORICON/BDESCON), NUMMOV (nº movimientos), IMPMOV (importe S9(13)V99).

Parámetros LINKAGE (interfaz de la librería) [L040 L1165-1197]

  • WKS-L40-CVES — registro entrada/salida:
  • WKS-L40-FUN-L040 9(02) — función solicitada.
  • Criterios: WKS-L40-FECHA, WKS-L40-SISTEMA, WKS-L40-PRODUCTO, WKS-L40-INSTRUMENTO, WKS-L40-PROCCON, WKS-L40-BCOSCON (redefine en BORICON/BDESCON), WKS-L40-MONCON, WKS-L40-CVETRACON, WKS-L40-ESQCONCON.
  • WKS-L40-IMPORTES OCCURS 100 TIMES — arreglo de salida (⚠ [HARDCODE] tope de 100 renglones): por renglón PROCESO, MONEDA, CVETRA, ESQCON, NUMMOV 9(08), IMPMOV S9(13)V99, BCOSDET (BCOORI/BCODES).
  • W77-RESULT-CORE-GL S9(11) — código de resultado devuelto.

Working-storage relevante

  • WKS-CORE-GLB01SISDIA (+ variantes F02–F11) y WKS-B01-CONB01 — layouts del ENTRY-POINT CONSISDIA / CONSISB01 (estado del día por sistema) [L040 L0308-0549].
  • WKS-B02ARCINTER, WKS-B04SISTEMA, WKS-B05PROCESOS, WKS-CORE-GLB09CONXSIS, WKS-CORE-GLB03SISMEN (+ F03–F22) — layouts de otros ENTRY-POINTs de LIB-CONTROL (declarados vía COPY; no todos usados por L040) [L040 L0540-0878].
  • Tabla de leyendas de error DMSII WKS-TAB-ERRDMSII (21 entradas NOTFOUND…INTLIBERROR) y WKS-CATEGORIAS [L040 L0898-0979].
  • WKS-NOMBASE-SEM — título dinámico de la base: "(CORE-GL)" + WKS-NOMBD + " ON CMEMP." [L040 L1018-1022] ⚠ [HARDCODE] pack CMEMP.
  • WKS-DATOS-HOST (CSI, equipo, línea batch) — poblado por CSIID IN SOPORTECOMS [L040 L1024-1028].
  • MENSAJE-LJ — formato de mensaje al operador SIST/PASO/MTP:TIPO>CODIGO<TEXTO(250) (COPY DESPLIEGA) [L040 L0263-0274] (BR: RN-CORE-GL-995).
  • Contadores/flags de control: W77-IND/W77-IND2 (índice arreglo), W77-CVETRA-ANT (CVETRA anterior para agrupar), W77-ERROR-BASE, W77-RESULT-LIBCON, W77-INTENTOS (reintentos de apertura), W77-BASE (88 W88-BASE-OPEN), WKS-ABRE-SEM/WKS-INICIO (estado de apertura de la base).

Códigos de resultado devueltos en W77-RESULT-CORE-GL (BR: RN-CORE-GL-992) [L040 L0050-0062 doc]: 0=OK · 1=función inválida / no inicializado · 2=función reservada 15–20 (doc: "fecha inválida") · 3=sistema sin totales · 4=producto sin totales · 5=instrumento sin totales · 6=base de control no disponible · 7=base MOVDIA no disponible · 8=sistema no dado de alta · 9=error DMSII (interno) · 99=fin de datos (EOF). ⚠ [DIVERGENCIA-KB] La KB (RN-CORE-GL-992) y el encabezado documentan 2 = fecha inválida, pero en el código 2 sólo se asigna en 00005-FUNCION-ERROR, alcanzado por las funciones reservadas 15–20 (función inválida). No hay validación explícita de fecha en L040. « divergencia KB: RN-CORE-GL-992 »

Notas de arquitectura de control:

  • Las funciones 21–34 (nivel esquema) reutilizan físicamente los párrafos de 1–14: el GO TO … DEPENDING ON mapea el índice 21→01-0100-SIS, 22→02-0100-PRD, … 34→14-0100 [L040 L1219-1254]. Dentro de cada Nn-0100/Nn-0110, el IF WKS-L40-FUN-L040 = n distingue el modo clave (acumula por CVETRA) del modo esquema (rama ELSE, un renglón por fila).
  • El seccionamiento COBOL es irregular: existen 01-SECCION, 02-SECCION, 04-SECCION pero no 03-SECCION. Las funciones se agrupan bajo la sección abierta más reciente.

PROCEDIMIENTO Punto_De_Entrada_Consulta_Totales():   // 00000-INICIO · [L040 L1203]
    // Sella la identidad para mensajería al operador ⚠[HARDCODE]
    MOVER "CORE-GL" A sistema_msg          // SISTEMA-LJ  [L040 L1206]
    MOVER "L040" A paso_msg             // PASO-LJ     [L040 L1207]
    MOVER "002"  A mtp_msg              // MTP-LJ      [L040 L1208]

    EJECUTAR Limpia_Variables_Y_Arreglo()             // [L040 L1210]

    SI funcion ∈ {0, 40, 41}                          // WKS-L40-FUN-L040  [L040 L1211]
        EJECUTAR Levanta_O_Cierra_Base()              // 00-0100-LEVANTA
    SINO
        // Desempaqueta bancos (formato 6D → 5D interno)  [L040 L1214-1216]
        MOVER bancos_consulta A bancos_6d             // WKS-L40-BCOSCON → WKS-BANCOS-6D
        MOVER banco_origen_6d  A banco_origen         // WKS-BORICON
        MOVER banco_destino_6d A banco_destino        // WKS-BDESCON
        SI base_inicializada = 1                      // WKS-INICIO  [L040 L1217]
            SI base_semanal_abierta = 1               // WKS-ABRE-SEM  [L040 L1218]
                // Despacho por número de función [L040 L1219-1254]
                IR_SEGUN funcion A:                    // GO TO … DEPENDING ON
                    1→SIS 2→PRD 3→PRD-INS 4→MON 5→PRD-MON 6→PRD-INS-MON
                    7→PRO 8→PRO-PRD 9→PRO-PRD-INS 10→PRO-MON 11→PRO-PRD-MON
                    12→PRO-PRD-INS-MON 13→SIS-PRO-BORI-BDES 14→SIS-BORI-BDES
                    15..20→Funcion_Error   // rango reservado → resultado 2 (BR: RN-CORE-GL-991)
                    21..34→ mismos párrafos que 1..14 (modo esquema)
                // Si función fuera de rango, cae aquí:
                SINO (base_semanal_abierta ≠ 1)
                    MOVER 7 A resultado    // base MOVDIA no disponible  [L040 L1256] (BR: RN-CORE-GL-997)
            SINO (base_inicializada ≠ 1)
                MOVER 1 A resultado        // no inicializada / función inválida  [L040 L1258]
    SALIR_PROGRAMA                                     // EXIT PROGRAM  [L040 L1259]

PROCEDIMIENTO Levanta_O_Cierra_Base():                // 00-0100-LEVANTA · [L040 L1285]

    MOVER 1 A W77-BASE ; SUMAR 1 A intentos             // [L040 L1356-1357]
    MOVER 0 A error_base, resultado ; MOVER LOW-VALUES A nulos  // [L040 L1359-1361]

                MOVER nombre_bd A nombre_bderr ; EJECUTAR Chequea_Estatus_DMSII()  // [L040 L1377-1378]

        MOVER 1 A base_semanal_abierta                   // [L040 L1396]

        MOVER 7 A resultado                              // base no disponible [L040 L1398] (BR: RN-CORE-GL-997)

4.2 Patrón genérico de las 14 secciones de consulta

Las funciones 1–14 (y sus gemelas de esquema 21–34) comparten un esqueleto idéntico de 7 párrafos. Se detalla aquí una sola vez; en 4.2 se listan las particularidades (llaves de búsqueda, códigos de "sin totales") de cada función. Nn = número de función; <crit> = criterio.

PROCEDIMIENTO Consulta_<crit>():                       // Nn-0100-<crit>
    EJECUTAR Encuentra_Primero_<crit>()                 // Nn-0105-FIND-FIRST
    SI error_base = 0
        SI funcion = Nn                                 // ── MODO CLAVE (acumula por CVETRA)
            MOVER cvetra_registro A cvetra_anterior
            MOVER 1 A idx
            EJECUTAR Mueve_Datos_<crit>(idx)            // primer renglón
            MOVER 0 A renglon[idx].nummov, .impmov
            EJECUTAR Acumula_<crit>()                   // Nn-0110: bucle principal
                MIENTRAS idx ≠ 100 Y error_base = 0 Y resultado = 0
            SI idx = 100                                // arreglo lleno → drena grupo actual
                EJECUTAR Acumula_<crit>()
                    MIENTRAS cvetra_registro ≠ cvetra_anterior Y error_base=0 Y resultado=0
        SINO                                            // ── MODO ESQUEMA (fun 21-34): un renglón por fila
            EJECUTAR Acumula_<crit>()  MIENTRAS idx≠100 Y error_base=0 Y resultado=0
            SI idx = 100
                EJECUTAR Acumula_<crit>() MIENTRAS cvetra corta grupo / error / resultado
    SALIR_PROGRAMA

PROCEDIMIENTO Encuentra_Primero_<crit>():              // Nn-0105-FIND-FIRST
    SI cvetra_consulta = 0 Y esqcon_consulta = 0        // consulta desde el inicio
        EJECUTAR FF_Inicial_<crit>()                    // Nn-0150
    SINO                                                // reanuda desde CVETRA/ESQCON dados
        EJECUTAR FF_Continuacion_<crit>()               // Nn-0155

PROCEDIMIENTO Acumula_<crit>():                        // Nn-0110-<crit>
    MOVER campos_registro (proceso, prd, ins, moneda, cvetra, esqcon, bancos) A área consulta
    SI funcion = Nn Y (mismo CVETRA [y misma MONEDA donde aplique])   // agrupa
        SUMAR nummov_registro  A renglon[idx].nummov     // COMPUTE acumulado
        SUMAR impmov_registro  A renglon[idx].impmov
    SINO                                                 // cambia de grupo → nuevo renglón
        MOVER 0 A renglon[idx].esqcon
        idx = idx + 1
        SI idx < 101 → EJECUTAR Mueve_Datos_<crit>(idx) ; MOVER cvetra A cvetra_anterior
        SINO CONTINUAR
    EJECUTAR Encuentra_Siguiente_<crit>()               // Nn-0160-FIND-NEXT

PROCEDIMIENTO Mueve_Datos_<crit>(idx):                 // Nn-0115-MUEVE-DATOS
    // Copia el registro DMSII al renglón idx del arreglo de salida
    MOVER prd, ins, proceso, moneda, cvetra, esqcon, nummov, impmov A renglon[idx]
    MOVER bancos_registro A bancos ; empaqueta a 6D en renglon[idx].bcosdet
    // ⚠[CODIGO-MUERTO] líneas .bcodes / B50-MOV-BCODES comentadas en TODAS las funciones

PROCEDIMIENTO FF_Inicial_<crit>():                     // Nn-0150
    FIND FIRST B50SXTOTXCVE AT <llaves del criterio>
       EN EXCEPCION:
          MOVER 1 A error_base

P012 · Receptor de Mensajes COMS TANDEM-GLOBALDIRECT (CORE-GL)

CORE-GLProgramaALGOL

Fuente: ALGOL_P012.alg (265 LOC) · Daemon COMS en línea · BC-ID: —

Convenciones: nombres traducidos (Unisys ALGOL → español legible); [P012 Lnnn] = línea física del fuente; (BR: RN-...) = regla del KB.

CTD: abreviatura de GLOBALDIRECT — confirmado en fuente L143: "RECEPTOR DE MENSAJES DE TANDEN-GLOBALDIREDT" (el texto hardcodeado en el programa nombra el subsistema destino).

1. Resumen funcional

P012 es un daemon COMS residente en memoria del sistema CORE-GL que actúa como receptor y clasificador de mensajes enviados por el sistema TANDEM-GLOBALDIRECT (plataforma de banca electrónica/cash management de GlobalBank). El programa escucha eventos DCI de entrada (DCIINPUTEVENT) y de tarea (DCITASKEVENT), clasifica cada mensaje recibido por su tipo de cabecera (HDR_TIPO) y nodo de origen (HDR_NODOORIG), y reenvía las confirmaciones de transacción a la biblioteca CORE-GLL012 mediante ENVIA_CD. Responde a consultas de estado (tipo 11/12) con estadísticas de operación en tiempo real. Implementa control operacional dinámico vía TASKVALUE (modo debug, hot-swap de librería, apagado, reconfiguración de dispersión), lo que lo posiciona como un proceso de larga vida con capacidad de auto-actualización sin reinicio.

4.2 PROCEDURE Error_Liga (ERROR_LIGA)

PROCEDIMIENTO Error_Liga(codigo_error, mensaje_error):          // ERROR_LIGA · [P012 L49]
  % Traduce código de error de vinculación a texto descriptivo y aborta el programa.
  % Param: codigo_error (VALUE INTEGER I), mensaje_error (STRING S — in/out)

  SEGÚN ABS(codigo_error) HACER:                                // [P012 L52]
    CASO 1:  mensaje_error += ": LIBRERIA NO ESTA EN DISK <"
    CASO 2:  mensaje_error += ": FAMILISIZE EXCEEDED <"
    CASO 3:  mensaje_error += ": ENTRY POINT EN MAS DE UNA LIBRERIA <"
    CASO 4:  mensaje_error += ": LA LIBRERIA NO ES DE SISTEMA <"
    CASO 5:  mensaje_error += ": NUMERO O PARAMETROS NO CORRESPONDEN <"
    CASO 6:  mensaje_error += ": LA LIBRERIA NO INICIO CON EXITO <"
    CASO 7:  mensaje_error += ": LIGA CIRCULAR DE LIBRERIAS <"
    CASO 8:  mensaje_error += ": ENTRY POINT BY CALL NO ESPECIFICADO <"
    CASO 9:  mensaje_error += ": BAD TASK PASSED BY A CALLING <"
    CASO 10: mensaje_error += ": FEATURE USED NOT IMPLEMENTED <"
    CASO 11: mensaje_error += ": TIPO INVALIDO EN LA LIBRERIA <"
    CASO 12: mensaje_error += ": DEBE RECOMPILAR EL PROGRAMA <"
    CASO 13: mensaje_error += ": DIRECTORIO INCOMPATIBLE, RECOMPILE <"
    CASO 14: mensaje_error += ": EL PROGRAMA NO PUEDE LIGAR UNA SL <"
    CASO 15: mensaje_error += ": LIBRERIA NO INICIADA <"
    CASO 16: mensaje_error += ": PROGRAMA NO AUTORIZADO <"

4.3 PROCEDURE Refresca (REFRESCA)

PROCEDIMIENTO Refresca():                                       // REFRESCA · [P012 L76]
  % Hot-refresh de CORE-GLL012: consulta su título vigente en CTL_VER y la re-vincula.
  % Permite actualizar la librería sin reiniciar el daemon.

  VARIABLES LOCALES:
    nombre_libreria[0:17]   // NOM_L — nombre de la librería a refrescar

  VINCULAR CTL_VER (CTLVERS. por función)                       // [P012 L79]
  DECLARAR LOCALMENTE DAME_TIT(alias, titulo) DESDE CTL_VER    // [P012 L80-82]
    % Obtiene el título físico de la librería identificada por 'alias'

  resultado_liga := LINKLIBRARY(CTL_VER)                       // [P012 L83]
  SI resultado_liga >= 0 ENTONCES                               // CTL_VER vinculada OK
    MOVER "CORE-GLL012       " → nombre_libreria                  // [P012 L85]
    SI DAME_TIT(nombre_libreria, buffer_mensaje) = 0 ENTONCES   // [P012 L86]
      % Título obtenido correctamente; actualizar la vinculación de CORE-GLL012
      REEMPLAZAR CORE-GLL012.TITLE CON buffer_mensaje              // [P012 L88]
      MIENTRAS LINKLIBRARY(CORE-GLL012) < 0 HACER                 // [P012 L89]
        ERROR_LIGA(resultado_liga, "CORE-GLL012")    // reintento con log de error
      FIN MIENTRAS
    FIN SI
  FIN SI

  DESVINUCAR CTL_VER                                            // [P012 L93]
FIN PROCEDIMIENTO Refresca

« [P012 L76-94] · Nota: el fuente tiene typo en el delimitador: "END OF REFESCA" (L94)
  en lugar de "END OF REFRESCA". ⚠ [TYPO-SOURCE] No afecta compilación ALGOL (el
  nombre es decorativo en MCP), pero puede confundir a herramientas de búsqueda. »

4.4 PROCEDURE Cambia_L012 (CAMBIA_L012)

PROCEDIMIENTO Cambia_L012():                                    // CAMBIA_L012 · [P012 L96]
  % Recicla la vinculación de CORE-GLL012: desvincula, espera y refresca.
  % Invocado por TASKVALUE=11 desde RUTEA para hot-swap de la librería en producción.

  resultado_liga := DESVINUCAR CORE-GLL012                         // [P012 L98]
  ESPERAR 3 segundos                          // WAIT((03))     // [P012 L99]
  EJECUTAR Refresca                                             // [P012 L100]
FIN PROCEDIMIENTO Cambia_L012

4.5 PROCEDURE Inicia (INICIA)

PROCEDIMIENTO Inicia():                                         // INICIA · [P012 L103]
  % Inicialización del daemon: vincula bibliotecas COMS, configura opciones de proceso
  % MCP, obtiene el CSI ID propio y resuelve los designadores de estación y salida.

  VINCULAR COMS_LIB (COMSSUPPORT. por función)                  // [P012 L105]
  DECLARAR LOCALMENTE GET_DESIGNATOR_USING_NAME(nombre, nemónico, designador)
    DESDE COMS_LIB                                              // [P012 L106-111]
    % Resuelve el designador numérico COMS asociado a un nombre de recurso

  % --- Vinculación de bibliotecas obligatorias ---
  SI LINKLIBRARY(COMS_LIB) < 0 ENTONCES                        // [P012 L113]
    MYSELF.STATUS := -1    // abortar si COMS_LIB no disponible
  FIN SI
  SI LINKLIBRARY(SHELL) < 0 ENTONCES                           // [P012 L114]
    MYSELF.STATUS := -1    // abortar si SHELL no disponible
  FIN SI

  % --- Obtener CSI ID del propio proceso ---
  LLAMAR CSIID(buffer_mensaje)                                  // [P012 L115]
  COPIAR buffer_mensaje → identificador_csi  [primeros 2 bytes] // [P012 L116]

  % --- Configurar opciones del proceso MCP ---
  MYSELF.OPTIONS :=                                             // [P012 L117-120]
    bit BDBASE = 1 &   // activar base de datos de proceso
    bit FAULT  = 1 &   // habilitar trapping de fallas
    bit DSED   = 1 &   // habilitar DSED (descarga estructurada)
    bit ARRAYS = 1     // habilitar verificación de arrays

  % --- Construir nombre de BD del proceso (BDNAME) ---
  MOVER "CORE-GL/LIST/P012/" CAT identificador_csi [2 bytes]       // [P012 L121-122]
       CAT "00/R000/" CAT TIME[15:48] CAT "."
       → buffer_mensaje
  ⚠ [HARDCODE-PATH] El path "CORE-GL/LIST/P012/" y el sufijo "00/R000/" son literales hardcodeados.
  REEMPLAZAR MYSELF.BDNAME CON buffer_mensaje                   // [P012 L123]

  % --- Habilitar canal de entrada COMS ---
  HABILITAR cabecera_entrada CON "ONLINE"    // ENABLE(COMSINHDR,"ONLINE") // [P012 L124]

  % --- Resolver designadores de recursos COMS ---
  MOVER "DEFAULTSTATION" → buffer_mensaje                       // [P012 L125]
  ⚠ [HARDCODE-RECURSO] Nombre "DEFAULTSTATION" hardcodeado.
  SI GET_DESIGNATOR_USING_NAME(buffer_mensaje, 1, designador_estacion) > 0 ENTONCES
    MYSELF.STATUS := -1   // falla si no existe la estación default // [P012 L127]
  FIN SI

  MOVER "OUTPUT OF LINEA" → buffer_mensaje                      // [P012 L128]
  ⚠ [HARDCODE-RECURSO] Nombre "OUTPUT OF LINEA" hardcodeado.
  SI GET_DESIGNATOR_USING_NAME(buffer_mensaje, 3, designador_salida) > 0 ENTONCES
    MYSELF.STATUS := -1   // falla si no existe la línea de salida  // [P012 L130]
  FIN SI
FIN PROCEDIMIENTO Inicia

4.6 PROCEDURE Informa (INFORMA)

PROCEDIMIENTO Informa():                                        // INFORMA · [P012 L133]
  % Genera y envía un reporte de estado a la terminal que realizó la consulta.
  % Invocado cuando HDR_TIPO = "11" o "12" (mensajes de consulta de estadísticas).

  VARIABLES LOCALES:
    puntero_escritura   // P — apunta al inicio del área de texto en buffer_mensaje

  conteo_consultas := conteo_consultas + 1   // TIPO11:=*+1        // [P012 L136]

  % --- Invertir origen y destino (responder al emisor) ---
  COPIAR nodo_destino → buffer_auxiliar  [2 bytes]              // [P012 L137]
  COPIAR nodo_origen  → nodo_destino     [2 bytes]              // [P012 L138]
  COPIAR buffer_auxiliar → nodo_origen   [2 bytes]              // [P012 L139]
  MOVER "01" → tipo_mensaje                                     // [P012 L140]
  % El tipo de respuesta es siempre "01" (respuesta estándar), sin importar si la consulta era "11" o "12".

  puntero_escritura := tc_destino                               // [P012 L141]

  % --- Construir cuerpo del mensaje de estado ---                // [P012 L142-154]
  ESCRIBIR EN puntero_escritura:
    " " × 20
    "RECEPTOR DE MENSAJES DE TANDEN-GLOBALDIREDT"                 // [P012 L143]
    ⚠ [TYPO-SOURCE] "TANDEN" debería ser "TANDEM"; "GLOBALDIREDT" debería ser "GLOBALDIRECT".
      Este texto está hardcodeado en el buffer y se envía tal cual a la terminal.
    CRLF CRLF
    " " × 8   "DESCRIPCION  NUMERO ULTIMO"  CRLF
    " " × 8   "CONSULTAS  = "  conteo_consultas [6 dígitos]     CRLF
    " " × 8   "CONFIRMADOS= "  conteo_confirmados [6 dígitos]
                                " "  ultimo_seq_confirmado [6 dígitos]  CRLF
    " " × 8   "TIPO 32    = "  conteo_tipo32 [6 dígitos]
                                " "  ultimo_seq_tipo32 [6 dígitos]      CRLF
    " " × 8   "NO ENVIES  = "  conteo_no_envio [6 dígitos]
                                " "  ultimo_seq_no_envio [6 dígitos]    CRLF
    " " × 8   "DUPLICADOS = "  conteo_duplicados [6 dígitos]
                                " "  ultimo_seq_duplicado [6 dígitos]   CRLF
    " " × 8   "INVALIDOS  = "  conteo_invalidos [6 dígitos]

  longitud_texto := OFFSET(puntero_escritura)                   // [P012 L155]
  % Calcula la longitud del texto construido mediante el avance del puntero.

  % --- Configurar cabecera de salida COMS ---
  cabecera_salida.DESTCOUNT       := 1                          // [P012 L156]
  cabecera_salida.AGENDA          := designador_salida          // [P012 L157]
  cabecera_salida.TEXTLENGTH      := longitud_texto             // [P012 L158]
  cabecera_salida.STATUSVALUE     := 0                          // [P012 L159]
  cabecera_salida.DESTINATIONDESG := designador_estacion        // [P012 L160]

  resultado_operacion := SEND(cabecera_salida,
                              cabecera_salida.TEXTLENGTH,
                              buffer_mensaje)                   // [P012 L161]
FIN PROCEDIMIENTO Informa

4.7 PROCEDURE Procesa (PROCESA)

PROCEDIMIENTO Procesa():                                        // PROCESA · [P012 L164]
  % Clasifica el mensaje COMS recibido y lo procesa según tipo y nodo de origen.
  % Es el núcleo de la lógica de negocio del daemon.

  longitud_texto := cabecera_entrada.TEXTLENGTH                 // [P012 L166]

  % === RAMA 1: Consulta de estado (tipos 11 y 12) ===          // [P012 L168]
  SI tipo_mensaje = "11" O tipo_mensaje = "12" ENTONCES
    EJECUTAR Informa
  SINO

  % === RAMA 2: Validación de mensaje de negocio ===            // [P012 L171-174]
  SI (tipo_mensaje ≠ "02" Y tipo_mensaje ≠ "32")
     O (longitud_texto < 42)
     O (nodo_origen ≠ "15" Y nodo_origen ≠ "16"
        Y nodo_origen ≠ "21" Y nodo_origen ≠ "22")
  ENTONCES
    conteo_invalidos := conteo_invalidos + 1                    // [P012 L175]
    ⚠ [HARDCODE-NODOS] Nodos origen válidos "15","16","21","22" hardcodeados.
    ⚠ [HARDCODE-TIPOS] Tipos válidos "02","32" hardcodeados.
    ⚠ [HARDCODE-UMBRAL] Longitud mínima 42 bytes hardcodeada.
    ⚠ [DESCARTE-SILENCIOSO] El mensaje inválido solo incrementa contador; sin log, sin alerta.
  SINO

  % === RAMA 3: Mensaje TIPO 02 (confirmación) ===              // [P012 L177]
  SI longitud_texto > 123 Y tipo_mensaje = "02" ENTONCES

Nota sobre RN-CORE-GL-1159: La ficha KB es un stub arquitectural de confianza media. La lectura completa del fuente determina con precisión la responsabilidad del programa:

« divergencia KB: RN-CORE-GL-1159 »

El KB describe P012 como "proceso auxiliar del núcleo" (genérico) y su fórmula pseudocódigo referencia incorrectamente "PROGRAM P007" en lugar de "PROGRAM P012" — evidencia de que la ficha fue generada por copy-paste desde la entrada de P007 (HEUR-024 confirmado para este artefacto).

La fuente establece que P012 es un receptor de mensajes COMS del sistema TANDEM-GLOBALDIRECT, con las siguientes responsabilidades concretas:

- Recibir mensajes tipo 02 (confirmaciones de transacción) desde nodos "15","16","21","22"

- Recibir mensajes tipo 32 (confirmaciones alternativas) y reenviarlas como tipo 2

- Atender consultas de estado (tipo 11/12) con estadísticas operacionales en tiempo real

- Implementar control operacional en caliente vía TASKVALUE (debug, hot-swap de librería, apagado, reconfiguración de dispersión)

- Delegar toda lógica de persistencia/DMSII a CORE-GLL012::ENVIA_CD

No tiene acceso directo a datasets DMSII. No procesa movimientos contables directamente. La estrategia RETAIN+ENCAPSULATE del KB es aplicable, pero la "lógica de dominio" a encapsular es de mensajería transaccional, no de "núcleo de movimientos contables" como sugiere el contexto del stub.

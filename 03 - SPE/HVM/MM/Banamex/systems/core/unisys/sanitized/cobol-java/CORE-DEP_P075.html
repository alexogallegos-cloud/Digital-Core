@Component
@RequiredArgsConstructor
public class CambioDiaTasklet implements Tasklet {

    private final CatalogoVersiones ctlvers;     // DAME_TIT IN CTLVERS
    private final ControlCaptacionL080 l080;     // CORE-DEPL080CTRL
    private final BitacoraOperacion lj;

    /** 000000-MODULO-DE-CONTROL. El parámetro ya llegó validado (s1). */
    @Override
    public RepeatStatus execute(StepContribution c, ChunkContext ctx) {
        String titulo = ctlvers.titulo("CORE-DEPL080CTRL")
                .orElseThrow(() -> new CambioDiaNoNotificadoException(
                        "ERROR EN CALL CTLVERS CORE-DEPL080"));   // el fuente solo lo registra
        ResultadoInibatch r = l080.inibatch(titulo);          // 200000-INIBATCH
        if (!r.exitoso()) {
            throw new CambioDiaNoNotificadoException("ERROR EN LLAMADO INIBATCH " + r.codigo());
        }
        return RepeatStatus.FINISHED;
    }
}

@Service
@RequiredArgsConstructor
public class CatalogoVersiones {

    private final CtlversClient cliente;

    /** 20000100-DAME-TIT-VERS: devuelve el título físico vigente de una librería lógica. */
    public Optional<String> titulo(String libId) {
        var r = cliente.dameTit(libId);                       // GIVING S000-CTR-CVEERROR
        if (r.cveError() != 0) {
            log.error("ERROR EN CALL CTLVERS {} RESULT={}", libId, r.cveError());   // código completo
            return Optional.empty();
        }
        return Optional.of(r.nombreLibreria());               // S000-CTR-NOMLIB X(72)
    }
}
@Service
@RequiredArgsConstructor
public class ControlCaptacionL080 {

    private final L080Gateway gateway;     // adaptador al servicio que reemplace a CORE-DEPL080CTRL

    /** 205000-INIBATCH-CALL: CALL "CORE-DEPL080INIBATCHP080 IN CORE-DEPL080CTRL" GIVING WKS-L080-RESULT. */
    public ResultadoInibatch inibatch(String version) {
        int codigo = gateway.inibatchP080(version);
        if (codigo != 0) {
            log.error("ERROR EN LLAMADO INIBATCH codigo={}", codigo);
        }
        return new ResultadoInibatch(codigo);
    }

RN-CORE-DEP-022Al arrancar, el programa valida contra el catálogo central de versiones del banco (CHECAME IN CTLVERS, PERFORM 20000100-CHECAME-VERSION) que su propia versión de software (identificada como "CORE-DEPP075", versión "25MTP003") sigue vigente y autorizada para ejecutarse. Si la validación falla (S000-CTR-CVEERROR negativo), registra el mensaje "ERROR DE VERSION" y marca el estatus de terminación del programa como fallido (CHANGE ATTRIBUTE STATUS OF MYSELF = -1) — pero esta marca de error NO detiene el flujo: no hay STOP RUN ni salto de párrafo asociado, así que el programa continúa de inmediato con la resolución de la librería central L080 (PERFORM 100000-L080), la cual reinicia el indicador de error a cero y evalúa de forma independiente su propia llamada (DAME_TIT). En consecuencia, un fallo de versión aquí deja el estatus final del run marcado como error, pero por sí solo no impide que se intente la notificación de cambio de día a P080 (ver regla línea 160).Validación de versión con CHECAME
RN-CORE-DEP-023El aviso de cierre del día bancario hacia el procesador central (PERFORM 200000-INIBATCH) solo se dispara si se cumplen dos condiciones anidadas: que la resolución de la librería central L080 haya sido exitosa (S000-CTR-CVEERROR = 0, ver regla línea 177) y, dentro de esa rama, que el parámetro recibido en la ejecución (W77-PARAM-WFL, RECEIVED BY CONTENT) sea exactamente 1. RN-CORE-DEP-024Antes de avisar el cierre del día bancario, el programa necesita ubicar la versión física correcta y vigente del procesador central (librería lógica "CORE-DEPL080CTRL", S000-CTR-LIBID), y la resuelve dinámicamente contra el catálogo central de versiones (DAME_TIT IN CTLVERS, PERFORM 20000100-DAME-TIT-VERS), aplicando el título resuelto con CHANGE ATTRIBUTE TITLE OF "CORE-DEPL080CTRL" para que la llamada posterior a INIBATCH (línea 195) apunte a la versión correcta. Si esta resolución falla (S000-CTR-CVEERROR distinto de 0), el programa registra el mensaje "ERROR EN CALL CTLVERS CORE-DEPL080 RESULT=<código>", pero SIN marcar el estatus de terminación como fallido. El efecto práctico es silencioso: al fallar la resolución, la condición de la regla anterior (línea 160) queda en falso y el programa omite el aviso de cambio de día a P080, terminando por STOP RUN sin notificarlo y sin ninguna señal de error en el estatus de salida del programa.Módulo de control a un Tasklet de un solo paso · Título vigente de CORE-DEPL080CTRL desde CTLVERS

Riesgos de migración
Cambio de día omitido sin señal de error

Si DAME_TIT de CTLVERS falla, 100000-L080 solo escribe el mensaje (líneas 180-185) y el programa termina con STOP RUN sin llamar a INIBATCH ni marcar STATUS -1. P080 no recibe el cambio de día y el orquestador ve un paso exitoso.

Resultado de INIBATCH en 9(02) sin signo

WKS-L080-RESULT (línea 41) no puede representar códigos negativos ni mayores a 99; un código como 100 se truncaría a 00 y la falla pasaría como éxito.

Comportamiento real de STATUS -1 sobre el propio proceso

El fuente usa CHANGE ATTRIBUTE STATUS OF MYSELF TO -1 tras la validación de versión (línea 157) y continúa el código. Según la semántica de MCP esto podría terminar el proceso de inmediato; la regla del brain asume que sigue.

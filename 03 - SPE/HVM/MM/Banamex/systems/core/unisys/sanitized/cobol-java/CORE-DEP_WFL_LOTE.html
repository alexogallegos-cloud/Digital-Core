La subrutina LOTEDIARIO obtiene de P100 la fecha de lote y el nodo, arma el nombre del directorio de control CORE-DEP/FILE/CTRLWFL y recorre unos 120 pasos. Antes de cada paso consulta con VALIARCHCTRL si ya existe su archivo de control, de modo que un reinicio salta lo que ya terminó. Los pasos corren de forma síncrona (RUN o llamada a subrutina) o asíncrona (PROCESS con WAIT posterior), algunos solo en fin de semana, fin de mes o en el nodo 10. Cuando un programa falla, la consola pide al operador reintentar, continuar, terminar o cambiar versión; al final se envían avisos de incidente por cada falla registrada.

        Calendario c = (Calendario) job.getExecutionContext().get("calendario");

/** FALLA: el WFL se detiene en consola (ACCEPT) hasta que el operador decide. */
public enum DecisionOperador { REINTENTAR, CONTINUAR, TERMINAR, CAMBIAR_VERSION }

@Component
@RequiredArgsConstructor
public class FallaPasoHandler implements StepExecutionListener {

    private final OperacionConsola consola;     // pantalla de operación / ticket con respuesta

    @Override
    public ExitStatus afterStep(StepExecution step) {
        if (step.getStatus() != BatchStatus.FAILED) return step.getExitStatus();

        boolean soloContinuar = step.getStepName().equals("CORE-DEPP101")
                && (fallasP130(step) > 0 || idFallaPaso(step) > 0);   // FALLAC1..3, IDFALLAPASO
        Set<DecisionOperador> opciones = soloContinuar
                ? EnumSet.of(CONTINUAR)
                : EnumSet.allOf(DecisionOperador.class);

        return switch (consola.espera(step, opciones)) {     // DO ACCEPT ... UNTIL
            case CONTINUAR       -> ExitStatus.COMPLETED.addExitDescription("continuado por operador");
            case TERMINAR        -> ExitStatus.FAILED;                   // GO FIN
            case REINTENTAR      -> new ExitStatus("REINTENTAR");        // transición al mismo step
            case CAMBIAR_VERSION -> new ExitStatus("CAMBIAR_VERSION");   // S006/WFL/CAMBIAVER
        };
    }
}

Riesgos de migración
Reinicio de P130 sin manejo

En SUB130 el ON RESTART está vacío y la nota del código (línea 6478) dice que falta abortar el job porque P130 es actualizador. Un reinicio del sistema a mitad del corte de comisiones queda a criterio del operador.

Continuación manual sin trazabilidad

La subrutina FALLA permite continuar el lote tras la falla de un programa con la opción C. No hay registro de quién tomó la decisión fuera de la bitácora de consola.

Avisos de incidente que se sobrescriben

IDFALLAPASO guarda un solo código; si varios pasos fallan en la misma ventana, AVISOINC al cierre solo notifica el último.

Comportamiento dependiente del host

El ambiente (producción, UAT, pruebas) y el nodo se deducen del nombre del equipo, y de eso depende si se envían archivos a Tesorería o se suben archivos a cinta (NODOSIST = 10).

Archivo de control como única prueba de terminación

VALIARCHCTRL solo verifica que el archivo exista. Un paso que deja su archivo de control pero termina con error de datos se salta en un reinicio.

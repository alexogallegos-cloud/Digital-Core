CORE-DEP · L036 a Java 21 Spring Boot

La librería mantiene en memoria, compartida por todos los usuarios, un registro de programas en ejecución indexado por usuario, número de programa, copia y tipo, con hasta 99 actividades por programa. Los programas llaman a los puntos de entrada S038L035_01 a S038L035_05 con buffers EBCDIC de formato fijo para dar de alta el programa, iniciar y terminar actividades y sumar registros procesados; cada entrada valida el buffer y devuelve un código de resultado documentado en la cabecera del fuente. Al terminar un programa se calcula su tiempo transcurrido y se graban el programa y sus actividades en los datasets S038B02PROGRAMAS y S038B03ACTIVIDAD. Otros puntos de entrada (30 a 34) exponen consultas para la pantalla de monitoreo.

/**
 * Sustituye LA_USERS, LA_PROGS, LA_DATOS_PROGS, LA_DATOS_ACT, LA_AGRUPXUSER y LA_PROGXAGRUP.
 * Los arreglos dispersos de MCP pasan a mapas: solo existen las llaves que se usan.
 */
@Component
public class RegistroProgramas {

    private final AtomicInteger siguienteIndice = new AtomicInteger(1);      // SIZE(LA_DATOS_PROGS) - 1
    private final ConcurrentMap<LlavePrograma, Integer> indices = new ConcurrentHashMap<>();
    private final ConcurrentMap<Integer, ProgramaEnCurso> programas = new ConcurrentHashMap<>();
    private final ConcurrentMap<Integer, ConcurrentMap<Integer, ProgramaEnCurso>> porAgrupador
            = new ConcurrentHashMap<>();                                    // LA_PROGXAGRUP

    /** LK_BEGINPROG: el alta es atómica por llave gracias a computeIfAbsent. */
    public int altaOIndice(LlavePrograma llave) {
        return indices.computeIfAbsent(llave, k -> siguienteIndice.getAndIncrement());
    }

    public Optional<ProgramaEnCurso> porIndice(int indice) {
        return Optional.ofNullable(programas.get(indice));
    }
}

    /** GRABABASE: upsert del programa y de cada actividad usada, en una sola transacción. */
    @Transactional
    public void graba(ProgramaEnCurso p) {
        ProgramaEntity e = programas.findByLlaveForUpdate(p.llave())        // LOCK ... AT
                .orElseGet(() -> new ProgramaEntity(p.llave()));            // CREATE si NOTFOUND
        e.copiaDe(p);                                                       // PUT B02-...
        programas.save(e);                                                  // STORE

        for (ActividadEnCurso a : p.actividadesUsadas()) {
            if (a.estatus() == EstatusActividad.EN_PROCESO) {
                a.terminaCon(p.fechaFin(), p.horaFin());   // las que no terminaron se terminan
            }
            ActividadEntity ae = actividades.findByLlaveForUpdate(p.llave(), a.numero())
                    .orElseGet(() -> new ActividadEntity(p.llave(), a.numero()));
            ae.copiaDe(a);
            actividades.save(ae);
        }
        // Un error lanza excepción y revierte todo; el MCP seguía y confirmaba lo que hubiera.
    }

public final class TiempoTranscurrido {

    public static long microsegundos(int fechaIni, long horaIniMicros, int fechaFin, long horaFinMicros) {
        LocalDateTime ini = LocalDate.parse(Integer.toString(fechaIni), DateTimeFormatter.BASIC_ISO_DATE)
                .atStartOfDay().plus(horaIniMicros, ChronoUnit.MICROS);
        LocalDateTime fin = LocalDate.parse(Integer.toString(fechaFin), DateTimeFormatter.BASIC_ISO_DATE)
                .atStartOfDay().plus(horaFinMicros, ChronoUnit.MICROS);
        return ChronoUnit.MICROS.between(ini, fin);   // cubre mismo día, mismo mes y cambio de mes o año
    }

    /** I_PROC_MMSTOHHMSCS: formato HHHHMMSSCC; los días se dejan en cero a propósito (nota 2 del fuente). */
    public static long aHhmmsscc(long micros) {
        Duration d = Duration.of(micros, ChronoUnit.MICROS);
        return d.toHours() * 1_000_000 + d.toMinutesPart() * 10_000
                + d.toSecondsPart() * 100L + d.toMillisPart() / 10;
    }

Riesgos de migración
Actualizaciones concurrentes sin candado

La librería se compila con SHARING = SHAREDBYALL (línea 6), pero solo el alta de programa y la grabación final usan INTERLOCK (LK_BEGINPROG y LK_ENDPROG). S038L035_03_ACTI_INI_C, _04_ACTI_FIN_C y _05_ACTU_REG_C modifican los arreglos compartidos sin candado; el contador DF_DA_NUM_LLAMADOS puede perder incrementos si dos tareas lo actualizan a la vez.

Errores de grabación ocultos al llamador

En GRABABASE (líneas 816-947) un error en STORE solo enciende B_ERROR, que además se reinicia a FALSE después de cada actividad (línea 940); ENDTRANSACTION se ejecuta siempre y S038L035_02_PROG_FIN_C devuelve 0 aunque la base no se haya actualizado. El monitoreo puede quedar incompleto sin que el programa de negocio se entere.

Arreglos de tamaño máximo declarado

LA_PROGS se declara [1:1000,1:1000,1:15,1:2] y LA_PROGXAGRUP [0:1000,1:15,1:1000,1:15,1:2] (líneas 117 y 238): son índices dispersos de decenas a cientos de millones de celdas que en MCP dependen de la paginación de arreglos. En Java deben ser mapas por llave, no arreglos.

Tiempo transcurrido entre meses depende de LOCSUP

D_PROC_ET (líneas 432-480) resuelve el mismo día y el mismo mes con aritmética propia y solo para otros casos llama a THECALENDAR; si la llamada falla, el tiempo queda en cero y solo se emite un mensaje por LJ.

Punto de entrada 99 vacío

S038L035_99_LEVANTA_C se exporta pero su cuerpo está vacío (líneas 5143-5146); su única función es forzar la carga de la librería.

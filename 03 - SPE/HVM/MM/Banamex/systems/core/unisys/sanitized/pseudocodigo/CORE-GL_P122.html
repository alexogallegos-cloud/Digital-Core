P122 · Gateway de Inyección de Movimientos Multi-Sistema (CORE-GL)

CORE-GLProgramaCOBOL

Fuente: COBOL_P122.cbl (2218 LOC) · Paso batch WFL LOTE (posición post-P120) · BC-13

Convenciones: nombres traducidos (Unisys→legible); [P122 Lnnnn] = línea física en MERGED; (BR: RN-CORE-GL-NNN) = regla de negocio.

1. Resumen funcional

P122 es el gateway de inyección de movimientos contables de sistemas externos no-Unisys al libro mayor CORE-GL. Recibe como parámetro de entrada el número de sistema originador (W77-SIST-PARAM) y, según éste, abre el archivo de fin-de-día correspondiente: ARCHC402 (formato 720 bytes) para los sistemas de plataforma C/S e IBM (C402, C600, S804), o ARCHS707 (formato GlobalDirect, 1261 bytes) para las plataformas Tandem (S707, S203).

Antes de procesar, valida la integridad estructural del archivo (presencia de Header "HD" y, en el caso de S804, también de Trailer "TR" con totales coherentes). Por cada registro de movimiento válido, mapea los campos al buffer interno WKS-MOV-DATOS e invoca la librería CARGAMOV1 IN LIB-REG (L002) para registrarlo en el log del CORE-GL. Al cierre envía un registro centinela con FUNCION 98 a L002 para marcar el fin del batch del sistema. En paralelo genera el archivo de punteo A01-PUNTEO con el detalle de los movimientos de alta (FUNCION 01) para conciliación posterior.

Para los sistemas 203 y 804 en el esquema de Alta Disponibilidad IBM, implementa control de idempotencia mediante el dataset CORE-GLB05PROCESOS: verifica si el proceso ya corrió en la fecha y aborta si es así; si no existe el registro lo crea al inicio y lo marca como terminado (STAPGM=01) al finalizar.

P122 no ejecuta lógica contable propia: actúa exclusivamente como adaptador de formato hacia L002, que es quien registra los movimientos en el GL.

2.2 Layouts de registro clave

R01-MOV-HEADER (720 bytes — leído desde ARCHC402/ARCHS707):

  • R01-MOV-HDR-HD PIC X(02) VALUE "HD" — identificador de cabecera
  • R01-MOV-HDR-SISTEMA PIC 9(04) — sistema originador
  • R01-MOV-HDR-FECHA PIC 9(08) — fecha de proceso
  • FILLER PIC X(710)

R01-MOV-DATOS (720 bytes — registro de movimiento C402):

  • R01-MOV-FUNCION PIC 9(02) — función: 01=movimiento, 11/21=variantes, 98=fin, "TR"=trailer
  • R01-MOV-SISTEMA PIC 9(04), R01-MOV-PRODUCTO PIC 9(04), R01-MOV-INSTRUMENTO PIC 9(02)
  • R01-MOV-SUCPROM PIC 9(04) — sucursal promotora
  • R01-MOV-CONTRATO PIC 9(16)
  • R01-TAB-CVEIMP OCCURS 5: CVETRAN(4) + INDLEY(2) + ESQCON(4) + IMPORTE(16V2) — hasta 5 claves de importe
  • Campos fecha: R01-MOV-FECMOV(8), R01-MOV-HORMOV(6), R01-MOV-FECCONT(8), R01-MOV-FECVAL(8)
  • R01-MOV-AUTORIZA(8), R01-MOV-AUT3ER(8), R01-MOV-REFNUM(20)
  • R01-MOV-CVEMDA(2), R01-MOV-NUMMDA(20) — moneda de la cuenta
  • R01-MOV-SUCOPER(4), R01-MOV-CAJAOPER(2) — operador
  • R01-MOV-TIPO-PROC(2) — tipo de proceso (IGNORADO en carga, ver BR RN-CORE-GL-853)
  • R01-MOV-IND-DATOS-ADIC(2) — indicador de presencia de datos adicionales
  • R01-MOV-DATOS-ADIC PIC X(364) — datos adicionales (leyendas, referencias, campos por sistema)

R01-MOV-TRAILER (720 bytes):

  • R01-MOV-TRA-HD PIC X(02) VALUE "TR"
  • R01-MOV-TRA-TOTREG PIC 9(10), R01-MOV-TRA-TOTCLAVES PIC 9(10), R01-MOV-TRA-TOTIMPORTE PIC 9(16)V99

WKS-REG-NVO (formato GlobalDirect S707, 1261 bytes display):

  • WKS-NVO-FUNCION(2), WKS-NVO-FORMATO(2), WKS-NVO-SISTEMA(4)
  • WKS-NVO-CVEIMP — 5 grupos: CVETRAN(6)+INDLEY(2)+ESQCON(4)+IMPORTE(18)+CVE-DESVIO(4)+GUIA-DESVIO(4)
  • Múltiples campos adicionales incluyendo datos de impuestos S203 (WKS-NVO-FILXAPL-MOVS-S203)

WKS-MOV-DATOS (540 bytes COMP, WITH LOWER-BOUNDS):

  • Equivalente COMP de R01-MOV-DATOS; es el buffer de llamada a L002
  • REDEFINES por sistema: WKS-MOV-REFNUM-CORE-DEP, WKS-MOV-REFNUM-S087, WKS-MOV-REFNUM-S404
  • WKS-MOV-FIL-FUTURO X(07) con múltiples REDEFINES por sistema (S264, S087, CORE-DEP, S501, S403, S252)
  • WKS-MOV-DATOS-ADIC X(354) — redefinido por sistema (REDS084, REDS087, REDS408, REDCORE-DEP, REDS501, REDS403, REDS404, REDS701, REDS702)

  │   OPEN OUTPUT A01-PUNTEO + escribe HDR punteo
  │   PERFORM 050-VALIDA-ARCHIVO UNTIL W77-ARCHIVO-OK=1   [L1653]

PROCEDIMIENTO Validar_Trailer_S707():   // 052-VALIDA-TR-707 · [P122 L1725]
> **Nota:** Este párrafo existe en el fuente pero su invocación está **comentada** en `050-VALIDA-ARCHIVO` (líneas 1697-1698 del MERGED). El código es código muerto en el flujo actual — el trailer de S707 nunca se valida.

```

LEER ARCHS707 EN WKS-REG-NVO AL FINAL MOVER 1 A flag_fin
SUMAR 1 A total_registros

SI flag_fin = 0
    MOVER WKS-NVO-FUNCION A W77-VALIDA-FUNCION
    SI funcion_es_válida (W88-VALIDA-FUNCION)   // 01, 11, 21 o 98
        SI WKS-NVO-FUNCION = 1
            PARA CADA índice DE 1 A 5
                EJECUTAR 054-ACUMULA   // acumula totales para verificar trailer
    SINO   // función no válida: puede ser el trailer
        MOVER WKS-REG-NVO A campo_alfanumerico_ID   // R01-MOV-TRA-HD (redefine)
        SI campo_alfanumerico_ID = "TR"   // es el trailer
            MOVER 1 A flag_trailer
            CALCULAR total_registros = total_registros - 1
            SI total_registros = R01-MOV-TRA-TOTREG
               Y total_importe  = R01-MOV-TRA-TOTIMPORTE
                SIGUIENTE SENTENCIA   // trailer correcto
            SINO
                // Trailer erróneo: construir mensaje y solicitar acción al operador
                MOVER ZERO A flag_header   // marca como inválido
```

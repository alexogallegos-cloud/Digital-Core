CORE-GL · L011 a Java 21 Spring Boot

L011 se levanta como librería congelada en modo CONTROL y exporta diez entry points con la misma firma: un arreglo EBCDIC de entrada y salida y un código de retorno entero. Al arrancar deduce de su propio nombre de objeto el sistema al que sirve, carga en memoria el catálogo de claves de transacción del S080, arma el calendario de hasta diez archivos del día pidiéndolo a L001/CONTROL y abre la base de movimientos en modo INQUIRY. Cada consulta traduce la fecha pedida a un juego de estructuras DMSII (cinco juegos, B0x a B4x), recorre el set correspondiente, enriquece cada movimiento con leyendas del archivo DESS y devuelve las ocurrencias empacadas en el mismo arreglo. Esta demostración cubre el ciclo de vida, la concurrencia y el entry point CONS_4ULT (últimos N movimientos por contrato o por moneda, sucursal y cuenta).

/*
 * ACQUIREL(En,An) / EPILOG LIBERA -> RELINQUISHL(En,An)
 * En ALGOL el estado de la consulta (ADATOS1, INDI, NUMDIA, cursores DMSII) vive en la
 * instancia de la librería y por eso cada entry point se serializa consigo mismo.
 * En Java ese estado es local al método y el cursor es propio de cada transacción,
 * así que el candado deja de ser necesario. Si se quiere conservar el límite de
 * concurrencia original, basta un semáforo de un permiso por operación:
 */
private final Semaphore candadoCons4Ult = new Semaphore(1, true);     // E2/A2

public ResultadoMovimientos ultimosMovimientos(UltimosMovsRequest req) {
    candadoCons4Ult.acquireUninterruptibly();                         // ACQUIREL(E2,A2)
    try {
        return cons4Ult(req);
    } finally {
        candadoCons4Ult.release();                                    // EPILOG PROCEDURE LIBERA
    }
}

/** CARGAFECHAS: FEC_DIA[0:9] y títulos de MOVS[i] / DESS[i] a partir de L001/CONTROL (CONSISDIA). */
@Component
@RequiredArgsConstructor
public class CalendarioDia {

    private final ControlCORE-GLClient control;          // L001/CONTROL
    private volatile List<DiaArchivo> dias = List.of();

    /** Un día de archivo: posición i del calendario, juego DMSII (i módulo 5) y títulos PACK. */
    public record DiaArchivo(int numFile, int numDia, int fecha, String tituloMovs, String tituloDess) {}

    void cargar() {
        var c = control.consisDia();
        var lista = new ArrayList<DiaArchivo>();
        for (int i = 0; i <= 9; i++) {
            int fecha = c.fechaArchivo(i);              // ISISDFECARM(ACONTROLE1,IND)
            if (fecha > 0) {
                String f6 = "%06d".formatted(fecha % 1_000_000);   // FEC_DIA FOR 6 DIGITS
                lista.add(new DiaArchivo(i, i > 4 ? i - 5 : i, fecha,
                        c.nombreMovs() + f6 + " ON " + c.packMovs() + ".",
                        c.nombreDess() + f6 + " ON " + c.packDess() + "."));
            }
        }
        dias = List.copyOf(lista);
    }

    /** Búsqueda que hace cada entry point; vacío significa código de retorno 4. */
    public Optional<DiaArchivo> buscar(int fechaConsulta) {
        return dias.stream().filter(d -> d.fecha() == fechaConsulta).findFirst();
    }
}

static final int PIVOTE_A2K = 50;

static LocalDate fechaA2k(int aammdd) {
    int aa = aammdd / 10_000, mm = aammdd / 100 % 100, dd = aammdd % 100;
    int siglo = (aa >= PIVOTE_A2K) ? 1900 : 2000;
    return LocalDate.of(siglo + aa, mm, dd);
}

private ResultadoMovimientos recorre(UltimosMovsRequest req, DiaArchivo dia,
                                    Stream<MovimientoDia> recorrido) {
    int nMov = req.numMovs();
    var salida = new ArrayList<OcurrenciaMovimiento>();
    long autContinuacion = 0;                                 // DAUTCORE-GL

    if (nMov > 0 && nMov < 31) {                              // fuera de 1..30 no se lee nada
        Iterator<MovimientoDia> it = recorrido.iterator();
        while (it.hasNext() && salida.size() <= nMov) {       // WHILE SIGUE AND INDI LEQ NMOV
            MovimientoDia m = it.next();
            if (m.estatus() <= 2) {                           // GET_DATOS = 0
                String leyenda = descripciones.leyenda(dia, m.nivelDescripcion());
                if (agrega(salida, nMov, m, m.claveTransaccion(), m.importe(), leyenda))
                    autContinuacion = m.autCORE-GL();            // REPLACE DAUTCORE-GL BY AUTCORE-GL
                if (m.indicadorImportes() > 0) {              // hasta 4 importes adicionales
                    for (ImporteAdicional ad : impAdic.de(dia, m.autCORE-GL())) {
                        if (ad.clave() <= 0 || salida.size() > nMov) break;
                        if (agrega(salida, nMov, m, ad.clave(), ad.importe(), leyenda))
                            autContinuacion = m.autCORE-GL();
                    }
                }
            }
            if (salida.size() + 1 > nMov) {
                // FIND PRIOR adicional: si ya no hay movimientos no hay nada que continuar
                if (!it.hasNext()) autContinuacion = 0;
                break;
            }
        }
    }
    int codigo = salida.isEmpty() ? 2 : 0;                    // INDI = 0 -> 2
    if (salida.size() < nMov) autContinuacion = 0;           // DAUTCORE-GL := 0, DNUMMOVS := INDI
    return ResultadoMovimientos.de(codigo, salida, autContinuacion);
}

private boolean agrega(List<OcurrenciaMovimiento> salida, int nMov, MovimientoDia m,
                    int claveOriginal, BigDecimal importe, String leyenda) {
    int clave = claveOriginal;
    if (catalogo.formato() == 3) {
        // formato 3: clave de 4 dígitos concatenada con el tipo de movimiento de 1 dígito
        clave = Integer.parseInt("%04d%d".formatted(m.claveBitacora(), m.tipoMovimiento()));
    }
    int envioEdc = catalogo.indicadorEdc(clave);            // IADFINDEDC(CVETRA)
    boolean visible = (catalogo.formato() == 3)
            ? envioEdc != 5
            : envioEdc != 5 || excepciones.clavesSiempreVisibles().contains(clave);
    if (salida.size() <= nMov && visible) {
        // IMPORTE := IMPORTE*100 y se escribe como dos bloques de 8 dígitos: entero en centavos
        BigDecimal centavos = importe.movePointRight(2).setScale(0, RoundingMode.UNNECESSARY);
        salida.add(OcurrenciaMovimiento.de(m, clave, centavos.movePointLeft(2), leyenda));
        return true;
    }
    return false;
}
Riesgos de migración
Ocurrencia de más en CONS_4ULT

Las condiciones INDI LEQ NMOV en el ciclo principal (línea 1749), en el ciclo de importes adicionales (línea 1763) y en REPLACE_DATOS (líneas 1563 y 1584) permiten escribir la ocurrencia NMOV+1. Un llamador que dimensione su arreglo exactamente para NMOV ocurrencias puede recibir datos fuera de su área.

Excepción EDC inconsistente entre formatos

Las claves 1009 y 1072 se devuelven aunque su indicador de estado de cuenta sea 5 solo cuando FORMATO_CAT no es 3 (líneas 1562-1585). El mismo movimiento se ve o no según el sistema que enlaza la librería.

Sistema deducido de la posición 31 del nombre

SIST_LIB se toma de MYSELF.NAME en la línea 7171. Un cambio en la convención de nombres del WFL de línea cambia el comportamiento de catálogos, monedas y TAX-ID sin error visible.

Reintentos infinitos de enlace

Los WHILE LINKLIBRARY(SOPORTE) < 0 y DELINKLIBRARY de las líneas 7157-7166 no tienen cuerpo ni límite; si SOPORTE no está disponible, LEVANTA queda en un ciclo sin fin.

Pivote Y2K fijo en 50

a2k_base_year = 50 (línea 14) interpreta los años 50 a 99 como siglo XX. La traducción deja el pivote explícito, pero el contrato AAMMDD de los consumidores debería migrarse a fecha completa.

MOVESPECIFICO sin serializar

Es el único entry point exportado que no ejecuta ACQUIREL ni declara EPILOG; comparte variables globales con el resto de la librería.

Pendiente de revisión SME
  • Confirmar con SME que los desplazamientos de los DEFINE de ADATOS1 están en dígitos de 4 bits: según POINTER(ADATOS1,4) la ocurrencia de CONS_4ULT mide 77 bytes y la leyenda LREFCTE 40 caracteres, no 80 como sugiere el comentario % 80 ni el pseudocódigo.
  • Confirmar cómo convierte ALGOL un DOUBLE con decimales en REPLACE ... FOR 8 DIGITS (truncamiento o redondeo) para el importe multiplicado por 100 en REPLACE_DATOS; la traducción asume que MOV-IMP siempre trae exactamente dos decimales.
  • Validar que el orden del set B01BXMDA..B41BXMDA y B01BXMOVCTO es por inserción dentro de la llave, para replicarlo con la columna secuenciaSet.
  • Confirmar si los sistemas 404, 707 y 804 (CLAVES_CFR) usan formato de catálogo 3, porque en ese formato no aplica la excepción de las claves 1009 y 1072.
  • La demostración cubre CONS_4ULT; los otros nueve entry points siguen el mismo patrón pero tienen reglas propias (Ley de Transparencia y TESOFE en MOVXCNT, paginación AUTCON en CONSULTA_CI) que requieren su propia revisión.
  • El inventario no asocia reglas del brain a L011; las reglas observadas en el fuente (filtro EDC, estatus mayor que 2, tope de 30 movimientos) no tienen ficha propia.

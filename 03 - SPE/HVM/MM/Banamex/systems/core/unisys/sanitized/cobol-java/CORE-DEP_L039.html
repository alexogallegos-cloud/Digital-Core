ACCESOBD04 abre la base DMSII CORE-DEPBD04TARJETAS en UPDATE o INQUIRY según el tipo de proceso que reporta L020 y la hora del día, y exporta diez entry points. Siete son consultas por set (relación contrato y tarjeta, TEF, cuenta global y cuenta origen, último movimiento del cliente y fecha del último archivo hacia S111). El resto del código, casi once mil líneas, es un motor que controla el arribo y la aplicación de archivos con los datasets CORE-DEPB07PARCHIVOS y CORE-DEPB08PCTRARRIBO, lanza los procesos hijos P030 y P031, escribe los archivos INTS, ERR e IMPDET y envía a INTELAR. Todo el motor se serializa con un INTERLOCK.

@Transactional(readOnly = true)
public ResultadoL040<RelacionTarjeta> dameTarjeta(String contrato) {
    if (contrato == null || contrato.length() < 12) {
        return new ResultadoL040<>(ResultadoL040.ENTRADA_CORTA, Optional.empty());     // SIZE(EA_ENTRADA) < 12
    }
    try {
        return prealtas.findFirstByContrato(contrato.substring(0, 12))
                .map(p -> new ResultadoL040<>(ResultadoL040.OK, Optional.of(new RelacionTarjeta(
                        p.getTarjeta(), contrato.substring(0, 12), p.getSucursalPromotora(), p.getNumCsi()))))
                .orElseGet(() -> new ResultadoL040<>(ResultadoL040.NOTFOUND, Optional.empty()));
    } catch (DataAccessException e) {
        log.error("ERROR DMSII BASE: CORE-DEPBD04TARJETAS", e);                          // DF_ERRORDB_DS
        return new ResultadoL040<>(ResultadoL040.ERROR_BASE, Optional.empty());
    }
}
@Transactional(readOnly = true)
public ResultadoL040<UltimoMovimiento> conInfoCte(String cliente) {
    modoBase.validaPrimeraConsulta();       // BG_VALIDA_BD: puede cerrar UPDATE y reabrir en INQUIRY
    if (cliente == null || cliente.length() < 12) {
        return new ResultadoL040<>(ResultadoL040.ENTRADA_CORTA, Optional.empty());
    }
    return motorRepo.findFirstByNumCliente(cliente.substring(0, 12))     // B09PSXCLIENTE
            .map(m -> new ResultadoL040<>(ResultadoL040.OK, Optional.of(UltimoMovimiento.de(m))))
            .orElseGet(() -> new ResultadoL040<>(ResultadoL040.NOTFOUND, Optional.empty()));
    // A diferencia del fuente, en NOTFOUND no se devuelven datos: no hay variables globales
    // B09P_* que arrastren el resultado de la consulta anterior.
}

class TipoProcesoPolicy {
    private final TipoProcesoClient l020;          // CORE-DEPL020TIPO_PROC: 0 Línea, 1 Batch, 2 Prelínea
    private final Clock clock;
    @Value("${core-dep.l040.hora-corte-update}") private LocalTime horaCorte;

    /** BG_ABRIR_BD_MODO_UPDATE. */
    boolean permiteUpdate() {
        RespuestaL020 r = l020.tipoProceso();      // I_RESULT y I_VALOR
        return r.resultado() == 0                  // cualquier error de L020 abre en INQUIRY
                && r.tipo() == 0                   // solo Línea; Prelínea (2) NO abre en UPDATE
                && LocalTime.now(clock).isBefore(horaCorte);
    }
}

    private boolean estabaDeInquiry;                 // BG_BD_ESTABA_DE_INQUIRY

    /** FORZA_BASE_EN_UPDATE: lo usan la función 4 del motor y PROC_FIN. */
    synchronized void forzaUpdate() {
        estabaDeInquiry = false;
        if (modoActual == ModoBase.INQUIRY) {
            estabaDeInquiry = true;
            reintentoApertura.execute(ctx -> {
                cambiaA(ModoBase.UPDATE);            // CIERRA_BASE + ABRE_BASE en UPDATE
                if (modoActual != ModoBase.UPDATE) throw new BaseNoDisponibleException(ctx.getRetryCount());
                return null;
            });
        }
    }

    /** REGRESA_BASE_A_INQUIRY: deshace el forzado si la base estaba en consulta. */
    synchronized void regresaAInquiry() {
        if (estabaDeInquiry) reintentoApertura.execute(ctx -> { cambiaA(ModoBase.INQUIRY); return null; });
    }
}

    private final CalendarioBancario calendario;                     // LOCSUP.THECALENDAR fn 20

    public RespuestaDispersion archDisp(int funcion, AreaComunDispersion area) {
        lkDisparch.lock();
        try {
            if (funcion < 1 || funcion > 4) return RespuestaDispersion.error(1);
            if (!calendario.esFechaValida(area.fechaLinea())) return RespuestaDispersion.error(2);
            if (funcion < 4 && (area.numCopia() < 1 || area.numCopia() > 7)) {
                return RespuestaDispersion.error(9);

                default -> creaDisperXHorario(area);      // CREA_DISPER_X_HORARIO
            };
        } finally {
            lkDisparch.unlock();                          // también cubre la EXCEPTION PROCEDURE LIBERA
        }
    }

Riesgos de migración
Datos de otro cliente en CONINFOCTE

En CORE-DEPL040_CONINFOCTE_C (líneas 11703-11718) el área de salida se llena con las variables globales B09P_* aunque el FIND haya fallado. Como la librería es compartida, un NOTFOUND devuelve los datos del último cliente consultado por cualquier programa.

Ciclos sin espera al cambiar el modo de la base

FORZA_BASE_EN_UPDATE y REGRESA_BASE_A_INQUIRY (líneas 1561-1568 y 1588-1595) repiten cierre y apertura sin pausa ni límite hasta lograr el modo; un fallo persistente deja al proceso girando dentro del INTERLOCK.

Interruptor de depuración en producción

MYSELF.TASKVALUE = 1020 (líneas 1244 y 11558) alterna los displays de la librería desde la consola del operador sin control adicional.

Hardcodes de títulos, objetos y horario

La base "(CORE-DEP)CORE-DEPBD04TARJETAS ON CAPTACION", la librería LIBLJ en PACK, el corte de las 22:00 para abrir en UPDATE y los objetos P030 y P031 ON CAPTACION están compilados. Se trasladan a application.yml.

Retornos sin asignar en funciones de títulos

DAME_TIT_WFL y DAME_TIT_P188 (líneas 1207-1217 y 1219 en adelante) se declaran INTEGER PROCEDURE pero no asignan su valor de retorno en ninguna rama, y PROC_INICIO lo evalúa. Un fallo de CTLVER al resolver CORE-DEPJBATCH o CORE-DEPP188 no se detecta de forma confiable al levantar la librería.

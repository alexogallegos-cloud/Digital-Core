L010 · Librería de Bitácora en Línea P010 (CORE-GL · ALGOL)

CORE-GLLibreríaALGOL

Fuente: ALGOL_L010.alg (573 LOC) · Librería MCP residente con FREEZE · sin BC de negocio (arquitectura AS-IS · RETAIN/ENCAPSULATE)

Convenciones: nombres traducidos (Unisys ALGOL→legible); [L010 Lnnn] = línea física del fuente; (BR: RN-CORE-GL-NNN) = regla de rules-core-gl-algol-wfl-stubs.md.

1. Resumen funcional

L010 es la librería de bitácora en línea (BITALIN = BITAcora en LÍNea, confirmado en ruta de carpeta y en el nombre del archivo pack BITA_P010) que registra cada transacción procesada por el programa P010 de banca central CORE-GL. Su único entry point exportado es GRABA_BITACORA(REGISTRO) [L010 L178], que escribe registros de hasta 1 260 caracteres en el archivo secuencial de log (CORE-GL)CORE-GL/FILE/LOGP010/AAMMDD ON CMEMP, acumulando contadores de totales (recibidos, altas, bajas, modificaciones, consultas y errores).

La librería implementa un ciclo de vida MCP completo: al cargarse en memoria ejecuta FREEZE(CONTROL, CONTROL_LIB) [L010 L571], quedando residente y atendiendo comandos del operador (HI 1–HI 25) a través de CONTROL_LIB. Se registra en el dataset de control de procesos B05 al arrancar (VERIFICA_B05/INICIA) y se da de baja al descongelarse (BAJA), garantizando una sola instancia activa mediante detección de duplicados via DCKEYIN.

« divergencia KB: RN-CORE-GL-1153 » — El stub del KB clasifica L010 como "librería de acceso a datos del sistema CORE-GL (par de la familia L006/L009/L011/L012)" y menciona acceso DMSII. El fuente real no accede a ningún dataset DMSII: opera exclusivamente con archivos PACK secuenciales. La función real es bitácora/auditoría de transacciones en línea para P010, no una capa de acceso a datos. Se documenta el código fuente.

4.2 · `GRABA_BITACORA` — Escritura de registro de bitácora (entry point exportado)

4.2 PROCEDIMIENTO `GRABA_BITACORA` — Escritura de registro de bitácora (entry point exportado)
> Líneas `[L010 L178–L202]`
> Parámetro de entrada: `REGISTRO` (EBCDIC ARRAY, tamaño variable — pasado por referencia)

```
PROCEDIMIENTO Escribe_Registro_Bitacora(registro_transaccion):  // GRABA_BITACORA · [L010 L178]

  [Definiciones locales del layout del buffer — DF_NOMINA, DF_FECHA, DF_HORA,
   DF_ESTACION, DF_SISTEMA, DF_CVETRAN, DF_TIPO_OPE, DF_MSG_IN, DF_MSG_OUT,
   DF_CVE_RES / IDF_CVE_RES — ver §2.7]

  longitud_mensaje := TAMAÑO(registro_transaccion)        // [L010 L195]

  // Truncar si excede el límite del registro físico
  SI longitud_mensaje > 1260 ENTONCES
    longitud_mensaje := 1260                              // [L010 L196] ⚠ truncamiento silencioso

  // Copiar al buffer de trabajo (1 260 bytes fijos)
  REEMPLAZAR reg_bita POR registro_transaccion PARA 1260  // [L010 L197]

  // Acumular contador de movimientos recibidos
  TOT_RECIBIDOS := TOT_RECIBIDOS + 1                      // [L010 L198]

  // Detectar error: clave de resultado > 1 indica error de transacción
  SI IDF_CVE_RES(reg_bita) > 1 ENTONCES
    TOT_ERRORES := TOT_ERRORES + 1                        // [L010 L200]
  FIN SI

  // Escribir registro de longitud fija al archivo de bitácora
  ESCRIBIR(BITA_P010, 1260, reg_bita)                     // [L010 L201]

FIN PROCEDIMIENTO
```

« [L010 L178–L202] »

**Notas:**
- La clave de resultado `IDF_CVE_RES` está en el desplazamiento 1 258 del buffer (últimos 2 bytes del registro).
- `CVE_RES = 0` o `1` → transacción exitosa; `> 1` → error.
- Los contadores `TOT_ALTAS`, `TOT_BAJAS`, `TOT_MODIF`, `TOT_CONS` **no se incrementan aquí** `[NO-DETERMINADO]` — se asume que los callers los incrementan directamente antes de llamar a GRABA_BITACORA, o que están reservados para uso futuro.

4.3 · `BAJA` — Cierre y baja del proceso en B05

4.3 PROCEDIMIENTO `BAJA` — Cierre y baja del proceso en B05
> Líneas `[L010 L204–L219]`

```
PROCEDIMIENTO Cierra_y_Baja_Proceso:  // BAJA · [L010 L204]

  // Enlazar biblioteca de control (necesaria para B05PROCESOS)
  resultado := ENLAZAR_BIBLIOTECA(CONTROL)                // [L010 L207]

  // Cerrar archivo de bitácora con lock
  CERRAR(BITA_P010, LOCK)                                 // [L010 L208]

  // Si la liga fue exitosa, registrar baja en el dataset B05
  SI resultado >= 0 ENTONCES

    // Inicializar buffer con ceros
    REEMPLAZAR ACONTROL_B05 POR 48"00" PARA TAMAÑO(ACONTROL_B05)   // [L010 L211]

    // Armar parámetros de función 22 (baja de proceso en B05)
    DFB05FUNCION(ACONTROL_B05) := 22    // función = baja   // [L010 L212] ⚠ HARDCODE función=22
    DFB05SISTEMA(ACONTROL_B05) := 151   // SIST_LIB         // [L010 L213]
    DFB05FECPRO(ACONTROL_B05)  := 0     // fecha proceso    // [L010 L214]
    DFB05NUMPRO(ACONTROL_B05)  := 10    // número proceso   // [L010 L215] ⚠ HARDCODE numpro=10

    // Llamar a B05PROCESOS para registrar la baja
    LLAMAR B05PROCESOS(ACONTROL_B05)                      // [L010 L216]

    // Desenlazar biblioteca de control
    DESENLAZAR_BIBLIOTECA(CONTROL)                        // [L010 L217]
  FIN SI

FIN PROCEDIMIENTO
```

4.4 · `VERIFICA_B05` — Guardia de instancia única

4.4 PROCEDIMIENTO `VERIFICA_B05` — Guardia de instancia única
> Líneas `[L010 L221–L358]`
> Variables locales: `ARR1, ARR2[0:200]`, `TOKEN[0:79]`, `NOM_LIB`, `MIX_SIN_MTP`, `LIB_SIN_MTP[0:71]`, `STR_LIB`, `STR_MIX`, `RESULT_CTL`, `MIX_L010`, `P_SAL`
> `SNR := MYSELF.MIXNUMBER` — MIX number de la librería actual

```
PROCEDIMIENTO Verifica_Instancia_Unica:  // VERIFICA_B05 · [L010 L221]

  SNR := MYSELF.MIXNUMBER                               // [L010 L223] MIX de esta instancia

  // Obtener nombre de la librería sin sufijo MTP (primeros 33 chars)
  REEMPLAZAR NOM_LIB POR MYSELF.NAME                    // [L010 L240]
  REEMPLAZAR LIB_SIN_MTP POR POINTER(NOM_LIB) PARA 33  // [L010 L241]

  // Consultar B05: función 1 = buscar procesos activos del sistema CORE-GL
  REEMPLAZAR ACONTROL_B05 CON CEROS                     // [L010 L242]
  DFB05FUNCION := 1 · SISTEMA := 151 · FECPRO := 0 · NUMPRO := 10  // [L010 L243–L247] ⚠ HARDCODE numpro=10
  RESULT_CTL := B05PROCESOS(ACONTROL_B05)               // [L010 L248]

  // Iterar sobre todos los procesos activos del sistema CORE-GL
  MIENTRAS RESULT_CTL = 0 HACER                         // [L010 L249]

    MIX_L010 := IDFB05MIX(ACONTROL_B05)                // [L010 L251] MIX del proceso encontrado

    // Consultar MIX mediante DCKEYIN para obtener info del proceso
    REEMPLAZAR ARR1 CON ESPACIOS (201 palabras)         // [L010 L252]
    ARMAR ARR1: MIX_L010 EN 5 DÍGITOS + "Y" + ceros    // [L010 L253–L255]
    DCKEYIN(POINTER(ARR1), ARR2)                        // [L010 L256] consulta al MCP
    P_SAL := POINTER(ARR2)

    // Leer primer token de la respuesta
    REEMPLAZAR TOKEN CON CEROS (80 palabras)
    REEMPLAZAR TOKEN POR P_SAL HASTA = " "             // [L010 L259]

    SI TOKEN = "INVALID" O TOKEN = "Task" ENTONCES     // [L010 L260] proceso ya no existe
      // Dar de baja en B05 (función 22)
      LLAMAR B05PROCESOS con FUNCION=22, SISTEMA=151, FECPRO=0, NUMPRO=10  // [L010 L261–L268]
    SINO
      // Proceso activo: extraer nombre de la librería del resultado DCKEYIN
      // (saltar 3 tokens: token1=MIX status, token2=…, token3=nombre librería sin MTP)
      LEER TOKEN (skip ceros)                          // [L010 L273]
      LEER TOKEN (skip hasta espacio)                  // [L010 L275] → token2, avanzar P_SAL
      LEER TOKEN (skip hasta espacio)                  // [L010 L278] → token3, avanzar P_SAL
      REEMPLAZAR MIX_SIN_MTP POR P_SAL PARA 33        // [L010 L281] nombre del proceso en B05

      STR_LIB := STRING(LIB_SIN_MTP, 35)              // [L010 L282] nombre de esta librería
      STR_MIX := STRING(MIX_SIN_MTP, 35)              // [L010 L283] nombre del proceso encontrado

      SI STR_MIX = STR_LIB ENTONCES                   // [L010 L284] mismo nombre → duplicado
        // Es otra instancia de L010/CORE-GL: intentar freezar (HI 4 → que se dé de baja)
        ARMAR ARR1: MIX_L010 EN 5 DÍGITOS + "HI 4" + ceros  // [L010 L287–L289]
        DCKEYIN(POINTER(ARR1), ARR2)                  // [L010 L290] enviar HI 4 al duplicado
        ESPERAR 5 segundos                            // [L010 L291] WAIT((5))
        DCKEYIN(POINTER(ARR1), ARR2)                  // [L010 L292] verificar estado

        SI ARR2 = "INVALID NUMBER" ENTONCES           // [L010 L293] duplicado ya cayó
          // Dar de baja en B05 (función 22)
          LLAMAR B05PROCESOS con FUNCION=22, SISTEMA=151  // [L010 L295–L302]
        SINO                                           // duplicado aún activo → error bloqueante
          // Construir mensaje de error para el operador
          REEMPLAZAR TXTMSG POR
            " L010 > " +
            "ERROR L010/S" + SIST_LIB (3 dígitos) +   // [L010 L307–L312]
            ", EXISTE UNA L010 CON MIX " + MIX_L010 (4 dígitos) +
            " DARLA DE BAJA PARA PODER CONT. "         // ⚠ HARDCODE mensaje de error
          LJ(CONLJ, MSGLJ)                             // desplegar en consola [L010 L313]
          ACCEPT(TXTMSG)                               // [L010 L314] ⚠ BLOQUEO: espera respuesta del operador
        FIN SI

        // Continuar consultando B05 (función 1, siguiente proceso)
        LLAMAR B05PROCESOS con FUNCION=1, SISTEMA=151  // [L010 L317–L322]
      SINO
        // Nombre distinto → proceso de otro sistema, dar de baja en B05 (función 22)
        LLAMAR B05PROCESOS con FUNCION=22, SISTEMA=151  // [L010 L326–L332]
      FIN SI
    FIN SI

  FIN MIENTRAS

  // Registrar esta instancia como proceso activo en B05 (función 19)
  REEMPLAZAR ACONTROL_B05 CON CEROS
  DFB05FUNCION := 19 · SISTEMA := 151 · FECPRO := 0 · NUMPRO := 10  // [L010 L337–L344] ⚠ HARDCODE numpro=10
  DFB05STAPGMA := "    " · STAPGMA_INT := 0
```

5.5 Divergencia con el KB

« divergencia KB: RN-CORE-GL-1153 »

El stub RN-CORE-GL-1153 clasifica L010 como "librería ALGOL de acceso a datos del sistema CORE-GL (par de la familia L006/L009/L011/L012)" con estrategia de migración RETAIN+ENCAPSULATE orientada a una "capa de repositorio" y menciona acceso DMSII.

El fuente real muestra:

  • Sin acceso DMSII alguno — ningún DATABASE, FIND, GET, STORE, OPEN de base DMSII.
  • Función real: bitácora/auditoría de transacciones en línea para P010 (escritura de log secuencial en archivo PACK).
  • No pertenece a la familia L006/L009/L011/L012 (data access); pertenece al subsistema de trazabilidad en línea.
  • La estrategia de migración RETAIN+ENCAPSULATE sí aplica, pero sobre un servicio de log, no de datos.
  • El KB infirió el propósito del nombre de carpeta (BITALIN) parcialmente correctamente (menciona "acceso"), pero erró en clasificarlo como data access layer.

L035_MAPLI · Fachada / Puerta de Enlace de Monitoreo de Aplicaciones (CORE-DEP · ALGOL)

CORE-DEPLibreríaALGOL

Fuente: L035.alg (374 LOC) · Librería stub residente: publica la API MAPLI a los programas COBOL y desacopla la implementación real (L036) · BC-XX

Convenciones: nombres traducidos (Unisys ALGOL→legible); [L035 Lnnnn] = línea física del fuente; (BR: RN-CORE-DEP-...) = regla de rules-core-dep-algol-wfl-stubs.md.

1. Resumen funcional

L035 es una librería ALGOL fachada (proxy / shim) del subsistema MAPLI. No implementa ninguna lógica de monitoreo: declara la librería importada MAPLICALL [L035 L20] y 11 puntos de entrada propios que son un envoltorio 1:1 de los PROCEDUREs homónimos S038L035_nn_*_C importados de esa librería [L035 L23–L69]. Cada envoltorio pregunta por el interruptor global B_LLAMAL036 [L035 L85]: si está activo delega en el procedimiento importado; si no, devuelve el código 99 sin tocar MAPLICALL [L035 L10–L12] (% 99 - LIBERRIA MAPLI NO DISPONIBLE. — errata del comentario en el fuente, se reproduce AS-IS).

La razón de existir de esta capa es doble: (a) permitir desligar en caliente la implementación (DELINKLIBRARY(MAPLICALL) [L035 L322]) para que los programas de negocio sigan corriendo aunque la base DMSII de monitoreo o la propia L036 no estén disponibles — devuelven 99 y continúan; (b) resolver dinámicamente el TITLE del objeto de L036 a través de la librería de control de versiones CTLVER/"CTLVERS" en vez de cablearlo [L035 L71–L79, L277–L284].

La librería es residente y controlable por operador: se congela con FREEZE(CONTROL, PROC_CONTROL) [L035 L372], y su hilo de control PROC_CONTROL [L035 L301] atiende comandos vía MYSELF.TASKVALUE para suspender la liga (1), rehacer la liga (2), consultar el estatus (3) y terminar (4).

4.6 · Contar_Registros_Estructura(buffer_entrada, buffer_salida) → entero

PROCEDIMIENTO Contar_Registros_Estructura(buffer_entrada, buffer_salida) → entero:  // S038L035_06_NUM_REGS · [L035 L166]
Único envoltorio **no trivial**: adapta un contrato de dos buffers EBCDIC al contrato de cuatro parámetros del procedimiento importado, y **traslada el espacio de códigos de error**.

```
// Variables locales
EBCDIC nombre_estructura[0:16]      // EA_ESTRUCTURA — 17 bytes  [L035 L172]
EBCDIC titulo_base    [0:56]        // EA_BASE       — 57 bytes  [L035 L173]
entero poblacion                    // I_POBLACION               [L035 L175]
entero resultado_interno            // I_RSLT                    [L035 L176]
REFERENCIA-A-ARREGLO salida_poblacion   // A_NUM_REGS            [L035 L178]

SI liga_a_L036_activa
   salida_poblacion := REFERENCIA A buffer_salida[*]             // [L035 L182]

   nombre_estructura := buffer_entrada       POR 17 bytes        // [L035 L184]
   titulo_base       := buffer_entrada[17]   POR 56 bytes        // [L035 L185]
   //  ⚠ el destino EA_BASE tiene 57 bytes y sólo se copian 56;
   //     el byte 56 nunca se inicializa aquí (L036 escanea BASE
   //     "UNTIL = ' '" en [L036 L4165] y depende de ese blanco)

   poblacion         := 0                                        // [L035 L186]
   resultado_interno := 0                                        // [L035 L187]

   LLAMAR MAPLICALL.S038L035_06_NUM_REGS_C(nombre_estructura,
                                           titulo_base,
                                           poblacion,
                                           resultado_interno)    // [L035 L188]

   SI resultado_interno > 0
      resultado := resultado_interno + 70    // ⚠ [HARDCODE-SOSPECHOSO] desplazamiento
                                             //    1..6 → 71..76 (ver tabla abajo)
   SINO
      resultado := 0
      salida_poblacion[0] := poblacion       // ⚠ escritura de PALABRA BINARIA
                                             //    sobre un arreglo EBCDIC
   FIN-SI
SINO
   resultado := 99
FIN-SI
```

> **Traducción de códigos** — el desplazamiento `+70` `[L035 L190]` mapea los resultados internos de L036 al espacio documentado en la cabecera de L036 `[L036 L50–L56]`:
> | interno (L036) | expuesto (L035) | Significado (texto exacto del fuente L036) |
> |---|---|---|
> | 1 | **71** | `NO SE ENCONTRO EL ARCHIVO DE CONTROL DE LA BASE` |
> | 2 | **72** | `TIPO DE DATASET INVALIDO` |
> | 3 | **73** | `NO SE ENCONTRO EL ARCHIVO DE DESCRIPCION` |
> | 4 | **74** | `NO SE PERMITEN SUBSET` |
> | 5 | **75** | `FALLA INTERNA DEL ENTRYPOINT (HABRA MAS INFORMACION EN EL SUMLOG)` |
> | 6 | **76** | `ESTRUCTURA DESCONOCIDA (INCLUYENDO LOS ACCESS'S)` |

> ⚠ `[HALLAZGO]` **Ruptura de convención de tipo en la salida.** Todos los demás entry points devuelven sus valores como dígitos EBCDIC (`REPLACE … FOR n DIGITS`). Aquí `A_NUM_REGS[0] := I_POBLACION` `[L035 L194]` escribe una **palabra binaria de 48 bits** en la posición 0 del arreglo EBCDIC de salida. El consumidor COBOL debe leerla como campo binario, no como numérico display.

« divergencia KB: RN-CORE-DEP-887 » — La regla describe MAPLI como «Librería ALGOL del subsistema MAPLI (administración de mapas/pantallas y su persistencia en la BD MAPLI)… CARGA_MAPA(id_pantalla) -> definición_mapa». La fuente contradice esa lectura en tres puntos verificables:

Búsqueda de los literales MAPA, PANTALLA, CARGA_MAPA, MAPLI_WOR, MAPLI_PRO (insensible a mayúsculas) sobre el directorio MAPLI completo: cero coincidencias en los 5 775 renglones de L035 + L036.

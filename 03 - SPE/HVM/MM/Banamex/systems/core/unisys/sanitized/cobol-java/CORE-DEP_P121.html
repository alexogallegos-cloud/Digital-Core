CORE-DEP · P121 a Java 21 Spring Boot

Abre CORE-DEPBD01CAPTACION para actualización y toma de B02 el indicador de corrida de autorizaciones pendientes (B02-CTR-AUTSPEND), el indicador alterno B02-CTR-AUTSPENDEAS, la fecha de lote y el CSI. Recorre B03 completo y, para cada contrato activo o bloqueado, decide si ya fue planchado en esta corrida comparando su indicador con el de B02. Si no lo fue, la autorización pendiente pasa a ser la diferencia entre los acumulados B03-FILLER1 y B03-FILLER2 (o cero si no es positiva), se limpian esos acumulados y se marca el contrato con el indicador de B02. Cada contrato modificado se guarda en su propia transacción y al final se informan contratos leídos, bloqueados y actualizados.

public class PlanchadoAutorizacionesJobConfig {

    /** 00000000-PRINCIPAL: INICIO, OPEN, PROCESO, CIERRO. */
    @Bean
    Job planchadoAutorizaciones(JobRepository repo, Step leeControl, Step planchaContratos) {
        return new JobBuilder("CORE-DEPP121", repo)
                .validator(p -> {
                    // WS-PARAM-121 RECEIVED BY CONTENT: solo 1 ejecuta el planchado.
                    if (!Long.valueOf(1).equals(p.getLong("param"))) {
                        throw new JobParametersInvalidException(
                                "PARAMETRO NO RECONOCIDO " + p.getLong("param"));
                    }
                })
                .start(leeControl)          // 20000100-ABRO-BASE: lectura de B02
                .next(planchaContratos)     // 50000100-PROCESO-PLANCHADO
                .build();
    }
}

@Component
@RequiredArgsConstructor
class LeeControlTasklet implements Tasklet {
    private final ControlCaptacionRepository b02;

    @Override
    public RepeatStatus execute(StepContribution c, ChunkContext ctx) {
        ControlCaptacion ctl = b02.findUnico()
                .orElseThrow(() -> new ProcesoAbortadoException("ERROR AL ABRIR LA BASE"));  // DMTERMINATE
        var ec = ctx.getStepContext().getStepExecution().getJobExecution().getExecutionContext();
        ec.putInt("indAutPend", ctl.indAutPend);
        ec.putInt("indAutPendEas", ctl.indAutPendEas);
        ec.putInt("csi", ctl.csi);
        return RepeatStatus.FINISHED;
    }
}

// Un error de lectura distinto de NOTFOUND lanza DataAccessException y el step queda FAILED.
@Component
@StepScope
public class PlanchadoProcessor implements ItemProcessor<Contrato, Contrato> {

    @Value("#{jobExecutionContext['indAutPend']}")    private int indCorrida;
    @Value("#{jobExecutionContext['indAutPendEas']}") private int indEas;

    @Override
    public Contrato process(Contrato c) {
        if (c.ctrAutsPend() == indCorrida) {                 // ya planchado en esta corrida
            return limpiaAcumuladosSiHay(c);                  // ver s6
        }
        if (c.ctrAutsPend() == indEas) {                     // planchado por el proceso alterno
            c.marcaCorrida(indCorrida);
            c.limpiaAcumulados();
            return c;
        }
        // CONTRATO NO PLANCHADO
        if (c.autPendiente().signum() <= 0 && c.filler1().signum() <= 0 && c.filler2().signum() <= 0) {
            return null;                                      // NEXT SENTENCE: sin cambios
        }
        BigDecimal diferencia = c.filler1().subtract(c.filler2());
        c.autPendiente(diferencia.signum() > 0 ? diferencia : BigDecimal.ZERO.setScale(2));
        c.limpiaAcumulados();                                 // FILLER1 = FILLER2 = 0
        c.marcaCorrida(indCorrida);
        return c;
    }
}
    /** Ramas CONTRATO PLANCHADO (líneas 352 y 362). */
    private Contrato limpiaAcumuladosSiHay(Contrato c) {
        if (c.filler1().signum() > 0 || c.filler2().signum() > 0) {
            c.limpiaAcumulados();
            return c;                                    // se guarda (WKS-SI-B03 = 1)
        }
        return null;                                     // sin cambios: no se escribe
    }

Riesgos de migración
Comentarios de CSI contradictorios

Los comentarios indican que en Monterrey no se actualiza, pero 50005005-APLI-DES-MTY (líneas 292-297) es idéntico a la rama de Valle de México y actualiza B03.

Error de lectura que no detiene el recorrido

En 50100005-LEE-B03 un error de FINDN distinto de NOTFOUND no enciende el fin de archivo (líneas 305-308); el programa sigue con el contenido anterior del área de B03.

Autorización pendiente borrada sin rastro

Cuando FILLER1 no supera a FILLER2, B03-AUT-PENDIENTE se pone en cero sin bitácora del valor anterior (líneas 342-348).

Encabezado desactualizado

La regla descrita en el comentario inicial (líneas 20-44) no incluye la comparación con B02-CTR-AUTSPENDEAS que el código hace en la línea 330.

Parámetro o CSI inválidos con fin normal

Un parámetro distinto de 1 o un CSI distinto de 04 y 10 solo generan un mensaje; el paso termina normal sin actualizar.

Pendiente de revisión SME
  • Confirmar con SME qué representan B03-FILLER1 y B03-FILLER2 (por el comentario de la línea 343, autorizaciones de compra y cancelaciones) y qué proceso los alimenta.
  • Confirmar qué proceso escribe B02-CTR-AUTSPENDEAS y por qué un contrato marcado con ese indicador se considera planchado.
  • Confirmar si la intención original era no actualizar en Monterrey, como dicen los comentarios.
  • El copybook CORE-DEP/INC/PRO/25MTP004 con las rutinas de acceso (FINDN, LOCK, STORE) no viene en el fuente; la semántica de WS-DB-NOTFOUND y del estatus 15 se infiere.

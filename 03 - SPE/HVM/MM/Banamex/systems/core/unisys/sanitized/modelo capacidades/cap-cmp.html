Indexado: ✅ 2026-08-12 — correlacionado vocab↔reglas↔capacidad (build-traceability.py · clave BC-XX)

Contexto: P103 genera diariamente el reporte de movimientos sospechosos de fraude hacia FraudLink/CNBV (Sistema S711). Monitorea tres códigos de transacción (2001, 2444 y 2496) en tres niveles jerárquicos de cada movimiento: movimiento principal, hasta 5 sub-movimientos SAD, y hasta 10 claves adicionales B13. El trailer de cierre tipo "9" permite a CNBV validar la integridad del archivo recibido. La ausencia de este reporte en cualquier día hábil es un incumplimiento regulatorio (Circular Única de Bancos — prevención de fraude).

CS-CMP-01: Movimiento con código de fraude — sin sub-movimientos ni B13 (happy path)

Tipo: happy-path Condición de entrada: Movimiento en CORE-DEPB07MOVDIA con B07-STATUS-MOVTO ≠ 1, B07-CLAVE-MOVTO = 2001 (o 2444/2496), B07-IND-MOVSADS = 0, sub-movimientos SAD vacíos Resultado: 1 registro FraudLink generado con sucursal (primeros 4 dígitos de B07-AUTORIZACION), B07-MED-ACCESO, B02-FECHA-LOTE, importe y referencia; WKS-NUM-REG acumulado en 1; ciclo continúa con siguiente movimiento Ancla: P103.txt:9528 (IF B07-CLAVE-MOVTO = 2001 OR 2444 OR 2496 → registro principal a E03-CVES2001) + P103.txt:9587-9588 (ADD 1 TO WKS-NUM-REG · ADD WKS-REG-E03-IMPORTE TO WKS-IMP-TOT) Secuencia:

T-CMP-001 (versión OK) → T-CMP-002 (CORE-DEPB02CONTROL leído)
  → [ciclo] T-CMP-003 (lectura B07) → T-CMP-004 (STATUS ≠ 1 → no filtrar)
    → T-CMP-005 (CLAVE = 2001 → registro FraudLink) → T-CMP-008 (ADD 1 + importe)
    → T-CMP-006 (5 SAD × vacíos → sin registros)
    → T-CMP-007 (B07-IND-MOVSADS = 0 → sin B13)
  → [siguiente] T-CMP-003 ...
  → [EOF] T-CMP-009 (trailer tipo "9")

CS-CMP-02: Movimiento principal + 5 sub-movimientos SAD con código monitoreado (volumen máximo SAD)

Tipo: happy-path (volumétrico) Condición de entrada: B07-CLAVE-MOVTO = 2001; los 5 entradas de B07-OTROS-MOVSAD tienen B07-CVE-MOVAD = 2001/2444/2496; B07-IND-MOVSADS = 0 Resultado: 6 registros FraudLink (1 principal + 5 SAD); todos comparten WKS-SUC-OPE del padre; WKS-NUM-REG acumula 6; WKS-IMP-TOT suma 6 importes Ancla: P103.txt:9522 (PERFORM 50001200-OPERO5-B07 5 TIMES → 5 sub-movimientos SAD) + P103.txt:9541 (IF B07-CVE-MOVAD (W77-IND-B07) = 2001 OR 2444 OR 2496 → registro SAD por cada coincidencia) Secuencia:

T-CMP-005 (movimiento principal → registro 1) → T-CMP-008 (+1)
  → T-CMP-006 (PERFORM 5 TIMES)
    → sub-mov 1 (CVE = 2001 → registro 2) → T-CMP-008 (+1)
    → sub-mov 2 (CVE = 2444 → registro 3) → T-CMP-008 (+1)
    → sub-mov 3 (CVE = 2496 → registro 4) → T-CMP-008 (+1)
    → sub-mov 4 (CVE = 2001 → registro 5) → T-CMP-008 (+1)
    → sub-mov 5 (CVE = 2001 → registro 6) → T-CMP-008 (+1)
  → T-CMP-007 (IND-MOVSADS = 0 → sin B13)

CS-CMP-03: Tres niveles completos — principal + SAD + B13 (máxima cardinalidad)

Tipo: happy-path (máxima cardinalidad regulatoria) Condición de entrada: B07-CLAVE-MOVTO = 2001; 5 SAD con código monitoreado; B07-IND-MOVSADS > 0 con B13 existente para el par contrato/autorización; las 10 entradas B13-CLAVES-TRANS tienen código = 2001/2444/2496 Resultado: Hasta 16 registros FraudLink por movimiento (1 principal + 5 SAD + 10 B13); WKS-NUM-REG acumula 16; CNBV recibe representación completa del evento de fraude en sus tres niveles Ancla: P103.txt:9523-9524 (IF B07-IND-MOVSADS > 0 → PERFORM 50001300-MOVS-B13) + P103.txt:9570 (PERFORM 50001350-BUSCA-B13 10 TIMES) + P103.txt:9575 (IF B13-CLAVE-MOVTO(W77-IND-B13) = 2001 OR 2444 OR 2496 → registro B13) Secuencia:

T-CMP-005 (principal → registro 1) → T-CMP-008 (+1)
  → T-CMP-006 (5 SAD → registros 2..6) → T-CMP-008 (×5)
  → T-CMP-007 (IND-MOVSADS > 0)
    → 90000007-B13-FIND (B07-NUM-CONTRATO + B07-AUTORIZACION → W77-SIN-B13 = 0)
    → 50001350-BUSCA-B13 (× 10 entradas)
      → B13-CLAVE-MOVTO = 2001/2444/2496 × 10 → registros 7..16 → T-CMP-008 (×10)

CS-CMP-04: Movimiento excluido por estatus 1 — sin registro FraudLink

Tipo: edge-case (exclusión silenciosa) Condición de entrada: B07-STATUS-MOVTO = 1 (hipótesis regulatoria: movimiento cancelado/anulado) Resultado: El movimiento no entra al análisis de código; no se genera ningún registro FraudLink ni se acumulan totales; ciclo continúa sin traza de la exclusión — CNBV no puede saber cuántos movimientos fueron filtrados por este criterio Ancla: P103.txt:9516 (IF B07-STATUS-MOVTO = 1 → excluye el movimiento del análisis de códigos, sin escritura ni contador) Secuencia:

T-CMP-003 (lectura B07) → T-CMP-004 (B07-STATUS-MOVTO = 1 → SIGUIENTE sin registro)
  → T-CMP-003 (siguiente movimiento)

CS-CMP-05: Error de lectura en CORE-DEPB07MOVDIA — abort sin trailer

Tipo: error-sistema (impacto regulatorio) Condición de entrada: WS-STATUS-BASE > 0 y ≠ 1 durante la lectura secuencial de CORE-DEPB07MOVDIA (p.ej. error de I/O de DMSII) Resultado: Proceso abortado vía CALL SYSTEM DMTERMINATE; archivo E03-CVES2001 queda incompleto sin trailer tipo "9"; FraudLink/CNBV recibe un archivo parcial sin total de control — incumplimiento regulatorio hasta que se reprocese el día correctamente Ancla: P103.txt:9506-9507 (IF WS-STATUS-BASE > 0 · IF WS-STATUS-BASE = 1 → EOF normal) + P103.txt:9513 (CALL SYSTEM DMTERMINATE cuando el status es > 0 y ≠ 1, tras la lectura 90000007-B07MOVDIA-FINDN) Secuencia:

T-CMP-003 (WS-STATUS-BASE = X, X ≠ 0 y X ≠ 1)
  → CALL SYSTEM DMTERMINATE (abort — sin T-CMP-009)
  [archivo FraudLink incompleto — sin trailer]

CS-CMP-06: Error de versión — abort antes de abrir el archivo de salida

Tipo: error-sistema Condición de entrada: S000-CTR-CVEERROR < 0 tras CHECAME IN CTLVERS al inicio del programa Resultado: Mensaje "ERROR DE VERSION" emitido; STATUS=-1 marcado (CHANGE ATTRIBUTE, no STOP RUN); el flujo del mecanismo interno cancela antes de abrir E03-CVES2001 — ningún registro se genera ese día; FraudLink/CNBV no recibe reporte Ancla: P103.txt:9447-9450 (IF S000-CTR-CVEERROR < 0 → MOVE "ERROR DE VERSION" · CHANGE ATTRIBUTE STATUS OF MYSELF TO -1), previo al OPEN OUTPUT E03-CVES2001 de P103.txt:9480 Secuencia:

T-CMP-001 (S000-CTR-CVEERROR < 0)
  → CHANGE ATTRIBUTE STATUS OF MYSELF TO -1
  → abort — T-CMP-002..009 nunca ejecutan
  [archivo FraudLink ausente — incumplimiento regulatorio]

Narrativa del flujo (Nivel 5)

Lectura en prosa del diagrama ensamblado anterior. Estado: Reconstruido.

El diagrama de Cumplimiento Regulatorio (BC-10) no es una cadena: es un abanico de reporteros y monitores independientes, cada uno con su propia fuente y su propio destino regulatorio. No existen aristas programa→programa dentro de la capacidad; la única cohesión es que P103 (CORE-DEP) y P106 (CORE-DEP) comparten la misma fuente de datos, el dataset de rechazos/movimientos del día RECHAZOS / MOVS del día (producido cross-cap por CARGAMOV/REGISTRA). Desde esa fuente, P103 (CORE-DEP · FRAUDLINK) detecta los movimientos con claves 2001/2444/2496 y genera el archivo de fraude hacia el sistema externo S711 (FRAUDLINK / CNBV). Del mismo origen, P106 (CORE-DEP · MOD-ARCH) procesa rechazos y logs y, vía CALL S016L428, cancela el contrato en S016 (status 31); por esa cancelación engancha many-to-many con la capacidad de orquestación (cap-orc).

Los demás nodos son fin-de-cadena aislados pero justificados. P090 (CORE-GL · RECLIDE) se alimenta de los totales LIDE del S502 y produce los archivos LIDE VDM/MTY/UNI hacia Banxico. P168 (CORE-DEP) lee la base de captación CORE-DEPBD01CAPTACION y genera el archivo ARCHIPAB hacia el IPAB. Por último, los dos monitores técnicos: P071 (CORE-GL) y P073 (CORE-GL) —ambos marcados [TÉCNICO]— reciben mensajes online del canal SA2 y emiten el listado técnico MONITOR 071/073. Cada reportero apunta a un regulador o sink distinto (CNBV, Banxico, IPAB o monitor técnico), sin flujo intermedio entre ellos.

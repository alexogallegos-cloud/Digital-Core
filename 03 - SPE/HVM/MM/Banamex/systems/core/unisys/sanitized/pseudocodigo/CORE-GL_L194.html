CORE-GLLibreríaALGOL

Fuente: ALGOL_L194.alg (114 LOC) · librería exportada ALGOL MCP · RN-CORE-GL-1156

Convenciones: nombres traducidos (Unisys MCP ALGOL → legible); [L194 Lnnn] = línea origen; (BR: RN-...) = regla de negocio asociada.

1. Resumen funcional

L194 es una librería ALGOL de utilería del sistema CORE-GL (Movimientos Contables — LegacyCore) que exporta un único procedimiento: REMUEVE_ARCHIVOS(DIR, FECHA). El procedimiento recorre el directorio MCP indicado por el parámetro DIR, consulta el estado de sus entradas mediante la llamada al sistema GETSTATUS con activación del campo de fecha de acceso (ACCESSDATE_BIT), y mueve (renombra con prefijo RESPALDO/) aquellos archivos cuya fecha de último acceso sea anterior a la fecha de corte FECHA, siempre que el archivo no esté en uso en el momento de la operación.

La librería se compila como FREEZE(TEMPORARY) — disponible en memoria durante la corrida — y expone exclusivamente REMUEVE_ARCHIVOS mediante bloque EXPORT. No accede a ninguna base de datos DMSII; la operación es íntegramente sobre el sistema de archivos MCP. (BR: RN-CORE-GL-1156)

« divergencia KB: RN-CORE-GL-1156 — El stub del KB describe la operación como "elimina archivos por criterio de fecha (housekeeping/retención)". El código fuente NO elimina archivos: los renombra asignando el prefijo RESPALDO/ al título del archivo via CLOSE(F, LOCK) con cambio de F.TITLE. La eliminación permanente, si existe, no está presente en este artefacto; podría ocurrir en un paso posterior no identificado en esta librería. La política de retención debe revisarse antes de asumir borrado definitivo. »

4.6 Procedimiento REMUEVE_ARCHIVOS — Lazo principal de directorio (DO...UNTIL)

// Lazo externo: itera bloques de respuesta GETSTATUS [L194 L58–L104]
HACER

    // Fijar tamaño del buffer de solicitud [L194 L60]
    buffer_getstatus[0] := 50
        // ⚠ [HARDCODE-TAMANO-BUFFER]: capacidad máxima fija en 50 palabras por bloque

    // Consultar estado del directorio al sistema MCP [L194 L61–L67]
    SI (estado_error := GETSTATUS(tipo_llamada, 0, 0 & 1 ACCESSDATE_BIT, buffer_getstatus)) ENTONCES
        // BGS=TRUE indica error de GETSTATUS (e.g. directorio no accesible)
        //  SI bandera_despliega ENTONCES ;   // [L194 L63] — rama vacía por diseño
        //  % DISPLAY("Error en GetStatus")   // código comentado [L194 L64] ⚠ [DESCARTE-SILENCIOSO]
        MOVER -1 A resultado_funcion          // REMUEVE_ARCHIVOS := -1 [L194 L65]
        IR A etiqueta_salida                  // GO TO XIT [L194 L66]
    FIN SI

    // Lazo interno: iterar entradas del directorio en el bloque actual [L194 L70–L101]
    indice := 1
    MIENTRAS (indice := indice + 1) MENOR QUE buffer_getstatus[0] HACER

        // Resolver el nodo real de la entrada (directo vs. indirecto) [L194 L72–L75]
        SI buffer_getstatus[indice].LEVELF DISTINTO DE 0 ENTONCES
            nodo_actual := buffer_getstatus[indice]
                // Entrada directa: el nodo es la propia celda GSA[I]
        SINO
            nodo_actual := buffer_getstatus[buffer_getstatus[indice].LINKF + 1]
                // Entrada indirecta: seguir el puntero LINKF al nodo real
        FIN SI

        // Construir nombre de archivo en buffer_archivo [L194 L76–L79]
        REEMPLAZAR puntero_actual := PUNTERO(buffer_archivo)
            CON vista_ebcdic[nodo_actual.LINKF + 2]
                PARA REAL(vista_ebcdic[nodo_actual.LINKF], 2),
                    // longitud del nombre tomada desde EA[ANOW.LINKF] campo [2 bytes]
                ".",                   // separador MCP
                48 bytes nulos         // relleno con 48"00" para terminar el nombre

        // Convertir a representación estándar [L194 L80]
        DISPLAYTOSTANDARD(puntero_actual, puntero_estandar)

        // Calcular fecha de acceso del archivo [L194 L81]
        fecha_acceso := 1900000 + buffer_getstatus[buffer_getstatus[indice].LINKF + ADBV + 1]
            // ⚠ [HARDCODE-BASE-FECHA]: base 1900000 fija; ADBV=15 también fijo
            // Formato: 1900000 + día-juliano MCP del último acceso

        // Evaluar criterio de retención [L194 L82–L83]
        SI fecha_acceso < fecha_corte ENTONCES
            // El archivo es más antiguo que la fecha de corte
            SI NO BOOLEANO(buffer_getstatus[buffer_getstatus[indice].LINKF + 1].SUBVALUE3F) ENTONCES
                // SUBVALUE3F=0 → archivo NO está en uso → candidato al movimiento

                // Mover archivo a directorio de respaldo [L194 L85–L99]
                SI bandera_remueve ENTONCES
                    // Paso 1: abrir el archivo con su nombre actual
                    REEMPLAZAR archivo_f.TITLE CON puntero_actual   // F.TITLE = nombre_original
                    ABRIR(archivo_f)                                 // OPEN(F) [L194 L88]

                    // Paso 2: construir nombre destino con prefijo RESPALDO/ [L194 L89–L94]
                    REEMPLAZAR puntero_actual := PUNTERO(buffer_archivo)
                        CON "RESPALDO/",                            // ⚠ [HARDCODE-RUTA-RESPALDO]
                            vista_ebcdic[nodo_actual.LINKF + 2]
                                PARA REAL(vista_ebcdic[nodo_actual.LINKF], 2),
                            ".",
                            48 bytes nulos
                    // Resultado: "RESPALDO/<nombre_original>.<relleno>"

                    // Paso 3: reasignar título y cerrar con bloqueo (= renombrar) [L194 L95–L96]
                    REEMPLAZAR archivo_f.TITLE CON puntero_actual   // F.TITLE = nombre_respaldo
                    CERRAR(archivo_f, LOCK)
                        // CLOSE(F, LOCK) con F.TITLE cambiado = rename en MCP
                        // El archivo queda en RESPALDO/ — NO es eliminado

                    // Paso 4: restaurar descriptor FILE para próxima iteración [L194 L97–L98]
                    archivo_f := (KIND=DISK, DEPENDENTSPECS, FILEUSE=IO, NEWFILE=FALSE)

                FIN SI  // bandera_remueve
            FIN SI  // no en uso (SUBVALUE3F=0)
        FIN SI  // fecha_acceso < fecha_corte

    FIN MIENTRAS  // lazo entradas del bloque actual [L194 L101]

    // Avanzar descriptor para solicitar el siguiente bloque al GETSTATUS [L194 L102]
    tipo_llamada := tipo_llamada & (4)[15:08]
        // Incrementa/modifica el campo SUBTYPEF del descriptor TYPE
        // para que la siguiente llamada GETSTATUS devuelva la siguiente página

HASTA NO BOOLEANO(buffer_getstatus[0].[47:1])
    // Termina el lazo externo cuando el bit [47] de GSA[0] es 0:
    // no quedan más bloques de entradas en el directorio [L194 L104]

etiqueta_salida:   // XIT: [L194 L105]
FIN PROCEDIMIENTO Remocion_Archivos_Por_Fecha   // END REMUEVE_ARCHIVOS [L194 L106]

5.3 Hallazgos y antipatrones detectados

IDTipoDescripciónLíneas fuente
HA-1⚠ [HARDCODE-FLAG-OVERRIDE]B_REMUEVE y B_DESPLIEGA se inicializan desde MYSELF.SW1/SW2 (switches del SO MCP) y se sobreescriben a TRUE en las líneas inmediatas. La inicialización desde los switches es código muerto; el comportamiento queda siempre fijo en modo ejecución real + display activo.L42–L45
HA-2⚠ [DESCARTE-SILENCIOSO]Los mensajes de error DISPLAY("Directorio erroneo") y DISPLAY("Error en GetStatus") están comentados. B_DESPLIEGA=TRUE no produce ningún efecto. Los fallos de validación de directorio y de GETSTATUS ocurren en silencio; el llamador solo detecta el error por el valor de retorno (-1/-2).L51, L64
HA-3⚠ [HARDCODE-BITS-TIPO-DIRECTORIO]El descriptor TYPE para GETSTATUS se construye con bits fijos literales. Cualquier cambio en la interfaz MCP o versión del sistema requeriría modificar esta constante directamente en el código.L57
HA-4⚠ [HARDCODE-TAMANO-BUFFER]GSA[0] := 50 fija la capacidad del bloque de buffer en 50 palabras en cada iteración del lazo externo.L60
HA-5⚠ [HARDCODE-BASE-FECHA]La base 1900000 para calcular ACC_DATE está hardcodeada. El parámetro FECHA debe expresarse en el mismo formato implícito para que la comparación sea válida.L81

HA-8⚠ [VARIABLE-NO-UTILIZADA]J y NODOS están declarados como INTEGER pero no aparecen en ninguna expresión del procedimiento. Posiblemente remanentes de una versión anterior.L24

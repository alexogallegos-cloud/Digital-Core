CORE-GL · P007 a Java 21 Spring Boot

Al arrancar se enlaza a COMSSUPPORT y SOPORTECOMS, obtiene el CSI, se habilita como programa COMS en línea y resuelve los designadores de DEFAULTSTATION y OUTPUT OF LINEA; después obtiene de CTRLVERS el título vigente de CORE-GLL009 y se liga a ella. Entra en un ciclo de eventos: cada mensaje recibido se clasifica por el tipo del encabezado. Las consultas 11 y 12 reciben un texto con contadores; los mensajes 02 de nodos 15, 16, 21 o 22 con un resultado numérico de 1 a 4 y los 32 con secuencia numérica se cuentan y se envían a CORE-GLL009 con su resultado y secuencia; todo lo demás se cuenta como inválido. Por TASKVALUE el operador enciende o apaga la traza, deshabilita el programa o recarga la librería en caliente.

/** Vista del buffer E_MSG (EBCDIC) recibido por COMS. Offsets base 0. */
public record MensajeCbii(byte[] raw, int longitudTexto) {

    private static final Charset EBCDIC = Charset.forName("IBM037");

    public String nodoDestino()  { return campo(2, 2); }    // HDR_NODODEST = E_MSG[02]
    public String nodoOrigen()   { return campo(16, 2); }   // HDR_NODOORIG = E_MSG[16]
    public String tipo()         { return campo(23, 2); }   // HDR_TIPO     = E_MSG[23]
    public String tcDestino()    { return campo(36, 6); }   // HDR_TC_DEST  = E_MSG[36]
    public String tcOrigen()     { return campo(42, 6); }   // HDR_TC_ORIG  = E_MSG[42]
    public String resultado()    { return campo(83, 7); }   // TXT_RESULT   = E_MSG[83] FOR 7
    public String secuencia02()  { return campo(92, 8); }   // TXT_SEQ      = E_MSG[92] FOR 8
    public String secuencia32()  { return campo(71, 6); }   // E_MSG[71] FOR 6

    private String campo(int offset, int largo) {
        return new String(raw, offset, largo, EBCDIC);
    }

    static boolean numerico(String s) { return s.chars().allMatch(c -> c >= '0' && c <= '9'); }  // TRUTHSET NUMEROS
}

@Service
@RequiredArgsConstructor
public class ProcesadorCbii {

    private final ReceptorCbiiProperties props;   // nodos-permitidos: ["21", "22", "15", "16"]
    private final ContadoresCbii contadores;
    private final ConfirmacionesClient l009;      // antes ENVIA_L009 IN CORE-GLL009

    private static final int MIN_TEXTO = 42;

    /** PROCEDURE PROCESA. Devuelve la respuesta solo para las consultas. */
    public Optional<String> procesa(MensajeCbii m) {
        String tipo = m.tipo();
        if (tipo.equals("11") || tipo.equals("12")) {
            return Optional.of(informa(m));                          // CONSULTA
        }
        if (!(tipo.equals("02") || tipo.equals("32"))
                || m.longitudTexto() < MIN_TEXTO
                || !props.nodosPermitidos().contains(m.nodoOrigen())) {
            contadores.invalido();                                   // ERRORES := * + 1
            return Optional.empty();
        }
        if (tipo.equals("02") && m.longitudTexto() > 123) procesaConfirmacion(m);
        else if (tipo.equals("32") && m.longitudTexto() > 77) procesaTipo32(m);
        else contadores.invalido();                                  // 02 o 32 demasiado corto
        return Optional.empty();
    }
}
public enum ResultadoCbii {
    CONFIRMADO(1), NO_ENVIAR(2), DUPLICADO(3), DUPLICADO_4(4);
    final int codigo;
    ResultadoCbii(int c) { codigo = c; }
    static ResultadoCbii de(int c) { return values()[c - 1]; }
}

private void procesaConfirmacion(MensajeCbii m) {
    String txt = m.resultado();                        // 7 posiciones
    int rslt = Character.digit(txt.charAt(0), 10);     // INTEGER(TXT_RESULT, 1): solo el primer dígito
    if (!MensajeCbii.numerico(txt) || rslt < 1 || rslt > 4) {
        contadores.invalido();
        return;
    }
    String s = m.secuencia02();
    if (!MensajeCbii.numerico(s)) {                    // nuevo: el fuente no valida TXT_SEQ
        contadores.invalido();
        return;
    }
    long seq = Long.parseLong(s);                      // INTEGER(TXT_SEQ, 8)
    ResultadoCbii r = ResultadoCbii.de(rslt);
    contadores.registra(r, seq);                       // TIPO02 / NOENVIO / DUPLIC y último SEQ
    if (contadores.traza()) {
        log.info("RECIBI 02: RSLT={}, SEQ={} DE NODO {}", rslt, seq, m.nodoOrigen());
    }
    l009.envia(r.codigo, seq);                         // ENVIA_L009(RSLT, SEQ)
}
private void procesaTipo32(MensajeCbii m) {
    String s = m.secuencia32();                         // E_MSG[71] FOR 6
    if (!MensajeCbii.numerico(s)) {
        contadores.invalido();
        return;
    }
    long seq = Long.parseLong(s);
    contadores.tipo32(seq);                             // TIPO32 y U_32
    if (contadores.traza()) {
        log.info("RECIBI 32: RSLT=2, SEQ={}", seq);
    }
    l009.envia(ResultadoCbii.NO_ENVIAR.codigo, seq);    // ENVIA_L009(2, SEQ): literal en el fuente
}

            %8sCONFIRMADOS= %06d %06d

            %8sDUPLICADOS = %06d %06d
            %8sINVALIDOS  = %06d""".formatted(contadores.snapshot().comoArgumentos());
    // El adaptador de salida responde al nodo origen con HDR_TIPO = "01".
}

/** Los eventos de TASKVALUE se vuelven operaciones de un endpoint de administración. */
@Component
@Endpoint(id = "cbii")
@RequiredArgsConstructor
public class ComandosOperadorEndpoint {

    private final ContadoresCbii contadores;
    private final IntegrationFlowContext flujos;
    private final ConfirmacionesClient l009;

    @WriteOperation
    public String comando(int valor) {
        return switch (valor) {
            case 2 -> { contadores.traza(true);  yield "TRAZA ON"; }
            case 3 -> { contadores.traza(false); yield "TRAZA OFF"; }
            case 4, 5, 6 -> {                                   // DISABLE PROGRAM CORE-GL07
                flujos.getRegistrationById("receptorCbii").stop();
                yield "RECEPTOR DESHABILITADO";
            }
            case 11 -> { l009.recarga(); yield "CORE-GLL009 RECARGADA"; }  // CAMBIA_L007
            default -> "SIN ACCION";
        };
    }
}

// RECEIVE con resultado 93 (abort del mensaje): se registra con nivel ERROR y se
// envía a una cola de mensajes muertos en lugar de volcarlo al TASKFILE.
// RECEIVE con resultado 99: fin ordenado; equivale al apagado del contexto de Spring.
@Component
@RefreshScope
@RequiredArgsConstructor
public class ConfirmacionesClient {

    private final CatalogoVersiones ctrlvers;       // antes DAME_TIT IN CTRLVERS
    private final ReceptorCbiiProperties props;     // reintentos-enlace, espera-recarga: 15s
    private volatile ConfirmacionesPort destino;

    /** PROCEDURE REFRESCA: obtiene la versión vigente y se liga a ella. */
    @PostConstruct
    public void enlaza() {
        String version = ctrlvers.versionVigente("CORE-GLL009")
                .orElseThrow(() -> new IllegalStateException("CTRLVERS sin título para CORE-GLL009"));
        destino = RetryTemplate.builder()
                .maxAttempts(props.reintentosEnlace())          // el fuente reintenta sin límite
                .fixedBackoff(Duration.ofSeconds(5))
                .build()
                .execute(x -> ConfirmacionesPort.conecta(version));
    }

    /** PROCEDURE CAMBIA_L007: suelta la librería, espera y vuelve a ligar. */
    public synchronized void recarga() throws InterruptedException {
        destino = null;
        Thread.sleep(props.esperaRecarga().toMillis());          // WAIT((15))
        enlaza();
    }

    public void envia(int resultado, long secuencia) {
        destino.envia(resultado, secuencia);                     // ENVIA_L009(RSLT, SEQ)
    }
}
Riesgos de migración
Secuencia sin validar en confirmaciones 02

En PROCESA el campo TXT_SEQ de 8 posiciones se convierte con INTEGER sin comprobar que sea numérico (línea 197), a diferencia del resultado (línea 192) y de la secuencia del tipo 32 (línea 213).

Volcado del mensaje completo a bitácora

Cuando RECEIVE devuelve 93, RUTEA escribe el buffer E_MSG completo en MYSELF.TASKFILE (línea 240). El contenido puede incluir datos operativos sensibles.

Reintento infinito al ligar CORE-GLL009

REFRESCA repite LINKLIBRARY mientras falle, llamando a ERROR_LIGA que pone el status en 3 (línea 98). Si CTRLVERS falla, REFRESCA termina sin asignar el título vigente ni ligar CORE-GLL009 de forma explícita, y el programa sigue recibiendo mensajes; qué versión se usa en ese caso depende del enlace implícito de MCP.

Contadores solo en memoria

Los contadores de confirmados, duplicados, tipo 32 e inválidos y las últimas secuencias viven en variables del proceso y se pierden en cada reinicio; no hay registro de los mensajes descartados.

Hardcodes

Nodos de origen permitidos 15, 16, 21 y 22; longitudes mínimas 42, 77 y 123; estaciones DEFAULTSTATION y OUTPUT OF LINEA; nombre de programa COMS CORE-GL07 y ruta de bitácora CORE-GL/LIST/P007. Se trasladan a application.yml.

Pendiente de revisión SME
  • El inventario no trae reglas del brain para P007 (reglas_brain vacío); ningún segmento se vinculó a reglas.
  • Confirmar el significado de los resultados 3 y 4 del tipo 02; el fuente los trata igual como duplicados.
  • Confirmar por qué el tipo 32 se entrega a CORE-GLL009 con resultado 2 y si la librería necesita distinguirlo.
  • Las longitudes de HDR_TC_DEST y HDR_TC_ORIG no están en el fuente; validar el layout del encabezado COMS con el SME de comunicaciones.
  • No se conoce el contrato interno de ENVIA_L009 (qué hace CORE-GLL009 con resultado y secuencia); la librería no forma parte de este fuente.

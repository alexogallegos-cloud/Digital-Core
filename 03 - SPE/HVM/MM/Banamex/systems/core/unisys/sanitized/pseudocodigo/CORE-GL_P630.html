P630 · LEE-MOVSNNN · Consulta y actualización de header de archivos de movimientos (CORE-GL)

CORE-GLProgramaCOBOL

Fuente: COBOL_P630.cbl (489 LOC) · Utilitario de mantenimiento batch · BC-02

Convenciones: nombres traducidos (Unisys→legible); [P630 Lnnnn] = número de línea de la columna de secuencia fuente; (BR: RN-CORE-GL-nnn) = regla de negocio.

1. Resumen funcional

P630 (LEE-MOVSNNN) es un utilitario de mantenimiento operativo del CORE-GL que opera sobre los archivos físicos de movimientos del sistema. Tiene dos modos de operación controlados por el parámetro de entrada WKS-FILE: modo consulta (WKS-FILE = "CON") que lee y despliega via el logger LJ la fecha del header de todos los archivos relevantes del sistema indicado, y modo actualización que reescribe la fecha en el registro header del archivo de movimientos correspondiente. El programa es invocado por operadores o por procesos WFL de mantenimiento cuando es necesario verificar o corregir la fecha de proceso de los archivos de movimientos. En el contexto del sistema CORE-GL (Libro Mayor GL de LegacyCore), los archivos de movimientos almacenan los asientos contables del día; su header registra la fecha de proceso y sirve como punto de control de integridad operacional.

Para el sistema CORE-DEP (Captación), el modo consulta incluye dos tipos adicionales de archivo (CB2 y CTD) que no existen para otros sistemas, reflejando el tratamiento especial que CORE-DEP recibe en toda la arquitectura P600.

2. Datos y archivos

2.1 Archivo operado

Nombre lógicoTítulo físico (dinámico)Modo accesoDescripción
A01-ERRSNNN(CORE-GL)CORE-GL/FILE/{tipo}S{sis}/{fecha} ON {pack}.I-O (actualiza) / INPUT (consulta)Archivo de movimientos cuyo header se consulta o actualiza. El título se construye dinámicamente vía WKS-ETI-CORE-GL-MOVANT.

El título físico del archivo es dinámico y se construye antes de cada OPEN mediante CHANGE ATTRIBUTE TITLE. Ver RN-CORE-GL-585.

2.2 Parámetros de entrada (PROCEDURE DIVISION USING)

Campo COBOLTipoSignificado
WKS-FILEPIC X(03)Tipo de operación / archivo: "CON"=consulta, "MOV"=movimientos, "DES"=datos adicionales, "CB2"=CB2 CORE-DEP, "CTD"=CTD CORE-DEP
WKS-FECHAPIC 9(06)Fecha de proceso en formato YYMMDD (6 dígitos)
WKS-SISTEMAPIC 9(03)Código numérico del sistema a operar (ej. 500 para CORE-DEP)

2.3 Layout del registro header del archivo de movimientos

El primer registro del archivo es el header, identificado por los primeros 2 bytes = "HD". El registro completo comparte el layout WKS-MOV-DATOS (990 bytes, definido en el COPY ESCRITURA de CPBAS):

CampoPICOffsetSignificado
WKS-MOV-ID-HDX(02)1-2Identificador de tipo: "HD" = header
WKS-MOV-FECHD9(08)3-10Fecha del archivo en 8 dígitos YYYYMMDD
(resto del registro)—11-990Datos del movimiento o filler

El campo WKS-MOV-ID-HD y WKS-MOV-FECHD son los únicos campos que P630 escribe en modo actualización.

2.4 Estructura ETI del nombre de archivo (WKS-ETI-CORE-GL-MOVANT)

"(CORE-GL)CORE-GL/FILE/"   PIC X(16)   — prefijo fijo
WKS-ETI-CORE-GL-FILE    PIC X(03)   — tipo: MOV / DES / CB2 / CTD
"S"                  PIC X(01)   — separador fijo
WKS-SIS-MOV          PIC 9(03)   — código sistema (ej. 500)
"/"                  PIC X(01)
WKS-SIS-FEC          PIC 9(06)   — fecha YYMMDD
" ON "               PIC X(06)
WKS-SIS-PACK         PIC X(15)   — pack físico Unisys (obtenido de B01SISDIA)
"."                  PIC X(01)

Ejemplo resultante: (CORE-GL)CORE-GL/FILE/MOVCORE-DEP/260716 ON CMEMP.

4. Lógica por sección

4.1 · Inicializar_Programa

PROCEDIMIENTO Inicializar_Programa():                      // 000000-INIC-PROGRAMA · [P630 L058000]
```
PROCEDIMIENTO Inicializar_Programa():                         // 000000-INIC-PROGRAMA · [P630 L058000]

  // --- Inicialización del logger LJ ---
  MOVER "CORE-GL"    A  sistema_lj         // SISTEMA-LJ  [P630 L059000]
  MOVER "P630"    A  paso_lj            // PASO-LJ     [P630 L060000]
  MOVER "002"     A  mtp_lj             // MTP-LJ      [P630 L061000]
  MOVER "I"       A  tipo_lj            // TIPO-LJ = Informativo  [P630 L062000]
  MOVER 020201    A  codigo_lj          // CODIGO-LJ   [P630 L063000]

  // --- Configurar librerías y obtener control del sistema ---
  EJECUTAR Configurar_Librerias_Y_Obtener_Pack()             // PERFORM 020400-LIBRERIAS [P630 L064000]

  // --- Cargar parámetros en ETI para construcción del nombre de archivo ---
  MOVER fecha_parametro         A  fecha_en_etiqueta          // WKS-FECHA → WKS-SIS-FEC  [P630 L066000]
  MOVER tipo_archivo_parametro  A  tipo_archivo_etiqueta      // WKS-FILE  → WKS-ETI-CORE-GL-FILE [P630 L067000]
  MOVER sistema_parametro       A  sistema_en_etiqueta        // WKS-SISTEMA → WKS-SIS-MOV [P630 L068000]

  // --- Selector de modo de operación ---
  SI tipo_archivo_parametro = "CON"   // WKS-FILE  [P630 L069100]
  ENTONCES
      EJECUTAR Consultar_Archivos()                           // PERFORM 020400-CONSULTA [P630 L069150]
  SINO
      EJECUTAR Actualizar_Header()                            // PERFORM 020400-ACTUALIZA [P630 L069300]
  FIN SI

  RETORNAR   // STOP RUN [P630 L069400]

  « [P630 L058000-L069400] · BR: RN-CORE-GL-581 — bifurcación FILE="CON" vs actualización »
```

> **Nota:** No hay validación de que `WKS-FILE` sea un valor reconocido (`MOV`, `DES`, `CB2`, `CTD`). Cualquier valor distinto de `"CON"` ejecuta el modo actualización. ⚠ [DESCARTE-SILENCIOSO] potencial si se pasa un tipo no reconocido.

4.2 · Configurar_Librerias_Y_Obtener_Pack

PROCEDIMIENTO Configurar_Librerias_Y_Obtener_Pack():      // 020400-LIBRERIAS · [P630 L080000]
```
PROCEDIMIENTO Configurar_Librerias_Y_Obtener_Pack():          // 020400-LIBRERIAS · [P630 L080000]

  // --- Configurar acceso a CTRLVERS por función ---
  CHANGE ATTRIBUTE LIBACCESS    DE "CTRLVERS" A BYFUNCTION    // [P630 L082000]
  CHANGE ATTRIBUTE FUNCTIONNAME DE "CTRLVERS" A "CTLVERS"     // [P630 L084000]

  // --- Configurar acceso a LOCSUP por función ---
  CHANGE ATTRIBUTE LIBACCESS    DE "LOCSUP" A BYFUNCTION      // [P630 L086000]
  CHANGE ATTRIBUTE FUNCTIONNAME DE "LOCSUP" A "LOCSUP"        // [P630 L087000]

  // --- Configurar título de LIB-DISP (logger S000) ---
  CHANGE ATTRIBUTE TITLE DE "LIB-DISP"
      A "(S000)S000/UTILITY/DESPLIEGA/OBJ/LIB ON PACK."       // [P630 L088000-L089000]

  // --- Obtener nombre de librería de control L001 via CTRLVERS ---
  MOVER "CORE-GLL001CTL" A  id_libreria_control                   // WKS-CTLVER-LIBID [P630 L095000]
  LLAMAR "DAME_TIT IN CTRLVERS"
         CON (id_libreria_control, nombre_libreria_control)
         RETORNANDO resultado_ctlver                           // W77-CTLVER-RESULT [P630 L096000-L098000]

  SI resultado_ctlver = 0
  ENTONCES
      // Librería encontrada en CTRLVERS — usar su título dinámico
      CHANGE ATTRIBUTE TITLE DE "CORE-GL-L001" A nombre_libreria_control   // WKS-CTLVER-NOMLIB [P630 L100000-L101000]
  SINO
      // Fallback: usar título hardcodeado
      CHANGE ATTRIBUTE TITLE DE "CORE-GL-L001"
          A "(CORE-GL)CORE-GL/OBJECT/L001/CONTROL ON CMEMP."                   // ⚠ [HARDCODE-SOSPECHOSO] [P630 L103000-L104000]
  FIN SI

  // --- Consultar B01SISDIA para obtener el pack del archivo de movimientos ---
  MOVER sistema_parametro A  sistema_b01         // WKS-SISTEMA → WKS-B01-SISTEMA [P630 L106000]
  MOVER 01                A  funcion_b01          // WKS-B01-FUNCION = función consulta [P630 L107000]
  LLAMAR "CONSISDIA IN CORE-GL-L001"
         CON (estructura_b01_sisdia)
         RETORNANDO resultado_b01                 // W77-RESULT-B01 [P630 L108000-L109000]

  SI resultado_b01 > 0
  ENTONCES
      // Error fatal: no se puede obtener el pack del archivo de movimientos
      MOVER resultado_b01 A  codigo_error          // W77-ERROR [P630 L112000]
      CONSTRUIR mensaje_lj =
          "NO PUEDO OBTENER FECHA DE PROCESO "
          " ERROR EN CORE-GL-L001 S" + sistema_parametro
          ", ERR #" + codigo_error                 // [P630 L113000-L115000]
      MOVER "O"      A  tipo_lj                    // Tipo "O" = error operativo [P630 L117000]
      MOVER 020901   A  codigo_lj                  // [P630 L118000]
      LLAMAR "LJ IN LIB-DISP"
             CON (contador_lj, mensaje_lj)         // [P630 L119000-L120000]
      SET MYSELF(STATUS) = -1                      // Terminación anormal [P630 L121000]
      // ⚠ El programa termina con status -1 — WFL recibe señal de fallo
  SINO
      // Éxito: pack del archivo de movimientos disponible
      MOVER pack_archivo_movimientos A  pack_sistema  // WKS-B01-NOMPACMOV → WKS-SIS-PACK [P630 L123000]
  FIN SI

  « [P630 L080000-L124000] · BR: RN-CORE-GL-586 — B01SISDIA función 1 como fuente de verdad para PACK »
  « [P630 L121000] · BR: RN-CORE-GL-586 — error fatal si B01SISDIA falla (SET STATUS -1) »
```

> El `SET MYSELF(STATUS) TO -1` es una terminación anormal MCP — equivale a un `System.exit(-1)` en Java. El WFL supervisor recibe el código de error y detiene la cadena. Sin pack no es posible construir el nombre ETI del archivo. ⚠ [RIESGO-EQUIVALENCIA]: en modernización este patrón debe mapearse a una excepción controlada con rollback.

4.3 · Actualizar_Header

PROCEDIMIENTO Actualizar_Header():                         // 020400-ACTUALIZA · [P630 L069600]
```
PROCEDIMIENTO Actualizar_Header():                             // 020400-ACTUALIZA · [P630 L069600]

  // El título WKS-ETI-CORE-GL-MOVANT ya fue cargado en INIC-PROGRAMA con:
  //   WKS-FILE  → WKS-ETI-CORE-GL-FILE  (el tipo de archivo a actualizar: MOV, DES, CB2, CTD)
  //   WKS-SISTEMA → WKS-SIS-MOV
  //   WKS-FECHA   → WKS-SIS-FEC
  //   WKS-SIS-PACK  (obtenido de B01SISDIA en LIBRERIAS)

  ABRIR A01-ERRSNNN EN MODO I-O                               // OPEN I-O [P630 L070000]
  LEER A01-ERRSNNN EN WKS-MOV-DATOS
       AL FINAL MOVER 1 A indicador_fin                       // READ AT END [P630 L071000]
       // Primer registro = header "HD"; si el archivo está vacío, indicador_fin=1
       // No hay manejo de error para archivo vacío — W77-FIN queda en 1 pero continúa

  // --- Loguear la fecha ACTUAL del header (antes de la actualización) ---
  CONSTRUIR mensaje_lj =
      "FECHA ARCHIVO " + fecha_header_leida                   // WKS-MOV-FECHD [P630 L071200-L071300]
  MOVER "I"      A  tipo_lj                                   // [P630 L071400]
  MOVER 020101   A  codigo_lj                                 // [P630 L071500]
  LLAMAR "LJ IN LIB-DISP"
         CON (contador_lj, mensaje_lj)                        // [P630 L071600-L071700]

  // --- Escribir el nuevo header ---
  MOVER "HD"         A  identificador_header                  // WKS-MOV-ID-HD = "HD" [P630 L072000]
                                                              // (BR: RN-CORE-GL-584)
  MOVER fecha_parametro A  fecha_header                       // WKS-FECHA → WKS-MOV-FECHD (6 dígitos) [P630 L073000]
  CALCULAR fecha_header = fecha_header + 20000000             // ADD 20000000 → convierte YYMMDD→YYYYMMDD [P630 L074000]
                                                              // ⚠ [HARDCODE-SOSPECHOSO] siglo XXI implícito
                                                              // (BR: RN-CORE-GL-583)

  REESCRIBIR WKS-MOV-DATOS                                    // REWRITE [P630 L075000]
             SI LLAVE INVÁLIDA
                 MOSTRAR "ERROR EN GRABAR HD"                 // DISPLAY — no-fatal, sin STOP RUN [P630 L076000]
             FIN SI                                           // ⚠ [DESCARTE-SILENCIOSO]: error no logueado a LJ
                                                              // (BR: RN-CORE-GL-588)

  CERRAR A01-ERRSNNN CON SAVE                                 // CLOSE WITH SAVE — persiste en disco [P630 L077000]
                                                              // (BR: RN-CORE-GL-587)

  « [P630 L069600-L077000] · BR: RN-CORE-GL-583 — conversión fecha 6→8 dígitos con ADD 20000000 »
  « [P630 L069600-L077000] · BR: RN-CORE-GL-584 — header identificado por "HD" en primeros 2 bytes »
  « [P630 L069600-L077000] · BR: RN-CORE-GL-587 — CLOSE WITH SAVE persiste el cambio en disco »
  « [P630 L069600-L077000] · BR: RN-CORE-GL-588 — INVALID KEY no-fatal, solo DISPLAY »
```

> **Antipatrón detectado:** si el `REWRITE` falla (INVALID KEY), el archivo se cierra con `CLOSE WITH SAVE` pero el header conserva la fecha anterior — estado inconsistente no detectado. El mensaje `DISPLAY` puede perderse en entorno batch. En modernización: convertir a excepción controlada con rollback explícito. ⚠ [DESCARTE-SILENCIOSO]

4.4 · Consultar_Archivos

PROCEDIMIENTO Consultar_Archivos():                        // 020400-CONSULTA · [P630 L079000]
```
PROCEDIMIENTO Consultar_Archivos():                            // 020400-CONSULTA · [P630 L079000]

  // --- Archivos adicionales solo para CORE-DEP ---
  SI sistema_parametro = 500            // WKS-SISTEMA = 500 ⚠ [HARDCODE-SOSPECHOSO] [P630 L079040]
  ENTONCES
      MOVER "CB2" A  tipo_archivo_etiqueta   // WKS-ETI-CORE-GL-FILE [P630 L079060]
      EJECUTAR Desplegar_Fecha_Archivo()     // PERFORM 020400-DESPLIEGA [P630 L079080]
      MOVER "CTD" A  tipo_archivo_etiqueta   // WKS-ETI-CORE-GL-FILE [P630 L079100]
      EJECUTAR Desplegar_Fecha_Archivo()     // PERFORM 020400-DESPLIEGA [P630 L079120]
  FIN SI
  // (BR: RN-CORE-GL-582 y RN-CORE-GL-590)

  // --- Archivos comunes a todos los sistemas ---
  MOVER "MOV" A  tipo_archivo_etiqueta        // WKS-ETI-CORE-GL-FILE [P630 L079140]
  EJECUTAR Desplegar_Fecha_Archivo()          // PERFORM 020400-DESPLIEGA [P630 L079160]
  MOVER "DES" A  tipo_archivo_etiqueta        // WKS-ETI-CORE-GL-FILE [P630 L079180]
  EJECUTAR Desplegar_Fecha_Archivo()          // PERFORM 020400-DESPLIEGA [P630 L079200]

  « [P630 L079000-L079200] · BR: RN-CORE-GL-582 — CB2/CTD solo se consultan para CORE-DEP »
  « [P630 L079040] · BR: RN-CORE-GL-590 — valor literal 500 hardcodeado para identificar CORE-DEP »
  « [P630 L079000-L079200] · BR: RN-CORE-GL-589 — consulta TODOS los archivos relevantes del sistema »
```

> Salida típica para `WKS-SISTEMA = 500`:
> ```
> FECHA ARCHIVO CB2 : 20260715
> FECHA ARCHIVO CTD : 20260715
> FECHA ARCHIVO MOV : 20260715
> FECHA ARCHIVO DES : 20260715
> ```
> Para otros sistemas (ej. CORE-GL): solo `MOV` y `DES`.

4.5 · Desplegar_Fecha_Archivo

PROCEDIMIENTO Desplegar_Fecha_Archivo():                   // 020400-DESPLIEGA · [P630 L079240]
```
PROCEDIMIENTO Desplegar_Fecha_Archivo():                       // 020400-DESPLIEGA · [P630 L079240]

  // Pre-condición: WKS-ETI-CORE-GL-FILE ya contiene el tipo de archivo a consultar
  // El título ETI completo (WKS-ETI-CORE-GL-MOVANT) se reconstruye con el nuevo tipo

  // --- Cambiar dinámicamente el título del archivo antes de abrirlo ---
  CHANGE ATTRIBUTE TITLE DE A01-ERRSNNN
         A  etiqueta_archivo_movimiento                        // WKS-ETI-CORE-GL-MOVANT [P630 L079270]
                                                               // (BR: RN-CORE-GL-585)

  ABRIR A01-ERRSNNN EN MODO INPUT                              // OPEN INPUT [P630 L079280]
  LEER A01-ERRSNNN EN WKS-MOV-DATOS
       AL FINAL MOVER 1 A indicador_fin                        // AT END [P630 L079300]
       // Solo se lee el primer registro (el header)
       // No hay validación adicional si el archivo está vacío

  CERRAR A01-ERRSNNN CON RELEASE                               // CLOSE WITH RELEASE [P630 L079340]
                                                               // (BR: RN-CORE-GL-587) — modo lectura, sin persistir

  // --- Construir y emitir mensaje de log con la fecha leída ---
  CONSTRUIR mensaje_lj =
      "FECHA ARCHIVO " + tipo_archivo_etiqueta                 // WKS-ETI-CORE-GL-FILE [P630 L079342]
      " : " + fecha_header_leida                               // WKS-MOV-FECHD [P630 L079344]
  MOVER "I"      A  tipo_lj                                    // Tipo informativo [P630 L079348]
  MOVER 020101   A  codigo_lj                                  // [P630 L079350]
  LLAMAR "LJ IN LIB-DISP"
         CON (contador_lj, mensaje_lj)                         // [P630 L079352-L079354]

  « [P630 L079240-L079360] · BR: RN-CORE-GL-585 — ruta dinámica via CHANGE ATTRIBUTE TITLE »
  « [P630 L079340] · BR: RN-CORE-GL-587 — CLOSE WITH RELEASE en modo consulta (sin persistir) »
  « [P630 L079240-L079360] · BR: RN-CORE-GL-589 — modo consulta: solo lectura del header, log via LJ »
```

> **Nota técnica (MCP):** el `CHANGE ATTRIBUTE TITLE` antes del `OPEN` es el mecanismo Unisys para la resolución dinámica del path físico del archivo. Sin este paso, el sistema abriría el archivo del último título asignado. En Java/Spring este patrón se mapea a un `Resource` con URI construida dinámicamente o a un `Path.of(...)` parametrizado.

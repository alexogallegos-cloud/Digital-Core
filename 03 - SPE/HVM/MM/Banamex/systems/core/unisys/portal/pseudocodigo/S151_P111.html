P111 · Carga Totales por Clave en BD Semanal (S151)

S151ProgramaCOBOL

Fuente: COBOL_P111.cbl (2374 LOC) · Paso batch post-P112 · BC-13

Convenciones: nombres traducidos (Unisys→legible); [P111 Lnnnn] = línea origen absoluta (cols 1-6); hardcodes preservados exactos.

1. Resumen funcional

P111 es el cargador batch de totales-por-clave de movimientos diarios en la base semanal S151BD10MOVDIA151 (dataset S151B50TOTXCVE). Lee el archivo de log de movimientos del día (L01-DATOS), filtra los registros con función=1 (movimiento activo) y estatus=1, los clasifica por la combinación (fecha-contable, tipo-proceso, producto, instrumento, moneda, bancos, clave-transacción, esquema-contable) mediante un sort en disco, y acumula importe acumulado + conteo de movimientos antes de persistir en el set DMSII S151B50TOTXCVE. Previamente limpia todos los registros B50 con fecha ≤ fecha-proceso, garantizando idempotencia del proceso. El resultado alimenta la conciliación de totales que realizan P001 (proyección de fecha) y P110-S500 (cuadre contable interbancario S500↔S151). En el lote diario se ejecuta inmediatamente después de P112 y antes de P113.

PROCEDIMIENTO Manejador_Interrupcion_Hardware():            // HI-INTERRUPT SECTION · INTERRUP-BY-HI · [P111 L1764]

  DESHABILITAR interrupciones  // DISALLOW INTERRUPT
  MOVER atributo TASKVALUE (código de interrupción del task propio) → indicador_interrupcion  // W77-INTERRUP

  SI indicador_interrupcion = 4  // W88-HI4: interrupción de alta prioridad (shutdown del sistema MCP)
  ENTONCES
    Limpiar línea de mensaje  // MOVE SPACES TO WLI-ENCAB-52
    MOVER "I" → tipo_log  // WLI-TIPO-LJ
    MOVER 020201 → codigo_lj  // ⚠ [HARDCODE-SOSPECHOSO] código de evento de terminación por HI-4
    MOVER "TERMINA P111 POR HI 4" → texto_mensaje  // WLI-TEXTO-LJ

    Reenviar mensaje a LJ operador  // CALL "LJ IN LIB-DISP" USING CONTADOR-LJ, MENSAJE-LJ

    ABORTAR  // STOP RUN
  SINO
    Limpiar línea de mensaje
    MOVER "E" → tipo_log, tipo_lj  // WLI-TIPO-LJ y TIPO-LJ
    MOVER 030101 → codigo_lj  // ⚠ [HARDCODE-SOSPECHOSO]
    MOVER "HI NO IMPLEMENTADO" → texto_mensaje, texto_lj  // WLI-TEXTO-LJ, TEXTO-LJ
    EJECUTAR 000-030-IMPRIME-MENSAJE
    Reenviar mensaje a LJ operador
  FIN-SI

PROCEDIMIENTO Inicio_Proceso():            // 000000-INICIO-PROCESO · [P111 L1792]

// --- Inicialización de librerías de sistema --- CAMBIAR título de LIB-DISP a "(S000)S000/UTILITY/DESPLIEGA/OBJ/LIB ON PACK." // [P111 L1795] CAMBIAR acceso de "SOPORTECOMS" a BYFUNCTION; nombre de función = "SOPORTECOMS" CAMBIAR acceso de "CTLVER" a BYFUNCTION; nombre de función = "CTLVERS"

  // --- Resolución dinámica de nombre de librería de control ---
  MOVER "S151L001CTL" → identificador_lib  // WKS-LIBID
  LLAMAR "DAME_TIT IN CTLVER" con (identificador_lib, nombre_lib_resuelto) GIVING resultado_ctlver  // WKS-NOMBLIB, W77-ERR-CTLVER
  SI resultado_ctlver = 0
  ENTONCES
    CAMBIAR título de LIB-CONTROL a nombre_lib_resuelto  // versión dinámica desde registro de versiones
  SINO
    CAMBIAR título de LIB-CONTROL a "(S151)S151/OBJECT/L001/CONTROL/02MTP001 ON CMEMP."  // ⚠ [HARDCODE-SOSPECHOSO] fallback
  FIN-SI

  // --- Inicialización de variables de log e identificación ---
  MOVER "S151" → sistema_lj  // SISTEMA-LJ
  MOVER "P111" → paso_lj, paso_backup2, encab_paso  // PASO-LJ, WKS-PASO-BACK2, WLI-RB-E1-PASO
  MOVER "004" → num_mtp_lj  // MTP-LJ ⚠ [HARDCODE-SOSPECHOSO] identifica la versión del paso
  MOVER "I" → tipo_log

  // --- Obtener identificador de host/CSI ---
  LLAMAR "CSIID IN SOPORTECOMS" con (datos_host)  // WKS-DATOS-HOST → WKS-NUMCSI, WKS-NOMEQUIPO, WKS-NOMCSI
  CANCELAR "SOPORTECOMS"
  CANCELAR "CTLVER"

// --- Activar manejador de interrupciones de hardware --- CONECTAR HI-INTERRUPT al atributo EXCEPTIONEVENT del task propio HABILITAR interrupciones // ALLOW INTERRUPT

  // --- Consulta de metadatos del sistema origen (S151B01SISDIA) ---
  MOVER num_sistema → parametro_sistema_b01, sistema_log, sistema_backup2, sistema_encab
    // WKS-PARAM-SIS → WKS-B01-SISTEMA, WKS-LOG-SISTEMA, WKS-SIS-BACK2, WLI-RB-E3-SISTEMA2
  MOVER num_csi_host → csi_b01, csi_reporte  // WKS-NUMCSI → WKS-B01-CSI, WKS-TR-CSI2
  MOVER 1 → funcion_b01  // WKS-B01-FUNCION = 1 (función: consultar S151B01SISDIA)
  LLAMAR "CONSISDIA IN LIB-CONTROL" con (estructura_s151b01sisdia) GIVING resultado_libcontrol
    // WKS-S151B01SISDIA → retorna: NOMPACMOV, FECPRO, NOMBDSEM, NOMPACSAL, STAARCLOG, etc.

  SI resultado_libcontrol = 0  // W77-RESULT-LIBCON: consulta exitosa
  ENTONCES
    MOVER nombre_pack_movimientos → pack_log  // WKS-B01-NOMPACMOV → WKS-PACK-LOG
    // Determinar fecha de proceso: TASKVALUE sobreescribe si se pasó desde el WFL
    SI taskvalue_de_mi_tarea > 0  // ATTRIBUTE TASKVALUE OF MYSELF (parámetro de fecha del WFL)
    ENTONCES
      MOVER taskvalue → fecha_proceso  // WKS-PARAM-FCH → WKS-FEC-PRO
    SINO
      MOVER fecha_proceso_b01 → fecha_proceso  // WKS-B01-FECPRO → WKS-FEC-PRO (fecha de control del sistema)
    FIN-SI
  SINO
    SI resultado_libcontrol = 1  // sistema no dado de alta en S151B01SISDIA
    ENTONCES
      MOVER "I" → tipo_lj
      MOVER 010401 → codigo_lj  // ⚠ [HARDCODE-SOSPECHOSO]
      MOVER "SISTEMA NO DADO DE ALTA" → texto_lj
      LLAMAR "LJ IN LIB-DISP" con (contador_lj, mensaje_lj)
      CAMBIAR STATUS del task a -1  // terminación anormal del proceso batch
    SINO  // cualquier otro error de la librería de control
      MOVER "I" → tipo_lj
      MOVER 010401 → codigo_lj  // ⚠ [HARDCODE-SOSPECHOSO] mismo código que caso anterior
      MOVER "ERROR EN BASE DE CONTROL" → texto_lj
      LLAMAR "LJ IN LIB-DISP" con (contador_lj, mensaje_lj)
      CAMBIAR STATUS del task a -1
    FIN-SI

PROCEDIMIENTO Abrir_Base_DMSII_Reintentos():            // 000700-ABRE-BASE · [P111 L1954]
  // Intenta abrir MOVDB en modo UPDATE; reintenta si está en uso exclusivo; aborta a los 5 intentos

  MOVER 1 → base_abierta  // W77-BASE = 1: se presume exitosa; se revierte en caso de WAIT
  SUMAR 1 → contador_intentos  // W77-INTENTOS: acumulado entre llamadas sucesivas

  SI estatus_bd_semanal = 0  // WKS-B01-STABDSEM = 0: base en estado habilitado para apertura
  ENTONCES
    ABRIR UPDATE MOVDB
      EN EXCEPCIÓN:
        SI DMSTATUS(OPENERROR) Y DMSTATUS(DMERRORTYPE) = 39  // ⚠ [HARDCODE-SOSPECHOSO] error 39 = base en uso exclusivo
        ENTONCES
          ESPERAR 20 segundos  // WAIT(20) ⚠ [HARDCODE-SOSPECHOSO] espera fija
          MOVER 0 → base_abierta  // W77-BASE = 0: señaliza retry al caller
        SINO
          MOVER "E" → tipo_log, tipo_lj
          MOVER 010101 → codigo_lj  // ⚠ [HARDCODE-SOSPECHOSO]
          MOVER " ERROR AL ABRIR LA BASE SEMANAL" → texto  // texto exacto del fuente
          EJECUTAR 000-030-IMPRIME-MENSAJE
          LLAMAR "LJ IN LIB-DISP"
          CAMBIAR STATUS del task a -1  // terminación anormal irreversible
        FIN-SI
  SINO
    // Base en estado inválido (STABDSEM ≠ 0: base no habilitada)
    Limpiar WLI-ENCAB-52
    MOVER "O" → tipo_log  // tipo Operador
    MOVER "010105" → codigo_lj  // ⚠ nota: asignado como cadena, no como número
    MOVER "ESTADO INVALIDO DE LA BASE DE MOVTOS" → texto
    EJECUTAR 000-030-IMPRIME-MENSAJE
    Propagar a LJ  // TIPO-LJ y TEXTO-LJ a MENSAJE-LJ
    LLAMAR "LJ IN LIB-DISP"
    CAMBIAR STATUS del task a -1
  FIN-SI

  // --- Control de reintentos máximos ---
  SI contador_intentos > 5  // ⚠ [HARDCODE-SOSPECHOSO] umbral máximo de reintentos
  ENTONCES
    MOVER "O" → tipo_log
    MOVER 0 → contador_intentos  // reset del contador para futuras invocaciones
    MOVER 060315 → codigo_lj  // ⚠ [HARDCODE-SOSPECHOSO]
    Obtener: categoria_dm = DMSTATUS(DMCATEGORY), subtipo_dm = DMSTATUS(DMERRORTYPE)
    STRING "ERROR EN BASE BD10 : ARCHIVO DE CONTROL EN USO EN FORMA EXCLUSIVA ERROR DMSII CAT. "
           + descripcion_categoria(categoria_dm)
           + " SUBCATEGORIA " + subtipo_dm
    DELIMITED BY SIZE → texto_lj
    LLAMAR "LJ IN LIB-DISP"
  FIN-SI

5. Reglas de negocio cubiertas

Sin reglas RN-S151-\* específicas para P111 en el catálogo de reglas del KB (rules-s151.md y archivos de rules por programa). No existe un archivo rules-s151-p111.md.

Clasificación: P111 es un programa utilitario batch (infrastructure helper) cuya función es gestionar los totales diarios por clave en la base semanal S151BD10MOVDIA151. No implementa reglas de negocio directas; prepara la estructura de datos (S151B50TOTXCVE) que otros programas utilizan para conciliación y proyección de fechas. Su relación con reglas de negocio es indirecta: los valores hardcodeados de sistema (87, 403, 404, 500) y de tipo_proceso (1, 11, 15-17, 40-43) reflejan decisiones de diseño del sistema que deberían documentarse como reglas de arquitectura.

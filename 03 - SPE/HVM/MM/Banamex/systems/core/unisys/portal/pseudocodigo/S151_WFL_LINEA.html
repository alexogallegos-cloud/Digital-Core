1. Resumen funcional

S151/WFL/LINEA/25MTP003 [WFL_LINEA L1] es el job de control operativo del entorno EN LÍNEA (online) del sistema S151. No contiene lógica de negocio contable: es una consola de operación parametrizada que el operador dispara desde el MCP pasando una cadena (STRING PARAMETRO), y que traduce esa cadena a una de 43 acciones operativas validadas sobre el gateway transaccional y las librerías del S151.

El mecanismo dominante no es RUN de programas de aplicación: para los 16 programas online del S151 el WFL envía comandos ENABLE PROGRAM / DISABLE PROGRAM al monitor transaccional SYSTEM/COMS a través de la utilería (S100)COMS/UTILITY/SENDTOMCS [WFL_LINEA L270, L283, L300, …], que es quien realmente arranca/detiene las copias online. Solo cinco objetos se ejecutan como tarea MCP propia: el calendario S000P100 [L74], S151P005 (carga de archivos) [L253], S151P090 (TOTALIDE) [L722], S151P612 (difusor de señal apertura/cierre) [L749] y S151P061 (ticket) [L850]; más el arranque diferido del WFL de LOTE (S151LOTE) en tres horarios fijos [L829-L831].

Lo dispara: el operador, manualmente, desde el MIX. No hay disparador de calendario ni encadenamiento desde otro WFL dentro de este fuente. Lo que produce: (a) cambios de estado en COMS (programas habilitados/deshabilitados), (b) instalación/promoción por plaza de las librerías L002/REGISTRAS, L011/CONSMOVS, L030/CONSULTAS y L040/TOTXCVES mediante COPY [L891, L1028, L1097, L1169], (c) bajas forzadas (HI 4) de las mix de las librerías L012 y L009 [L1227-L1276], (d) tres arranques programados del WFL de LOTE en modo CORRESOLO P021 [L829-L831], (e) archivos de impresión S151/LIST/... forzados vía SYSTEM/FORZA y taskfiles S151/TASKFILE/P005|P090|P061/..., y (f) una carátula de job S151/CARATULA/LINEA/<yymmdd>/<mix> [L1294-L1295].

Para migración: es el runbook ejecutable del online. Su reemplazo en el target no es un traductor de WFL sino un orquestador/consola de operación (panel de arranque de servicios + scheduler) que modele: las 43 acciones operativas, el diálogo interactivo con el operador (ACCEPT/WAIT), la política de reintento ante falla, el enrutamiento por nodo/plaza y las dependencias con el monitor transaccional (BR: RN-S151-1162). Ver §5.4 para las divergencias con la ficha del KB.

2.7 Interfaz con el monitor transaccional COMS

Patrón repetido 32 veces (16 ENABLE + 16 DISABLE), literal e idéntico salvo el nombre del programa:

<TASK> (STATUS = NEVERUSED);
DO BEGIN
   RUN (S100)COMS/UTILITY/SENDTOMCS("*SYSTEM/COMS","*") [<TASK>];
   DATA COMMANDS
   ENABLE|DISABLE PROGRAM <NOMBRE_COMS>
?
   IF <TASK>(TASKVALUE) NEQ 1 THEN
      WAIT ("DAR OK CUANDO *SYSTEM/COMS ESTE ACTIVO", OK);
END UNTIL <TASK>(TASKVALUE) = 1;

⚠ [BUCLE-SIN-LÍMITE] el DO … UNTIL taskvalue=1 no tiene contador de reintentos: si COMS nunca responde 1, el ciclo es infinito y solo lo rompe la intervención humana en el WAIT repetida indefinidamente. Se repite en las 32 rutinas.

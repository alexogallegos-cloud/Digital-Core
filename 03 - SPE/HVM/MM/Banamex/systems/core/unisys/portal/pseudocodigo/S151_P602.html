P602 · Cambio de Estado en B04SISTEM (S151 / Banamex)

S151ProgramaCOBOL

Fuente: COBOL_P602.cbl (749 LOC) · Utilitario de control operativo · batch nocturno WFL LOTE

Convenciones: nombres traducidos (Unisys MCP-COBOL → legible); [P602 Lnnnn] = línea de origen en fuente; (BR: RN-S151-NNN) = regla de negocio del KB.

1. Resumen funcional

P602 (PROGRAM-ID: CALLLIBCTL) es un programa wrapper de control operativo con ~50 LOC de lógica propia (749 LOC totales incluyen estructuras COPY expandidas de la librería de control). Su única función es cambiar el campo ESTATUS en el dataset S151B04SISTEM para un número de sistema dado, invocando la librería compartida S151L001CTL (LIBCTL) en dos fases secuenciales: primero consulta el registro actual (función 01) y luego aplica la modificación (función 37 = CAMBIO). Es convocado por el WFL del batch nocturno pasando exactamente dos parámetros en PROCEDURE DIVISION USING: número de sistema (9(03)) y valor de estatus destino (9(02)). No contiene lógica de negocio propia — la regla real reside en la rutina MANTB04SISTEM dentro de LIBCTL; cualquier validación del valor de estatus ocurre ahí. Los errores en consulta o actualización son no-fatales: se registran via librería de display LIB-DISP (utilitario S000) y el programa termina con STOP RUN de todas formas.

3. Mapa de control

Jerarquía de párrafos y flujo de control:

PROCEDURE DIVISION USING WKS-PARAMETROS                          [P602 L685]
│
└─ 000100-INICIO                                                 [P602 L686]
     │  (inicializar MENSAJE-LJ, CODIGO-LJ=051001)
     ├─ PERFORM 000200-LIBRERIAS                                 [P602 L693]
     │    │ (configurar CTLVER BYFUNCTION → "CTLVERS")
     │    │ (configurar LIB-DISP → utilitario S000)
     │    │ CALL "DAME_TIT IN CTLVER" USING "S151L001CTL"
     │    │   SI OK  → CHANGE TITLE OF "LIBCTL" TO WKS-NOMLIB
     │    │   SI ERR → CHANGE TITLE OF "LIBCTL" TO fallback CMEMP  ⚠ [HARDCODE]
     │    └─ CANCEL "CTLVER"
     │
     ├─ PERFORM 000300-LLAMA-LIBCTL                              [P602 L694]
     │    │
     │    │─ [FASE 1: Consulta previa]
     │    │   MOVE 1  TO WKS-B04-FUNCION
     │    │   MOVE WKS-PARAM-SISTEMA TO WKS-B04-SISTEMA
     │    │   CALL "B04SISTEM IN LIBCTL" USING WKS-B04SISTEMA
     │    │   SI resultado > 0 → log "ERROR AL CONSULTAR B04"   (no-fatal)
     │    │
     │    └─ [FASE 2: Actualización]
     │        MOVE 37 TO WKS-B04-FUNCION
     │        MOVE WKS-PARAM-ESTATUS TO WKS-B04-ESTATUS
     │        CALL "MANTB04SISTEM IN LIBCTL" USING WKS-B04SISTEMA
     │        SI resultado > 0 → log "ERROR AL ACTUALIZAR B04"  (no-fatal)
     │
     ├─ CANCEL "LIBCTL"                                          [P602 L695]
     └─ STOP RUN                                                 [P602 L696]

Complejidad ciclomática: 3 (un flujo principal + 2 condiciones de error independientes, ambas no-fatales). P602 es un wrapper de complejidad mínima; toda la complejidad real reside en MANTB04SISTEM dentro de LIBCTL.

4. Lógica por sección

Convención: cada PROCEDIMIENTO corresponde a un párrafo COBOL. Los tres párrafos de la PROCEDURE DIVISION se listan en orden de ejecución. Las variables se nombran en español la primera vez que aparecen, con el nombre COBOL original entre comentarios.

4.1 · Inicio

PROCEDIMIENTO Inicio():  // 000100-INICIO · [P602 L686]
```
PROCEDIMIENTO Inicio():                 // 000100-INICIO · [P602 L686-696]

  // --- Inicialización del bloque de mensaje a operador ---
  MOVER "0151"   A sistema_mensaje      // SISTEMA-LJ — código del sistema S151
  MOVER "P602"   A paso_mensaje         // PASO-LJ    — identificador del programa
  MOVER "002"    A mtp_mensaje          // MTP-LJ     — número de release MTP
  MOVER ESPACIOS A texto_mensaje        // TEXTO-LJ   — limpiar texto de mensaje
  MOVER "I"      A tipo_mensaje         // TIPO-LJ    — "I" = informativo
  MOVER 051001   A codigo_mensaje       // CODIGO-LJ  = 051001 ⚠ [HARDCODE-SOSPECHOSO]

  «  [P602 L687-692] »

  // --- Secuencia principal de ejecución ---
  EJECUTAR Configurar_Librerias()       // → párrafo 000200-LIBRERIAS
  EJECUTAR Llamar_LibreríaControl()     // → párrafo 000300-LLAMA-LIBCTL

  // --- Liberación de LIBCTL de memoria del proceso MCP ---
  CANCELAR "LIBCTL"                     // Libera la librería dinámica del address space
  // En Java/Spring: equivalente a destruir el bean de servicio de control

  «  [P602 L695] · (BR: RN-S151-556) »

  RETORNAR                              // STOP RUN — fin del programa

  «  [P602 L696] »
```

**Notas:**
- El `CANCEL "LIBCTL"` es mandatorio en Unisys MCP-COBOL para liberar el segmento de código de una librería cargada dinámicamente. Sin él, la librería quedaría residente en memoria del proceso para la sesión. (BR: RN-S151-556)
- `CODIGO-LJ = 051001` es un hardcode de identificación del punto de inicio del programa — no hay catálogo visible que lo documente.

4.2 · Configurar_Librerias

PROCEDIMIENTO Configurar_Librerias():  // 000200-LIBRERIAS · [P602 L698]
```
PROCEDIMIENTO Configurar_Librerias():    // 000200-LIBRERIAS · [P602 L698-715]

  // --- Paso 1: Configurar CTLVER para usar entry-point CTLVERS ---
  CAMBIAR ATRIBUTO LIBACCESS    DE "CTLVER" A BYFUNCTION
  // BYFUNCTION = mecanismo MCP para seleccionar una función dentro de una librería
  CAMBIAR ATRIBUTO FUNCTIONNAME DE "CTLVER" A "CTLVERS"
  // "CTLVERS" = módulo de control de versiones que resuelve nombres de librerías

  «  [P602 L700-701] · (BR: RN-S151-552) »

  // --- Paso 2: Configurar LIB-DISP (utilitario de display de mensajes S000) ---
  CAMBIAR ATRIBUTO TITLE DE "LIB-DISP" A
    "(S000)S000/UTILITY/DESPLIEGA/OBJ/LIB ON PACK"
  // Ruta física MCP del utilitario de display de mensajes al operador de sala

  «  [P602 L703-704] »

  // --- Paso 3: Resolver nombre físico de LIBCTL via CTLVERS ---
  MOVER "S151L001CTL" A identificador_librería  // WKS-LIBID — ID de S151L001CTL

  LLAMAR "DAME_TIT IN CTLVER"
    USANDO  identificador_librería,             // WKS-LIBID  — entrada: ID de librería
            nombre_físico_librería              // WKS-NOMLIB — salida:  título resuelto
    DANDO   codigo_error_ctlver                 // W77-ERR-CTLVER — 0=OK, >0=error

  «  [P602 L707-708] · (BR: RN-S151-552) »

  // --- Paso 4: Asignar ruta a LIBCTL (dinámica o fallback hardcodeado) ---
  SI codigo_error_ctlver = 0 ENTONCES
    // CTLVERS resolvió el nombre correctamente
    CAMBIAR ATRIBUTO TITLE DE "LIBCTL" A nombre_físico_librería
    // LIBCTL ahora apunta a la versión activa de S151L001CTL en catálogo

  SINO
    // CTLVERS falló — usar ruta de emergencia hardcodeada
    CAMBIAR ATRIBUTO TITLE DE "LIBCTL" A
      "(S151)S151/OBJECT/L001/CONTROL  ON CMEMP"
    // ⚠ [HARDCODE-SOSPECHOSO]: ruta con doble espacio entre "L001" y "ON"
    //   — posible artefacto de formato fijo COBOL-85; verificar en migración
    //   — depende de que el pack CMEMP esté montado en el sistema MCP

    «  [P602 L711-713] · (BR: RN-S151-553) »
  FIN-SI

  // --- Paso 5: Liberar CTLVER de memoria ---
  CANCELAR "CTLVER"
  // CTLVER ya cumplió su propósito; se libera para no consumir recursos

  «  [P602 L715] »

RETORNAR
```

**Notas:**
- El mecanismo `CHANGE ATTRIBUTE ... BYFUNCTION` es específico de Unisys MCP-COBOL. No tiene equivalente directo en Java/Spring; debe reimplementarse como un lookup de configuración centralizado. (BR: RN-S151-552)
- La ruta de fallback `"(S151)S151/OBJECT/L001/CONTROL  ON CMEMP"` contiene dos espacios entre `L001` y `ON` — debe preservarse exactamente en cualquier migración o verificarse contra el sistema de archivos MCP real. (BR: RN-S151-553)
- `pack_CMEMP // CMEMP = pack físico de producción donde reside el objeto compilado de LIBCTL` — si el pack no está montado, el fallback también fallará silenciosamente.

4.3 · Llamar_LibreríaControl

PROCEDIMIENTO Llamar_LibreríaControl():  // 000300-LLAMA-LIBCTL · [P602 L717]
```
PROCEDIMIENTO Llamar_LibreríaControl():   // 000300-LLAMA-LIBCTL · [P602 L717-749]

  // =========================================================
  // FASE 1: Consulta previa del registro actual en B04SISTEM
  // =========================================================
  // Propósito: verificar que el registro del sistema exista antes de modificarlo.
  // Un error aquí es no-fatal — el programa continúa a la fase 2.

  MOVER 0 A resultado_libctl             // W77-RESULT-LIBCON — limpiar código retorno
  MOVER 1 A función_b04                  // WKS-B04-FUNCION = 1 → CONSULTA
  MOVER número_sistema_param             // WKS-PARAM-SISTEMA
    A  sistema_b04                       // WKS-B04-SISTEMA

  «  [P602 L724-726] · (BR: RN-S151-551, RN-S151-557) »

  LLAMAR "B04SISTEM IN LIBCTL"
    USANDO  bloque_b04sistema            // WKS-B04SISTEMA — entrada/salida completa
    DANDO   resultado_libctl             // W77-RESULT-LIBCON — 0=OK, >0=error

  «  [P602 L728-729] »

  SI resultado_libctl > 0 ENTONCES
    // Error en consulta — registrar y continuar (NO se aborta)
    MOVER "ERROR AL CONSULTAR B04" A texto_mensaje   // TEXTO-LJ
    LLAMAR "LJ IN LIB-DISP"
      USANDO  contador_mensajes_lj,      // CONTADOR-LJ
              mensaje_lj                 // MENSAJE-LJ — bloque completo de mensaje
    // ⚠ [DESCARTE-SILENCIOSO]: el error se muestra al operador pero el programa
    //   continúa a la FASE 2 — posible escritura sobre un registro inexistente
    //   o registro en estado inesperado. Riesgo de desfase operativo.

    «  [P602 L730-733] · (BR: RN-S151-555) »
  FIN-SI

  // =========================================================
  // FASE 2: Actualización del campo ESTATUS en B04SISTEM
  // =========================================================
  // Propósito: escribir el nuevo valor de estatus pasado por parámetro.
  // Función 37 = CAMBIO GENÉRICO en la convención DMSII de Unisys.
  // Un error aquí también es no-fatal — se registra y STOP RUN termina normalmente.

  MOVER 0  A resultado_libctl            // W77-RESULT-LIBCON — limpiar código retorno
  MOVER 37 A función_b04                 // WKS-B04-FUNCION = 37 → CAMBIO

  «  [P602 L739-740] · (BR: RN-S151-557) »

  MOVER número_sistema_param             // WKS-PARAM-SISTEMA
    A  sistema_b04                       // WKS-B04-SISTEMA
  MOVER estatus_destino_param            // WKS-PARAM-ESTATUS
    A  estatus_b04                       // WKS-B04-ESTATUS
  // estatus_b04 // WKS-B04-ESTATUS — semáforo que gobierna si el sistema puede
  //   procesar: 2=en proceso (P000 habilitado), 3=cierre iniciado, 4=cierre completo
  //   Valores inferidos de P610/P677; no visibles ni validados en P602.

  «  [P602 L741-742] · (BR: RN-S151-554, RN-S151-558) »

  LLAMAR "MANTB04SISTEM IN LIBCTL"
    USANDO  bloque_b04sistema            // WKS-B04SISTEMA — entrada completa
    DANDO   resultado_libctl             // W77-RESULT-LIBCON — 0=OK, >0=error
  // MANTB04SISTEM = rutina de mantenimiento físico de B04SISTEM en LIBCTL.
  // Toda la validación del valor de ESTATUS ocurre dentro de esta rutina.
  // P602 no valida que PARAM-SISTEMA sea un sistema válido
  // ni que PARAM-ESTATUS sea un valor permitido. (BR: RN-S151-554, RN-S151-559)

  «  [P602 L743-744] · (BR: RN-S151-557, RN-S151-559) »

  SI resultado_libctl > 0 ENTONCES
    // Error en actualización — registrar y continuar (NO se aborta)
    MOVER "ERROR AL ACTUALIZAR B04" A texto_mensaje  // TEXTO-LJ
    LLAMAR "LJ IN LIB-DISP"
      USANDO  contador_mensajes_lj,      // CONTADOR-LJ
              mensaje_lj                 // MENSAJE-LJ
    // ⚠ [DESCARTE-SILENCIOSO]: si la actualización falla sin que el JCL externo
    //   detecte el error, el ESTATUS en B04SISTEM queda sin cambiar pero el
    //   proceso caller continúa — riesgo de desfase en el ciclo de vida del sistema.

    «  [P602 L745-748] · (BR: RN-S151-555) »
  FIN-SI

RETORNAR
  // Control regresa a 000100-INICIO → CANCEL "LIBCTL" → STOP RUN
```

**Notas:**
- El gate de dos fases (F01 → F37) implementa la convención DMSII de Unisys: siempre consultar antes de modificar para verificar existencia del registro. (BR: RN-S151-551)
- Ambas condiciones de error (`resultado_libctl > 0`) son no-fatales por diseño. Esto crea un riesgo documentado: si la actualización falla silenciosamente, el estatus en `B04SISTEM` no cambia pero el proceso caller asume que sí cambió. (BR: RN-S151-555)
- La función `37` sigue la convención de operaciones DMSII de Unisys: 1=consulta, 19=alta, 22=baja, 37=cambio. Esta convención es transversal a todo el ecosistema S151/S500. (BR: RN-S151-557)

5.2 Código muerto / código de infraestructura sin uso en lógica propia

Las ~690 LOC de WORKING-STORAGE que declaran estructuras COPY (WKS-S151B01SISDIA, WKS-CONSISDIA-F02..F11, WKS-B01-CONB01, WKS-B02ARCINTER, WKS-B05PROCESOS, WKS-S151B09CONXSIS, WKS-S151B03SISMEN..F03..F22) no se referencian en ningún punto de la PROCEDURE DIVISION de P602. Son declaraciones de compatibilidad con la API completa de LIBCONTROL, incluidas por el COPY para que el compilador MCP reconozca las estructuras, pero P602 solo usa WKS-B04SISTEMA. En una modernización estas estructuras pueden eliminarse del wrapper o externalizarse a un archivo de include compartido.

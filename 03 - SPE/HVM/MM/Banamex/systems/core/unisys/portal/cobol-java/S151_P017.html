S151 · P017 a Java 21 Spring Boot

P017 abre S151BD13BIFIN con reintentos cada 10 segundos y se queda en un ciclo de ESPERACOMS. Cada mensaje de 534 bytes trae encabezado COMS, ACA, SA0 y SA2 y un área de usuario de 409 bytes con dos formatos posibles. Si el destino es S151, el subcódigo decide qué registro buscar: 1 busca en B07 por fecha, contrato, autorización y ocurrencia; 2 busca en B07 por cliente con el formato SERV2; 3 busca en B10DOMI, que es el registro que generó P013. Si la dirección del mensaje es respuesta de alta (2) y el registro está enviado (1), o respuesta de baja (4) y el registro está cancelado (3), el estatus del registro toma el valor de la dirección y se guarda el código de error; cualquier otra combinación se reporta como dirección errónea.

@Configuration
@RequiredArgsConstructor
public class ReceptorS702Config {

    /** 000000-PROCESO-GLOBAL: INICIO, PROCESO UNTIL W77-FIN = 1, CIERRA-BD, STOP RUN. */
    @Bean
    IntegrationFlow receptorS702(ComsInboundAdapter coms, RespuestaS702Router router) {
        return IntegrationFlow.from(coms)                 // 200600-COMS-RECEIVE
                .filter(MensajeS702.class, m -> m.sa0().paraS151(),
                        f -> f.discardChannel("descartados"))      // EXIT PERFORM si no es S151
                .route(router)                             // subcódigo 1, 2 o 3
                .get();
    }

    /** 700100-ABRE-BD UNTIL W77-FIN = 0 OR W77-INTENTO > 6, con WAIT(10) entre intentos. */
    @Bean
    RetryTemplate aperturaBifin() {
        return RetryTemplate.builder()
                .maxAttempts(7)                            // el contador empieza en 0 y corta en > 6
                .fixedBackoff(Duration.ofSeconds(10))
                .build();
    }
}
@Component
@RequiredArgsConstructor
public class ComsInboundAdapter extends MessageProducerSupport {

    private final ComsClient coms;                   // ESPERACOMS / RECEIVE COMS-IN
    private final DiaOperativo dia;                  // 202000-VALIDA-FEC-ACTUAL

    @Override
    protected void doStart() {
        Thread.ofVirtual().name("p017-coms").start(() -> {
            while (isRunning()) {
                EventoComs ev = coms.espera(Duration.ofSeconds(30));
                switch (ev.tipo()) {
                    case MENSAJE -> recibe();
                    case TIMEOUT -> dia.verificaCambioDeDia();     // rota display y monitor
                    case HI      -> { if (ev.hi() == 4 || ev.hi() == 6) stop(); }
                    default      -> log.warn("EVENTO DESCONOCIDO {}", ev.tipo());
                }
            }
        });
    }

    private void recibe() {
        RecepcionComs r = coms.receive();
        switch (r.statusKey()) {
            case 99 -> stop();                                  // FIN DE PROGRAMA X ESTATUS
            case 0, 89, 91, 92, 93 -> sendMessage(MessageBuilder.withPayload(r.mensaje()).build());
            default -> log.error(">> ERROR RECEIVE MSG >>> CS-COMS-IN-STATUS-KEY = {} {}",
                                 r.statusKey(), r.mensaje());
        }
    }
}

Riesgos de migración
Sistema origen sin validar

Los niveles 88 W88-SA0-TRN-OSIS-S702 y W88-SA0-TRN-OSIS-C845 (líneas 106-107) no se usan en la PROCEDURE DIVISION. P017 solo filtra por destino S151 (línea 1578) y acepta respuestas de cualquier sistema origen.

Deadlock que continúa con un registro no localizado

Las búsquedas LOCK FIRST dejan WKS-EOF en 0 ante DEADLOCK y el párrafo llamador no reintenta (líneas 1591, 1603 y 1615). La evaluación de las líneas 1620 y 1849 usa el estatus del registro que tenga el área en ese momento.

Actualización perdida por deadlock en STORE

700200-ALMACENA-REG y 700200-ALMACENA-REG-B10 hacen FREE y siguen ante DEADLOCK (líneas 1774-1775 y 1885-1886). La respuesta de S702 no queda aplicada y no se informa.

Llave de B10 sin contrato

La condición por contrato en la búsqueda y en el mensaje de B10 está comentada (líneas 1609, 1912 y 1925).

Código de error arrastrado en subcódigo 2

La rama de subcódigo 2 (líneas 1593-1603) no asigna WKS-ERROR, así que el error que se graba es el del último mensaje de subcódigo 1 o 3.

Hardcodes

Destino S151 (0151), subcódigos 1, 2 y 3, corte de reintentos de apertura en W77-INTENTO > 6 con WAIT(10), estatus de COMS aceptables 0, 89, 91, 92 y 93, nodo 04 como MTY y cualquier otro como VDM en el título del display (líneas 1822-1824). Se trasladan a application.yml.

bian_ref: 10.1.1 Access Control + T.3.5 Security

1Contexto funcional

La capacidad de Seguridad y Control de Acceso agrupa los mecanismos transversales que protegen los datos y el acceso a los sistemas del POC. Tiene dos piezas: P655 (SCRAMBLING) enmascara los datos personales (PII) —nombres de titulares, representantes legales y domicilios de las cuentas de captación— en las bases DMSII de S500 para usarlas en ambientes de prueba sin exponer información sensible, en cumplimiento de PCI-DSS y de las obligaciones de privacidad bancaria (Banxico, CNBV); está diseñado para operar solo en ambientes no-productivos, aunque tiene un defecto documentado (fail-open: si el hostname no está en la lista reconocida, no bloquea la ejecución en producción). P060 (TransIT/XATMI) actúa como servidor de control de acceso de transacciones distribuidas. La capacidad absorbe además el mapeo BIAN 10.1.1 Access Control (ver "Capacidad adicional").

3Casuísticas

CS-SEC-01: Enmascaramiento completo exitoso — corrida nueva en ambiente de prueba (happy path)

Tipo: happy-path Condición de entrada: Hostname = VDMBETA/ACYPGAMA/MONALFA/ACYPOMEGA (ambiente prueba); sin checkpoint previo; todos los contratos B03, grupos CPE B37 y cuentas CPE B39 disponibles Resultado: Bloque calculado (1800 - HH - MM - SS) ajustado a par; archivo checkpoint creado; nombres de contratos intercambiados por bloques; representantes y domicilios CPE sustituidos; cuentas CPE con nombre consistente con su contrato vinculado; checkpoint actualizado al terminar Ancla: P655_SCRAMBLING.txt:295-300 (IF WKS-MY-HOST = VDMBETA/ACYPGAMA/ACYPBETA/MONALFA/ACYPOMEGA → MOVE 1 TO W77-ES-PRUEBA) + :324 (COMPUTE W77-CONTA-01 = 1800 - WKS-TIME-HH - MM - SS; ajuste par en :327 DIVIDE / :333 SUBTRACT 1) Secuencia:

T-SEC-001 (hostname → prueba) → T-SEC-002 (no bloquea — no producción)
  → T-SEC-003 (bloque = 1800 - tiempo) → T-SEC-004 (ajuste par)
  → T-SEC-005 (no existe checkpoint → crear nuevo)
  → [ciclo B03CONTRATOS por bloques]
    → T-SEC-007 (intercambiar nombres dentro del bloque) × N bloques completos
    → T-SEC-008 (último bloque: si impar → contrato central recibe W77-NOMBRE-PTE)
  → T-SEC-009 (B37GRUPOCPE: LOCK NEXT → sustituir REPRES + DOMICILIO)
  → T-SEC-010 (B39CTASCPE: copiar nombre de B03 o generar sintético)

CS-SEC-02: Fail-open ante hostname no reconocido — enmascaramiento sin control de ambiente

Tipo: error-seguridad (🔴 DEFECTO CRÍTICO) Condición de entrada: Hostname no está en ninguno de los 7 nombres reconocidos (p.ej. VDMKAPPA tras failover, o nodo nuevo del banco) Resultado: Ni W77-ES-PRODUCCION ni W77-ES-PRUEBA se activan; el intento de bloqueo (T-SEC-002) no se dispara; el programa trata el host desconocido como no-productivo y ejecuta el enmascaramiento completo sobre las bases DMSII sin ninguna advertencia — inclusive si el host es productivo. Riesgo: el enmascaramiento de datos PII puede ocurrir sobre datos reales de producción Ancla: P655_SCRAMBLING.txt:291-300 (IF/ELSE hostname: solo VDMALFA/MONBETA→W77-ES-PRODUCCION y los 5 de prueba→W77-ES-PRUEBA; sin rama para host no listado → ninguna bandera se activa) + :304 (el bloqueo solo dispara IF W77-ES-PRODUCCION = 1; no hay STOP RUN) Secuencia:

T-SEC-001 (hostname NO reconocido → sin clasificación)
  → T-SEC-002 (W77-ES-PRODUCCION = false → no bloquea)
  → T-SEC-003 → T-SEC-004 → ... → T-SEC-010
  [enmascaramiento completo ejecutado sin validación de ambiente]

CS-SEC-03: Reanudación desde checkpoint — corrida interrumpida en contrato N

Tipo: happy-path (variante resiliente) Condición de entrada: Corrida anterior interrumpida; archivo "S500/FILE/SCRBLING/{CSI}/{fecha}" existe en disco con encabezado válido (tipo, CSI, fecha y contador > 0 coinciden con la corrida actual) Resultado: Tamaño de bloque del checkpoint (WKS-I99-HEAD-BLQ) sobreescribe el recién calculado (W77-CONTA-01); cursor de B03CONTRATOS avanza hasta el contrato N del checkpoint (20000600-BUSCA-REINICIO); enmascaramiento continúa desde ese punto sin reprocesar contratos anteriores Ancla: P655_SCRAMBLING.txt:437-447 (READ I99-SCRBLING INTO WKS-I99-REG-00 → MOVE WKS-I99-HEAD-BLQ TO W77-CONTA-01 + PERFORM 20000600-BUSCA-REINICIO) + :456 (párrafo 20000600-BUSCA-REINICIO avanza cursor B03) Secuencia:

T-SEC-001 → T-SEC-002 → T-SEC-003 → T-SEC-004
  → T-SEC-005 (checkpoint EXISTE)
  → T-SEC-006 (valida → todos los campos coinciden, contador > 0)
    → W77-CONTA-01 = WKS-I99-HEAD-BLQ (restaura bloque previo)
    → cursor B03 avanza a contrato N (20000600-BUSCA-REINICIO)
  → [ciclo B03 retoma desde N]
    → T-SEC-007 / T-SEC-008 → T-SEC-009 → T-SEC-010

CS-SEC-04: "Bloqueo" de producción sin corte real — enmascaramiento continúa en VDMALFA/MONBETA

Tipo: error-seguridad (🟠 CRÍTICO) Condición de entrada: Hostname = VDMALFA o MONBETA (servidores productivos del banco); WFL programa P655 en producción por error operativo Resultado: W77-ES-PRODUCCION = true; mensaje "NO CORRE EN PRODUCCION; HOST: " emitido; STATUS = -1 marcado; pero sin STOP RUN ni GOBACK — el programa continúa abriendo B03CONTRATOS, B37GRUPOCPE y B39CTASCPE productivos y ejecuta el enmascaramiento de PII real sobre la base de datos de producción. El único control real es la disciplina operativa del WFL scheduler Ancla: P655_SCRAMBLING.txt:291-293 (IF WKS-MY-HOST = VDMALFA OR MONBETA → MOVE 1 TO W77-ES-PRODUCCION) + :304-309 (IF W77-ES-PRODUCCION = 1 → STRING "NO CORRE EN PRODUCCION; HOST:" + PERFORM 70000050-MENSAJE + CHANGE ATTRIBUTE STATUS OF MYSELF TO -1; sin STOP RUN/GOBACK) Secuencia:

T-SEC-001 (hostname = VDMALFA → W77-ES-PRODUCCION = true)
  → T-SEC-002 (STATUS = -1, mensaje error → sin STOP RUN → continúa)
  → T-SEC-003 → T-SEC-004 → T-SEC-005 → T-SEC-006
  → T-SEC-007 → T-SEC-008 → T-SEC-009 → T-SEC-010
  [enmascaramiento completo ejecutado sobre datos PRODUCTIVOS]

CS-SEC-05: Último bloque de contratos con cantidad impar

Tipo: edge-case Condición de entrada: Al llegar al fin del cursor B03CONTRATOS (W77-EOF-B03 = 1), el último bloque tiene un número impar de contratos Resultado: Posición central calculada (W77-REG-MEDIO = W77-TOT-DIV + 1); contrato en posición central recibe el nombre ya enmascarado del primer contrato leído en todo el archivo (W77-NOMBRE-PTE, capturado cuando W77-TOT-LEIDOS = 1); el resto de contratos del bloque mantienen el intercambio normal por índice Ancla: P655_SCRAMBLING.txt:584-591 (párrafo 50002060-VAL-REGS → COMPUTE W77-REG-MEDIO = W77-TOT-DIV + 1) + :569-570 (IF W77-REG-MEDIO = W77-IND-BXX → MOVE W77-NOMBRE-PTE TO B03-NOMBRE; W77-NOMBRE-PTE capturado en :518) Secuencia:

[fin del ciclo B03 → W77-EOF-B03 = 1]
  → T-SEC-008 (50002060-VAL-REGS)
    → DIVIDE W77-LEIDOS BY 2 GIVING W77-TOT-DIV REMAINDER W77-DIV-RESTO
    → IF REMAINDER ≠ 0:
        W77-REG-MEDIO = W77-TOT-DIV + 1
        contrato[W77-REG-MEDIO] ← W77-NOMBRE-PTE (nombre del primer contrato)
    → resto del bloque: intercambio normal por índice

CS-SEC-06: Cuenta CPE sin contrato vinculado en B03 — nombre sintético secuencial

Tipo: edge-case Condición de entrada: Cuenta en B39CTASCPE con campo B39-CONTRATO que no localiza match en B03CONTRATOS ya procesados (W77-NO-B03 ≠ 0) Resultado: Nombre generado como "NOMBRE DE PRUEBA " donde la secuencia arranca en 10000 y se incrementa de 12 en 12 por cada cuenta sin match; garantiza que el campo B39-NOMBRE no quede en blanco; la secuencia se reinicia en cada corrida (no persiste en checkpoint) Ancla: P655_SCRAMBLING.txt:634-644 (PERFORM 90000003-B03SXCTOW-FIND; IF W77-NO-B03 = 0 → copia B03-NOMBRE; ELSE ADD 12 TO W77-SEQ-NOMB + STRING "NOMBRE DE PRUEBA " W77-SEQ-NOMB INTO B39-NOMBRE) + :210 (77 W77-SEQ-NOMB PIC 9(06) VALUE 10000) Secuencia:

T-SEC-010 (B39-CONTRATO → 90000003-B03SXCTOW-FIND → W77-NO-B03 ≠ 0)
  → W77-SEQ-NOMB = W77-SEQ-NOMB + 12
  → B39-NOMBRE = "NOMBRE DE PRUEBA " + W77-SEQ-NOMB

Narrativa del flujo (Nivel 5)

Lectura en prosa del diagrama de secuencia anterior: explica paso a paso el enmascaramiento de PII con el vocabulario controlado del Digital Brain. Estado: Reconstruido.

El ciclo arranca cuando el WFL Scheduler lanza (INITIATE) el programa P655 (S500) —la subrutina de SCRAMBLING— con la intención de correrlo en un ambiente de prueba. P655 (S500) es el enmascarador de datos personales (PII) que anonimiza titulares, representantes legales y domicilios de las cuentas de captación de S500 antes de replicarlas a entornos no productivos.

Como primer acto, P655 (S500) clasifica el ambiente por hostname (T-SEC-001): lee ATTRIBUTE HOSTNAME OF MYSELF de Unisys MCP hacia WKS-MY-HOST y lo compara contra la lista cerrada de 7 nombres. Aquí se abre la decisión del diagrama: si el host es VDMALFA o MONBETA (productivos), activa W77-ES-PRODUCCION y ejecuta T-SEC-002, que marca STATUS = -1 y emite el mensaje "NO CORRE EN PRODUCCION; HOST: " —pero sin STOP RUN, por lo que el flujo continúa igualmente (fail-open documentado, 🟠 CRÍTICO CS-SEC-04). Si el host no está en ninguno de los 7 nombres (p. ej. VDMKAPPA tras failover), ni W77-ES-PRODUCCION ni W77-ES-PRUEBA se activan y T-SEC-002 no se dispara: el enmascaramiento corre sin control de ambiente (fail-open silencioso, 🔴 DEFECTO-PROD CS-SEC-02, RN-S500-036). Solo cuando el host es un ambiente de prueba válido no hay bloqueo alguno.

Resuelto el ambiente, P655 (S500) calcula el tamaño del bloque de intercambio (T-SEC-003): con ACCEPT TIME deriva W77-CONTA-01 como 1800 - HH - MM - SS (o 200 - HH - MM - SS para el host ACYPBETA), un valor que varía según la hora de arranque ([HARDCODE-SOSPECHOSO] RN-S500-029). Acto seguido ajusta la paridad par del bloque (T-SEC-004): si W77-CONTA-01 MOD 2 ≠ 0, resta 1 para garantizar intercambios simétricos entre pares de contratos.

Antes de enmascarar, el flujo consulta el checkpoint en disco S500/FILE/SCRBLING/{CSI}/{fecha} (T-SEC-005). Aquí se ramifica: si el checkpoint existe, P655 (S500) lee su encabezado y lo valida (T-SEC-006) —tipo, CSI, fecha y contador—; si todos los campos coinciden y el contador es > 0, restaura el bloque previo (W77-CONTA-01 ← WKS-I99-HEAD-BLQ) y avanza el cursor de S500B03CONTRATOS hasta el contrato N mediante 20000600-BUSCA-REINICIO, reanudando sin reprocesar (CS-SEC-03); si el encabezado no coincide, regenera el checkpoint desde cero con 20000300-GEN-ARCH. Si no existe checkpoint, lo crea nuevo con 20000300-GEN-ARCH y arranca desde el inicio.

Comienza entonces el ciclo de enmascaramiento de contratos (T-SEC-007): por cada bloque de W77-CONTA-01 contratos, P655 (S500) toma registros de S500B03CONTRATOS con LOCK NEXT hacia una tabla en memoria, intercambia los nombres por pares de índice (50002000-MODIF-NOMBRE, shuffling de B03-NOMBRE), escribe de vuelta los nombres ya enmascarados y actualiza el contador del checkpoint tras cada bloque.

Cuando el cursor llega al fin del archivo (W77-EOF-B03 = 1) y el último bloque tiene cantidad impar (T-SEC-008), entra el paso opcional 50002060-VAL-REGS: se calcula la posición central (W77-REG-MEDIO = W77-TOT-DIV + 1) y al contrato central se le asigna el nombre ya enmascarado del primer contrato leído en todo el archivo (W77-NOMBRE-PTE), mientras el resto del bloque mantiene el intercambio normal por índice (CS-SEC-05).

A continuación, P655 (S500) recorre el ciclo de grupos CPE sobre S500B37GRUPOCPE (T-SEC-009): por cada grupo hace LOCK NEXT, sustituye el representante legal B37-REPRES por "REPRESENTANTE LEGAL GRUPO {N}" y el domicilio B37-DOMICILIO por "DOMICILIO DEL GRUPO {N}" —ambos indexados por número de grupo— y escribe el registro enmascarado. (El nombre o razón social del grupo B37-NOMBRE y el número de cuenta NO se enmascaran.)

Finalmente corre el ciclo de cuentas CPE sobre S500B39CTASCPE (T-SEC-010): por cada cuenta hace LOCK NEXT y busca su B39-CONTRATO en S500B03CONTRATOS mediante 90000003-B03SXCTOW-FIND. Si encuentra el contrato vinculado (W77-NO-B03 = 0), copia a B39-NOMBRE el B03-NOMBRE ya enmascarado —preservando la consistencia con el contrato—; si no hay match (W77-NO-B03 ≠ 0), genera un nombre sintético "NOMBRE DE PRUEBA {seq}" con W77-SEQ-NOMB que arranca en 10000 y se incrementa de 12 en 12 (CS-SEC-06). Con todas las cuentas enmascaradas, P655 (S500) ejecuta el STOP RUN y devuelve el control al WFL Scheduler con el enmascaramiento completo.

Caminos alternativos: el enmascaramiento se ejecuta aun cuando el ambiente NO debería permitirlo, por el defecto fail-open documentado. Si el hostname no está entre los 7 reconocidos (CS-SEC-02, RN-S500-036), el programa trata el nodo como no productivo y anonimiza sin advertencia —incluso sobre datos reales—. Si el host es productivo (VDMALFA/MONBETA, CS-SEC-04), P655 (S500) marca STATUS = -1 y emite el mensaje de error, pero sin STOP RUN ni GOBACK: continúa abriendo B03/B37/B39 productivos y enmascara PII real; el único control efectivo es la disciplina operativa del WFL Scheduler. Como variante resiliente, si una corrida se interrumpió y el checkpoint S500/FILE/SCRBLING/{CSI}/{fecha} sigue válido (CS-SEC-03), la reanudación restaura el bloque (WKS-I99-HEAD-BLQ) y retoma desde el contrato N sin reprocesar los anteriores.

Capacidad adicional: 10.1.1 Access Control (merge)

BIAN: 10.1.1 · Access Control · incorporado en cap-sec.md por solapamiento técnico con T.3.5 Security

Sistemas: S500+S151 · Programas: P010 (LINEA) · P655 (SCRAMBLING) · Librería: SEGURIDAD (VALIDA_FACULTAD) / LIB-CONTROL (L010_CONTROL) · Mecanismos: FACULTAD / Q015 / HI 41/42

Contexto funcional

El modelo de control de acceso de Banamex S151 opera en el programa P010 (LINEA) como hub dispatcher online. Cada petición al sistema es interceptada por el paragraph 300010-CHECA-ENTIDAD, que evalúa el campo W77-FACULTAD para determinar el nivel de autorización de la sucursal operadora respecto al sistema consultado:

Valor FACULTADSemánticaResultado (CVE-RESOL)
1Acceso restringido a la propia sucursal de capturaCVE-RESOL=1 (sucursal propia, pantalla ≠ 17) · CVE-RESOL=3 + MSG=87 (otra sucursal o Panel 17)
2Cross-sucursal autorizadoCVE-RESOL=1 (siempre; toda pantalla incluida P17)
3Acceso denegado incondicionalmenteCVE-RESOL=3 + MSG=87 (error de seguridad)

El nivel de FACULTAD se recupera de cinco tablas en memoria (WKS-TAB-FAC ... WKS-TAB4-FAC) indexadas por (sucursal × sistema), con cobertura de hasta 5000 sucursales en rangos de 1000. El resultado se propaga al campo W77-CVE-RESOL y se archiva en la bitácora CNBV (WKS-BIT-CVE-RESULT).

Cada pantalla del hub tiene asignado un código de transacción Q015{NNN} hardcodeado que se valida contra el sistema externo SEGURIDAD mediante la llamada VALIDA_FACULTAD IN SEGURIDAD. El paragraph 420300-CALL-FACULTAD ejecuta esta llamada; sus códigos negativos (-9=suspendido, -11..-2=error de validación) se mapean a MSG=78. La validación puede habilitarse (HI 41 → W77-VALIDA-SEG=1) o deshabilitarse (HI 42 → W77-VALIDA-SEG=2) en tiempo de ejecución sin reinicio del proceso y sin registro en bitácora.

El programa P655 (SCRAMBLING), documentado en la sección principal de esta capacidad, comparte con el control de acceso el mecanismo de clasificación de ambiente por hostname (T-SEC-001 / RN-S500-027). El mismo defecto de fail-open ante host no reconocido que afecta al enmascaramiento PII afecta también al acceso sin control a las bases DMSII S500 — el hallazgo debe resolverse de forma unificada en la migración.

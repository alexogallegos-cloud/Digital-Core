P103 valida su versión, lee el registro de control de Captación para obtener el CSI y la fecha de lote, y abre el archivo S500/FILE/S711/FRAUDLINK con un header. Recorre S500B07MOVDIA y, salvo los movimientos con estatus 1, revisa la clave del movimiento principal, las de sus cinco movimientos adicionales y, si los hay, las diez claves adicionales de S500B13MOVCVES. Cada clave 2001, 2444 o 2496 produce un registro de detalle con sucursal, medio de acceso, fecha, clave, importe y referencia. Al final escribe un trailer con el número de registros y la suma de importes.

/** Archivo E03-CVES2001: registros de 60 posiciones, tipo 1 header, 2 detalle, 9 trailer. */
public sealed interface RegistroFraudlink permits Header, Detalle, Trailer {
    String aLinea();   // ancho fijo de 60
}

/** WKS-E03-HEADER: "1" + "S500" + "S711" + CSI + " " + fecha + 40 blancos. */
record Header(int csi, LocalDate fechaLote) implements RegistroFraudlink {
    public String aLinea() {
        return "1S500S711%02d %s%-40s".formatted(csi, fechaLote.format(BASIC_ISO_DATE), "");
    }
}

/** WKS-REG-E03-CVES. */
record Detalle(int banco,                 // 9(04): siempre 0002 en el fuente
               int sucursalOperacion,     // 9(04): primeros 4 dígitos de B07-AUTORIZACION
               String medioAcceso,        // 9(16): campo WKS-REG-E03-CHQRA (nombre legado)
               int clave, LocalDate fecha,
               BigDecimal importe,        // 9(11)V99 -> escala 2, sin signo
               long referencia) implements RegistroFraudlink {
    public String aLinea() {
        return "2%04d%04d%16s%04d%s%013d%010d".formatted(banco, sucursalOperacion, medioAcceso,
                clave, fecha.format(BASIC_ISO_DATE), Fixed.sinPunto(importe, 11, 2), referencia);
    }
}

/** WKS-E03-TRAILER: "9" + registros 9(08) + importe 9(12)V99 + 37 blancos. */
record Trailer(long registros, BigDecimal importeTotal) implements RegistroFraudlink {
    public String aLinea() {
        return "9%08d%014d%-37s".formatted(registros, Fixed.sinPunto(importeTotal, 12, 2), "");
    }
}

/** RD-WKS-AUTORIZ-MOV: 14 dígitos = sucursal(4) + caja(2) + secuencia(8). */
record Autorizacion(long valor) {
    int sucursal()  { return (int) (valor / 10_000_000_000L); }
    int caja()      { return (int) (valor / 100_000_000L % 100); }
    long secuencia() { return valor % 100_000_000L; }
}

FlatFileItemWriter<RegistroFraudlink> archivoFraudlink(ControlCaptacionRepository control,
                                                       FraudlinkProperties props,
                                                       CifrasControl cifras) {
    ControlCaptacion b02 = control.find()
            .orElseThrow(() -> new ProcesoAbortadoException("ERR FIND B02CONTROL"));   // CALL SYSTEM DMTERMINATE
    var header = new Header(b02.numCsi(), b02.fechaLote());       // fecha de LOTE, no de línea
    String titulo = props.titulo(b02.numCsi(), b02.fechaLote());  // S500/FILE/S711/FRAUDLINK/{csi}/{aaaammdd}.

    return new FlatFileItemWriterBuilder<RegistroFraudlink>()
            .name("e03Cves2001")
            .resource(new FileSystemResource(titulo))
            .lineAggregator(RegistroFraudlink::aLinea)
            .headerCallback(w -> w.write(header.aLinea()))                    // 20000600-GEN-HEADER
            .footerCallback(w -> w.write(new Trailer(cifras.registros(),
                                                     cifras.importe()).aLinea()))   // 20000700-GEN-TRAILER
            .build();
}

/** 50001000-PROCESO. */
public List<RegistroFraudlink> process(MovimientoDia m) {
    if (m.statusMovto() == 1) return null;                       // NEXT SENTENCE: no se reporta
    var aut = new Autorizacion(m.autorizacion());
    var r = new ArrayList<RegistroFraudlink>();
    movimientoOriginal(m, aut).ifPresent(r::add);                // 50001100-MOV-ORIG
    r.addAll(otrosMovimientos(m, aut));                          // 50001200-OPERO5-B07 5 TIMES
    if (m.indMovsAds() > 0) r.addAll(clavesAdicionales(m, aut)); // 50001300-MOVS-B13
    return r;
}

    private static final Set<Integer> CLAVES_FRAUDE = Set.of(2001, 2444, 2496);   // p103.claves-monitoreadas

    /** 50001100-MOV-ORIG. */
    private Optional<RegistroFraudlink> movimientoOriginal(MovimientoDia m, Autorizacion aut) {
        if (!CLAVES_FRAUDE.contains(m.claveMovto())) return Optional.empty();
        return Optional.of(new Detalle(props.banco(), aut.sucursal(), m.medioAcceso(),
                m.claveMovto(), fechaLote,
                Fixed.trunca(m.importe(), 11, 2),      // MOVE a 9(11)V99: pierde dígitos altos, sin signo
                m.referenciaNumerica()));
    }
    /** 50001200-OPERO5-B07, ejecutado 5 TIMES con W77-IND-B07 de 1 a 5. */
    private List<RegistroFraudlink> otrosMovimientos(MovimientoDia m, Autorizacion aut) {
        return IntStream.rangeClosed(1, 5)
                .mapToObj(m::otroMovimiento)                         // B07-OTROS-MOVSAD(i)
                .filter(ad -> CLAVES_FRAUDE.contains(ad.clave()))
                .<RegistroFraudlink>map(ad -> new Detalle(props.banco(), aut.sucursal(),
                        m.medioAcceso(), ad.clave(), fechaLote,
                        Fixed.trunca(ad.importe(), 11, 2), ad.referencia()))
                .toList();
    }
    /** 50001300-MOVS-B13 y 50001350-BUSCA-B13 (10 TIMES). */
    private List<RegistroFraudlink> clavesAdicionales(MovimientoDia m, Autorizacion aut) {
        Optional<MovimientoClaves> b13;
        try {
            b13 = b13Repo.findByContratoAndAutorizacion(m.contrato(), m.autorizacion());   // B13SXCTOAUT
        } catch (DataAccessException e) {
            throw new ProcesoAbortadoException("ERR FIND A B13 CTO=%s AUT=%d"
                    .formatted(m.contrato(), m.autorizacion()), e);                       // DMTERMINATE
        }
        return b13.map(reg -> IntStream.rangeClosed(1, 10)
                        .mapToObj(reg::clave)                                              // B13-CLAVES-TRANS(i)
                        .filter(c -> CLAVES_FRAUDE.contains(c.clave()))
                        .<RegistroFraudlink>map(c -> new Detalle(props.banco(), aut.sucursal(),
                                m.medioAcceso(), c.clave(), fechaLote,
                                Fixed.trunca(c.importe(), 11, 2), c.referencia()))
                        .toList())
                  .orElse(List.of());                                                      // W77-SIN-B13 = 1
    }

/** 50002000-ESC-ARCHIVO: contador y suma que alimentan el trailer. */
@Component
@StepScope
public class CifrasControl implements ItemWriteListener<List<RegistroFraudlink>> {

    private static final BigDecimal TOPE_9_12_V99 = new BigDecimal("999999999999.99");
    private long registros;                                       // WKS-NUM-REG 9(08)
    private BigDecimal importe = BigDecimal.ZERO.setScale(2);     // WKS-IMP-TOT 9(12)V99

    @Override
    public void afterWrite(Chunk<? extends List<RegistroFraudlink>> items) {
        items.getItems().stream().flatMap(List::stream)
             .map(Detalle.class::cast)
             .forEach(d -> {
                 registros++;
                 importe = importe.add(d.importe());              // suma exacta de escala 2
                 if (importe.compareTo(TOPE_9_12_V99) > 0) {
                     throw new DesbordamientoAcumuladorException(importe);   // COBOL truncaría en silencio
                 }
             });
    }

    public long registros() { return registros; }
    public BigDecimal importe() { return importe; }
}

RN-S500-001Antes de generar el reporte diario hacia FraudLink, el programa valida que la versión que se está ejecutando coincida con la registrada en el catálogo central de versiones del banco (librería S100VERSIONES); si no coincide, aborta la tarea y el archivo de salida hacia FraudLink nunca llega a abrirse — no se genera ningún reporte ese día. Técnicamente: la validación ocurre en el paragraph 10000100-TIT-LIBS (PERFORM 10000100-VERSIONES → 20000100-CHECAME-VERSION); IF S000-CTR-CVEERROR < 0 se emite el mensaje "ERROR DE VERSION" y se cancela con CHANGE ATTRIBUTE STATUS OF MYSELF TO -1 (mecanismo de cancelación distinto al CALL SYSTEM DMTERMINATE usado en el resto del programa).Rutina principal y validación de versión
RN-S500-002Si el registro maestro de control de captación (S500B02CONTROL) no puede leerse correctamente, el proceso cancela antes de abrir el archivo de salida y no se genera el reporte hacia FraudLink/CNBV (S711) ese día. Técnicamente: en 20000100-ABRE-BASE, tras PERFORM 90000002-B02CONTROL-FIND sobre S500B02CONTROL (base de captación S500BD01CAPTACION), IF WS-STATUS-BASE > 0 el proceso cancela vía CALL SYSTEM DMTERMINATE antes de abrir el archivo E03-CVES2001. Ese mismo registro de control aporta B02-NUM-CSI (nodo/instancia) y B02-FECHA-LOTE (fecha de proceso batch, no la fecha de línea), usados como cabecera del archivo.Apertura de la base, fecha de lote y header; escritura del trailer
RN-S500-003El programa recorre secuencialmente todos los movimientos del día para evaluarlos como posible reporte a FraudLink; al llegar al final del archivo termina el ciclo de forma normal, pero cualquier otro error de lectura aborta el proceso completo. Técnicamente: en el ciclo principal (50001000-PROCESO), tras cada PERFORM 90000007-B07MOVDIA-FINDN (lectura secuencial de S500B07MOVDIA), IF WS-STATUS-BASE > 0: valor 1 marca W77-EOF-B07 = 1 (fin de archivo, término normal del ciclo UNTIL); cualquier otro valor distinto de cero cancela el proceso vía CALL SYSTEM DMTERMINATE.Ciclo sobre B07MOVDIA: fin de datos, error y movimientos excluidos
RN-S500-004Ciertos movimientos se excluyen del análisis de fraude antes de evaluar su código de transacción: si el estado del movimiento (B07-STATUS-MOVTO) es igual a 1, se descarta sin generar ningún registro; cualquier otro valor continúa hacia la evaluación de código de transacción (MOV-ORIG, OPERO5-B07, MOVS-B13). Nota de verificación: el catálogo DASDL solo documenta B07-STATUS-MOVTO como "Estado del movimiento en curso", sin enumerar sus valores posibles — no hay confirmación en las fuentes revisadas de que el valor 1 signifique específicamente cancelación o anulación; esa interpretación queda como hipótesis razonable de convención bancaria, no como hecho verificado.Ciclo sobre B07MOVDIA: fin de datos, error y movimientos excluidos
RN-S500-005Los movimientos con código de transacción 2001, 2444 o 2496 — las claves que el banco monitorea para prevención de fraude — se reportan a FraudLink/CNBV (S711) con sucursal, medio de acceso, fecha, código e importe. Técnicamente (50001100-MOV-ORIG, IF B07-CLAVE-MOVTO = 2001 OR 2444 OR 2496): el registro incluye WKS-SUC-OPE (sucursal, primeros 4 dígitos de B07-AUTORIZACION vía REDEFINES RD-WKS-AUTORIZ-MOV — los otros 2+8 dígitos, caja y secuencia, se descomponen pero no se usan en este registro), B07-MED-ACCESO (medio de acceso; catálogo B07-TIPO-MEDACCES: 0=Contrato,1=Chequera,2=Tarjeta,3=PIN, aunque el campo destino conserva el nombre legado WKS-REG-E03-CHQRA), B02-FECHA-LOTE (fecha de proceso batch), B07-CLAVE-MOVTO (código de transacción) y B07-IMPORTE más B07-REFER-NUME (referencia). WKS-SUC-OPE se calcula una sola vez por movimiento padre (línea 232) y se reutiliza en los registros de sus sub-movimientos B07 y B13.Registros de 60 bytes del archivo FRAUDLINK y desglose de la autorización · Movimiento principal con clave monitoreada
RN-S500-006El monitoreo de fraude no se limita al movimiento principal: cada movimiento puede traer hasta 5 sub-movimientos asociados (grupo "Otros Movimientos SAD"), y cada uno de ellos con código 2001, 2444 o 2496 genera también su propio registro independiente en el archivo FraudLink. Técnicamente (50001200-OPERO5-B07, PERFORM ... 5 TIMES desde 50001000-PROCESO): IF B07-CVE-MOVAD (W77-IND-B07) = 2001 OR 2444 OR 2496, cada sub-movimiento del grupo B07-OTROS-MOVSAD (×5) genera su registro con el mismo WKS-SUC-OPE del movimiento padre pero su propio código/importe/referencia (B07-CVE-MOVAD, B07-IMP-MOVAD, B07-REF-MOVAD indexados por W77-IND-B07).Cinco movimientos adicionales del mismo registro B07
RN-S500-007El reporte a FraudLink alcanza también un tercer nivel de detalle: cuando el movimiento indica que existen claves de transacción adicionales asociadas al contrato, el programa las revisa una por una (hasta 10) y genera un registro FraudLink adicional por cada una que tenga un código de fraude monitoreado. Técnicamente: si B07-IND-MOVSADS > 0, se ejecuta 50001300-MOVS-B13, que localiza S500B13MOVCVES por B07-NUM-CONTRATO (FK) + B07-AUTORIZACION; si existe (W77-SIN-B13 = 0), recorre hasta 10 veces (50001350-BUSCA-B13) el grupo B13-CLAVES-TRANS×10 de ese contrato/autorización. RN-S500-008Cada vez que se escribe un registro en el archivo FraudLink, el programa acumula un conteo de registros y una suma de importes reportados; al cerrar el archivo, ambos totales se escriben como registro de cierre (trailer), permitiendo que FraudLink/CNBV valide que recibió el archivo completo, sin registros perdidos ni duplicados. Técnicamente, la operación se implementa como una pareja de ADD, no como una sentencia COMPUTE (paragraph 50002000-ESC-ARCHIVO, ejecutado por cada registro escrito). Fórmula: WKS-NUM-REG = WKS-NUM-REG + 1 (ADD 1 TO WKS-NUM-REG; contador PIC 9(08), inicia en 0) y WKS-IMP-TOT = WKS-IMP-TOT + WKS-REG-E03-IMPORTE (ADD WKS-REG-E03-IMPORTE TO WKS-IMP-TOT; acumulador PIC 9(12)V99, inicia en 0). Al cerrar (80000000-TERMINA → 20000700-GEN-TRAILER) se escribe el registro tipo "9" WKS-E03-TRAILER con WKS-NUM-REG y WKS-IMP-TOT como total de cierre del archivo. Nota técnica: WKS-REG-E03-IMPORTE es PIC 9(11)V99 (11 enteros) mientras B07-IMPORTE/B13-IMPORTE de origen son NUMBER 14,2 en el DASDL — un importe individual con más de 11 dígitos enteros se truncaría al mover al registro de detalle (riesgo estructural de bajo impacto práctico, no observado como incidente real).Registros de 60 bytes del archivo FRAUDLINK y desglose de la autorización · Apertura de la base, fecha de lote y header; escritura del trailer · Cifras de control por registro escrito y cierre
Riesgos de migración
Truncamiento del importe

WKS-REG-E03-IMPORTE es PIC 9(11)V99 (línea 101) y recibe importes de B07 y B13 con un MOVE sin control de tamaño (líneas 247, 260 y 294). Los dígitos altos se pierden en el detalle y en el total.

Importes sin signo

Ni el detalle ni el total tienen signo; si B07 o B13 trajeran importes negativos, se reportarían como positivos.

Exclusión por estatus no documentada

Los movimientos con B07-STATUS-MOVTO = 1 se omiten (línea 229) sin que el fuente explique qué significa ese estatus.

B13 ausente sin aviso

Si el indicador B07-IND-MOVSADS es mayor que cero y B13 no tiene registro, las claves adicionales no se revisan y no queda rastro (líneas 270-283).

Hardcodes

El banco 0002, las claves 2001, 2444 y 2496, los identificadores S500 y S711 del header y la ruta S500/FILE/S711/FRAUDLINK están compilados. Se trasladan a application.yml.

Desbordamiento silencioso del total

WKS-IMP-TOT es PIC 9(12)V99 sin ON SIZE ERROR (línea 301). La versión Java falla de forma explícita.

Pendiente de revisión SME
  • Confirmar el significado de B07-STATUS-MOVTO = 1; el catálogo DASDL solo lo describe como estado del movimiento.
  • Confirmar si INVALID KEY en el WRITE de un archivo secuencial de disco se activa en MCP; de no hacerlo, los errores de escritura no se detectan.
  • Confirmar si el medio de acceso (B07-MED-ACCESO) debe viajar en la posición WKS-REG-E03-CHQRA, cuyo nombre sugiere número de chequera, y cómo lo interpreta S711.
  • La lectura de B02CONTROL y B07MOVDIA está en el copybook S500/INC/PRO/25MTP002, que no viene en el fuente; se supuso que el estatus 1 significa fin de datos o registro inexistente, como indica su uso en el programa.

S151 · P680 a Java 21 Spring Boot

El comentario de cabecera dice que P680 genera archivos a partir de la base de control, pero el código hace lo contrario: abre en entrada seis archivos S151/FILE/Bnn.../aammdd y, por cada registro, bloquea el registro de la base del mismo sistema o lo crea si no existe, copia los campos y lo guarda. Todo corre dentro de una sola transacción NO-AUDIT sobre S151B99REINICTL que se cierra al final. El CSI de B01 se fuerza a cero y los errores de DMSII solo se informan en consola, sin detener la carga.

@ConfigurationProperties("p680")
public record P680Properties(String pack, Map<String, String> archivos) {

    /** WKS-PARAM-FECHA 9(08) se mueve a WKS-FEC-Bnn 9(06): el nombre lleva AAMMDD sin siglo. */
    public String titulo(String dataset, LocalDate fecha) {
        return archivos.get(dataset).replace("{aammdd}", fecha.format(DateTimeFormatter.ofPattern("yyMMdd")))
               + " ON " + pack + ".";
    }

@Configuration
@EnableConfigurationProperties(P680Properties.class)
public class RestauracionControlJobConfig {

    /** 00-0000-CONTROL. El orden se conserva: B01, B02, B03, B04, B05 y B09. */
    @Bean
    Job restauraControlS151(JobRepository repo,
                            Step restauraB01, Step restauraB02, Step restauraB03,
                            Step restauraB04, Step restauraB05, Step restauraB09) {
        return new JobBuilder("S151P680", repo)
                .start(restauraB01)
                .next(restauraB02)
                .next(restauraB03)
                .next(restauraB04)
                .next(restauraB05)
                .next(restauraB09)
                .build();
    }

    /** Plantilla de cada step: lector del archivo de respaldo y escritor JPA que hace alta o cambio. */
    @Bean
    Step restauraB01(JobRepository repo, PlatformTransactionManager tx,
                     FlatFileItemReader<RespaldoSistemaDia> lectorB01, RestauraSistemaDiaWriter writer) {
        return new StepBuilder("restauraB01", repo)
                .<RespaldoSistemaDia, RespaldoSistemaDia>chunk(500, tx)
                .reader(lectorB01)
                .writer(writer)
                .build();
    }
}
@Component
@RequiredArgsConstructor
class ContextoRestauracion implements JobExecutionListener {

    private final SoporteComs coms;        // CSIID OF SOPORTECOMS
    private final P680Properties props;

    @Override
    public void beforeJob(JobExecution je) {
        int csiReal = coms.csiId().numero();
        // El fuente obtiene el CSI y en la línea siguiente lo sustituye por cero.
        je.getExecutionContext().putInt("csi", 0);
        log.info("CSI de ejecución {} ignorado; B01 se restaura con CSI 0", csiReal);
    }
}

// BEGIN-TRANSACTION NO-AUDIT ... END-TRANSACTION AUDIT abarcan las seis cargas.
// En Java cada chunk confirma su propia transacción; para conservar el "todo o nada" del fuente
// la alternativa es cargar en tablas de staging y publicar con un último step transaccional:
@Bean
Step publicaRestauracion(JobRepository repo, PlatformTransactionManager tx, PublicadorControl publicador) {
    return new StepBuilder("publicaRestauracion", repo)
            .tasklet((c, ctx) -> { publicador.reemplazaDesdeStaging(); return RepeatStatus.FINISHED; }, tx)
            .build();
}

@Component
@StepScope
@RequiredArgsConstructor
class RestauraSistemaDiaWriter implements ItemWriter<RespaldoSistemaDia> {

    private final SistemaDiaRepository b01;
    @Value("#{jobExecutionContext['csi']}") private int csi;     // siempre 0

    /** 02-00104-GRABA-B01SISDIA. */
    @Override
    public void write(Chunk<? extends RespaldoSistemaDia> chunk) {
        for (var r : chunk) {
            SistemaDia d = b01.findForUpdate(r.sistema(), csi)          // LOCK B01SXSISDIA
                    .orElseGet(() -> SistemaDia.nuevo(r.sistema(), csi)); // NOTFOUND: CREATE
            d.setFechas(r.fechaProceso(), r.fechaConsulta(), r.fechaProceso151());
            d.setStatusRegistro(r.statusRegistro());
            d.setArchivos(r.saldos(), r.movimientos(), r.desglose(), r.errores());   // nombres y packs
            d.setBaseSemanal(r.baseSemanal());
            d.setStatusBaseSemanal(r.statusBaseSemanal());   // el fuente NO restaura este campo
            d.setNumArchivo(r.numArchivo());
            d.setTercerNivel(r.tercerNivel());
            d.setCalendario(r.calendario());                // 02-00130-FECHAS, 10 ocurrencias
            b01.save(d);                                    // STORE
        }
    }
}
@Component
@RequiredArgsConstructor
class RestauraBaseMensualWriter implements ItemWriter<RespaldoBaseMensual> {

    private final BaseMensualRepository b03;

    @Override
    public void write(Chunk<? extends RespaldoBaseMensual> chunk) {
        for (var r : chunk) {
            BaseMensual b = b03.findForUpdate(r.sistema()).orElseGet(() -> BaseMensual.nueva(r.sistema()));
            // ... modalidad, CSI responsable, tipo de base, ciclos, base de saldos ...
            b.setSecuenciasHistoricas(r.secOkHi(), r.secInfHi(),
                                      r.secErrHi());   // el fuente pone SECERRHI en SECINFHI (línea 537)
            int ciclos = Math.min(5, r.numCiclosDia());   // UNTIL W77-IND > 5 OR > B03-SIS-NUMCICDIA
            for (int i = 0; i < ciclos; i++) {
                var c = r.ciclos().get(i);
                b.setCiclo(i, c.nombreBase(),
                           c.numeroBase(),               // el fuente mueve el NOMBRE a NUMBDMOV (línea 558)
                           c.aamm(), c.secOk(), c.secInf(), c.secErr(), c.statusBase());
            }
            b03.save(b);
        }
    }
}

Riesgos de migración
Función contraria a la documentada

La cabecera (líneas 5-8) y el inventario describen P680 como generador de archivos de respaldo; el código abre los archivos en entrada y escribe en S151BD99CONTROL. Es un programa de restauración.

Restauración que colapsa registros

B05, B04 y B09 se bloquean solo por sistema (líneas 608, 577 y 652). Si el respaldo contiene varios registros del mismo sistema, cada uno sobrescribe al anterior y solo queda el último.

Asignaciones incorrectas en B03

La línea 537 mueve SECERRHI a SECINFHI y la línea 558 mueve el nombre de la base al número de base. El campo STABDSEM de B01 no se restaura (líneas 430-442).

Carga parcial confirmada

Los errores de DMSII solo se despliegan (900000-CHE-STA) y la transacción única se confirma al final (línea 401), dejando la base de control en un estado mixto entre el respaldo y lo que había.

CSI forzado a cero

El CSI de ejecución se obtiene y se reemplaza por cero (líneas 384-385); B01 siempre se restaura con CSI 0, coherente con L001.

Valores fijos

Rutas de los seis archivos, el pack CMEMP, el título de LIBLJ y la función SOPORTECOMS están compilados. Se trasladan a application.yml.

Pendiente de revisión SME
  • Corregir la descripción del inventario y del brain: P680 restaura S151BD99CONTROL desde archivos, no genera respaldos. Confirmar con SME qué programa genera los archivos S151/FILE/Bnn/aammdd que P680 consume.
  • Confirmar si los sets B04SXNOMSIS, B05SXPROCESO y B09SXCONXSIS tienen como llave única solo el sistema; de no ser así, la restauración pierde registros.
  • Confirmar si limitar los ciclos de B03 con B03-SIS-NUMCICDIA (línea 544) en lugar de NUMCICMES es intencional.
  • Confirmar con SME si una restauración con errores parciales es aceptable o si debe fallar completa, antes de decidir la tolerancia a fallos del job.

S500 · P060 a Java 21 Spring Boot

Al arrancar arma el título de su TASKFILE con la fecha y el número de mix, se liga a las librerías de versiones y de saldos, y determina por el nombre del equipo si corre en Monterrey o en Valle de México. Con eso obtiene los designadores de dos servicios, S500_Con_Cto_M o S500_Con_Cto_V y S500_SdoParNac, y el del tipo de buffer X_OCTET. Después espera eventos de COMS en ciclos de 60 segundos; cuando llega un mensaje lo recibe con TP_SvcStart, valida servicio y tipo de buffer, invoca la librería S500L020 para consultar el contrato o el saldo y responde con TP_Return un buffer de 2000 bytes. Termina cuando TransIT devuelve el código 14.

@ConfigurationProperties("p060")

    public enum Plaza { M, V }
    public record Servicios(String consultaContrato, String saldoNacion) {}

    public String nombreConsultaContrato() {
        return servicios.consultaContrato().replace("{plaza}", plaza.name());
    }
}

}
/** Los dos servicios quedan expuestos por un gateway de entrada con enrutamiento por nombre. */
@Bean
IntegrationFlow consultasS500(P060Properties p, ConnectionFactory mensajes) {
    return IntegrationFlow
            .from(Jms.inboundGateway(mensajes)
                     .destination("s500.consultas")
                     .requestTimeout(60_000))                           // WS-ESPERACOMS-TIEMPO
            .transform(Message.class, this::comoBytes)                  // X_OCTET: bytes sin tipado
            .route(Message.class, m -> m.getHeaders().get("servicio", String.class),
                   r -> r.subFlowMapping(p.nombreConsultaContrato(), sf -> sf.handle(consultaContrato))
                         .subFlowMapping(p.servicios().saldoNacion(),  sf -> sf.handle(saldoNacion))
                         .defaultOutputToParentFlow())
            .get();
}

/** MAIN: alta de declarativas, librerías y servicios; luego PROCESO UNTIL WS88-EOJ. */
@Component
@RequiredArgsConstructor
public class ServidorConsultasLifecycle implements SmartLifecycle {

    private final DefaultMessageListenerContainer contenedor;  // reemplaza el ciclo ESPERACOMS
    private volatile boolean activo;

    @Override public void start() { contenedor.start(); activo = true; }   // 00000000-ALTA-TOLTP

    /** WS-EOJ = 1: el contenedor deja de tomar mensajes y espera a que termine el que está en curso. */
    @Override public void stop()  { contenedor.stop(); activo = false; }

    @Override public boolean isRunning() { return activo; }
}
@Bean
DefaultMessageListenerContainer contenedor(ConnectionFactory cf) {
    var c = new DefaultMessageListenerContainer();
    c.setConnectionFactory(cf);
    c.setDestinationName("s500.consultas");
    c.setReceiveTimeout(60_000);        // ESPERACOMS con WS-ESPERACOMS-TIEMPO = 60
    c.setConcurrentConsumers(1);        // P060 atiende un mensaje a la vez
    return c;
}
// Eventos 2 (ACCEPT de consola), 3 (HI) y 4 (timeout) solo reinician la espera;
// el HI con TASKVALUE 1 se expone como endpoint de Actuator con las banderas del mensaje en curso.
/** 00000000-VE-SIHAY-SERV: recibe el mensaje con un tope de 2000 bytes (TPTRUNC). */
byte[] recibe(Message<byte[]> m) {
    byte[] cuerpo = m.getPayload();
    if (cuerpo.length > props.longitudRespuesta()) {
        // El fuente activa TPTRUNC e ignora el error 127: procesa el mensaje truncado.
        log.warn("Mensaje de {} bytes truncado a {}", cuerpo.length, props.longitudRespuesta());
        metricas.counter("p060.mensajes.truncados").increment();
        cuerpo = Arrays.copyOf(cuerpo, props.longitudRespuesta());
    }
    return cuerpo;
}

/** 00000000-VALIDA-SERV. WS-CVE-ERROR-VA: 1 buffer inválido, 2 designador inválido. */
public enum ErrorValidacion { NINGUNO, BUFFER_INVALIDO, SERVICIO_INVALIDO }

ErrorValidacion valida(Message<?> m) {
    String servicio = m.getHeaders().get("servicio", String.class);
    if (!serviciosRegistrados.contains(servicio)) {
        return ErrorValidacion.SERVICIO_INVALIDO;           // RCODE = WS-TOLTP-SERV-DESC
    }
    if (!(m.getPayload() instanceof byte[])) {
        return ErrorValidacion.BUFFER_INVALIDO;             // RCODE = WS-TOLTP-BUFFER-INVAL
    }
    return ErrorValidacion.NINGUNO;
}

/** 00000000-PROCESA-TRAN: con error no se consulta, pero siempre se responde. */
RespuestaS500 procesa(Message<byte[]> m) {
    ErrorValidacion e = valida(m);
    return (e == ErrorValidacion.NINGUNO) ? despacha(m) : RespuestaS500.error(e);
}
/** 00000000-PROCESA-SERV: ambos servicios reciben el mismo layout de entrada (WS-S500L020-0101-CTO). */
RespuestaS500 despacha(Message<byte[]> m) {
    String servicio = m.getHeaders().get("servicio", String.class);
    PeticionContrato pet = PeticionContrato.desde(m.getPayload());

    ResultadoL020 r = servicio.equals(props.nombreConsultaContrato())
            ? librerias.consultaContrato(pet)       // 20000500-S500L020CONTRATO
            : librerias.saldoParaNacion(pet);       // 20000500-S500L020SDOPARNAC
    return RespuestaS500.ok(r.resultado(), r.salida());   // BUF-RESULT + BUF-INFO
}

/** S500L020 se expone como servicio reusable (arquetipo L), no como librería ligada en tiempo de ejecución. */
public interface ConsultasS500L020 {
    ResultadoL020 consultaContrato(PeticionContrato p);
    ResultadoL020 saldoParaNacion(PeticionContrato p);
}
/** 00000000-ENVIA-MSG: la respuesta siempre mide 2000 bytes. */
public record RespuestaS500(int rcode, int resultado, byte[] info) {

    static final int LONGITUD = 2000;          // WS-TOLTP-LEN

    public byte[] aBytes() {
        ByteBuffer b = ByteBuffer.allocate(LONGITUD);
        b.put(Layout.resultado(resultado));    // WS-TOLTP-BUF-RESULT
        b.put(info, 0, Math.min(info.length, b.remaining()));
        return b.array();                      // relleno con ceros hasta 2000
    }
}

@ServiceActivator(inputChannel = "respuestas")
byte[] responde(RespuestaS500 r) {
    try {
        return r.aBytes();
    } catch (RuntimeException e) {
        log.error("TP_Return: {}", e.getMessage());   // el fuente solo despliega y sigue
        throw e;
    }
}

Riesgos de migración
Truncamiento silencioso de mensajes

El programa activa TPTRUNC con longitud 2000 e ignora el error XATMI 127 (línea 294). Un mensaje más largo se procesa truncado sin dejar rastro.

Plaza deducida del nombre del equipo

Con un hostname no reconocido, P060 asume Valle de México y registra S500_Con_Cto_V (líneas 166-173). Un equipo nuevo en Monterrey atendería con el sufijo equivocado.

Servicio sin sufijo geográfico

S500_SdoParNac se registra con el mismo nombre en ambas plazas (línea 205).

Cierre de recursos fuera de este fuente

Con el código 14 el programa sale del ciclo y ejecuta STOP RUN; no hay llamada visible a TP_Term ni estadísticas finales en este archivo. Si existen, están en el copybook S500/INC/PRO/25MTP002.

Pendiente de revisión SME
  • RN-S500-243 menciona un contador de timeouts y RN-S500-246 menciona TP_Term y estadísticas finales; ninguno aparece en P060. Confirmar si viven en el copybook S500/INC/PRO/25MTP002 o si la redacción de las reglas debe ajustarse.
  • RN-S500-245 dice que el error de buffer se registra en la librería DISP; el fuente solo devuelve el código al cliente (líneas 323-324).
  • Confirmar si el layout de entrada de S500L020SDOPARNAC es el mismo que el de S500L020CONTRATO.
  • El transporte destino (JMS, Kafka o HTTP) depende de cómo se migren los clientes actuales de TransIT; el ejemplo usa JMS solo como referencia.

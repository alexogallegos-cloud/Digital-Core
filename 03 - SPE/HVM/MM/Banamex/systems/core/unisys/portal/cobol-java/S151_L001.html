L001 abre S151BD99CONTROL en modo de actualización al cargarse y exporta once procedimientos. Cada uno recibe un solo arreglo EBCDIC que es a la vez entrada y salida, lo interpreta con macros DEFINE posicionales, despacha por el código de función de las dos primeras posiciones y regresa un entero de resultado. Mantiene la ocurrencia diaria por sistema (B01) con sus fechas de proceso y el calendario de diez días hábiles de archivos, el catálogo de sistemas (B04), las bases mensuales (B03), los nombres de archivos intermedios (B02), la bitácora de procesos con su Mix ID (B05) y las conexiones por sistema (B09). Todo acceso reintenta una vez ante DEADLOCK y toda escritura abre una transacción NOAUDIT o se suma a la del llamador.

@Component
@RequiredArgsConstructor
class SistemaDiaFinder {

    private final SistemaDiaRepository b01;
    private final MensajeriaConsola consola;

    /** BUSCASISDIA: hasta dos intentos; el segundo DEADLOCK devuelve BLOQUEO_AGOTADO (14). */
    @Retryable(retryFor = PessimisticLockingFailureException.class, maxAttempts = 2,
               backoff = @Backoff(delay = 0))
    @Transactional(readOnly = true)
    public Optional<SistemaDia> busca(String sistema, int csi) {
        return b01.findBySistemaAndCsi(sistema, csi);          // B01SXSISDIA
    }

    @Recover
    Optional<SistemaDia> agotado(PessimisticLockingFailureException e, String sistema, int csi) {
        throw new ControlException(ResultadoControl.BLOQUEO_AGOTADO, e);
    }

    ResultadoControl resultado(Optional<SistemaDia> r, String sistema, int csi) {
        if (r.isEmpty()) {
            consola.despliega("NO EXISTE SISTEMA %04d PARA CSI %02d".formatted(Integer.parseInt(sistema), csi));
            return ResultadoControl.NO_EXISTE;
        }
        return ResultadoControl.OK;
    }
}
@Component
@RequiredArgsConstructor
class EscrituraControl {

    private final SistemaDiaRepository b01;

    /**
     * STORE_B01(ACCION). BEGINTRANSACTION con AUDITERROR tipo 1 significa que el llamador ya
     * tiene una transacción abierta: se escribe dentro de ella y no se cierra.
     * Propagation.REQUIRED reproduce exactamente eso.
     */
    @Transactional(propagation = Propagation.REQUIRED)
    public ResultadoControl guarda(SistemaDia registro, Accion accion) {
        try {
            if (accion == Accion.STORE) b01.save(registro); else b01.delete(registro);
            return ResultadoControl.OK;
        } catch (DataAccessException e) {
            // En la transacción propia el fuente ejecuta ERRORDB (RESULT := 9).
            // En la del llamador el ERRORDB está comentado: el error se pierde y RESULT queda en 0.
            log.error("L001/CONTROL, ERROR EN DMSII ESTRUCTURA S151B01SISDIA", e);
            throw new ControlException(ResultadoControl.NOMBRE_BASE_VACIO, e);   // 9: no se oculta
        }
    }

    enum Accion { STORE, DELETE }
}

class AltaSistemaDia {

    private static final int DIAS_CALENDARIO = 10;      // B01-SIS-FECARCMOV[1..10]
    private final SistemaDiaFinder finder;
    private final EscrituraControl escritura;
    private final CalendarioBancario cal;

    /** ALTA_SISDIA (función 19). */
    @Transactional
    public ResultadoControl alta(SistemaDiaDto d) {
        if (finder.bloquea(d.sistema(), d.csi()).isPresent()) {
            return ResultadoControl.YA_EXISTE;                    // RESULT := 3
        }
        LocalDate fecha = d.fechaProceso();
        if (!cal.esDiaHabil(fecha)) {
            return ResultadoControl.ERROR_CALENDARIO;             // RESULT := 4
        }
        int numDia = cal.diaSemana(fecha).getValue();             // función 6; ver pendiente sobre la numeración
        if (numDia < 1 || numDia > 5) {
            throw new IllegalStateException("Día hábil fuera de lunes a viernes: " + fecha);  // el fuente haría STORE sin CREATE
        }
        var reg = SistemaDia.nuevo(d, fecha, numDia);              // CREATE + PUT, STAREG = 0, NUMARC = NUMDIA
        reg.fijaDiaArchivo(numDia, fecha);

        // Avanza día por día y ocupa la siguiente posición con cada día de lunes a viernes,
        // sin volver a consultar la función 18: los feriados entre semana sí ocupan posición.
        int pos = numDia;
        LocalDate f = fecha;
        while (pos < DIAS_CALENDARIO) {
            f = cal.sumaDias(f, 1);                               // función 8
            int dia = cal.diaSemana(f).getValue();
            if (dia > 1 && dia < 6) reg.fijaDiaArchivo(++pos, f); // el fuente usa > 1, no > 0
        }
        // ... segundo ciclo (líneas 1170-1201): llena las posiciones 1..NUMDIA-1 con los días siguientes
        return escritura.guarda(reg, EscrituraControl.Accion.STORE);
    }

Riesgos de migración
Errores de transacción ignorados

En las macros STORE_B01 (líneas 74-108) y STORE_B05 (líneas 2600-2633), si BEGINTRANSACTION falla con un error distinto de AUDITERROR tipo 1 la rama ELSE está vacía: no se escribe el registro y el resultado sigue en 0. Dentro de la transacción del llamador el ERRORDB está comentado, así que un STORE fallido también regresa 0.

Resultados sobrescritos en ALTA_SISDIA

Los resultados 9 (error DMSII) y 14 (bloqueo agotado) se reemplazan por 3 en la línea 1212. Un programa que reintenta solo ante 14 nunca lo verá en el alta.

Alta de B05 sin control de duplicado ni de bloqueo

ALTA_B05 (líneas 2700-2748) regresa 0 si el registro ya existe o si se agotaron los reintentos. CONB05PROCESO (líneas 2646-2698) tampoco asigna 14 y ejecuta el GET aun cuando el FIND no posicionó un registro.

CSI forzado a cero

CONSISDIA y MANTSISDIA reemplazan en el arreglo de entrada y salida el CSI por 0 (líneas 441-442 y 1409-1410). El catálogo de errores anuncia un resultado 6 por CSI inválido que en B01 no puede ocurrir.

Código de resultado no documentado

El resultado 14 se usa en todos los ciclos de reintento (por ejemplo líneas 263 y 1076) pero no aparece en el catálogo de la cabecera (líneas 26-44).

Valores fijos

Títulos de LIBLJ y de la base con el pack CMEMP, la función LOCSUP del calendario, el tamaño de diez días del arreglo de archivos y MAXWAIT de 20 están compilados. Se trasladan a application.yml.

P005 · EXTRACTOR — Extractor de saldos GL hacia Tesorería (S151 · Banamex · Unisys ClearPath MCP)

S151ProgramaCOBOL

Fuente: COBOL_P005.cbl (3641 LOC) · Batch nocturno diario S151 (paso 25MTP002) · BC-06

Convenciones: nombres traducidos (Unisys→legible); [P005 Lnnnn] = origen (col 1-6 del fuente); (BR: RN-S151-...) = regla de negocio.

⚠ marcas: [HARDCODE], [CÓDIGO-MUERTO], [CRONOS2K] (puente Y2K activo por $SET OMIT).

1. Resumen funcional

P005 (PROGRAM-ID EXTRACTOR) es el extractor canónico de saldos contables del subsistema GL S151. Lee los archivos de "arribo" de saldos (SALDOS, 90 bytes, derivados del dataset DMSII S151BD02ADSALDO) que los sistemas fuente depositan cada día, y por cada sistema/CSI integra esos saldos a la base de datos DMSII S151 (datasets de cliente B03SDOCTE, sucursal B02SDOSUC, global B01SDOGLOB, fecha-valor SAR B10FECHVAL, cancelación fecha-valor B11CANFVAL) dentro de transacciones auditadas (S151B91REINICIO). En paralelo genera: (a) el archivo TESORERIA de 56 bytes en ASCII (único puente cross-plataforma MCP→Tesorería, BR: RN-S151-1010/1011/1018), (b) el archivo de respaldo SDOS-SAL (156 bytes) que se transfiere por INTELAR (ADMONXFERS), y (c) dos reportes impresos de 132 columnas: REPORTE (control de arribos) y V00-REPORTE2 (bitácora de mensajes) (BR: RN-S151-1012/1019).

El programa maneja tres formatos de registro de saldo determinados por el campo de control del archivo (SDO-CTL-FORMATO): FORMATO 1 = saldos "anteriores"/ANT (única ruta que escribe TESORERIA), FORMATO 2 = formato viejo, FORMATO 3 = formato nuevo/NVO (el más rico: añade SAR, saldo-anterior de aportación y cancelación de fecha-valor). Cada formato tiene su propia familia de párrafos casi idéntica (2xxx = FORMATO 2, 5xxx = FORMATO 1/ANT, 6xxx = FORMATO 3/NVO). Es pre-Y2K (escrito septiembre 1998) y fue parchado con el proyecto CRONOS2K: casi toda fecha de 6 dígitos (AAMMDD) se convierte a 8 dígitos (CCAAMMDD) mediante rutinas A2K-* seleccionadas por directivas de compilación $SET OMIT (BR: RN-S151-1017).

Regla operativa clave: no procesa fines de semana salvo día hábil especial NVOPSO. En días de conversión "nuevos pesos" (WS-DIAPBAS-NVOPSO) divide todo importe entre WS-FACTOR-NVOPSO (1000) [HARDCODE].

2. Datos y archivos

Archivos (FILE-CONTROL / FD):

  • SALDOS (SELECT OPTIONAL, DISK) — entrada. REG-SALDOS PIC X(90). DEPENDENTSPECS=TRUE → estructura ligada a S151BD02ADSALDO. Un archivo por sistema/CSI/fecha; su título se arma dinámicamente en 2200-ARMA-ETIQUETAS. [P005 L45-51] (BR: RN-S151-1013)
  • SDOS-SAL (DISK) — salida. REG-SDOS-SAL PIC X(156) = 90 (saldo base) + 66 (enriquecimiento). Título W-ETIQ-SDOS-INT. Se envía por INTELAR. [P005 L53-61] (BR: RN-S151-1014)
  • TESORERIA (DISK) — salida. REG-TESORERIA PIC X(56), EXTMODE IS ASCII (conversión EBCDIC→ASCII automática del MCP), DEPENDENTSPECS=TRUE. Antes eran 54 bytes (PIC X(54) comentado) — CRONOS2K lo amplió a 56 [P005 L63-71]. (BR: RN-S151-1010, 1011, 1018)
  • REPORTE (PRINTER) — LINEA-CSI PIC X(132). Reporte de control de arribos. [P005 L73-77] (BR: RN-S151-1012)
  • V00-REPORTE2 (PRINTER) — V00-R00-REPORTE2 PIC X(132). Reporte/bitácora de mensajes (encabezados WLI-ENCAB-*). [P005 L40-43] (BR: RN-S151-1012, 1019)

Base de datos DMSII: DB S151BD02ADSALDO ALL [P005 L82]. Datasets escritos (vía sub-esquemas): S151B03SDOCTE (saldos cliente, llave B03SXCTE), S151B02SDOSUC (saldos sucursal, llave B02SXSUC), S151B01SDOGLOB (saldos globales, llave B01SXCSI), S151B10FECHVAL (fecha-valor SAR, llave B10SXFECHVAL), S151B11CANFVAL (cancelación fecha-valor, llave B11SXCANFVAL). Auditoría/reinicio: S151B91REINICIO. Registro de control B92-CTR-* (CSI, fecha, arribos).

Layouts de registro de saldo (redefiniciones de REG-SALDOS 90 bytes según CVES): el primer byte-grupo -CVES discrimina el tipo:

  • 10 → cliente (SDO-CTE- / ANT-CTE- / NVO-CTE-*): sistema, sucursal, moneda, cuenta, institución, sucursal-expedición, nombre, saldo-anterior, saldo-actual, fecha.
  • 20 → sucursal (-SUC-): sistema, sucursal, moneda, saldo-ant, saldo-act, fecha.
  • 30 → global (-GLO-): sistema, moneda, saldo-ant, saldo-act, fecha.
  • 40 → SAR (NVO-SAR-*, sólo FORMATO 3): tabla de 5 ocurrencias fecha/importe/número.
  • 50/60 → aportación anterior y cancelación fecha-valor (NVO-ANT-, NVO-CAN-, sólo FORMATO 3).
  • 90 → trailer/totales de control (-TRA-): sistema y número de registros esperado (para cuadre).
  • SDO-CTL-* (primer registro del archivo) = registro de control: claves, CSIO, sistema, fecha-proceso (FPRO), fecha-creación (DCRE), hora-creación (HCRE), FORMATO.

Tablas WORKING-STORAGE (20 ocurrencias, una por sistema integrado): TAB-SIST (sistema), TAB-ARRIBO, FPRO-TAB/DCRE-TAB/HCRE-TAB (fechas), RLEI-TAB (registros leídos), RGRA-TAB (registros grabados), NOMB-TAB (nombre archivo), RLEY-TAB (leyenda/estado). CUAL-CSI(n) y NOMBRE-CSI(n) = catálogos de centros CSI. Banderas 77: 77-EOF, 77-EOF-SDOS, 77-CSI, 77-DIA-SEM, 77-DIAS-PTE, 77-FORMATO, 77-LEI-AUXKEY, 77-AUX (punto de error para 8000-BD-ERROR).

Fechas CRONOS2K: copybook S151/CRONOS2K/CPY/WS define familia A2K-FEC-* (formatos MDCA, CAMD, DMCA, AMD, MDA, DMA, CCAA, CAM, AM, Julian) y A2K-BASE-YEAR PIC 9(02) VALUE 50 [HARDCODE, L256] = pivote de siglo: año < 50 ⇒ siglo 20, si no ⇒ siglo 19. WKS-DATE-ARRAY2 PIC X(21) DISPLAY WITH LOWER-BOUNDS (BR: RN-S151-1015).

S151 · L010 a Java 21 Spring Boot

Al levantarse, la librería resuelve por control de versiones los títulos de S080L710 y de la librería CONTROL de S151, verifica en el dataset B05 que no exista otra L010 viva y se registra con su número de mezcla. Obtiene el CSI del equipo con SOPORTECOMS y la fecha contable con CONSISDIA, y abre la bitácora (S151)S151/FILE/LOGP010/AAMMDD ON CMEMP, creándola o agregando al final. Cada llamada a GRABA_BITACORA copia el registro recibido a un buffer de 1 260 caracteres, cuenta recibidos y errores según la clave de respuesta y lo escribe. Mientras haya usuarios enlazados atiende comandos HI del operador; al quedarse sin usuarios cierra la bitácora y se da de baja en B05.

/** Contrato que exponía EXPORT GRABA_BITACORA. */
public interface BitacoraP010 {
    void grabaBitacora(byte[] registro);     // EBCDIC ARRAY REGISTRO[*]
}

@Service
@RequiredArgsConstructor
class BitacoraP010Service implements BitacoraP010 {

    static final int LONG_REGISTRO = 1260;   // MAXRECSIZE 210 palabras x 6 caracteres
    static final int POS_CVE_RES = 1258;     // IDF_CVE_RES: 2 dígitos

    private final ArchivoBitacora archivo;
    private final AtomicLong totRecibidos = new AtomicLong();
    private final AtomicLong totErrores = new AtomicLong();

    @Override
    public void grabaBitacora(byte[] registro) {
        byte[] reg = Arrays.copyOf(registro, LONG_REGISTRO);   // rellena con ceros si viene corto
        totRecibidos.incrementAndGet();
        int cveRes = Ebcdic.entero(reg, POS_CVE_RES, 2);
        if (cveRes > 1) {
            totErrores.incrementAndGet();                       // clave de respuesta 2..99
        }
        archivo.escribe(reg);                                   // WRITE(BITA_P010,1260,REG_BITA)
    }
}

@Component
@RequiredArgsConstructor
class CicloVidaBitacora implements SmartLifecycle {

    private final ResolutorVersiones versiones;   // VERSIONES: títulos de S080L710 y CONTROL
    private final RegistroInstancia registro;     // VERIFICA_B05: una sola instancia viva
    private final ArchivoBitacora archivo;        // INICIA: CSI, fecha contable y apertura
    private volatile boolean activo;

    @Override
    public void start() {
        versiones.resuelve();
        registro.registraUnica();
        archivo.abreDelDia();
        activo = true;                // FREEZE(CONTROL, CONTROL_LIB): queda residente
    }

    @Override
    public void stop() {              // BAJA
        archivo.cierra();
        registro.baja();              // función 22 en B05
        activo = false;
    }

    @Override public boolean isRunning() { return activo; }
}

@Component
@RequiredArgsConstructor
class FechaContableResolver {

    private final SoporteComs soporte;          // CSIID OF SOPORTECOMS
    private final ControlSistemas control;      // CONSISDIA de (S151)S151/OBJECT/L001/CONTROL

    /** CONSULTA_B01: función 1 para el sistema 500 en el CSI del equipo. */
    LocalDate fechaContable() {
        int csi = soporte.csiDelHost();
        ConsultaSistema r = control.consisdia(1, 500, csi);
        if (r.resultado() > 0) {
            // MYSELF.STATUS := -1
            throw new LibreriaNoDisponibleException(
                    "L010 > ERROR EN CONSULTA DE LIB S151/L001, SISTEMA S151 " + r.resultado());
        }
        return r.fechaContable();               // ISISDFECCON: posiciones 16-23
    }
}
@Component
@RequiredArgsConstructor
class ArchivoBitacora {

    private final BitacoraProperties props;
    private final FechaContableResolver fecha;
    private FileChannel canal;

    /** ASIGNA_ARCHIVOS: OPEN(…,WAIT) si no existe; OPEN(…,ATEND) si ya existe. */
    synchronized void abreDelDia() {
        Path ruta = props.ruta(fecha.fechaContable());
        try {
            canal = FileChannel.open(ruta,
                    StandardOpenOption.CREATE, StandardOpenOption.WRITE, StandardOpenOption.APPEND);
        } catch (IOException e) {
            throw new UncheckedIOException("No se pudo abrir " + ruta, e);
        }
    }

    synchronized void escribe(byte[] reg) {
        try {
            canal.write(ByteBuffer.wrap(reg));
        } catch (IOException e) {
            throw new UncheckedIOException(e);
        }
    }

    synchronized void cierra() {        // CLOSE(BITA_P010, LOCK)
        try { if (canal != null) canal.close(); } catch (IOException ignored) { }
    }
}
@Component
@RequiredArgsConstructor
class RegistroInstancia {

    private final ProcesosRepository b05;        // dataset B05 vía B05PROCESOS
    private final InstanciaInfo yo;              // nombre de la librería y PID (antes MIXNUMBER)

    /** VERIFICA_B05: si hay otra L010 viva con el mismo nombre, no se continúa. */
    @Transactional
    void registraUnica() {
        for (Proceso p : b05.registrados(151, 10)) {              // función 1
            if (!yo.procesoVivo(p.mix())) {                          // DCKEYIN "<mix> Y" = INVALID
                b05.baja(p);                                         // función 22: registro huérfano
            } else if (p.nombreLibreria().equals(yo.nombreSinVersion())) {
                throw new InstanciaDuplicadaException(               // original: aviso y ACCEPT
                        "EXISTE UNA L010 CON MIX " + p.mix() + " DARLA DE BAJA PARA PODER CONT.");
            }
        }
        b05.alta(151, 10, yo.pid());                                 // función 19 con MIXNUMBER
    }
}

Riesgos de migración
Escrituras y contadores sin serialización

GRABA_BITACORA incrementa TOT_RECIBIDOS y TOT_ERRORES y escribe en BITA_P010 sin INTERLOCK ni EVENT (líneas 195-201), en una librería SHAREDBYALL que usan varias copias del P010. Los contadores del HI 1 pueden perder incrementos.

Buffer más corto que el registro

REG_BITA [0:1255] recibe 1 260 caracteres y la clave de respuesta se lee en la posición 1258; el código depende del redondeo del arreglo a palabras de 6 caracteres. LONG_MSG se calcula y no se usa para limitar la copia.

Reapertura en caliente

El HI 25 cierra la bitácora y la reabre mientras las copias del P010 siguen enlazadas, sin bloquear las escrituras concurrentes.

Fecha de bitácora tomada de Captación

CONSULTA_B01 consulta el sistema 500 (línea 408) y no el 151 para obtener la fecha contable que nombra el archivo.

Exclusión de instancias débil

VERIFICA_B05 envía HI 4 a la L010 previa, pero ese comando no la baja; el flujo depende de que el operador la termine manualmente antes de responder al ACCEPT.

Código muerto

El DEFINE VALIDA_CVE (líneas 133-142) referencia LIB_SBC, que no se declara, y nunca se invoca; los contadores de altas, bajas, modificaciones y consultas no se incrementan en ningún punto.

Pendiente de revisión SME
  • Confirmar si la fecha contable de la bitácora debe ser la del sistema 500 o la del 151.
  • Confirmar el nombre real del archivo consumido aguas abajo: LOGP010 (código) o BITAP010 (comentario de la línea 13).
  • Identificar qué programa del P010 llama a GRABA_BITACORA y con qué longitud de registro, para validar el riesgo de lectura fuera del arreglo.
  • Confirmar si el MCP serializa las escrituras concurrentes a un archivo declarado en una librería compartida o si pueden intercalarse.
  • El inventario no asigna reglas del brain a este componente; los segmentos quedan sin reglas.

S151 · P158 a Java 21 Spring Boot

Recibe el número de sistema en PROCEDURE DIVISION USING y rechaza cualquiera fuera de la lista permitida. Lee LOG151 (movimientos del día producidos por P170) y su archivo de descripciones LOG151-COMP por llave. En el INPUT PROCEDURE de un SORT filtra cada movimiento, escribe un registro de punteo por clave de transacción en L07-DATOS y, si la transacción aplica a estado de cuenta, arma el registro S050 y lo dirige a MOVSXCONT, MOVSXCONT-500, MOVSXCONTCHEQ o los archivos TESOFE según producto y sistema, acumulando totales para el trailer. El OUTPUT PROCEDURE imprime los listados por nodo, sucursal y contrato; al final dispara por WFL los listados MOVXCONT y MOVXSCON y espera la residencia del archivo de P170.

/** KEY-PRINC: SORT ARCH-ORD ON ASCENDING KEY, en este orden exacto. */
public record LlaveOrden(int subnodo,        // 9(04) COMP
                         int sucProm,        // 9(04) COMP
                         int tipoProd,       // 1 = producto 66, 2 = cualquier otro
                         String contrato,    // 9(16): String para conservar ceros
                         int prod,           // 0 salvo sistemas 407/408
                         int instrum,
                         int sucOper,
                         int cajaOper,
                         long autS151)       // 9(08) COMP
        implements Comparable<LlaveOrden> {

    private static final Comparator<LlaveOrden> ORDEN = Comparator
            .comparingInt(LlaveOrden::subnodo)
            .thenComparingInt(LlaveOrden::sucProm)
            .thenComparingInt(LlaveOrden::tipoProd)
            .thenComparing(LlaveOrden::contrato)          // misma longitud (lpad 16): orden numérico
            .thenComparingInt(LlaveOrden::prod)
            .thenComparingInt(LlaveOrden::instrum)
            .thenComparingInt(LlaveOrden::sucOper)
            .thenComparingInt(LlaveOrden::cajaOper)
            .thenComparingLong(LlaveOrden::autS151);

    @Override public int compareTo(LlaveOrden o) { return ORDEN.compare(this, o); }
}

@Component
public class FechasCronos2k {

    /** A2K-BASE-YEAR VALUE 50: AA < 50 es 20AA; AA >= 50 es 19AA. Ventana 1950-2049. */
    private final int pivote;

    public FechasCronos2k(@Value("${s151.fechas.pivote-siglo:50}") int pivote) {
        this.pivote = pivote;
    }

    /** A2K-OBTAIN-CENTURY. */
    public int siglo(int aa) {
        return (aa < pivote) ? 20 : 19;
    }

    /** A2K-CONV-AMD-TO-CAMD: AAMMDD de 6 dígitos a LocalDate con el pivote explícito. */
    public LocalDate deAamMdd(int aammdd) {
        int aa = aammdd / 10_000, mm = (aammdd / 100) % 100, dd = aammdd % 100;
        return LocalDate.of(siglo(aa) * 100 + aa, mm, dd);
    }

    /** A2K-CONV-CAMD-TO-AMD: se usa para el nombre del backup (WKS-FECHA-BACKUP, 6 dígitos). */
    public String aAamMdd(LocalDate f) {
        return f.format(DateTimeFormatter.ofPattern("yyMMdd"));
    }
}

@Component

public class SistemaPermitidoValidator implements JobParametersValidator {

    private final P158Properties props;

    /** Equivale a PROCEDURE DIVISION USING W77-SIST-PARAM y al IF de 000-000-CHECA-DIA. */
    @Override
    public void validate(JobParameters params) throws JobParametersInvalidException {
        Long sistema = params.getLong("sistema");
        if (sistema == null || !props.sistemasPermitidos().contains(sistema.intValue())) {
            // STOP RUN tras escribir el mensaje en V00-REPORTE2 y en LJ
            throw new JobParametersInvalidException("EL P158 NO CORRE PARA ESTE SISTEMA");
        }
    }
}

@Component
@RequiredArgsConstructor
public class TotalesYCierreTasklet implements Tasklet {

    private final JobLauncher launcher;
    private final Job listadoMovimientos;       // antes BEGIN JOB ... RUN P170 vía CALL SYSTEM WFL
    private final ArchivoResidencia residencia; // ATTRIBUTE RESIDENT OF I01-MOVIMIENTOS
    private final P158Properties props;

    @Override
    public RepeatStatus execute(StepContribution c, ChunkContext ctx) throws Exception {
        int sistema = ctx.getStepContext().getJobParameters().get("sistema") instanceof Long l ? l.intValue() : 0;
        lanza("MOVXCONT", ctx);
        if (sistema == 500) {
            lanza("MOVXSCON", ctx);             // listado con subcuentas, solo sistema 500
        }
        // 12750-VALIDA-RESI170: WAIT (15) mientras el archivo no exista. En COBOL no hay tope.
        Path i01 = residencia.resuelve(props.tituloInmov(), ctx);
        Awaitility.await().pollInterval(Duration.ofSeconds(15))
                  .atMost(props.esperaMaximaP170())          // nuevo: tope configurable
                  .until(() -> Files.exists(i01));
        Files.delete(i01);                                  // OPEN INPUT ... CLOSE WITH PURGE
        return RepeatStatus.FINISHED;
    }

    private void lanza(String listado, ChunkContext ctx) throws Exception {
        launcher.run(listadoMovimientos, new JobParametersBuilder()
                .addString("listado", listado)
                .addLocalDate("fechaProceso", FechaProceso.de(ctx))
                .toJobParameters());
    }
}

/** 150-010-LEE-REGISTRO. Devuelve las acciones a realizar con un movimiento de LOG151. */
Acciones evalua(MovimientoLog151 m, int sistema) {
    boolean activo = m.funcion() == 1 && (m.status() == 1 || m.status() == 2)
            && (m.origen() == 1 || m.origen() == 3);                      // W77-REGACT
    int productos = (sistema == 87) ? m.agrupDesvProd() : m.producto();  // W77-PRODUCTOS
    boolean devolucionEspecial = (sistema == 407 || sistema == 408)
            && m.tipoProc() > 79 && m.tipoProc() < 90;

    // Punteo contra S500 (L07-DATOS). Se reproduce la precedencia real del IF de las
    // líneas 10803-10804: (sistema = 500 AND tipo = 40) OR tipo = 41 OR tipo = 42 OR tipo = 43.
    boolean excluyePunteo = (sistema == 500 && m.tipoProc() == 40)
            || m.tipoProc() == 41 || m.tipoProc() == 42 || m.tipoProc() == 43;
    boolean punteo = !devolucionEspecial
            && m.funcion() == 1 && m.status() == 1 && m.tipoProc() > 19
            && !excluyePunteo;

    // Envío al SORT: aquí el fuente sí usa paréntesis y la exclusión 40-43 es solo para 500.
    boolean alSort = !props.soloPunteo(sistema) && activo && !devolucionEspecial
            && !(sistema == 500 && m.tipoProc() > 39 && m.tipoProc() < 44);

    return new Acciones(productos, punteo, alSort);
}

    public Optional<Destino> destino(MovimientoLog151 m, int csi) {
        if (!props.csisTesofe().contains(csi)) return Optional.empty();
        for (ServicioTesofe s : catalogo) {          // la tabla viene ordenada por índice

            // contra WKS-CAT-NUMMDA. Se conserva la diferencia hasta que el SME la confirme.
            String cuentaMda = (s.indServ() == 50) ? m.numMda() : m.catNumMda();
            boolean coincide = (s.contrato().equals(m.contrato()) || s.sucCuenta().equals(cuentaMda))
                    && s.producto() == m.producto() && s.instrumento() == m.instrumento();

                return Optional.of(s.indServ() == 50 ? Destino.MOVSXCONT_ESOF     // S502 IMPUESTOS
                                                     : Destino.MOVSXCONT_ESOF2);  // S701 PAGOS
            }
        }
        return Optional.empty();

Riesgos de migración
Precedencia de AND y OR en el filtro de punteo

En 150-010-LEE-REGISTRO (líneas 10803-10804) la condición IF W77-SIST-PARAM = 500 AND A00-R01-TIPO-PROC = 40 OR 41 OR 42 OR 43 se evalúa como (500 y 40) o 41 o 42 o 43. Los procesos 41 a 43 no generan punteo en ningún sistema. La decisión equivalente para el SORT (líneas 10824-10825) sí usa paréntesis.

Espera sin límite del archivo de P170

12750-VALIDA-RESI170 hace WAIT (15) hasta que exista I01-MOVIMIENTOS, sin contador. Si P170 falla, P158 queda colgado al final del cierre.

Comparación distinta entre servicios TESOFE 50 y 51

En 150-091-PREG-CUENTA-TESOFE el servicio 50 compara la sucursal-cuenta con A00-R01-NUMMDA (línea 11575) y el 51 con WKS-CAT-NUMMDA (línea 11589). Una de las dos puede estar mal.

Saneo silencioso de moneda

150-025-MUEVE-GRABA-SORT cambia a 1 cualquier moneda fuera de 1 a 99 sin registrar el caso (líneas 10839-10840).

Hardcodes de sistemas, CSI y catálogos

La lista de sistemas permitidos, los sistemas de solo punteo (17 y 404), los CSI de TESOFE (10 y 32), los productos 66, 1 y 500 y los nombres de listados MOVXCONT y MOVXSCON están compilados. Se trasladan a application.yml.

Ventana Y2K

El pivote A2K-BASE-YEAR = 50 interpreta los años de 2 dígitos dentro de 1950-2049; fechas de 6 dígitos posteriores a 2049 se convertirían al siglo XX.

  • Confirmar cuál de las dos comparaciones de cuenta en 150-091-PREG-CUENTA-TESOFE es la correcta (A00-R01-NUMMDA frente a WKS-CAT-NUMMDA).
  • Validar con datos de producción que WKS-SORT-HORA-DD corresponde a los segundos (RN-S151-374).

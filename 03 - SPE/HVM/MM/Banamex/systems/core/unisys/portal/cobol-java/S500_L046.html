S500 · L046 a Java 21 Spring Boot

L046 mantiene una tabla de hasta 2048 folios con su estado, su hora de vencimiento, su tiempo de reintento y el texto del mensaje de cancelación. Expone altas (GUARDAMSG), bajas condicionadas al estado (RESUELVEMSG), bajas incondicionales (BORRAMSG), purga total (OLVIDATODO), un informe de ocupación (INFORMA) y el procedimiento ENVIA_CANCELACIONES, que corre como demonio. El demonio despierta en el próximo vencimiento, marca como cancelado cada folio vencido, envía su mensaje a la salida COMS de la línea y lo reprograma, sin borrarlo, hasta que el programa cliente lo resuelve. Todo vive en memoria; no hay archivos ni base de datos.

/** Una cancelación pendiente: el folio, su estado y el mensaje que se reenviará. */
public record CancelacionPendiente(long folio,
                                   boolean vencido,          // bit [47:1] de MEM
                                   Duration timeout,         // TIME_OUT[j]
                                   Instant vence,            // VENCE[j] (segundos del día en MCP)
                                   byte[] mensaje) {         // CONTEXTO[j,*] de SZ[j] bytes
    public CancelacionPendiente {
        mensaje = mensaje.clone();
    }
    CancelacionPendiente reprogramada(Instant ahora) {
        return new CancelacionPendiente(folio, true, timeout, ahora.plus(timeout), mensaje);
    }
}

public enum ResultadoGuarda { OK, SIN_LUGAR, DUPLICADO, MSG_MAYOR_MAX, MSG_MAYOR_AREA,
                               TIEMPO_MENOR_MINIMO, FOLIO_INVALIDO }   // 0..6

/** GUARDAMSG(FOLIO, TIEMPO, MSG_SZ, EDO, MSG). */
public ResultadoGuarda guarda(long folio, Duration tiempo, byte[] msg, int msgSz, boolean vencido) {
    if (msgSz > props.tamMaxMensaje())       return ResultadoGuarda.MSG_MAYOR_MAX;        // 3
    if (msgSz > msg.length)                  return ResultadoGuarda.MSG_MAYOR_AREA;       // 4
    if (tiempo.compareTo(props.tiempoMinimo()) < 0) return ResultadoGuarda.TIEMPO_MENOR_MINIMO; // 5
    if (folio < 1)                           return ResultadoGuarda.FOLIO_INVALIDO;       // 6

    Instant ahora = clock.instant();
    var nueva = new CancelacionPendiente(folio, vencido, tiempo,
            vencido ? ahora : ahora.plus(tiempo),            // EDO = 0: vence en TIEMPO segundos
            Arrays.copyOf(msg, msgSz));

    synchronized (this) {                                     // capacidad y alta en un solo paso
        if (pendientes.containsKey(folio))              return ResultadoGuarda.DUPLICADO;  // 2
        if (pendientes.size() >= props.capacidad())     return ResultadoGuarda.SIN_LUGAR;  // 1
        pendientes.put(folio, nueva);
    }
    return ResultadoGuarda.OK;
}
public enum ResultadoBaja { OK, NO_SE_PUDO, NO_EXISTE }    // RESUELVEMSG: 0, 1, 2

/** RESUELVEMSG: solo da de baja si el estado guardado coincide con el esperado. */
public ResultadoBaja resuelve(long folio, boolean estadoEsperado) {
    if (folio <= 0) return ResultadoBaja.NO_EXISTE;   // el fuente busca 48"FFFFFFFFFFFF": nunca existe
    var previo = new AtomicReference<CancelacionPendiente>();
    pendientes.computeIfPresent(folio, (k, c) -> {
        previo.set(c);
        return c.vencido() == estadoEsperado ? null : c;      // null = remover
    });
    if (previo.get() == null) return ResultadoBaja.NO_EXISTE;
    return previo.get().vencido() == estadoEsperado ? ResultadoBaja.OK : ResultadoBaja.NO_SE_PUDO;
}

/** BORRAMSG: baja sin importar el estado. El fuente devuelve 1 tanto si no existe como si no pudo bloquear. */
public int borra(long folio) {
    return pendientes.remove(folio) != null ? 0 : 1;
}
// Al remover, el mensaje deja de ser alcanzable; en el fuente CONTEXTO, SZ y TIME_OUT conservan
// el texto anterior en memoria compartida hasta que otra alta ocupe la ranura.
/** OLVIDATODO: vacía la tabla. 1 si no pudo tomar el control global. */
public int olvidaTodo() {
    synchronized (this) {
        int purgados = pendientes.size();
        pendientes.clear();
        log.warn("L046 OLVIDATODO: {} cancelaciones pendientes descartadas sin enviar", purgados);
    }
    return 0;
}

// Con un mapa concurrente la limpieza es atómica respecto a cada folio y no arrebata envíos en curso.

class EnviadorCancelaciones {
    private final RegistroFolios registro;
    private final MessageChannel salidaLinea;     // "OUTPUT OF LINEA": Spring Integration -> MQ/Kafka

    private final MeterRegistry metricas;         // ENVIOS y VUELTAS

    /** ENVIA: cada folio vencido se marca, se envía y se reprograma; no se elimina. */
    @Scheduled(fixedDelayString = "${s500.l046.revision:5s}")
    void revisa() {
        metricas.counter("l046.vueltas").increment();
        Instant ahora = clock.instant();                   // Instant: sin problema de medianoche
        registro.vencidas(ahora).forEach(c -> {
            boolean enviado = salidaLinea.send(MessageBuilder.withPayload(c.mensaje())
                    .setHeader("folio", c.folio()).build());
            if (enviado) {
                registro.reprograma(c.folio(), c.reprogramada(ahora));  // MEM[j].[47:1] := 1; VENCE += TIME_OUT
                metricas.counter("l046.envios").increment();
            } else {
                log.error("No se pudo enviar la cancelación del folio {}", c.folio());  // el fuente no revisa SEND
            }
        });
    }
}

Riesgos de migración
Candado global que puede quedar tomado

En GUARDAMSG el EPILOG libera LK_S500 solo si J > 0 (línea 74); con la tabla llena o con la ranura 0 asignada el candado queda tomado y todas las altas posteriores fallan con 1.

Carreras en altas y contador

El duplicado se revisa antes de tomar LK_S500 (líneas 87 y 90) y P se incrementa y decrementa bajo candados distintos (líneas 100, 121 y 140).

Reenvío sin tope y sin verificar el envío

Un folio vencido se reenvía cada TIME_OUT hasta que alguien lo resuelve, sin límite de intentos (líneas 226-234), y el resultado de SEND no se evalúa.

Manejo de la medianoche

Las horas son segundos del día (TIME(1)/60). CAMBIO_DIA se calcula (línea 216) y nunca se usa; el ajuste de VENCE en la línea 223 no cubre todos los casos.

Residuo de mensajes en memoria compartida

Las bajas no limpian CONTEXTO, SZ ni TIME_OUT y la purga limpia el texto solo parcialmente (línea 60); el contenido queda visible para cualquier programa enlazado.

Volatilidad

Con FREEZE(TEMPORARY) la tabla se pierde al desenlazarse el último programa; las cancelaciones pendientes no se envían ni quedan en bitácora.

Pendiente de revisión SME
  • El layout del mensaje de cancelación lo define el programa cliente (P045, según el pseudocódigo); L046 lo trata como opaco. Confirmar su estructura antes de elegir el formato del mensaje en el broker.
  • Confirmar la semántica del segundo argumento de LOCK(x, 5) y de los valores 1 y 2 que devuelve, deducidos por uso.
  • Definir si la tabla debe persistir (base de datos o Redis) para no perder cancelaciones en un reinicio; el sistema actual no lo hace.
  • Definir un tope de reintentos y una alerta por folio que no se confirma.
  • INFORMA (informe de ocupación por COMS) no se incluyó en esta demostración; en Java se cubriría con métricas y un endpoint de Actuator.

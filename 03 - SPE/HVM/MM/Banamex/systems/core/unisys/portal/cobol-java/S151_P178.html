P178 espera a que el control mensual de LIB-CONTROL indique que P025 terminó, marca su propio inicio y abre la base de saldos de S151 en actualización. Ordena el archivo de saldos del sistema origen y acumula por producto, instrumento y moneda el importe del concepto 2 en una tabla en memoria de 25 por 15 por 19. Después recorre la posición B70 del CSI y la fecha de proceso: imprime el reporte de posición, compara el saldo actual contra la tabla y, si no coincide, reemplaza el saldo de B70 por el del sistema origen y hace STORE. Para S500 y S555 escribe además un archivo de saldos separado por comas y lo envía por INTELAR.

/** Valores de WKS-B03-STABDSAL que usa P178. */
enum EstatusSaldos {
    PENDIENTE_P025,   // < 3: P025 no ha terminado
    LISTO,            // 3: P025 terminó
    EN_PROCESO,       // 4: P178 ya inició (reinicio tras falla)
    OMITIR,           // 99, o 5 convertido a 99 (alta disponibilidad, IBM 2015)
    YA_EJECUTADO;     // > 5

    static EstatusSaldos of(int v) {
        if (v < 3) return PENDIENTE_P025;
        if (v == 3) return LISTO;
        if (v == 4) return EN_PROCESO;
        if (v == 5 || v == 99) return OMITIR;
        return YA_EJECUTADO;
    }
}

@Component
@StepScope
@RequiredArgsConstructor
class EsperaP025Tasklet implements Tasklet {
    private final ControlSistemaClient control;          // CONSISMEN IN LIB-CONTROL, función 1
    private final VerificacionProperties props;          // p178.espera-p025: PT15M
    @Value("#{jobParameters['sistema']}") private Integer sistema;   // W77-PARAM-SISTEMA

    @Override
    public RepeatStatus execute(StepContribution c, ChunkContext ctx) throws InterruptedException {
        EstatusSaldos e = EstatusSaldos.of(control.estatusSaldos(sistema));
        switch (e) {
            case PENDIENTE_P025 -> {
                log.info("NO HA TERMINADO P025 DETENGO PROCESO 15 MINS");
                Thread.sleep(props.esperaP025().toMillis());   // WAIT (900)
                return RepeatStatus.CONTINUABLE;               // vuelve a consultar
            }
            case YA_EJECUTADO -> throw new ProcesoAbortadoException("ERROR YA SE EJECUTO ESTE PROCESO");
            default -> {
                c.getStepExecution().getJobExecution().getExecutionContext().put("estatus", e.name());
                return RepeatStatus.FINISHED;
            }
        }
    }
}
@Bean
Job verificacionSaldos(JobRepository repo, Step esperaP025, Step marcaInicio,
                       Step cargaSaldosOrigen, Step verificaPosicion, Step envioIntelar,
                       Step marcaFin) {
    JobExecutionDecider omitir = (job, step) ->
            "OMITIR".equals(job.getExecutionContext().getString("estatus"))
                    ? new FlowExecutionStatus("OMITIR") : new FlowExecutionStatus("CONTINUAR");

    return new JobBuilder("S151P178", repo)
            .start(esperaP025)
            .next(omitir).on("OMITIR").end()                     // W77-EOF = 2: no procesa, no marca fin
            .from(omitir).on("CONTINUAR")
                .to(marcaInicio)                                  // CONSISMEN función 9, STABDSAL = 4
                .next(cargaSaldosOrigen)                          // SORT A02 (210000 / 220000)
                .next(verificaPosicion)                           // 200010 / 200011
                .next(envioIntelar)                               // solo S500 y S555
                .next(marcaFin)                                   // 999999-FIN, STABDSAL = 5
            .end()
            .build();
}

/** WKS-TABLA-POSICION + WKS-TAB-RELPROD/RELINS/RELMON. */
@Component
@StepScope
public class TablaPosicion {

    public static final int MAX_PROD = 25, MAX_INST = 15, MAX_MON = 19;   // OCCURS 25 / 15 / 19

    /** Llave natural en lugar de índices asignados por orden de llegada. */
    public record Llave(int producto, int instrumento, int moneda) {}

    private final Map<Llave, BigDecimal> importes = new HashMap<>();   // WKS-TAB-IMP S9(15)V9(02)
    private final Set<Integer> productos = new LinkedHashSet<>();
    private final Set<Integer> instrumentos = new LinkedHashSet<>();
    private final Set<Integer> monedas = new LinkedHashSet<>();

    public void suma(Llave k, BigDecimal importe) {
        registra(productos, k.producto(), MAX_PROD);
        registra(instrumentos, k.instrumento(), MAX_INST);
        registra(monedas, k.moneda(), MAX_MON);
        importes.merge(k, importe.setScale(2), BigDecimal::add);         // suma exacta, escala 2
    }

    public Optional<BigDecimal> importe(Llave k) { return Optional.ofNullable(importes.get(k)); }

    /** WKS-POS-PROD/INST/MON > 0: la dimensión apareció en SDOENT aunque no en esta combinación. */
    public boolean conIndice(Llave k) {
        return productos.contains(k.producto()) && instrumentos.contains(k.instrumento())
                && monedas.contains(k.moneda());
    }

    /** El COBOL no valida el tope al asignar índice; aquí se falla en lugar de salirse del arreglo. */
    private static void registra(Set<Integer> s, int v, int max) {
        if (s.add(v) && s.size() > max) throw new CapacidadTablaException(v, max);
    }
}

@Component
@StepScope
@RequiredArgsConstructor
class SaldoOrigenProcessor implements ItemProcessor<RegistroSdoEnt, RegistroSdoEnt> {

    @Value("#{jobParameters['sistema']}") private Integer sistema;
    private final TablaPosicion tabla;

    /** 210200-MUEVE-DATOS-APL. Cada sistema origen guarda la moneda en un campo distinto. */
    int moneda(RegistroSdoEnt r) {
        return switch (sistema) {
            case 500, 555 -> r.moneda();
            case 87       -> r.mon();
            case 84       -> (r.producto() == 84 && (r.instrumento() == 15 || r.instrumento() == 17))
                             ? 3 : r.monS084();
            default       -> 1;
        };
    }

    @Override
    public RegistroSdoEnt process(RegistroSdoEnt r) {
        // 210300-BUSCA-IMPORTE: primer renglón de los 30 con CVESDO = 2
        r.saldos().stream().limit(30)
                .filter(s -> s.claveSaldo() == 2)
                .findFirst()
                .ifPresent(s -> tabla.suma(
                        new TablaPosicion.Llave(r.producto(), r.instrumento(), moneda(r)),
                        s.importe()));                 // COMPUTE sin ROUNDED: suma exacta en escala 2
        return r;
    }
}

    private final SaldosCsvWriter csv;                  // E01-SDOS, solo S500 y S555

    @Override
    public Posicion process(Posicion b70) {
        // WKS-SDOACT-PRO es PIC 9(14)V99 sin signo: el COBOL compara el valor absoluto
        BigDecimal saldoActualSinSigno = b70.saldo(2).abs();
        boolean diferencia = false;

        if (b70.producto() > 0 && b70.instrumento() > 0 && b70.moneda() > 0) {
            var k = new TablaPosicion.Llave(b70.producto(), b70.instrumento(), b70.moneda());
            if (tabla.conIndice(k)) {      // 200034: cada dimensión ya apareció en SDOENT y su índice es < 26, < 16, < 20
                BigDecimal origen = tabla.importe(k).orElse(BigDecimal.ZERO.setScale(2));
                if (saldoActualSinSigno.compareTo(origen) != 0) {   // NOT =, sin tolerancia
                    b70.saldo(2, origen);                          // el sistema origen manda
                    diferencia = true;
                }
            }
        }
        // el renglón del archivo lleva el saldo de B70 anterior a la corrección y sin signo
        csv.escribe(b70.fecha(), b70.producto(), b70.instrumento(), b70.moneda(),
                    b70.saldo(1).abs(), saldoActualSinSigno);
        return diferencia ? b70 : null;
    }

record RenglonSaldo(LocalDate fecha, int producto, int instrumento, int moneda,
                    BigDecimal saldoAnterior, BigDecimal saldoActual) {

    private static final DateTimeFormatter DDMMAAAA = DateTimeFormatter.ofPattern("ddMMuuuu");

    String formatea() {
        return String.join(",",
                fecha.format(DDMMAAAA),                                   // 9(08)
                "%04d".formatted(producto), "%02d".formatted(instrumento),
                "%02d".formatted(moneda),
                Fixed.sinPunto(saldoAnterior, 14, 2),                     // 9(14)V99: 16 dígitos, punto implícito
                Fixed.sinPunto(saldoActual, 14, 2));
    }
}

    public RepeatStatus execute(StepContribution c, ChunkContext ctx) {

            }
        }
        return RepeatStatus.FINISHED;
    }

     * 900000-CHECA-STATUS registra categoría, tipo y estructura y regresa.
     * En Java un error de persistencia se propaga y el chunk se revierte;
     * solo NOTFOUND, que el COBOL trata como fin de datos, se convierte en vacío.

    <T> Optional<T> leer(Supplier<T> acceso) {
        try {
            return Optional.ofNullable(acceso.get());
        } catch (EmptyResultDataAccessException e) {
            return Optional.empty();                         // DMSTATUS(NOTFOUND)
        } catch (DataAccessException e) {
            log.error("BASE DATOS: {} ERROR EN BD: {}", e.getClass().getSimpleName(), e.getMessage());
            throw e;                                         // cambio deliberado frente al COBOL
        }
    }

Riesgos de migración
Solo S500 y S555 alimentan la comparación

En 210100-PROCESA (líneas 3514-3521) el RELEASE al SORT exige sistema 500 o 555 con producto 1 e instrumento 3. Para S084, S087 o S408 la tabla queda vacía, ninguna posición obtiene índice y 200034-COMPARA-SDOS no compara nada: el programa imprime el reporte y termina con estatus 5 sin haber verificado saldos. Hay que confirmar con qué sistemas se ejecuta hoy P178.

Comparación sin signo

WKS-SDOACT-PRO es PIC 9(14)V99 sin signo (línea 1205) y es el operando de la comparación contra WKS-TAB-IMP, que sí tiene signo. Diferencias de signo pasan sin corrección y saldos negativos correctos se reescriben.

Archivo a S500 con el saldo previo a la corrección

El renglón de E01-SDOS se escribe con los valores copiados de B70 antes de 200034-COMPARA-SDOS (líneas 3442-3446), por lo que S500 recibe el saldo de S151 sin corregir y sin signo.

Errores de base de datos y de envío no detienen el proceso

900000-CHECA-STATUS solo despliega el error (líneas 4488-4506) y el fallo de INTELAR solo se registra (líneas 3311-3320). El estatus final 5 se escribe de todos modos.

Índices sin tope al construir la tabla

210200-MUEVE-DATOS-APL incrementa W77-TOT-PROD, W77-TOT-INST y W77-TOT-MON sin compararlos contra 25, 15 y 19 antes del COMPUTE (líneas 3547-3575). El tope solo se revisa al comparar.

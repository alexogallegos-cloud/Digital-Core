P114 · Extracción de Información ICA (S151)

S151ProgramaCOBOL

Fuente: COBOL_P114.cbl (2153 LOC) · Rol en batch: generación diaria del archivo INFOICA (compensación interbancaria ICA) · BC-06

Convenciones: nombres traducidos (Unisys→legible); [P114 Lnnnn] = origen fuente; (BR: RN-...) = regla de negocio.

1. Resumen funcional

P114 (S151-P114-EXTRAEICA) extrae las operaciones ICA del día desde el sistema 264 (motor de mensajería interbancaria Unisys ClearPath) y produce el archivo de salida INFOICA, que concentra los movimientos interbancarios confirmados del día para su posterior conciliación y contabilidad en el sistema S151.

El programa abre el archivo ICA del día vía la librería propietaria LIBICA (entry ABREDIAICA), lee todos los registros de mensajería SA2 uno a uno (REGISTRO-ICA), filtra los mensajes con código de servicio válido (valores 10, 11, 20, 21) y los escribe en un archivo intermedio CLASIFICA. Al finalizar la lectura cierra el enlace ICA, calcula dinámicamente la memoria y disco necesarios para el SORT, y ordena CLASIFICA por llave de mensaje y estado ICA. Luego recorre el archivo ordenado extrayendo únicamente las transacciones que alcanzaron estado confirmado/procesado con respuesta válida (estatus de salida 2 ó 3), y genera registros de detalle en INFOICA con estructura Header / N registros de detalle / Trailer. El código de host origen/destino ("MON" ó "VDM") se determina por el número de CSI donde corre el proceso. Si el archivo ICA del día no existe, el programa aborta con STATUS=-1.

El programa fue desarrollado en noviembre de 1998 por Ing. Anselmo Sánchez Martínez y la última versión registrada es 25MTP001.

2.2 Layouts de registro clave

WS-REGISTRO-SA2 — Mensaje ICA completo (layout SA2, ≥160 bytes con FILLER 2200):

  • MSG-HEADER (36 bytes): MSG-HDR-PREFIX, MSG-HDR-APPLDEST, MSG-HDR-CCRDEST, MSG-HDR-LSNORI, MSG-HDR-STATORI (tipo+SOPE+priv+caja), MSG-HDR-CCRORI, MSG-HDR-COMPUT-ORI, MSG-HDR-NIVSEG, MSG-HDR-APPLORIG, MSG-HDR-ACTION, MSG-HDR-SCREEN, MSG-HDR-CAJA-SEG, MSG-HDR-TIME
  • MSG-SA0 (30 bytes): MSG-COD-TRAN-1 (APL+COD+SBC — COD con 88 COD-SERV-VALIDO VALUES 10,11,20,21), MSG-COD-TRAN-2, MSG-DIRECCION (1=envío / 2=regreso / 4=revocación), MSG-LONG, MSG-TIEMPO-ESPERA, MSG-COD-RESPUESTA (1=solicitud / 2=respuesta / 3=timeout / 4=entregado / 6=conf-apli / 7=aceptado / 8=seguridad / 9=error)
  • MSG-SA2 (46 bytes): ID-MSG (88 ID-SA2="000"), SA2-VERSION (88 VERSION-SA2="B"), SA2-CLASE (0=original / 1=repetición), SA2-ESTADO (0=no-nec / 1=aplicada / 2=rechazada), SA2-MODO (1=interactivo / 2=notificación / 3=certificado), SA2-IDENT (ent-num-origen 4 + cja-cod-origen 3 + trn-num 8 + trn-fecha 6 + trn-hora 6), SA2-MODALIDAD (88 SA2-MOD-OK = 10,11,20,21)
  • TRAN-MON-SOLYREVOC (152 bytes — overlapped por varios REDEFINES): CTA-NUM (X20), TRN-IMP (9(16)V99), MND-CVE (9(03)), TRN-FEC-SOLICITUD (9(06) AAMMDD), TRN-CVE-DESC (9(04)), TRN-REF-OPERACION (X(20)), TRM-REF-LOCAL (X(28))
  • TRAN-MON-RESP-APLI (REDEFINES de SOLYREVOC): incluye TMSYR-TRN-NUM-AUTOR (9(20)) — clave de autorización
  • CLASIF (REDEFINES de SOLYREVOC): bytes 109–116 = EDO-ICA (9(08)) con 88-levels de estado

Fuente: COBOL_P115.cbl (~7050 LOC) · rol en batch: COMPENREG (compensación regional/nacional, MTP001-DIARIO) · BC-06 / BC-11

Convenciones: nombres traducidos (Unisys→legible); [P115 Lnnnn] = línea origen; (BR: RN-...) = regla de negocio. ⚠ marca hardcodes / código muerto / descartes silenciosos.

1. Resumen funcional

P115 (S151-P115-COMPENREG, escrito en enero de 1999) ejecuta el control y la compensación contable regional de las operaciones en línea de un CSI (Centro de Sistemas Informáticos / plaza). Lee el archivo INFOICA (Información de Cuentas por Aplicar, extraída del ICA de cada nodo/host), valida cada movimiento, concilia parejas (operado/aplicado/pendiente/enviado/denegado), elimina duplicados y anulaciones, y produce dos interfaces contables: (a) el enlace al sistema S028 paso 010 para la compensación regional, y (b) el LOG-CSI que se envía al CSI corporativo (S030 paso 140) para la compensación nacional. Emite además una carátula de cifras de control y varios reportes de transmisión por sistema, por nodo y de operaciones eliminadas. (BR: RN-S151-766, RN-S151-770)

El flujo es un pipeline de 5 fases sobre archivos-LOG intermedios, cada una resuelta con un SORT de Unisys con OUTPUT PROCEDURE propios: SORT1 (detección de errores: duplicados, anulados, diálogo sin pareja), SORT2 (resumen y grabado de compensación nacional en LOG-CSI + archivo COMPENSACION), SORT3 (reportes de transmisión y enlace S028), SORT4 (pendientes — desactivado en este corpus, ver ⚠) y SORT5 (reporte de operaciones eliminadas). El programa se apoya en el copybook CRONOS2K (párrafos A2K-*) para conversión de fechas Y2K y en el copybook CPBAS para el manejo de reportes/DISPLAY.

⚠ Observación de corpus: gran parte de la salida impresa (WRITE LREPn ...) y toda la rama de PENDIENTES (archivo, SORT4 y párrafos 25xxx, 226xx-pend) están comentadas (prefijos ***, *ASM). El programa hoy calcula y concilia, pero no imprime físicamente los reportes ni persiste el archivo de pendientes; los acumuladores y cortes de control sí se ejecutan. Se marca cada caso en §4.

2.2 Layout clave — detalle INFOICA WS-REG-DET-INFOICA [P115 L986-1031]

Campos usados por la lógica de negocio (el registro X(160) se redefine así):

  • WS-RDI-NOD-ORI 9(02) — nodo origen
  • WS-RDI-CSI-DES 9(02) — CSI destino · RDI-CSI-DES-VAL = {1,2,4,6,10}

  • WS-RDI-APL-ORI 9(04) / WS-RDI-APL-DES 9(04) — aplicación (sistema) origen/destino
  • WS-RDI-STA-TRN 9(02) — status transacción: 1=ENVIADO 2=APLICADO 3=OPERADO 4=DENEGADO 5=PENDIENTE (RDI-STA-TRN-VAL = 1..5)

  • WS-RDI-MON-TRN 9(03) — clave de moneda
  • WS-RDI-FEC-CON 9(08) — fecha contable · WS-RDI-CVE-AUT X(20) — clave de autorización · WS-RDI-NUM-TRN 9(08)

  • LLAVE-COMP = FECHA-COMP 9(6) + CSI-LOCAL-COMP 9(2) + MONEDA-COMP 9(3) + APL-ORI-COMP 9(4) + CSI-FORANEO-COMP 9(2) + FILLER 9(1). 88s de validez: LOCAL/FORAN = {1,2,4,6,10}, MONEDA = 1..999, APL-ORI = 1..9999.

  • DUMMY-COMP 9(2) — discriminador registro control vs detalle.

P103 trabaja sobre el archivo secuencial (S151)S151/FILE/CONTROL/CORP, cuyo primer registro trae CSI y fecha de proceso y los siguientes la última fecha procesada por cada sistema, terminando en el sistema 999. Con parámetro 01 lee el header y publica la fecha en el atributo VALUE de la propia tarea para que el WFL la use. Con parámetro 02 calcula el siguiente día hábil con THECALENDAR de LOCSUP, imprime un listado que compara la fecha de cada sistema contra la del header, reabre el archivo en I-O y reescribe el header con la fecha proyectada.

@Configuration
public class ControlFechasJobConfig {

    /** El WFL pasaba 01 o 02; aquí es un JobParameter validado. */
    @Bean
    Job controlFechas(JobRepository repo, Step consultaFecha, Step proyectaFecha) {
        JobExecutionDecider modo = (je, se) -> new FlowExecutionStatus(
                switch (je.getJobParameters().getString("parametro")) {
                    case "01" -> "CONSULTA";
                    case "02" -> "PROYECTA";
                    default   -> throw new IllegalArgumentException(
                            "W77-PARAMETRO debe ser 01 o 02");   // en COBOL: STOP RUN sin hacer nada
                });
        return new JobBuilder("S151P103", repo)
                .start(modo)
                    .on("CONSULTA").to(consultaFecha)
                .from(modo)
                    .on("PROYECTA").to(proyectaFecha)
                .end()
                .build();
    }
}

    public RepeatStatus execute(StepContribution c, ChunkContext ctx) {
        HeaderControl h = control.leeHeader();        // OPEN INPUT + READ
        bitacora.info("INICIO PROCESO PARA CONSULTA DE FECHA DE PROCESO : " + h.fechaProceso());

        // CHANGE ATTRIBUTE VALUE OF MYSELF TO WKS-FEC-6D: el WFL lee la fecha como AAMMDD.
        // En Java se publica completa y el adaptador del orquestador decide el formato.
        ctx.getStepContext().getStepExecution().getJobExecution()
           .getExecutionContext().put("fechaProceso", h.fechaProceso());
        c.setExitStatus(new ExitStatus("COMPLETED",
                h.fechaProceso().format(DateTimeFormatter.ofPattern("yyMMdd"))));
        return RepeatStatus.FINISHED;
    }
}

List<RenglonEstatus> estatus(ControlCorporativo cc) {
    var renglones = new ArrayList<RenglonEstatus>();
    for (DetalleControl d : cc.sistemas()) {                     // AT END también termina
        if (d.esSentinela(props.sentinelaFin())) break;         // WKS-DET-SIST = 999
        String msg = d.fechaProceso().equals(cc.header().fechaProceso())
                ? "SE EJECUTO CORRECTAMENTE"
                : "NO HA SIDO PROCESADO DESDE";                 // seguido de la fecha del sistema
        renglones.add(new RenglonEstatus("%03d".formatted(d.sistema()), msg, d.fechaProceso()));
    }
    return renglones;   // informativo: un sistema atrasado no detiene la proyección
}
@Override

    LocalDate proxima = proyecta(cc.header());                   // segmento anterior

RN-S151-201P103 recibe un parámetro de entrada `W77-PARAMETRO` (PIC 9(02)) que determina su modo de operación. Si W77-PARAMETRO = 01, ejecuta CONSULTA: lee el archivo de control, proyecta la fecha en el atributo de valor del propio programa (`CHANGE ATTRIBUTE VALUE OF MYSELF`), y cierra. Si W77-PARAMETRO = 02, ejecuta PROYECTA: lee el control, calcula la próxima fecha hábil via THECALENDAR, genera el reporte de status de sistemas, y actualiza el archivo corporativo. El modo CONSULTA es used by otros programas del lote para conocer la fecha de proceso activa; el modo PROYECTA es ejecutado al final del lote para avanzar la fecha al día siguiente hábil.Despacho por W77-PARAMETRO · Modo consulta: la fecha viaja en el VALUE de la tarea
RN-S151-202P103 lee el archivo secuencial `(S151)S151/FILE/CONTROL/CORP` (declarado como A01-CONTROL, ORGANIZATION IS SEQUENTIAL). Este archivo tiene una estructura compuesta: el primer registro es el header con WKS-HD-CSI (CSI, 2 dígitos) y WKS-HD-FECPRO (fecha de proceso, 8 dígitos). Los registros siguientes son detalles por sistema: WKS-DET-SIST (sistema, 3 dígitos) y WKS-DET-FECPRO (fecha de proceso del sistema, 8 dígitos). El archivo es la fuente de verdad de la fecha contable activa del sistema S151. Es actualizado solo en modo PROYECTA al final del lote.Archivo CONTROL/CORP con título compilado · Header y detalle del control, parámetros de LOCSUP
RN-S151-203En modo PROYECTA, P103 llama a la rutina `THECALENDAR IN LOCSUP` con FORMATO=12, FUNCION=13, y WKS-FECHA2="00000001" (+1 día). THECALENDAR es el servicio de calendario de días hábiles bancarios del sistema S006 (LOCSUP). La función 13 con formato 12 calcula la próxima fecha hábil bancaria después de WKS-FECHA1 (fecha actual). El resultado se devuelve en WKS-FECHA1. Si W77-FUNCION > 0 (error), P103 aborta con SET MYSELF(STATUS) TO -1. La fecha calculada se guarda en W77-FECHA-PROFUT y luego se escribe en WKS-HD-FECPRO del archivo de control.Siguiente día hábil con THECALENDAR
RN-S151-204El archivo corporativo A01-CONTROL contiene registros de detalle para cada sistema dependiente de S151. La lectura secuencial de estos registros termina cuando se encuentra WKS-DET-SIST = 999 (sentinel de fin de lista), o cuando se llega al EOF. Esta regla determina cuántos sistemas son validados — cualquier sistema con WKS-DET-SIST < 999 es reportado. El sentinel 999 está hardcoded como condición de terminación del loop `000100-CHECA-STATUS`.Header y detalle del control, parámetros de LOCSUP · Estatus de cada sistema contra la fecha del header
RN-S151-205En modo PROYECTA, P103 lee todos los registros de detalle del archivo de control y para cada sistema verifica si su WKS-DET-FECPRO coincide con WKS-HD-FECPRO (la fecha de proceso del día). Los sistemas monitoreados son S084, S087, S408, S500 y S701. Si las fechas coinciden → "SE EJECUTO CORRECTAMENTE". Si no coinciden → "NO HA SIDO PROCESADO DESDE". Este reporte es el "ESTATUS DE PROCESO DE LOS SISTEMAS" que aparece en el encabezado (WLI-TIT2-RESUM). La validación es informativa — P103 no aborta si un sistema no procesó, solo lo reporta.Estatus de cada sistema contra la fecha del header
RN-S151-206Al finalizar la generación del reporte (en modo PROYECTA), P103 reabre el archivo de control en modo I-O y actualiza el header con la fecha del próximo proceso: `MOVE W77-FECHA-PROFUT TO WKS-HD-FECPRO` seguido de `REWRITE A01-REG-CONTROL`. Si el REWRITE falla (INVALID KEY), P103 reporta el error y aborta con SET MYSELF(STATUS) TO -1. Esta actualización es la última acción del lote — una vez que FECPRO se avanza, todos los programas del lote siguiente usarán la nueva fecha.Reapertura en I-O y reescritura del header
RN-S151-207P103 usa el mecanismo Unisys `SET MYSELF(STATUS) TO -1` para indicar fallo al WFL orquestador. Este mecanismo es equivalente a un código de retorno no-zero en sistemas convencionales. Se activa en dos situaciones: (1) Error en THECALENDAR (W77-FUNCION > 0 después de la llamada). (2) Error en REWRITE del archivo de control (INVALID KEY). Cuando el WFL recibe STATUS=-1, puede activar ON TASKFAULT y ejecutar su lógica de recuperación (en SUB103, si existe: ir a FALLA(103) o BACKFORZA103).Siguiente día hábil con THECALENDAR · Reapertura en I-O y reescritura del header
RN-S151-917En modo consulta, P103 lee el registro header del archivo de control corporativo (S151/FILE/CONTROL/CORP), extrae la fecha de proceso (WKS-HD-FECPRO) y la publica hacia el orquestador del batch asignándola al atributo VALUE de la propia tarea (en formato de 6 dígitos). Así otros pasos del WFL pueden obtener la fecha de proceso vigente del sistema.Modo consulta: la fecha viaja en el VALUE de la tarea
RN-S151-918En modo proyección, P103 calcula la próxima fecha de proceso a partir de la fecha actual del header mediante THECALENDAR de LOCSUP (función 13, formato 12 → siguiente día hábil). Si el calendario falla, aborta con estatus -1 y no actualiza el control. Riesgos de migración
Parámetro inválido termina con éxito

Si W77-PARAMETRO no es 01 ni 02, 000000-PROGRAMA (líneas 323-329) llega a STOP RUN sin hacer nada y sin marcar error.

Abort sin salida explícita

Después de SET MYSELF(STATUS) TO -1 (líneas 497 y 533) no hay STOP RUN. Si el MCP no detiene la tarea en ese momento, el flujo continúa hasta reescribir el header.

INVALID KEY en archivo secuencial

El REWRITE de la línea 522 usa INVALID KEY sobre un archivo ORGANIZATION IS SEQUENTIAL, donde esa condición no aplica; el manejo de error podría ser código muerto.

Ventana entre cierre y reapertura

El archivo se cierra (línea 517) y se reabre en I-O (línea 519) antes de reescribir; otro proceso podría modificarlo en ese intervalo.

Fecha de seis dígitos hacia el WFL

CHANGE ATTRIBUTE VALUE OF MYSELF recibe WKS-FEC-6D (línea 443): la fecha publicada no lleva siglo.

Pivote de siglo fijo

Las líneas 379-382 reconstruyen el siglo con una ventana en 50 aunque la fecha ya trae ocho dígitos.

Pendiente de revisión SME
  • RN-S151-205 y RN-S151-920 dicen que el reporte de estatus se genera para S084, S087, S408, S500 y S701; esa lista solo aparece en el comentario de las líneas 8-11. En el código los sistemas salen del archivo de control, por lo que la lista real depende de su contenido.
  • Confirmar con SME si SET MYSELF(STATUS) TO -1 termina la tarea de inmediato en esta versión del MCP.
  • Confirmar si la rama INVALID KEY del REWRITE (líneas 522-533) se ha ejecutado alguna vez.
  • Validar si THECALENDAR función 13 con desplazamiento 1 devuelve el siguiente día hábil o el siguiente día natural.
  • W77-PARAMETRO está declarado como 77 en WORKING-STORAGE y se usa en PROCEDURE DIVISION USING sin LINKAGE SECTION; confirmar cómo lo recibe del WFL.

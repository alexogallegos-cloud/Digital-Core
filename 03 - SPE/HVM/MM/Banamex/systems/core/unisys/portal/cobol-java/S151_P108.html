S151 · P108 a Java 21 Spring Boot

Lee LOG151, la bitácora de movimientos punteados, junto con su complemento LOG151-COMP, y espera nuevos registros cuando encuentra la marca de función 99 hasta recibir la función 98 o la 97 de S500. Cada movimiento autorizado (función 1, estatus 1 o 2) se copia a MOVIMIENTOS con una fila por clave de transacción y, si va a contabilidad, se escribe en MOVCONTASORT y MOVCONTASORTFS. Esos archivos se ordenan, se agrupan por filial, origen, moneda, sector, producto, instrumento, sucursal, transacción y esquema, y cada grupo se traduce a cuentas contables con el archivo indexado ARCH-ESQCON para escribir MOVCONTABLES (ALFA) y MOVCONTABLESFS (Full-Suite). Después genera la bitácora S028, el cuadre contable, la posición y los rechazos, y dispara P110 por WFL.

/** A00-R01-REGMOV: un registro de LOG151 (REG-LOGS151 PIC X(450)). */
public record MovimientoLog(
        int funcion,                 // 9(02) COMP: 1 movimiento, 97 paridad/fin S500, 98 fin, 99 espera
        int formato,
        int sistema,                 // 9(04) COMP: 500 activa el filtro Teletón y el fin por paridad
        int producto,                // 9(04) COMP (REDEFINES TIPOCREDITO / TIPO-PROD)
        int instrumento,             // 9(02) COMP (REDEFINES PORTAFOLIO / FONDO)
        List<Imputacion> imputaciones,   // CVEIMP X(95): OCCURS 5 o CVETRAN1..5, misma memoria
        int moneda,                  // 1 MN, 5 dólares
        int origen,                  // 1, 2 o 3 según el canal; decide bitácora y contabilidad
        String cliente,              // 9(12) COMP: String para no perder ceros
        int sector,                  // 9(02) COMP: sector CNBV antes de normalizar
        int sucursalPromotora,
        String contrato,             // 9(16) COMP
        int status,                  // A00-R01-STATUS (línea 2287): 1 contable, 2 solo bitácora
        int tipoProceso) {           // A00-R01-TIPO-PROC; resto de campos omitidos en el extracto

    /** A00-R01-ELE-CVEIMP: una clave de transacción con su esquema e importe. */
    public record Imputacion(int cveTran,          // 9(06) COMP; 0 = posición vacía
                             int indLeyenda,
                             int esquemaContable,  // 9(04) COMP (REDEFINES A00-R01-TM)
                             BigDecimal importe,   // 9(16)V99 COMP -> escala 2
                             int cveDesvio,
                             int guiaDesvio) {}

    /** El COBOL recorre las cinco posiciones hasta la primera CVETRAN en cero (21100, línea 7405). */
    public List<Imputacion> vigentes() {
        return imputaciones.stream().takeWhile(i -> i.cveTran() != 0).toList();
    }
}

@ConfigurationProperties("p108")
public record P108Properties(List<EsquemaValido> esquemasValidos) {
    public record EsquemaValido(int producto, int instrumento, int moneda,
                                Map<Integer, List<Integer>> esquemas) {}
}

/** 21124-VALIDA-ESQ-SEC: producto-instrumento-moneda, luego esquema, luego sector. */
@Component
@RequiredArgsConstructor
public class ValidadorEsquemaSector {
    private final P108Properties props;

    public Optional<String> valida(int prd, int ins, int mon, int esquema, int sector) {
        var pim = props.esquemasValidos().stream()
                .filter(e -> e.producto() == prd && e.instrumento() == ins && e.moneda() == mon)
                .findFirst();
        if (pim.isEmpty())                        return Optional.of("PROD-INS NO EXISTE");
        var sectores = pim.get().esquemas().get(esquema);
        if (sectores == null)                     return Optional.of("ESQUEMA NO EXISTE");
        return sectores.contains(sector) ? Optional.empty() : Optional.of("SECTOR NO EXISTE");
    }
}

/**
 * 21000-ESCOGE-MOVS: LOG151 crece mientras P108 lo lee. La función 99 marca el fin
 * físico actual; P108 libera el archivo, espera y vuelve a leer desde lo ya procesado.
 */
@Component
@StepScope
@RequiredArgsConstructor
public class Log151ResidenteReader implements ItemReader<MovimientoLog> {

    private final Log151Archivo log;          // acceso relativo por LOG-KEY y complemento LOG151-COMP
    private final P108Properties props;       // p108.espera-funcion-99: 120s  (WAIT(120))
    private final ControlOperador operador;   // HI 2 del operador (W88-FIN-POR-HI)
    private long leidos;                      // W77-TP-REG-LEIDOS

    @BeforeStep
    void abre() {
        log.abre();
        log.leeSiguiente();                   // el fuente lee y descarta un primer registro (6736)
        leidos = 2;                           // ADD 2 TO W77-TP-REG-LEIDOS
    }

    @Override
    public MovimientoLog read() throws InterruptedException {
        MovimientoLog m = log.leeSiguiente();
        while (m != null && m.funcion() == 99) {
            if (operador.finSolicitado()) return null;
            log.liberaYCierra();                              // CLOSE LOG151 WITH RELEASE
            Thread.sleep(props.esperaFuncion99().toMillis());
            log.abre();
            m = log.leePosicion(leidos);                      // SEEK LOG151 RECORD con LOG-KEY
        }
        if (m == null || m.funcion() == 98) return null;      // AT END o cierre del día
        leidos++;
        return log.conComplemento(m);                         // APUDES > 0: READ LOG151-COMP
    }
}
/** 20060-FILTRA-MOVS-TELETON + 21010-SELECCIONA-REG. */
@Component
@StepScope
@RequiredArgsConstructor
public class SeleccionMovimientoProcessor implements ItemProcessor<MovimientoLog, MovimientoLog> {

    private static final Set<Integer> PROC_TELETON = Set.of(40, 41, 42, 43);   // p108.teleton.tipos-proceso
    private final ParidadDelDia paridad;   // W77-PARIDAD-C-DLS / W77-PARIDAD-A-DLS
    private final FinDeLote fin;           // el reader consulta esta bandera
    private final Contadores cont;         // W77-TP-REG-PROCESADOS / W77-TP-REG-ELIMINADOS

    @Override
    public MovimientoLog process(MovimientoLog m) {
        if (m.sistema() == 500 && PROC_TELETON.contains(m.tipoProceso())) {
            return null;                   // NEXT SENTENCE: ni se cuenta ni se procesa
        }
        if (m.funcion() == 97 && m.sistema() == 500) {
            fin.marca();                   // MOVE 1 TO W77-EOF
            // IMPORTE1/100 hacia PIC 9(04)V9(04): la escala 4 es exacta; el tope entero no
            paridad.fija(Paridad.de9v4(m.importe(1).movePointLeft(2)),
                         Paridad.de9v4(m.importe(2).movePointLeft(2)));
        }
        if (m.funcion() == 1 && (m.status() == 1 || m.status() == 2)) {
            cont.procesado();
            return m.conFilial(intercompany.buscaPorCliente(m.cliente()));   // 21010-CARGA-INTERCOMPANY
        }
        cont.eliminado();
        return null;
    }
}

/** Lee MOVCONTASORT ya ordenado y entrega un grupo por llave. */
@RequiredArgsConstructor
public class AgrupadorContableReader implements ItemReader<GrupoContable> {

    private final SingleItemPeekableItemReader<MovContaSort> sort;

    @Override
    public GrupoContable read() throws Exception {
        MovContaSort primero = sort.read();
        if (primero == null) return null;
        var llave = primero.llave();
        BigDecimal importe = primero.importe();
        // 20110-PROC-MONEDA: moneda distinta de 1 enciende W77-ABO-SORT y corta tras un registro
        if (primero.moneda() == 1) {
            for (MovContaSort sig = sort.peek(); sig != null && sig.llave().equals(llave); sig = sort.peek()) {
                importe = Importe.tope14v2(importe.add(sort.read().importe()));   // W77-IMP-SORT 9(14)V99
            }
        }
        MovContaSort siguiente = sort.peek();   // ver riesgo: el COBOL toma actividad y banca de aquí
        return new GrupoContable(llave, primero, importe, siguiente);
    }
}

@Service
@RequiredArgsConstructor
public class GeneradorAsientos {

    private final CatalogoTransacciones catalogo;        // WKS-PT-AGR-CONT, WKS-CESQ-CLAVE
    private final EsquemaContableRepository esquemas;    // ARCH-ESQCON (KEYEDIOII) -> JPA
    private final ValidadorEsquemaSector validador;
    private final CuentaPuente1503 puente;
    private final Acumulado4014 acumulado4014;
    private final ReporteErrores reporte;

    /** 21102-GRABA-MOVCONT: un grupo de MOVCONTASORT produce cero o más asientos ALFA. */
    @Transactional(readOnly = true)
    public List<AsientoContable> genera(GrupoContable g) {
        var asientos = new ArrayList<AsientoContable>();
        int agrupador = catalogo.agrupadorContable(g.cveTran());
        if (agrupador < 1 || agrupador > 300 || g.esquema() < 1 || g.esquema() > 109) {
            reporte.escribe("ERROR EN DATOS CONTABLES,AGRUPADOR %d CVE.CONT. %d CVE.TRAN. %d"
                    .formatted(agrupador, g.esquema(), g.cveTran()));
        } else {
            int clave = catalogo.claveEsquema(agrupador, g.esquema());
            if (clave == 0) {
                reporte.registra(g, "ESQUEMA NO EXISTE");
            } else {
                esquemas.findTop10ByClaveOrderByOrden(clave).stream()      // 21121, hasta 10 renglones
                        .filter(e -> e.naturaleza() == 1 || e.naturaleza() == 2)
                        .map(e -> puente.ajusta(AsientoContable.de(g, e), g.origen()))
                        .forEach(asientos::add);
                // La validación ocurre DESPUÉS de generar los asientos: solo informa.
                validador.valida(g.producto(), g.instrumento(), g.moneda(), g.esquema(), g.sector())
                         .ifPresent(motivo -> reporte.registra(g, motivo));
            }
        }
        // Estas dos reglas corren aunque el bloque anterior haya fallado.
        if ((g.cveTran() == 1009 || g.cveTran() == 3011) && g.origen() == 3) {
            asientos.add(puente.asientoCargo(g));                         // 21123-GRABA-CUENTA-1009
        }
        if (g.cveTran() == 4014 && g.origen() == 3) {
            acumulado4014.suma(g);                                        // 21123-GRABA-CUENTA-4014
        }
        return asientos;
    }
}

    private final Map<Celda, BigDecimal> totales = new HashMap<>();

    public void suma(GrupoContable g) {
        int m = (g.moneda() == 1 || g.moneda() == 5) ? g.moneda() : 1;          // otra moneda cuenta como MN

Riesgos de migración
Errores de validación que no se imprimen

21105-IMPRIME-ERRORES (líneas 7459-7470) mueve los datos a WSR-REPORTE-DETALLE y suma WS-NUM-LINERR, pero no hay ningún WRITE de ese renglón ni llamada a 21107-IMPRIME-ENCABERR. Los rechazos por esquema, sector, producto-instrumento y sector en ceros no dejan rastro.

Validación posterior a la escritura

En 21102 (líneas 7558-7569) los asientos de MOVCONTABLES se escriben en 21121 antes de ejecutar 21124-VALIDA-ESQ-SEC. Un esquema o sector inválido no impide que el asiento llegue a S500.

Truncamiento de importes

El importe del movimiento es PIC 9(16)V99 y los campos de MOVCONTASORT, MOVCONTABLES y MOVIMIENTOS son PIC 9(14)V99. El MOVE pierde los dígitos altos sin aviso.

Actividad y banca sin origen confiable

RMS-ACTIVIDAD y RMS-BANCA no se asignan al escribir MOVCONTASORT y, al generar el asiento, se leen del registro que provocó el corte. W77-ACT-SORT y W77-BAN-SORT se guardan pero nunca se usan.

Sector 15 duplicado y tabla de esquemas con huecos

El sector 15 aparece en dos ramas de la normalización (líneas 7340 y 7343) y las entradas 6 a 8 de la tabla de esquemas dejan vacía la posición 1 de sectores, lo que vuelve inválidos esos esquemas en dólares.

Hardcodes contables

Cuentas 150301000000, 150301100400 y 150301041000, CSI 04 y 35, tipos de proceso Teletón 40 a 43, producto 66 instrumento 6 para reembolsos, límites 300 y 109 de agrupador y esquema, y la espera de 120 segundos están compilados. Se trasladan a application.yml.

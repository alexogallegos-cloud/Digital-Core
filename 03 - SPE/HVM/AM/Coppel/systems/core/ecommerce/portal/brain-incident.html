Escenario 0 · INC-2026-09-16-001
Ocurre incidente — BASKET_POOL_EXHAUSTED
Escenario de degradación del servicio de carrito. Cubre la experiencia del usuario, la observabilidad y la resolución.
Dado  que el pool de conexiones de SFCC Basket API
       alcanza su límite de 50 conexiones simultáneas
Y     el subgraph carrito recibe la mutación addToCart

Cuando el usuario hace tap en "Agregar al carrito"

Entonces el UI aplica optimistic update (contador +1)
Y       SFCC Basket API responde HTTP 503 en 2 003 ms
Y       el subgraph emite error code BASKET_POOL_EXHAUSTED
Y       el carrito se revierte (contador −1, rollback)
Y       el usuario ve toast de error en rojo
Y       Datadog RUM registra checkout.add_to_cart.error

# SLO de resolución
Y       si el error se sostiene > 2 min → alerta P1 a N3
Y       resolución esperada < 10 min (MTTR N3)
⚠ Diferencia spec vs. producción
El spec define timeout: 3 000 ms con rollback automático y toast de error. En producción, el pool de SFCC se agotó sin que el circuit breaker activara el fallback — el spec indica que debe haber un retry con backoff antes de emitir el error al usuario.

Catálogo de errores — carrito subgraph
Errores definidos en el spec
BASKET_POOL_EXHAUSTED · HTTP 503 · retryable: true
Causa: El pool de conexiones de SFCC Basket API (límite=50) está saturado.
Trigger: Pico de tráfico > 50 addToCart/seg simultáneos.
UI esperado: Rollback optimistic, toast rojo, retry sugerido.
Acción N3: Ampliar pool SFCC o activar queue de requests.
Impacto: $180,000 MXN/min · alerta en <2 min.
OUT_OF_STOCK · HTTP 409 · retryable: false
Producto sin inventario disponible. No afecta el pool de carrito.
CART_MAX_ITEMS · HTTP 400 · retryable: false
El carrito ya alcanzó el límite de 50 ítems por sesión.
Criterios de aceptación — US-003
Estado actual vs. spec
  • ✓
    AC-1: El botón aplica optimistic update (contador +1) antes de la respuesta del API.
  • ✓
    AC-2: Si el API responde éxito, el carrito persiste y el contador se mantiene.
  • ✓
    AC-3: Si el API falla, el carrito se revierte y el contador regresa al valor anterior.
  • ✓
    AC-4: El usuario ve un toast de error en rojo con mensaje claro.
  • ✗
    AC-5: FALLANDO — El subgraph debe ejecutar 1 retry con backoff de 500 ms antes de escalar el error al cliente. En producción se salta el retry y devuelve 503 directamente.
  • ✗
    AC-6: FALLANDO — El circuit breaker debe abrirse tras 5 errores consecutivos y activar el fallback de cola. El circuit breaker no está configurado en el ambiente productivo.
  • ✓
    AC-7: Datadog RUM registra el evento checkout.add_to_cart.error con el código de error y la latencia.
  • ✓
    AC-8: La alerta P1 se dispara si la tasa de error supera el 20% durante 2 minutos consecutivos.

Pipeline de extracción — de código ABAP a cerebro semántico
Cinco etapas de transformación convierten archivos .abap en un grafo semántico consultable por agentes de AI.
Paso 1
parse-abap.py
Parsea archivos .abap — extrae objetos, métodos, dependencias (CALL FUNCTION/NEW), acceso SQL (SELECT/UPDATE/INSERT/DELETE) y autoría desde headers.
→ objects-inventory.json
→
Paso 2
extract-vocabulary.py
Tokeniza identificadores ABAP — clasifica en ENTIDAD, ACCION, REG, PREFIJO, MODIF y alinea cada término al modelo de dominio BIAN de microfinanzas.
→ vocab-gentera.json
→
Paso 3
extract-rules.py
Detecta 6 tipos de patrones de lógica de negocio: IF/CHECK, AUTHORITY-CHECK, MESSAGE E, RAISE, CATCH y WHERE clauses. Produce id, tipo, condición, business_name y riesgo.
→ rules-gentera.json
→
Paso 4
build-brain.py
Construye brain.db: carga objetos, reglas, vocabulario y dominios BIAN en SQLite. Crea índices FTS5 para búsqueda semántica sobre reglas, términos y objetos.
→ digital-brain/brain.db
→
Agente API
brain.py
GENCOREBrain — interfaz Python de consulta: reglas por objeto, por tipo, por riesgo, búsqueda semántica FTS5, candidatos de migración, diagramas Mermaid.
→ GENCOREBrain()

Arquitectura del Digital Brain — Tres capas

Hallazgos clave del primer análisis
Lo más relevante detectado al analizar /CBB/CL_DB_TVARVC — el primer archivo ABAP del corpus Gentera.
Señal IFRS detectada
Las 4 reglas de riesgo MEDIO corresponden a MESSAGE e005(/cbb/msg_ifrs_cn) — un mensaje del namespace IFRS de Compartamos Banco. Esta clase gestiona parámetros que controlan procesos probablemente sensibles a IFRS 9. Confirmar con SME de negocio antes de tomar la decisión 7R para este dominio.
Patrón Singleton
El método S_GET_INSTANCE implementa el patrón Singleton — garantiza una única instancia de la clase que administra TVARVC. En la migración al target cloud, este singleton debe modelarse explícitamente como bean Spring singleton o ApplicationScoped de Quarkus, no como objeto libre.
Feature flags sobre TVARVC
Los métodos IS_EVENT_ACTIVE e IS_EVENT_ACTIVE_HIGH implementan un sistema de feature flags sobre la tabla SAP estándar TVARVC. El mecanismo controla la activación de eventos de negocio. En el target cloud debe migrarse como servicio de configuración dedicado (p.ej., AWS AppConfig, LaunchDarkly).
Namespace /CBB/ organizado
Todo el código está bajo el namespace /CBB/ (Compartamos Banco), no en prefijos Z/Y ad-hoc. Esto indica desarrollo custom estructurado. Para ampliar el corpus solicitar export TADIR filtrando DEVCLASS LIKE '/CBB/%' y también '/CBCR/%' (segundo namespace detectado).

Cómo escalar el corpus
Con un objeto analizado, el brain está en estado inicial. Para cubrir el landscape completo de Gentera, agregar archivos y re-ejecutar el pipeline.
Datos a solicitar al cliente
  1. Export de TADIR filtrando DEVCLASS LIKE '/CBB/%' y DEVCLASS LIKE '/CBCR/%' — inventario completo de objetos custom
  2. Bulk export de fuentes ABAP vía ABAPGit o RFC_READ_REPORT — archivos .abap por clase, programa y función
  3. Export CSV de tablas Z (DD02L con TABNAME LIKE '/CBB/%') — modelo de datos del namespace custom
  4. Lista de módulos SAP activos — para enriquecer el mapeo a dominios BIAN (FI, SD, HCM, etc.)
Con cada nuevo archivo: copiar a source/CLASS/, source/PROG/ o source/FUGR/ según tipo, luego ejecutar:
python parse-abap.py && python extract-vocabulary.py && python extract-rules.py && python digital-brain/build-brain.py

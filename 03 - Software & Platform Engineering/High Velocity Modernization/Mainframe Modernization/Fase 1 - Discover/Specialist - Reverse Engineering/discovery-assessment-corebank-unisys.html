Executive summary

Consolidated output of the Discover phase for the core banking system SISTEMA-CORE-UNISYS (Unisys ClearPath, ~830 programs). This deliverable gathers the artifacts of RE methodology stages 0 through 4 together with the tooling input, and enables the decision that closes the phase: the 7R decision per program and the wave plan.

Nature of this case. This Assessment uses a synthetic system from the Training Lab as a sample (graph-as-data, 830 nodes). The structural dimensions (graph, hubs, cycles, domains, access) are real and measured; the dimensions that require deep source code or runtime telemetry — business rules (Stage 3) and the NFR baseline — are flagged [TEMPLATE] because the synthetic corpus does not contain them. In a real engagement these are populated from the client source and SMF data.

Discover verdict — what we found

  • Four utility hubs concentrate the blast radius (logger, date converter, DMSII wrappers): any change touches them. They are mandatory foundation work.
  • Clear CQRS split: 357 inquiry programs (low risk, early waves) versus 461 update programs (ACID core, late).
  • 114 Retire candidates: 30 in a dead cluster plus 84 emergent orphans to validate against production logs.
  • Domains cannot be read from the call graph: multi-signal fusion with the copybook layer raises clustering purity from 65% to 97%; 15 programs escalate to a human decision.
  • Nine cycles (105 programs) break migration ordering: each SCC migrates as one indivisible unit.

Data and coupling Stage 2

The data model and, above all, the copybook coupling — the hidden hairball that does not appear in the call graph and is the number one reason a Strangler Fig fails.

Copybook coupling — cross-cutting layer

CopybookProgramsMeaningSeam risk
CB-RETCODE725standard return codeuniversal (ignore for domain)
CB-ENCABEZADO681record headeruniversal
CB-IMPORTE404monetary amountspans 5 domains
CB-CLIENTE340customer mastercross-domain
CB-CUENTA239account mastercross-domain
CB-ASIENTO227accounting entry (GL)spans 4 domains
Critical finding. Two programs that never call each other are still coupled when they share CB-ASIENTO or CB-CUENTA. This coupling is invisible in the call graph and must govern the service cut, not the calls alone.

NFR baseline and tooling Stage 1.4

NFR baseline — non-functional specification [TEMPLATE, requires telemetry]

An NFR is not inferred: it is measured from the real behavior of the legacy (SMF type 30 and 110, transaction catalog, data volumes). The synthetic corpus has no runtime data, so the baseline is shown as a template with the dimensions to instrument.

NFR dimensionSource in a real engagementStatus here
Throughput (peak / avg TPS)SMF type 110 (CICS), region monitorinstrument

Access pattern (consistency)inquiry vs update classificationmeasured: 357 inquiry, 461 update
Criticality (blast radius)hub fan-inmeasured
Mapping to SLOs (closed in DESIGN): the baseline is the ceiling. The target for the new system: P95 latency no worse than the mainframe (SLO-MM-02), availability at least 99.95% (SLO-MM-03), equivalence drift under 0.01% (SLO-MM-01).

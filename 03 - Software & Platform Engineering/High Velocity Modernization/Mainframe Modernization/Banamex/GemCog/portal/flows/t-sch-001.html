Reglas de negocio

RN-S500-009 — P075: llave de inicio del ciclo nocturno S500
P075 CambioDia T-SCH-003 · T-SCH-004 · T-SCH-005 🔴 CRÍTICO W77-PARAM-WFL · INIBATCH · WKS-L080-RESULT
P075 es la llave de inicio del ciclo nocturno de S500. Sin la notificación INIBATCH a P080, ningún proceso batch del día puede avanzar. El parámetro W77-PARAM-WFL=1 es la única guarda de seguridad — sin él la notificación no se emite. El resultado de INIBATCH se evalúa en WKS-L080-RESULT: 0=OK, >0=error. Solo cuando RESULT>0 se marca STATUS=-1 y el WFL puede detener el job stream.
* P075 — Guarda de seguridad y notificación de cierre IF W77-PARAM-WFL = 1 CALL S500L080CTRL USING INIBATCH WKS-L080-RESULT IF WKS-L080-RESULT > 0 PERFORM 000-030-IMPRIME-MENSAJE *> "ERROR EN INIBATCH" CHANGE ATTRIBUTE STATUS = -1 *> WFL detecta y detiene job stream END-IF END-IF *> Si W77-PARAM-WFL ≠ 1 → no se emite ninguna notificación (dry-run del WFL)
Impacto migración: En cloud, el acoplamiento directo P075→P080 via INIBATCH debe reemplazarse por un evento publicado (SNS/Pub-Sub/EventBridge) al orquestador central. El scheduler no debe depender de una llamada sincrónica entre programas COBOL — el orquestador debe ser el único punto de control del inicio del ciclo nocturno.
RN-S500-010 — Falla silenciosa en resolución de S500L080CTRL (DAME_TIT)
P075 CambioDia T-SCH-002 🟠 AMBER DAME_TIT · CTLVERS
Si DAME_TIT falla al resolver S500L080CTRL en CTLVERS, el mensaje de error se registra pero el STATUS del programa NO se marca como fallido. P080 nunca recibe la notificación INIBATCH y el ciclo batch de S500 queda bloqueado sin señal visible al WFL scheduler. El scheduler continúa creyendo que el cierre fue exitoso porque STATUS=0.
* T-SCH-002 — Resolución de título físico de P080 CALL CTLVERS USING DAME_TIT "S500L080CTRL" WKS-TITULO-L080 IF WKS-TITULO-L080 = SPACES PERFORM 000-030-IMPRIME-MENSAJE *> mensaje de error registrado * CHANGE ATTRIBUTE STATUS = -1 *> NO SE HACE — STATUS queda en 0 GO TO P075-EXIT *> sale sin notificar — ciclo bloqueado END-IF
Impacto migración: En el sistema destino, el health-check del servicio equivalente a P080 debe ser explícito y verificable antes de proceder. Una falla en la resolución del endpoint debe ser un error fatal con abort y alerta P1 — no un mensaje registrado con salida silenciosa.
RN-S500-011 — P100: único punto de verdad temporal del sistema S500
P100 Fecha-de-Proceso T-SCH-006..015 oracle de fechas · S006LOCSUP
P100 es el único punto de verdad temporal del sistema. Implementa opciones 0..9 y 31 para toda la aritmética de fechas bancarias. Ningún programa debería calcular fechas de proceso de forma independiente — toda la aritmética de días hábiles y naturales pasa por S006LOCSUP función 15. El acceso a S500B02CONTROL (fecha de línea, fecha de lote, nodo activo) es obligatorio al inicio de cualquier consulta.
* P100 — Opciones de cálculo de fechas bancarias EVALUATE WKS-OPCION WHEN 0 *> opción 0: fecha de línea sin proyección (default) WHEN 5 PERFORM SCH-014-FECHA-MANUAL WHEN 6 PERFORM SCH-010-ULTIMO-DIA-MES-ANTERIOR WHEN 7 PERFORM SCH-011-PRIMER-DIA-MES-ACTUAL WHEN 8 MOVE B02-FECHA-LINEA TO WKS-FECHA-RESULTADO *> retorna fecha de línea WHEN 9 PERFORM SCH-013-INDICADOR-TELTON WHEN 31 MOVE B02-USO-FUTURO-05 TO WKS-NODO-RESULTADO *> retorna nodo activo WHEN OTHER *> si opción > 0 AND días > 0 al mismo tiempo → fallback silencioso MOVE B02-FECHA-LINEA TO WKS-FECHA-RESULTADO END-EVALUATE *> Proyección N días: siempre vía S006LOCSUP función 15 CALL S006LOCSUP USING FUNCION-15 B02-FECHA-LINEA WKS-DIAS WKS-FECHA-RESULTADO
Impacto migración: P100 debe migrarse como microservicio de calendarios bancarios. S006LOCSUP función 15 contiene el calendario de días hábiles de Banamex — debe migrarse como dato (tabla de días festivos + reglas de cálculo), no como código. El microservicio debe exponer un API REST con los mismos 7+ tipos de cálculo de fecha que P100.
RN-S500-012 — Fallback silencioso P100 ante parámetros inválidos
P100 Fecha-de-Proceso T-SCH-012 🟠 AMBER fallback · B02-FECHA-LINEA
Si el caller envía una combinación inválida de parámetros (opción > 0 AND días > 0 al mismo tiempo, o opción 3 con días > 1), P100 retorna B02-FECHA-LINEA directamente sin emitir ningún error al caller. El caller puede interpretar este resultado como válido cuando en realidad se disparó el fallback por error de integración. Dos corridas con los mismos parámetros producen el mismo resultado, ocultando el defecto.
Impacto migración: El microservicio destino debe devolver HTTP 400 (Bad Request) ante parámetros inválidos — no silenciosamente retornar la fecha de línea. Agregar validación de entrada explícita en el API con códigos de error descriptivos. Implementar pruebas de equivalencia que cubran específicamente los casos límite de combinaciones inválidas.

Vocabulario

INIBATCH
Entry point · S500L080CTRL
Función en S500L080CTRL que notifica a P080 el cierre del día bancario. Sin esta llamada, el ciclo nocturno de S500 no puede arrancar. P075 la invoca solo cuando W77-PARAM-WFL=1 y S500L080CTRL fue resuelto exitosamente por DAME_TIT.
S500B02CONTROL
Dataset DMSII · registro de control S500
Registro de control del sistema S500. Contiene la fecha de línea (B02-FECHA-LINEA), la fecha de lote (B02-FECHA-LOTE), el nodo activo (B02-USO-FUTURO-05) y el indicador de campaña Teletón. Es la fuente primaria de todas las consultas de fecha en P100.
S006LOCSUP
Librería · cálculo de fechas bancarias
Librería de cálculo de fechas bancarias de Banamex. Función 15: proyección de N días hábiles o naturales desde una fecha base. Contiene el calendario oficial de días festivos y hábiles bancarios. Ningún programa debe calcular fechas bancarias sin pasar por esta librería.
W77-PARAM-WFL
PIC 9(1) · parámetro enviado por WFL
Parámetro enviado por el WFL orquestador a P075. Debe ser 1 para que P075 emita la notificación INIBATCH de cierre del día bancario. Es la única guarda de seguridad que controla si P075 dispara o no el inicio del ciclo nocturno de S500.
WKS-L080-RESULT
PIC 9(2) · resultado INIBATCH
Resultado devuelto por S500L080CTRL tras la invocación INIBATCH. 0 = P080 aceptó la notificación y el ciclo nocturno puede arrancar. Cualquier valor mayor que 0 indica que P080 rechazó la notificación — P075 debe marcar STATUS=-1 para que el WFL detenga el job stream.
FECPRO
PIC 9(8) · fecha de proceso AAAAMMDD
Fecha de proceso oficial del sistema en formato AAAAMMDD. Es el anchor temporal de todos los movimientos del día. Normalmente coincide con B02-FECHA-LINEA; puede diferir en corridas de recuperación o reprocesos.
FECCON
PIC 9(8) · fecha de contabilización
Fecha de contabilización de los movimientos. Normalmente igual a FECPRO; puede diferir en recuperaciones o cuando un movimiento del día anterior se contabiliza al día siguiente. Distinción relevante para el GL y la conciliación CNBV.
B02-FECHA-LINEA
PIC 9(8) · fecha de operación en línea
Fecha de operación en línea leída desde S500B02CONTROL. Base de todas las proyecciones de P100 — opciones 6, 7, 8 y el fallback silencioso retornan esta fecha o la calculan a partir de ella. Es la fuente de verdad temporal del sistema.

Hallazgos de migración — P075 CambioDia + P100 Fecha-de-Proceso

Tarea Hallazgo Severidad Acción requerida
T-SCH-004 Acoplamiento P075→P080: el cierre del día bancario depende de una llamada directa y sincrónica entre programas COBOL (P075 llama INIBATCH en S500L080CTRL). Sin esta notificación el ciclo nocturno completo queda bloqueado. 🔴 CRÍTICO En cloud: reemplazar INIBATCH por un evento publicado (SNS/Pub-Sub/EventBridge) al orquestador central. El scheduler cloud es el único punto de control del inicio del ciclo nocturno — no debe existir acoplamiento directo entre servicios.
T-SCH-002 Falla silenciosa DAME_TIT: si la resolución del título físico de P080 falla, P075 sale sin STATUS=-1. El WFL scheduler no detecta el error y el ciclo batch queda bloqueado sin señal visible. 🟠 ALTO En cloud: el health-check del servicio equivalente a P080 debe ser explícito, verificable y sincrónico antes de proceder. Falla de health-check = falla fatal con abort y alerta P1 — no salida silenciosa.
T-SCH-012 Fallback silencioso P100: parámetros inválidos retornan B02-FECHA-LINEA sin error. El caller puede usar fechas incorrectas sin saberlo — error de integración oculto en producción. 🟠 ALTO El microservicio de fechas destino debe devolver HTTP 400 ante parámetros inválidos. Implementar validación de entrada explícita con códigos de error descriptivos. Cubrir casos límite en pruebas de equivalencia.
T-SCH-009 Calendario bancario en S006LOCSUP: la lógica de días hábiles/festivos está embebida en código COBOL (librería S006LOCSUP función 15). No existe una fuente de datos externa del calendario — el calendario está hardcodeado en la librería. 🟠 ALTO Migrar como tabla de días festivos en base de datos relacional + servicio de cálculo de fechas. El calendario debe ser administrable (agregar días festivos sin redeploy). Validar contra el calendario oficial BANXICO antes del cutover.
T-SCH-003 Acoplamiento temporal del orquestador: W77-PARAM-WFL=1 como única guarda de seguridad del cierre del día. Si el WFL envía PARAM≠1 por error, P075 no notifica y el ciclo nocturno no arranca — sin error visible. 🟡 MEDIO En el orquestador cloud, la condición de inicio del ciclo nocturno debe ser explícita, auditable y configurable. Eliminar la dependencia en un parámetro numérico de un dígito — usar un evento de control con payload estructurado.

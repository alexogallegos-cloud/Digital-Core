T-SEC-001 · P655 SCRAMBLING — Enmascaramiento de Datos PII

S500 P655 — SCRAMBLING · 10 tareas · B03 + B37 + B39 Tipo: enmascaramiento PII · datos de prueba Frecuencia: Batch on-demand · ambientes de prueba Regla: RN-S500-578 · RN-S500-579 (defectos de seguridad) Confianza: Alta

Alerta de seguridad — Defectos documentados en producción

Dos defectos de seguridad CRÍTICOS activos en P655 DEFECTO-PROD
DEFECTO 1 — Ejecución en producción sin STOP RUN (RN-S500-578): P655 detecta los hostnames de producción (VDMALFA / MONBETA), emite el mensaje "NO CORRE EN PRODUCCION" y marca STATUS=-1, pero no ejecuta STOP RUN. El programa continúa y enmascara las bases de datos DMSII productivas (B03CONTRATOS, B37GRUPOCPE, B39CTASCPE). El único control real es la disciplina operativa del WFL scheduler. Acción inmediata: agregar STOP RUN / GOBACK tras STATUS=-1.
DEFECTO 2 — Fail-open ante hostname no reconocido (RN-S500-579): Si el hostname no está en la lista cerrada de 7 nombres (por ejemplo, un nuevo nodo tras failover o expansión del clúster), ni W77-ES-PRODUCCION ni W77-ES-PRUEBA se activan. P655 ejecuta el enmascaramiento completo sobre datos desconocidos sin ningún aviso. Acción inmediata: cambiar lógica a allowlist — solo ejecutar si hostname está en lista de prueba; cualquier otro hostname debe invocar STOP RUN.

Reglas de negocio

RN-S500-578 — Ejecución en producción sin STOP RUN [DEFECTO-PRODUCCIÓN]
COBOL_P655.txt T-SEC-002 🔴 CRÍTICO — DEFECTO PROD VDMALFA · MONBETA · PII · DMSII
P655 detecta los hostnames de producción (VDMALFA / MONBETA), emite el mensaje "NO CORRE EN PRODUCCION; HOST: X" y marca STATUS=-1, pero NO ejecuta STOP RUN ni GOBACK. El programa continúa a la siguiente instrucción y ejecuta el enmascaramiento completo sobre las bases DMSII productivas — B03CONTRATOS, B37GRUPOCPE y B39CTASCPE. El único control real es la disciplina operativa del WFL scheduler para no ejecutar P655 en producción. No existe ninguna barrera de código.
* T-SEC-002 — Detección de producción (VDMALFA / MONBETA) EVALUATE HOSTNAME WHEN "VDMALFA" WHEN "MONBETA" SET W77-ES-PRODUCCION TO TRUE PERFORM 000-IMPRIME-MENSAJE *> "NO CORRE EN PRODUCCION; HOST: VDMALFA" CHANGE ATTRIBUTE STATUS = -1 *> marca error en WFL * STOP RUN *> DEFECTO: STOP RUN no está presente * *> programa continúa a la siguiente instrucción * *> y ejecuta el enmascaramiento PII sobre datos reales END-EVALUATE
Acción requerida (inmediata): Agregar STOP RUN o GOBACK inmediatamente después de CHANGE ATTRIBUTE STATUS = -1. El control de producción debe ser una barrera de código — no una barrera operativa. En el sistema destino (cloud), el servicio debe fallar con HTTP 500 y abort ante cualquier intento de enmascaramiento en ambiente productivo.
RN-S500-579 — Fail-open ante hostname no reconocido [DEFECTO-PRODUCCIÓN]
COBOL_P655.txt T-SEC-001 🔴 CRÍTICO — DEFECTO PROD ATTRIBUTE HOSTNAME · lista cerrada · allowlist
P655 mantiene una lista cerrada de 7 hostnames: VDMALFA y MONBETA (producción) y VDMBETA, ACYPGAMA, ACYPBETA, MONALFA y ACYPOMEGA (prueba). Si el hostname del servidor no está en ninguna de estas listas — por ejemplo, un nuevo nodo añadido tras un failover, un nodo de DR o una expansión del clúster — ni W77-ES-PRODUCCION ni W77-ES-PRUEBA se activan. P655 ejecuta el enmascaramiento completo sobre las bases del ambiente desconocido sin ninguna advertencia al operador ni al WFL.
* T-SEC-001 — Clasificación de ambiente por hostname (lista cerrada de 7) EVALUATE HOSTNAME WHEN "VDMALFA" WHEN "MONBETA" SET W77-ES-PRODUCCION TO TRUE WHEN "VDMBETA" WHEN "ACYPGAMA" WHEN "ACYPBETA" WHEN "MONALFA" WHEN "ACYPOMEGA" SET W77-ES-PRUEBA TO TRUE WHEN OTHER *> DEFECTO: fail-open — ningún flag se activa *> W77-ES-PRODUCCION = FALSE, W77-ES-PRUEBA = FALSE *> P655 continúa como si fuera prueba, sin advertencia *> Enmascaramiento sobre ambiente desconocido END-EVALUATE
Acción requerida (inmediata): Cambiar la lógica a allowlist estricta: solo se permite la ejecución si el hostname está explícitamente en la lista de prueba. Cualquier hostname no reconocido debe tratarse como producción potencial y ejecutar STOP RUN. En cloud, el servicio de enmascaramiento debe recibir el ambiente como parámetro explícito validado en el API gateway — no inferido del hostname.
RN-S500-580 — Bloque potencialmente cero o negativo cerca de medianoche
COBOL_P655.txt T-SEC-003 🟠 AMBER bloque · 1800-HH-MM-SS
El tamaño del bloque de contratos se calcula como 1800 - HH - MM - SS (hora, minutos y segundos del sistema al momento de inicio de P655). Si P655 se lanza justo antes de las 00:00, el resultado puede ser cercano a cero o negativo. El comportamiento en este caso no está documentado en el código fuente — el cálculo de índices de intercambio de nombres puede producir resultados inesperados o un bucle infinito.
Impacto migración: Agregar MAX(bloque, 200) como valor mínimo garantizado. En cloud, el tamaño del bloque debe ser un parámetro de configuración explícito — no un valor calculado a partir de la hora del sistema. Implementar validación pre-ejecución que rechace corridas con bloque calculado menor o igual a cero.
RN-S500-581 — Secuencia sintética B39 no persiste entre corridas (inicio=10000, paso=12)
COBOL_P655.txt T-SEC-010 B39CTASCPE · consistencia entre ambientes
Para cuentas CPE en B39CTASCPE sin match en B03CONTRATOS, P655 genera nombres sintéticos con la secuencia inicio=10000, paso=12: "NOMBRE DE PRUEBA 10000", "NOMBRE DE PRUEBA 10012", "NOMBRE DE PRUEBA 10024", etc. La secuencia se reinicia al inicio de cada corrida — no persiste en el checkpoint. Si P655 se ejecuta dos veces sobre el mismo ambiente de prueba, las secuencias son idénticas entre corridas, lo que puede romper la consistencia referencial si otros sistemas de prueba ya leen los nombres de la corrida anterior.
Impacto migración: El servicio de enmascaramiento destino debe persistir el último contador de secuencia entre corridas (en BD o en el checkpoint extendido). Dos corridas sobre el mismo ambiente no deben generar nombres idénticos — la consistencia de los datos de prueba depende de nombres sintéticos únicos y estables.

Vocabulario

SCRAMBLING
Término Banamex · enmascaramiento PII
Nombre del proceso de enmascaramiento de datos PII (Personally Identifiable Information) en ambientes de prueba de S500. P655 implementa SCRAMBLING mediante shuffling de nombres entre contratos (B03), sustitución sintética en grupos CPE (B37) y copia o generación de nombres en cuentas CPE (B39).
B03CONTRATOS
Dataset DMSII · tabla de contratos S500
Tabla de contratos de captación S500 en base de datos DMSII. P655 procesa B03CONTRATOS en bloques, intercambiando los nombres de los titulares entre pares de contratos dentro de cada bloque (shuffling). El índice WKS-TB-NOM-PREF controla qué contrato recibe el nombre de cuál otro.
B37GRUPOCPE
Dataset DMSII · grupos de cuentas CPE
Grupos de cuentas CPE (Cuentas de Personas Empresariales) en DMSII. P655 sustituye el representante legal por "REPRESENTANTE LEGAL GRUPO N" y el domicilio por "DOMICILIO DEL GRUPO N", donde N es el identificador del grupo. El dato original queda sobrescrito en el ambiente de prueba.
B39CTASCPE
Dataset DMSII · cuentas individuales CPE
Cuentas individuales CPE en DMSII. P655 enmascara el nombre del titular: si el contrato tiene match en B03CONTRATOS (ya enmascarado), copia el nombre enmascarado de B03. Si no hay match, genera un nombre sintético "NOMBRE DE PRUEBA N" con secuencia inicio=10000, paso=12.
PII
Concepto regulatorio · datos personales
Personally Identifiable Information — datos que identifican a una persona física. En el contexto de P655: nombres de titulares de contratos bancarios, representantes legales y domicilios. Protegidos por PCI-DSS, regulación CNBV/Banxico y Ley Federal de Protección de Datos Personales. La alteración de PII en producción constituye un incidente de seguridad regulatorio.
ATTRIBUTE HOSTNAME
Instrucción MCP · identificación del servidor
Instrucción propietaria de Unisys MCP que retorna el nombre del servidor donde está ejecutando el programa. P655 la usa en T-SEC-001 para determinar el ambiente (producción vs prueba). Su equivalente en cloud es una variable de entorno inyectada por el orquestador de contenedores o un parámetro explícito del API.
W77-NOMBRE-PTE
Campo buffer · nombre pendiente del bloque impar
Nombre del primer contrato leído en la corrida (o en el bloque actual). Usado para el contrato central del último bloque impar: cuando el número de contratos en el último bloque es impar, el contrato del centro no tiene par de intercambio — recibe W77-NOMBRE-PTE como nombre enmascarado.
Checkpoint SCRBLING
Archivo disco · reanudación de corrida
Archivo en disco con ruta "S500/FILE/SCRBLING/CSI/fecha" que persiste el bloque procesado y el cursor al contrato N hasta donde se enmascaró la corrida. Permite reanudar P655 tras una interrupción sin rehacer el trabajo previo. El checkpoint no persiste el contador de secuencia sintética de B39.

Hallazgos de migración — P655 SCRAMBLING

Tarea Hallazgo Severidad Acción requerida
T-SEC-002 [DEFECTO-PROD] Ejecución en producción sin STOP RUN: P655 detecta VDMALFA/MONBETA, marca STATUS=-1 pero no ejecuta STOP RUN. Continúa y enmascara PII reales en bases DMSII productivas (B03, B37, B39). Incidente de seguridad regulatorio activo. 🔴 CRÍTICO Agregar STOP RUN / GOBACK inmediatamente después de CHANGE ATTRIBUTE STATUS=-1 en el código fuente. En cloud: el servicio debe abortar con HTTP 500 ante parámetro de ambiente = producción. Control de código obligatorio — no solo operativo.
T-SEC-001 [DEFECTO-PROD] Fail-open ante hostname no reconocido: lista de 7 hostnames hardcodeada. Cualquier nodo nuevo (failover, DR, expansión del clúster) no está en la lista — P655 ejecuta enmascaramiento completo sin validar el ambiente. Riesgo de alterar datos PII reales en nodos no catalogados. 🔴 CRÍTICO Cambiar a allowlist estricta: solo ejecutar si hostname está explícitamente en lista de prueba. Cualquier hostname desconocido = STOP RUN. En cloud: eliminar inferencia de ambiente por hostname; recibir ambiente como parámetro explícito validado en el API gateway o como variable de entorno inyectada.
T-SEC-003 Bloque variable 1800-HH-MM-SS: bloque puede ser cero o negativo si P655 se lanza cerca de medianoche. Comportamiento no documentado — riesgo de loop infinito o división por cero en el cálculo de índices de shuffling. 🟠 ALTO Agregar MAX(bloque, 200) como valor mínimo garantizado. En cloud: tamaño de bloque como parámetro de configuración explícito — no calculado a partir de la hora del sistema. Implementar validación pre-ejecución.
T-SEC-010 Secuencia sintética B39 no persiste: inicio=10000, paso=12 se reinicia en cada corrida. Dos corridas sobre el mismo ambiente generan nombres idénticos — rompe la consistencia referencial de datos de prueba entre corridas sucesivas. 🟠 ALTO Persistir el último contador de secuencia en BD o en el checkpoint extendido. En cloud: el servicio de enmascaramiento debe garantizar nombres sintéticos únicos y estables entre corridas sobre el mismo ambiente.
T-SEC-007 Shuffling en memoria de bloques grandes: el intercambio de nombres dentro del bloque usa índices WKS-TB-NOM-PREF cargados en working-storage. Si el bloque es muy grande y la memoria MCP está bajo presión, el comportamiento puede ser inesperado. 🟡 MEDIO En cloud: implementar el shuffling como operación de base de datos (UPDATE con subquery de par) en lugar de carga en memoria. Eliminar la dependencia del tamaño del bloque en la hora del sistema.

Diagrama de secuencia

sequenceDiagram
  participant WFL as WFL Orquestador (LOTE)
  participant P112 as P112 PUNTEO POR CLAVES
  participant LIBCON as LIBCONTROL (BD99CONTROL)
  participant PT as Catálogo PT (9,999 max)
  participant LEY as Leyendas TRANS1..4 (12,000 max)
  participant MOV as Archivo Movimientos S500
  participant ARCHCAT as ARCH-CAT (guías contables)
  participant S028 as Tabla S028 (naturalezas)
  participant RPT as Reporte CNBV B-0111B

  WFL->>P112: INITIATE (WKS-PARAM-SIS, WKS-PARAM-FCH)

  P112->>LIBCON: T-REC-001 Validar sistema en BD99CONTROL
  alt W77-RESULT-LIBCON distinto de 0
    LIBCON-->>P112: Sistema no existe o no activo
    P112->>WFL: STOP RUN — abort sistema inválido
  else OK
    LIBCON-->>P112: Sistema validado

    P112->>P112: T-REC-002 Fecha proceso (parámetro prevalece sobre control)
    P112->>P112: T-REC-003 CRONOS2K — AAMMDD a AAAAMMDD (umbral año menor a 50)

    P112->>PT: T-REC-004 Cargar catálogo PT en memoria (máx 9,999)
    alt WKS-PT-NUM-LEYEN mayor a 9999
      PT-->>P112: Overflow catálogo PT
      P112->>WFL: STOP RUN — abort total reconciliación fallida
    else OK
      PT-->>P112: Catálogo PT cargado

      P112->>LEY: T-REC-005 Cargar tabla leyendas TRANS1..4 (máx 12,000)
      alt Overflow leyendas
        LEY-->>P112: Overflow
        P112->>WFL: STOP RUN — abort
      else OK
        LEY-->>P112: Leyendas cargadas

        P112->>MOV: T-REC-006 Filtrar FUNCION=1 AND STATUS=1
        P112->>P112: T-REC-007 Normalizar producto (S403/S404 a fideicomiso · S087 a 87)
        P112->>P112: T-REC-008 Normalizar moneda/libro (S403/S404 a 0/0 · S264 a 01)
        P112->>P112: T-REC-009 SORT 5D LIBRO+PRODUCTO+MONEDA+CVETRAN+ESQCON

        loop Por cada movimiento filtrado y ordenado
          P112->>P112: T-REC-010 Validar libro contable (12 libros + FOBAPROA)
          alt Libro inválido
            P112->>RPT: Rechaza registro — libro fuera de rango
          else Libro válido
            P112->>S028: T-REC-011 Resolver naturaleza CVETRAN
            S028-->>P112: WLI-AFECS028 (1=C/2=A/3=N/4=COM)

            P112->>P112: T-REC-013 Validar S403/S404 fondos y productos

            P112->>ARCHCAT: T-REC-012 Gate INDS151=2 + KEY-CAT 7 campos
            alt KEY-CAT encontrado en ARCH-CAT
              ARCHCAT-->>P112: Punteo exitoso
              P112->>P112: T-REC-015 Acumular W77-IMPMOV + W77-NUMMOV
              P112->>RPT: T-REC-016 Línea OK (50 líneas/hoja)
            else KEY-CAT no encontrado
              ARCHCAT-->>P112: Sin match — brecha
              P112->>P112: T-REC-014 REL-TRAN-GUIA CONTABLE INEXISTENTE
              P112->>RPT: T-REC-016 Línea brecha — AFECS115=15
            end
          end

          opt Cambio de clave — control break
            P112->>RPT: T-REC-015 Subtotales 5 niveles (ESQCON a LIBRO)
          end
        end

        P112->>RPT: Total general todos los libros
        P112-->>WFL: STOP RUN (éxito)
      end
    end
  end

Reglas de negocio

RN-S151-008 — Gate de equivalencia S500↔S151: INDS151=2 + ARCH-CAT
COBOL_P112.txt párrafo BUSCA-EN-ARCH-CAT 🔴 CRÍTICO T-REC-012 RIESGO-EQUIVALENCIA
P112 determina si cada movimiento S500 tiene guía contable equivalente en S151 mediante un doble gate: primero verifica INDS151=2 (marcador GL del catálogo PT), luego construye una clave compuesta de 7 campos (KEY-CAT) con REDEFINES COMP y la busca en ARCH-CAT. Match = punteo exitoso. Sin match = brecha "REL-TRAN-GUIA CONTABLE INEXISTENTE" — reportable al regulador CNBV B-0111B. La integridad de ARCH-CAT determina si el cuadre contable cierra sin brechas.
* T-REC-012 — Párrafo BUSCA-EN-ARCH-CAT IF WKS-INDS151 = 2 MOVE SISTEMA TO WKS-SISTEMA *> campo 1 MOVE CVETRAN TO WKS-CVETRAN *> campo 2 MOVE ESQCON TO WKS-ESQCON *> campo 3 MOVE CAT-MON TO WKS-MONEDA *> campo 4 (normalizado) MOVE CAT-LIBRO TO WKS-LIBRO *> campo 5 (normalizado) MOVE CIA TO WKS-CIA *> campo 6 MOVE GUIA TO WKS-GUIA *> campo 7 *> KEY-CAT redefine los 7 campos — 23 bytes totales (REDEFINES COMP) READ ARCH-CAT KEY IS KEY-CAT INVALID KEY MOVE "REL-TRAN-GUIA CONTABLE INEXISTENTE" TO WLI-TIPOERROR *> exactamente 35 chars — contrato de interfaz MOVE "15" TO WLI-AFECS115 PERFORM IMPRIME-BRECHA NOT INVALID KEY PERFORM ACUMULA-PUNTEO END-READ END-IF
Impacto migración: ARCH-CAT debe migrarse como servicio de guías contables con los 7 campos como índice compuesto explícito. El acceso REDEFINES COMP debe reescribirse como consulta parametrizada. Cualquier cambio en layout rompe KEY-CAT silenciosamente. El texto exacto "REL-TRAN-GUIA CONTABLE INEXISTENTE" (35 chars) es un contrato de interfaz — versionar y documentar antes de modificar.
RN-S151-013 — Límite 9,999 claves en catálogo PT — overflow aborta reconciliación total
COBOL_P112.txt T-REC-004 🔴 CRÍTICO HARDCODE-SOSPECHOSO
El catálogo paramétrico PT tiene un límite hardcodeado de 9,999 claves. Si al cargar en memoria (T-REC-004) el contador excede este límite, P112 aborta con STOP RUN inmediato — sin procesar ningún movimiento del día. El reporte CNBV queda vacío, toda la reconciliación falla y se requiere reproceso manual. Un crecimiento orgánico del catálogo puede disparar este abort sin previo aviso. El mismo patrón aplica a la tabla de leyendas TRANS1..4 con límite de 12,000 (RN-S151-012).
* T-REC-004 — Carga catálogo PT PERFORM UNTIL WS-EOF-PT = 1 READ ARCH-PT AT END MOVE 1 TO WS-EOF-PT NOT AT END ADD 1 TO WKS-PT-NUM-LEYEN IF WKS-PT-NUM-LEYEN > 9999 *> límite hardcoded DISPLAY "ERROR: OVERFLOW CATALOGO PT - LIMITE 9999" STOP RUN *> abort total — ningún movimiento procesado END-IF MOVE REG-PT TO WKS-TABLE-PT(WKS-PT-NUM-LEYEN) END-READ END-PERFORM
Impacto migración: Eliminar los límites hardcodeados. Usar estructuras dinámicas (List/Map) en el sistema target sin límite fijo. Implementar monitoreo de crecimiento del catálogo PT con alerta cuando supere el 80% del límite actual para anticipar el abort. Nunca replicar el patrón STOP RUN sin recovery — el proceso destino debe fallar con rollback y alerta P1.
RN-S151-019 — CRONOS2K: conversión año 2 dígitos → 4 (umbral año ≤50 = siglo XXI)
COBOL_P112.txt T-REC-003 HARDCODE-SOSPECHOSO bomba de tiempo 2051
P112 convierte fechas de 6 dígitos (AAMMDD) a 8 dígitos (AAAAMMDD) usando el parche CRONOS2K. La lógica: si el año de 2 dígitos es ≤50 → siglo XXI (20xx); si es >50 → siglo XX (19xx). Este umbral funciona correctamente hasta el año 2050. A partir de 2051, el año "51" se interpretará como 1951 en lugar de 2051 — un error de fecha silencioso que afectará todos los movimientos del día con fecha incorrecta en el reporte CNBV.
* T-REC-003 — CRONOS2K MOVE WKS-FCH-2D(1:2) TO WKS-ANIO-2D IF WKS-ANIO-2D <= 50 *> umbral hardcoded MOVE "20" TO WKS-SIGLO *> 2000-2050 → siglo XXI ELSE MOVE "19" TO WKS-SIGLO *> 1951-1999 → siglo XX END-IF STRING WKS-SIGLO WKS-ANIO-2D WKS-MES WKS-DIA DELIMITED SIZE INTO WKS-FCH-8D *> fecha 8 dígitos
Impacto migración: Eliminar la lógica CRONOS2K completamente. Usar tipos DATE nativos del sistema target con año de 4 dígitos en todos los campos. Asegurar que los datos históricos con año de 2 dígitos se migren con el pivote correcto (≤50 = 20xx, >50 = 19xx) durante la carga inicial. La bomba de tiempo expira en 2051 — no replicar el umbral en el sistema destino.
RN-S151-020 — "REL-TRAN-GUIA CONTABLE INEXISTENTE" — contrato de interfaz de brecha
COBOL_P112.txt T-REC-014 CNBV B-0111B RIESGO-EQUIVALENCIA
Cuando P112 detecta una brecha (KEY-CAT no encontrado en ARCH-CAT), emite el literal "REL-TRAN-GUIA CONTABLE INEXISTENTE" (exactamente 35 caracteres) en WLI-TIPOERROR y asigna "15" a WLI-AFECS115. Estos valores son consumidos por parsers downstream del reporte CNBV B-0111B y el Sistema 115 de gestión de brechas regulatorias. Cualquier variación — espacios, mayúsculas, truncamiento — puede hacer que las brechas no sean detectadas automáticamente.
* T-REC-014 — Reportar brecha (texto exacto 35 chars — NO modificar sin versionar) MOVE "REL-TRAN-GUIA CONTABLE INEXISTENTE" TO WLI-TIPOERROR * 0 1 2 3 <- posición * 0123456789012345678901234567890123456 * ^-- 35 caracteres exactos --^ MOVE "15" TO WLI-AFECS115 *> afectación Sistema 115 ADD 1 TO WKS-CONTADOR-BRECHAS PERFORM IMPRIME-LINEA-BRECHA
Impacto migración: Documentar "REL-TRAN-GUIA CONTABLE INEXISTENTE" como contrato de interfaz con hash de contenido. En el sistema target, implementar códigos de error estructurados (enum + mensaje) en lugar de texto libre hardcodeado. Versionar el texto antes de cualquier cambio y validar con todos los consumidores downstream (CNBV, Sistema 115, auditoría) que procesan el string exacto.

Vocabulario

ARCH-CAT
Archivo indexado · catálogo de guías contables
Catálogo maestro de la reconciliación S500↔S151. Contiene las reglas de equivalencia: para cada combinación válida de los 7 campos (KEY-CAT), registra la guía contable correspondiente. Su integridad y completitud determinan si el cuadre CNBV cierra sin brechas. Cualquier cambio en S500 (nuevo CVETRAN) debe reflejarse simultáneamente en ARCH-CAT.
KEY-CAT
PIC X(23) · REDEFINES COMP · clave compuesta 7 campos
Clave compuesta de 23 bytes que P112 construye para cada movimiento y usa para buscar en ARCH-CAT. Formada por SISTEMA(3)+CVETRAN(4)+ESQCON(3)+MONEDA(2)+LIBRO(2)+CIA(3)+GUIA(6). Se construye via REDEFINES COMP — frágil ante cambios de PIC en cualquier campo.
Catálogo PT
Tabla en memoria · máx 9,999 claves
Catálogo paramétrico cargado en memoria al inicio de P112 (T-REC-004). Contiene los indicadores WKS-PT-CGENTRA, NATS028, INDS151 e INDBITA para cada CVETRAN. Si INDS151=2, el movimiento pasa al gate de equivalencia ARCH-CAT. Límite hardcodeado de 9,999 claves — overflow aborta toda la reconciliación del día.
INDS151
Indicador en catálogo PT · PIC 9(1)
Indicador que determina si un CVETRAN tiene entrada equivalente en S151 GL. Solo INDS151=2 activa el gate de equivalencia ARCH-CAT (T-REC-012). Cualquier otro valor excluye el movimiento de la reconciliación silenciosamente — sin registro de la exclusión. Un INDS151 incorrecto puede excluir miles de movimientos sin alerta.
WLI-TIPOERROR
PIC X(35) · contrato de interfaz CNBV
Campo de texto que registra el motivo de la brecha de reconciliación. El valor "REL-TRAN-GUIA CONTABLE INEXISTENTE" (35 caracteres exactos) es un contrato de interfaz consumido por parsers downstream de CNBV y Sistema 115. Cualquier variación rompe la detección automática de brechas en sistemas regulatorios.
Control break 5 niveles
T-REC-015 · jerarquía de subtotales
P112 acumula y reporta subtotales en 5 niveles jerárquicos al detectar cambio de clave: ESQCON (nivel 1, más fino) → CVETRAN → MONEDA → PRODUCTO → LIBRO (nivel 5, más grueso). El reporte CNBV B-0111B usa esta estructura para permitir drill-down de brechas por dimensión.
FOBAPROA
Libro contable residual · 1994-1995
Uno de los 12 libros contables hardcodeados en T-REC-010. FOBAPROA (Fondo Bancario de Protección al Ahorro) es un programa de rescate bancario de 1994-1995. Su presencia en el catálogo hardcoded indica que Banamex aún procesa movimientos asociados a este fondo histórico en el sistema legado.
CNBV B-0111B
Reporte regulatorio · Comisión Nacional Bancaria
Reporte regulatorio que P112 genera como output principal. Contiene el listado de punteos exitosos y brechas de reconciliación del día, con subtotales por 5 dimensiones. WKS-CONTADOR-BRECHAS > 0 al cierre activa escalación inmediata a la mesa de operaciones — las brechas deben investigarse antes del cierre contable.

Hallazgos de migración — P112 PUNTEO POR CLAVES

TareaHallazgoSeveridadAcción requerida
T-REC-012 Gate ARCH-CAT: cualquier cambio en guía contable sin actualizar ARCH-CAT rompe la reconciliación para ese CVETRAN — brechas masivas silenciosas. 🟠 CRÍTICO Externalizar ARCH-CAT a base de datos configurable con versionado de guías contables. Pruebas de equivalencia del 100% de combinaciones antes del go-live.
T-REC-012 Clave KEY-CAT con REDEFINES COMP — frágil ante cambios de layout. Un cambio de PIC en cualquier campo altera silenciosamente KEY-CAT sin error de compilación. 🟠 CRÍTICO Reescribir acceso como consulta parametrizada con 7 columnas explícitas y tipadas. Nunca usar REDEFINES en arquitectura target. Prueba unitaria que verifique KEY-CAT para combinaciones conocidas.
T-REC-004 · T-REC-005 Overflow catálogo PT (9,999) o tabla leyendas (12,000) aborta toda la reconciliación del día — reporte CNBV vacío, reproceso manual requerido. 🟠 CRÍTICO Eliminar límites hardcodeados. Usar estructuras dinámicas (List/Map) en target. Monitorear crecimiento del catálogo PT con alerta al 80% del límite actual.
T-REC-014 Texto "REL-TRAN-GUIA CONTABLE INEXISTENTE" (35 chars exactos) es contrato de interfaz — parsers downstream de CNBV dependen del string exacto. 🟠 CRÍTICO Documentar con hash de contenido como contrato de interfaz. Implementar código de error estructurado (enum) en target. Versionar antes de cualquier cambio.
T-REC-010 12 libros contables hardcodeados incluyendo FOBAPROA (1994-1995). Nuevo libro regulatorio CNBV requiere recompilación del binario. 🟡 ALTO Mover catálogo de libros a tabla configurable en base de datos. Gestionar via configuración sin recompilación. Verificar si FOBAPROA sigue activo en producción.
T-REC-007 S087 producto=87 hardcodeado — nuevos productos de cheques ignorados silenciosamente sin contador de descartados. 🟡 ALTO Reemplazar por lectura real de A00-R01-PRODUCTO. Implementar contador de movimientos descartados por producto no reconocido con alerta diaria.
T-REC-003 CRONOS2K — año >50 interpretado como siglo XX. Bomba de tiempo expira 2051. 🟡 ALTO Eliminar lógica CRONOS2K. Usar tipo DATE nativo con 4 dígitos de año en el sistema target. Migrar datos históricos con pivote correcto (≤50=20xx, >50=19xx).
T-REC-008 S264/SPEI restringido a MXN (CAT-MON=01) — brecha silenciosa sin diagnóstico de causa cuando el movimiento es en divisa distinta. 🟡 MEDIO Emitir código de error específico "RESTRICCION-MONEDA-BASE" en lugar de caer en la brecha genérica. Permite al equipo contable identificar la causa raíz.

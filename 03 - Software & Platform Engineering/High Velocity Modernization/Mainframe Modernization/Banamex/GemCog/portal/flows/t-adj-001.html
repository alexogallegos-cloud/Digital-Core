Reglas de negocio

RN-S151-748 — Sin mecanismo de recuperación completo (DMTERMINATE post-PURGE)
COBOL_P360.txt T-ADJ-P360-012 / T-ADJ-P360-015 / T-ADJ-P360-016 🔴 CRÍTICO
Si DMTERMINATE ocurre en P360 después de que P330 ya ejecutó CLOSE WITH PURGE sobre algunos archivos del pack, esos archivos están destruidos físicamente e irreversiblemente. P360 hace rollback atómico de su integración DMSII, pero no existe mecanismo para restaurar los archivos del pack. La única recuperación posible es reejecutar P330 completo desde la base fuente original.
* T-ADJ-P360-012 — Error en STORE → DMTERMINATE rollback atómico IF WKS-DMSTATUS NOT = NOTFOUND PERFORM 010105-EMIT-OPERATOR-MSG *> mensaje operador código 010105 PERFORM 09-0000-CLASIFICA-ERROR *> WKS-TAB-ERRDMSII (21 tipos) CALL SYSTEM DMTERMINATE *> rollback atómico — dump completo END-IF *> Si DMTERMINATE ocurre después de que algunos archivos *> fueron cerrados con CLOSE WITH PURGE: sin recuperación posible. *> Reejecutar P330 completo desde DMSII_Fuente original.
Impacto migración: El sistema destino debe implementar idempotencia completa: el equivalente de P360 debe poder reintentarse sin necesidad de reejecutar la extracción. Diseñar mecanismo de checkpointing por estructura con confirmación explícita de integración antes de destruir el archivo fuente. Reemplazar el modelo "todo-o-nada con archivos planos" por un pipeline event-driven con at-least-once delivery y offset tracking por estructura DMSII.
RN-S151-728 — Pipeline no paralelizable ni modernizable as-is
COBOL_P330.txt / COBOL_P360.txt T-ADJ-P330-012 / T-ADJ-P360-015 🔴 CRÍTICO
CLOSE WITH LOCK y CLOSE WITH PURGE son mecanismos propietarios Unisys MCP sin equivalente en ninguna plataforma moderna. Los archivos planos en el pack compartido son el único canal de intercambio entre P330 y P360. La secuencia fija B20→B21→B70→B71→B72→B80 no es paralelizable — un fallo en cualquier estructura deja las siguientes sin procesar. El caso de uso completo debe rediseñarse como CDC + streaming.
*> T-ADJ-P330-012 — CLOSE WITH LOCK (barrera de sincronización propietaria MCP) CLOSE R20 WITH LOCK *> sin equivalente en cloud/POSIX CLOSE R21 WITH LOCK CLOSE R70 WITH LOCK CLOSE R71 WITH LOCK CLOSE R72 WITH LOCK CLOSE R80 WITH LOCK *> T-ADJ-P360-015 — CLOSE WITH PURGE (destrucción física irreversible) CLOSE R20 WITH PURGE *> elimina el archivo del pack — irreversible CLOSE R21 WITH PURGE *> sin equivalente en sistemas de archivos modernos CLOSE R70 WITH PURGE CLOSE R71 WITH PURGE CLOSE R72 WITH PURGE CLOSE R80 WITH PURGE
Impacto migración: El pipeline P330+P360 debe rediseñarse como pipeline event-driven: CDC desde DMSII_Fuente → broker de mensajes (Kafka) → consumer de integración en DMSII_Destino. Los mecanismos CLOSE WITH LOCK y CLOSE WITH PURGE se reemplazan por at-least-once delivery con idempotencia en el consumer. La sincronización entre extracción e integración se implementa como handshake explícito basado en confirmación de consumo de cada partición.
RN-S151-722 — ATTRIBUTE VALUE OF MYSELF (control de ejecución propietario MCP)
COBOL_P330.txt T-ADJ-P330-003 MCP propietario · override de fecha
P330 determina la fecha de proceso usando el atributo del job MCP: si ATTRIBUTE VALUE OF MYSELF = 0, obtiene la fecha de CONSISDIA (modo normal); si es distinto de cero, el atributo del job funciona como override implícito de fecha para reprocesos históricos. Este mecanismo de control de ejecución es propietario de Unisys MCP y no tiene equivalente en plataformas modernas.
* T-ADJ-P330-003 — Determinación de fecha de proceso IF ATTRIBUTE VALUE OF MYSELF = 0 PERFORM CONSISDIA *> fecha de proceso normal → WKS-B01-FECPRO MOVE WKS-B01-FECPRO TO WKS-FECHA-PROC ELSE MOVE ATTRIBUTE VALUE TO WKS-FECHA-PROC *> atributo del job = override END-IF *> T-ADJ-P330-004: CRONOS2K — pivote A2K-BASE-YEAR=50 *> AA menor a 50 → siglo 20 (2000-2049); AA mayor o igual a 50 → siglo 19 (1950-1999)
Impacto migración: Reemplazar ATTRIBUTE VALUE OF MYSELF por un parámetro explícito de fecha de proceso en la interfaz del job o del servicio equivalente. El valor debe validarse antes de ejecutar cualquier extracción DMSII. Los casos de reproceso histórico deben documentarse como casos de uso explícitos con interfaz propia, no como un side-channel del atributo del job de ejecución.
RN-S151-721 — ESTATUS=3 obligatorio en sistema destino (P360)
COBOL_P360.txt T-ADJ-P360-003 / T-ADJ-P360-004 validación destino · LIBCONTROL
P360 valida el sistema destino antes de abrir la base: ESTATUS=3 desde B04SISTEM vía LIBCONTROL (base activa estándar). TIPBD debe estar en {1,2,5,6} (tipo de base de saldos compatible) desde B03SISMEN vía CONSISMEN. Cualquier desviación causa abort inmediato con STATUS=-1. En producción, esta validación protege contra integraciones accidentales en bases inactivas o de tipo incorrecto.
* T-ADJ-P360-003 — Validar ESTATUS del sistema destino IF WKS-B04-ESTATUS NOT = 3 MOVE -1 TO WKS-STATUS STOP RUN *> abort inmediato — base destino no activa * T-ADJ-P360-004 — Validar TIPBD del sistema destino IF WKS-B03-TIPBD NOT IN (1, 2, 5, 6) DISPLAY "EL SISTEMA NO UTILIZA BASE DE SALDOS" MOVE -1 TO WKS-STATUS STOP RUN *> abort — tipo de base no compatible con P360
Impacto migración: La validación ESTATUS=3 debe preservarse en el sistema destino como precondición explícita de integración — implementar como health check del ambiente destino antes de iniciar cualquier escritura. TIPBD fuera de {1,2,5,6} debe generar alerta operacional P1, no solo abort silencioso con STATUS=-1. Verificar que el catálogo de tipos de base sea configurable y no hardcoded.

Vocabulario

ATTRIBUTE VALUE OF MYSELF
MCP Attribute · control de ejecución
Mecanismo de control de ejecución propietario Unisys MCP. Valor=0 → ejecución normal (fecha de CONSISDIA); valor distinto de cero → actúa como override de fecha para reprocesos históricos. Sin equivalente en plataformas modernas — requiere rediseño como parámetro explícito.
CLOSE WITH LOCK
MCP file command · sincronización
Cierre de archivo con bloqueo en Unisys MCP. Previene acceso concurrente hasta que el receptor lo abra explícitamente. Es la barrera de integridad entre P330 (escritura) y P360 (lectura). Sin equivalente en sistemas de archivos POSIX o cloud — debe reimplementarse como handshake explícito.
CLOSE WITH PURGE
MCP file command · destrucción física
Cierre destructivo e irreversible de archivo en Unisys MCP. Elimina el archivo físico del pack al cerrar — la eliminación es atómica con el cierre del archivo. P360 usa PURGE para limpiar los archivos temporales después de confirmar integración exitosa. No hay equivalente POSIX.
WKS-NOMBRE-PACK
PIC X(12) · pack de disco compartido
Nombre del pack de disco compartido. Área de intercambio entre P330 (escribe 6 archivos planos) y P360 (lee los mismos 6 archivos). La misma instancia del pack debe ser físicamente visible por ambos programas — restricción de topología en entornos MCP distribuidos como VDM (CDMX) y MTY.
DMTERMINATE
MCP system call · terminación con dump
Llamada al sistema Unisys MCP para terminación con dump diagnóstico. Produce rollback atómico de las transacciones DMSII en vuelo. Distinto de STATUS=-1 — DMTERMINATE incluye diagnóstico completo del estado DMSII al momento del fallo y clasificación por WKS-TAB-ERRDMSII (21 tipos de error).
B72POSCONTA
DMSII S151 · posición contable
Tabla de posición contable con 10 dimensiones de clave en DMSII. La estructura más crítica del pipeline GL ADJ. Extraída por P330 y reintegrada por P360 como registro completo con todos sus campos: SDOANT (saldo anterior), CARGOS, ABONOS, SDOACT (saldo actual) y NATCTA (naturaleza de cuenta).
LIBCONTROL
Librería S151 · control del sistema
Biblioteca de control del sistema S151. Provee acceso a CONSISDIA (fecha de proceso), CONSISMEN (tipo de base de saldos) y B04SISTEMA (ESTATUS del sistema). Es el punto de entrada principal para validaciones de estado tanto en P330 (validación fuente, T-ADJ-P330-002) como en P360 (validación destino, T-ADJ-P360-003).

Hallazgos de migración — Pipeline ADJ P330+P360

Tarea Hallazgo Severidad Acción requerida
T-ADJ-P360-015/016 Sin recuperación post-PURGE. Fallo en P360 después de CLOSE WITH PURGE de algunos archivos del pack deja esos archivos destruidos físicamente. No existe punto de recuperación parcial — reejecutar P330 completo desde DMSII_Fuente. 🟠 CRÍTICO Implementar idempotencia completa: P360 debe poder reintentarse sin reejecutar P330. Diseñar checkpointing por estructura con confirmación explícita de integración antes de emitir PURGE de cada archivo.
T-ADJ-P330-013 Pipeline no paralelizable. Secuencia fija B20→B21→B70→B71→B72→B80 — DMTERMINATE en cualquier estructura deja las siguientes sin procesar y sin mecanismo de retoma desde el punto de fallo. 🟠 CRÍTICO Rediseñar como pipeline event-driven: CDC desde DMSII_Fuente → Kafka → consumer de integración con offset tracking por estructura. Eliminar la dependencia de archivos planos secuenciales y del pack compartido.
T-ADJ-P330-003 ATTRIBUTE VALUE OF MYSELF — mecanismo propietario MCP sin equivalente en cloud. Usado como override implícito de fecha de proceso para reprocesos históricos, sin visibilidad en la firma del programa. 🟡 ALTO Reemplazar por parámetro explícito de fecha de proceso en la interfaz del job. Documentar los casos de uso de reproceso histórico como casos de uso formales con interfaz propia y validación explícita.
T-ADJ-P360-012 WKS-TAB-ERRDMSII con 21 tipos hardcoded. Nuevos códigos de error DMSII no reconocidos por la tabla de clasificación caen en categoría genérica sin diagnóstico adecuado para el operador. 🟡 MEDIO Externalizar la tabla de clasificación de errores DMSII a configuración. Implementar alerta automática para códigos de error no reconocidos por la tabla de 21 tipos.
T-ADJ-P330-012 / T-ADJ-P360-015 CLOSE WITH LOCK y CLOSE WITH PURGE propietarios de Unisys MCP. Sin equivalente en ninguna plataforma moderna — la sincronización entre extracción e integración y la limpieza de archivos temporales deben rediseñarse completamente. 🟠 CRÍTICO Implementar sincronización como handshake explícito basado en mensajería o flag en base de datos. Sustituir PURGE por política de retención con eliminación explícita post-confirmación de integración exitosa.

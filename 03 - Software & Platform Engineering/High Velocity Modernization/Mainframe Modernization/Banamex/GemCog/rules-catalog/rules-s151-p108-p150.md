## PARTE I — P108: GL Bitácora (Reglas RN-S151-121 a RN-S151-150)

### P108 — Contexto general
P108 es el escribidor contable dual del sistema S151. Lee el archivo **MOVIMIENTOS** (bitácora interna), aplica tablas de normalización CNBV y de esquemas contables, y produce:
- **MOVCONTABLES** (interfaz ALFA hacia S500)
- **MOVCONTABLESFS** (interfaz Full Suite hacia S500)
- **MOVCONTASORT / MOVCONTASORTFS** (archivo ordenado para S500)
- **PAQCONTAB / PAQCONTAB-FS** (paquete contable)
- **CUADRECONT** (cuadre contable)
- **REPCONTABLE** (reporte contable)
- **DIFALFAVSFFS** (diferencias ALFA vs Full Suite)
- **Archivo S115** (interfaz CNBV regulatoria)
- **BITACORA / MOVSXSUCCAJ** (archivos de auditoría / S028)

**Descripción**  
Cada registro de MOVIMIENTOS puede contener hasta 5 CVETRANs independientes (slots 1 a 5), cada uno con su propio IMPORTE y ESQCON. El párrafo 21100-GRABA-ARCHIVOS itera sobre los 5 slots usando un PERFORM VARYING con índice W77-INDCVE. Para cada slot no-cero, ejecuta la cadena completa de escritura: normalización de SECTOR, lookup de cuenta contable, escritura a MOVCONTABLES/FS, escritura a MOVCONTASORT/FS y escritura a MOVIMIENTOS Bitácora (si INDBITA activo).
**Restricción de escritura a MOVCONTASORT:** El sub-párrafo `21101-GRABA-ARCHCON` (que produce MOVCONTASORT/MOVCONTASORTFS) solo se ejecuta cuando `A00-R01-STATUS = 1 AND (A00-R01-ORIGEN = 1 OR 3)`. **Trigger**  
Invocado desde 20000-GRABA-ARCHIVOS-CONTABLES para cada registro de MOVIMIENTOS leído.

**Campos COBOL**

| Campo | PIC | Descripción |
|-------|-----|-------------|
| RM-CVE-TRANS(idx) | 9(04) OCCURS 5 | Slot de CVETRAN (1 a 5) |
| RM-IMPORTE(idx) | 9(14)V99 OCCURS 5 | Importe por slot |
| RM-ESQ-CONT(idx) | 9(04) OCCURS 5 | Esquema contable por slot |
| W77-INDCVE | 9 | Índice del loop (1..5) |

**Vocabulario relacionado**  
`CVETRA` (vocab-s151.md): clave de transacción · `MOVIMIENTOS` · `CONTABILIDAD` · `LOTE`

**Fórmula / pseudocódigo:**
```
PERFORM VARYING W77-INDCVE FROM 1 BY 1
        UNTIL W77-INDCVE > 5 OR RM-CVE-TRANS(W77-INDCVE) = 0
  PERFORM 21101-GRABA-ARCHCON
  PERFORM 21110-GRABA-MOV-BITACORA
  PERFORM 21102-GRABA-MOVCONT
END-PERFORM
```

**Excepciones documentadas:**
- Un movimiento genera hasta 5 registros contables independientes; el sistema destino debe soportar cardinalidad 1:N.
- El orden de los slots es significativo para el cuadre contable; no se pueden reordenar en el sistema destino.
- STATUS=2 no genera registros en MOVCONTASORT ni MOVCONTASORTFS — solo MOVCONTABLES. El sistema destino debe replicar esta restricción o perderá la equivalencia en la reconciliación GL de S500.

**Traza de código**

```
    PERFORM 21110-GRABA-MOV-BITACORA

```

**Riesgos de migración**  
- Un movimiento puede generar hasta 5 registros contables independientes — el sistema destino debe soportar esta cardinalidad 1:N.  
- El slot 5 rara vez se usa en producción pero existe en el esquema; las pruebas de equivalencia deben cubrirlo.  
- El orden de los slots es significativo para el cuadre: no se pueden reordenar.

## PARTE II — P150: Interfaz CITI ALR/AHR/OCM (Reglas RN-S151-151 a RN-S151-180)

### P150 — Contexto general
P150 es el generador de reportes intercompany de Banamex hacia CITI. Lee los archivos contables del día (MOVCONTABLES, archivo de saldos) y produce tres reportes regulatorios internos del grupo CITI:
- **ALR** (Account Level Report): saldos diarios por cuenta consolidados por filial
- **AHR** (Account History Report): historial de movimientos individuales del día
- **OCM** (Open Collections Management): posición de cobranza por antigüedad

**ALERTA BRANCH=484**: el código de filial CITI está hardcodeado como `484` en ≥5 campos. Es el discriminador crítico de la separación Banamex/CITI.

**Upstream**: MOVCONTABLES (output de P108), archivos de saldos S151
**Downstream**: ALR, AHR, OCM → CITI intercompany · CNBV B-0111B

**Descripción**
Después de que P150 termina con RETURN-CODE=0, el WFL maestro dispara un job de transmisión que envía ALR, AHR, OCM y BATCH-HEADER al servidor CITI vía SFT/SFTP sobre red intercompany. El job verifica el acuse de recibo de CITI y registra el resultado en el log de transmisión S151. Este job es externo a P150 pero es la dependencia de completitud del proceso diario CITI.

**Trigger**
RETURN-CODE=0 de P150 detectado por el WFL maestro S151.

**Campos COBOL**
*(Job de transmisión externo — no COBOL P150)*

| Campo | Descripción |
|-------|-------------|
| WFL-STATUS-TRANS | Status del job de transmisión (OK/ERROR) |
| LOG-TRANS-CITI | Log de confirmación CITI (acuse de recibo) |

**Vocabulario relacionado**
`ALR` · `AHR` · `OCM` · `LOTE` · `BIFIN`

**Fórmula / pseudocódigo:**
```
[WFL maestro:] IF RETURN-CODE(P150) = 0:
  RUN JOB-TRANSMISION-CITI (ALR, AHR, OCM, BATCH-HEADER)
  IF ACK-CITI = OK: LOG "TRANSMISION EXITOSA"
  ELSE: ALERTA-OPERATIVA "FALLO EN TRANSMISION CITI"
```

**Excepciones documentadas:**
- CITI puede rechazar el lote aun con transmisión exitosa si BATCH-HEADER no coincide con conteos — el acuse solo confirma recepción, no validez.
- Si la transmisión falla, los archivos permanecen en el servidor MCP para re-transmisión manual dentro de la ventana CITI.

**Traza de código**
```
Programa : WFL maestro S151 + job externo de transmisión SFT/SFTP
P150     : no controla la transmisión directamente
Confianza: MEDIA — arquitectura de transmisión inferida del contexto
```

**Riesgos de migración**
- Reemplazar SFT/SFTP por API REST CITI con autenticación mutual TLS y webhook de confirmación de recepción.
- El job de transmisión debe ser observable: métricas de latencia, tasa de éxito, alertas automáticas en caso de rechazo CITI.

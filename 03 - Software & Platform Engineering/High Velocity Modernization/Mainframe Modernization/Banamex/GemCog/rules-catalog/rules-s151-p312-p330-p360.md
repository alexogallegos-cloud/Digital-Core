| `A2K-OBTAIN-CENTURY` | función | Rutina CRONOS2K que calcula el siglo CC a partir del año AA |


**Riesgos de migración:** El año pivote 50 implica que fechas como "51" se interpretan como 1951, no 2051. En 2025 esta regla aún no genera fechas futuras erróneas para datos históricos. Sin embargo, si el sistema maneja fechas de contratos que puedan llegar a 2050+, la lógica de pivot fallará. En la migración debe reemplazarse por fechas de 4 dígitos en todos los campos temporales.

### RN-S151-749 — Secuencia canónica de integración: orden fijo de las 6 estructuras

| Campo | Valor |
|-------|-------|
| **Identificador** | RN-S151-749 |
| **Nombre** | Secuencia canónica de integración: orden fijo de las 6 estructuras |
| **Versión** | v2 |
| **Estado ciclo** | En validación |
| **Fecha actualización** | 2026-07-27 |
| **BC-ID** | BC-09 |
| **bian_ref** | — |
| **Tipo regla** | Consulta análisis SBVR (dt-mainframe-analyst) |
| **Tipo técnico** | control-datos |
| **Confianza** | alta |
| **Veredicto** | PENDIENTE SME |
| **Regulador** | N/A — operacional |
| **Programa ejecutor** | S151/P360 |
| **Evidencia código** | Análisis fuente (dt-mainframe-analyst): elevar Traza de código a archivo:línea exacta |
| **Dataset DMSII** | Análisis interno: derivar de Campos COBOL / DASDL |

**Descripción:** P360 integra las 6 estructuras en un orden fijo y secuencial, nunca en paralelo: B20 → B21 → B70 → B71 → B72 → B80. Cada estructura se procesa completamente (sort + open + loop + close con purge) antes de iniciar la siguiente. El cierre con `CLOSE WITH PURGE` elimina los archivos planos temporales después de integrarlos, garantizando que no puedan ser reprocesados accidentalmente. Este orden no es aleatorio: B20 (saldo diario por contrato) precede a B21 (saldo mensual), y B70 (posición) precede a B71 (posición adicional) y B72 (contable), reflejando una jerarquía de dependencia entre estructuras.

**Trigger:** Sección `00-0000-INICIO`, flujo principal en `00-0100-CTL-PROCESO`.

**Campos involucrados:** `WS-EOF-B20..B80`, `WS-INTEGRADOS-B20..B80`

**Vocabulario en la fórmula:**

| Término | Tipo | Descripción breve |
|---------|------|-------------------|
| `CLOSE WITH PURGE` | operación-Unisys | Cierra y elimina el archivo plano temporal del pack después de procesarlo |
| `PERFORM UNTIL WS-EOF = 1` | control-flujo | Loop de lectura/integración registro a registro por cada estructura |

**Traza de código (COBOL):**
```
PERFORM 01-0000-VERIFICACION.
PERFORM 02-0000-PROC-STRUCTURE-B20.
PERFORM 03-0000-PROC-STRUCTURE-B21.
PERFORM 04-0000-PROC-STRUCTURE-B70.
PERFORM 05-0000-PROC-STRUCTURE-B71.
PERFORM 06-0000-PROC-STRUCTURE-B72.
PERFORM 07-0000-PROC-STRUCTURE-B80.
PERFORM 09-0000-PROC-IMPRESION.
PERFORM 10-0000-PROC-TERMINA.
```

**Riesgos de migración:** La semántica de `CLOSE WITH PURGE` (eliminación del archivo fuente) es un comportamiento destructivo crítico. En la migración, el servicio equivalente debe: (a) marcar los archivos como procesados (no eliminarlos inmediatamente), (b) o implementar el borrado sólo tras confirmar la transacción de base de datos. Si se paraleliza la integración en la arquitectura destino, debe analizarse si existe dependencia real entre estructuras o si pueden procesarse concurrentemente.

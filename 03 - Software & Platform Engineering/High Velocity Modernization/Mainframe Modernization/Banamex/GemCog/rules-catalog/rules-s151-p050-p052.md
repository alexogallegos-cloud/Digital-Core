### RN-S151-281 — THECALENDAR FUN=18: verificación de día hábil

|-------|-------|
| **Identificador** | RN-S151-281 |
| **Nombre** | THECALENDAR FUN=18: verificación de día hábil |

| **Confianza** | alta |
| **Veredicto** | PENDIENTE SME |
| **Regulador** | — |
| **Programa ejecutor** | P050 |
| **Evidencia código** | Análisis fuente (dt-mainframe-analyst): elevar Traza de código a archivo:línea exacta |
| **Dataset DMSII** | Análisis interno: derivar de Campos COBOL / DASDL |

**Descripción:** P050 invoca `THECALENDAR IN LOCSUP` con FUN=18 para determinar si la fecha de proceso es día hábil bancario. La convención de retorno es **contraintuitiva**: retorno `0` significa **INHÁBIL** (y dispara FUN=13 para avanzar al siguiente hábil); retorno `≠ 0` significa **HÁBIL** (la fecha se usa directamente). [QC-P1-CORREGIDO: convención original documentada al revés — verificado líneas 9512-9522 COBOL_P050.txt]. Esta función es invocada solamente cuando el CSI es 10 (VDM) o 4 (MON) — los nodos de mayor volumen. Para otros CSI, la verificación se omite.

**Trigger:** Inicio de proceso de concentración de saldos; verificación de fecha antes de ejecutar cierre

**Campos involucrados:**

| Campo COBOL | Tipo | Rol |
|-------------|------|-----|
| `WS-FUNCION` | PIC 9(02) | Código de función THECALENDAR — valor 18 para consulta de día hábil |
| `WS-FECHA1` | PIC X(08) | Fecha a verificar en formato AAAAMMDD |
| `WS-FECHA2` | PIC X(08) | Parámetro adicional — ZEROS para esta consulta |
| `WS-FORMATO` | PIC 9(02) | Formato de fecha — valor 13 (post-CRONOS 2000) |
| `WKS-DIA-HABIL` | PIC 9 VALUE 0 (L6381) | Resultado: **0=INHÁBIL** (dispara FUN=13), **≠0=HÁBIL** (usa fecha directamente) [QC-P1-CORREGIDO] |

**Traza de código:**
```
PROGRAMA: P050ADSALDOS
SECCIÓN/PÁRRAFO: (consulta de día hábil)
Líneas fuente: 9504–9511 (primera ocurrencia) · 10001–10011 (segunda ocurrencia)

MOVE WS-FECHA-AMD TO WS-FECHA1 WS-FECHA3          [L9504]
MOVE ZEROS        TO WS-FECHA2                    [L9505]
MOVE 18           TO WS-FUNCION                   [L9506]
MOVE 13           TO WS-FORMATO                   [L9507]
CALL "THECALENDAR IN LOCSUP" USING                [L9508]
     WS-FUNCION, WS-FECHA1, WS-FECHA2, WS-FORMATO [L9509]
MOVE WS-FECHA1-NUM TO WKS-DIA-HABIL              [L9510]
IF WKS-DIA-HABIL = 0 → día INHÁBIL → ejecuta FUN=13 [L9512] [QC-P1-CORREGIDO]
ELSE → día HÁBIL → usa WS-FECHA-AMD directamente [L9521-9522]
```

**Vocabulario relacionado:** `LOCSUP` (servicio de calendario S006), `THECALENDAR` (función externa LOCSUP), `LOTE` (ciclo batch que usa esta verificación), `CTLVERS` (control de versiones del módulo)

**Fórmula / pseudocódigo:**
```
MOVE 18 TO WS-FUNCION; MOVE 13 TO WS-FORMATO
CALL "THECALENDAR IN LOCSUP" USING WS-FUNCION, WS-FECHA1, WS-FECHA2, WS-FORMATO
MOVE WS-FECHA1-NUM TO WKS-DIA-HABIL
IF WKS-DIA-HABIL = 0 → día INHÁBIL (invocar RN-282 para avanzar al siguiente hábil) [QC-P1-CORREGIDO]
ELSE → día HÁBIL (continúa proceso con la fecha actual)
```

**Excepciones documentadas:**
- Solo aplica si CSI=4 (MON) o CSI=10 (VDM); otros nodos CSI omiten verificación
- Convención invertida (0=hábil, ≠0=inhábil) es contraintuitiva y fuente probable de bug en reimplementación

**Riesgos de migración:**
- La convención real (0=INHÁBIL, ≠0=HÁBIL) es contraintuitiva — el nombre del campo sugiere lo contrario; riesgo alto de bug en reimplementación [QC-P1-CORREGIDO]
- Restricción CSI=4 o CSI=10 está hardcodeada — agregar nuevos nodos requiere modificación de código
- `THECALENDAR IN LOCSUP` es dependencia del sistema S006 de Banamex — debe reemplazarse con servicio de calendario equivalente

**Estado validación:** pendiente HITL

**Descripción:** Cuando la verificación FUN=18 devuelve `WKS-DIA-HABIL ≠ 0` (día inhábil), P050 invoca nuevamente `THECALENDAR` con FUN=13 y `FECHA2="00000001"` para calcular el siguiente día hábil. El resultado se almacena en `WKS-FECHA-PROCESO-HABIL`. Esta lógica garantiza que el proceso de concentración nunca ejecute en día inhábil bancario.

**Trigger:** Resultado de RN-S151-281 indica día inhábil

**Campos involucrados:**

| Campo COBOL | Tipo | Rol |
|-------------|------|-----|
| `WS-FUNCION` | PIC 9(02) | Código de función — valor 13 para avanzar al siguiente hábil |
| `WS-FECHA2` | PIC X(08) | `"00000001"` — indica avanzar 1 día |
| `WKS-FECHA-PROCESO-HABIL` | fecha | Destino del siguiente día hábil calculado |

**Traza de código:**
```
PROGRAMA: P050ADSALDOS · Líneas: 9513–9520

IF WKS-DIA-HABIL = 0 → día INHÁBIL (ENTRA: ejecuta FUN=13) [QC-P1-CORREGIDO]
  MOVE WS-FECHA-AMD  TO WS-FECHA1               [L9513]
  MOVE "00000001"    TO WS-FECHA2               [L9514]
  MOVE 13            TO WS-FUNCION              [L9515]
  MOVE 13            TO WS-FORMATO              [L9516]
  CALL "THECALENDAR IN LOCSUP" USING            [L9517]
       WS-FUNCION, WS-FECHA1, WS-FECHA2,        [L9518]
       WS-FORMATO
  MOVE WS-FECHA1 TO WKS-FECHA-PROCESO-HABIL    [L9520]
ELSE → día HÁBIL (no entra; usa fecha directamente) [L9521-9522]
```

**Vocabulario relacionado:** `LOCSUP`, `LOTE`, `LINEA` (modo de operación online que requiere conocer la fecha hábil vigente)

**Fórmula / pseudocódigo:**
```
IF WKS-DIA-HABIL = 0 (INHÁBIL):  [QC-P1-CORREGIDO: era "≠ 0 (inhábil)" — condición invertida]
  MOVE "00000001" TO WS-FECHA2; MOVE 13 TO WS-FUNCION
  CALL "THECALENDAR IN LOCSUP" USING WS-FUNCION, WS-FECHA1, WS-FECHA2, WS-FORMATO
  MOVE WS-FECHA1 TO WKS-FECHA-PROCESO-HABIL
ELSE (WKS-DIA-HABIL ≠ 0 → HÁBIL): MOVE WS-FECHA-AMD TO WKS-FECHA-PROCESO-HABIL
```

**Excepciones documentadas:**
- El delta "00000001" es específico del protocolo THECALENDAR; no equivale universalmente a +1 día calendario
- Puentes largos (fin de semana + festivos) producen saltos de múltiples días

**Riesgos de migración:**
- El valor `"00000001"` como delta de avance es específico del protocolo THECALENDAR — el nuevo sistema debe replicar exactamente esta semántica
- Si el avance produce un puente largo (fin de semana + festivos), el resultado puede diferir de implementaciones que avanzan exactamente 1 día calendario

**Estado validación:** pendiente HITL

**Descripción:** Al presentar saldos globales o de cliente cuando `WS-DE-MONEDA = 1` (MXN), P050 divide `B01-GLO-ACTUAL` y `B01-GLO-ANTES` entre 1,000 antes de moverlos a los campos de visualización. Para otras monedas, el saldo se usa directamente sin división. La variación (ACTUAL − ANTES) también se divide entre 1,000 cuando MONEDA=1. Esto implica que en BD02ADSALDO los saldos MXN se almacenan en centavos × 10 (o en milésimas de peso), no en pesos. `[HARDCODE-SOSPECHOSO]` — el factor 1,000 está hardcodeado sin constante nombrada.

**Trigger:** Consulta de saldos globales (función 300-GLOBALES) o de cliente (función 410-CLIENTE)

**Campos involucrados:**

| Campo COBOL | Tipo | Rol |
|-------------|------|-----|
| `WS-DE-MONEDA` | PIC 9(02) | Código de moneda — 1 = MXN |
| `B01-GLO-ACTUAL(WS-IND-SIS)` | COMP | Saldo actual en BD02ADSALDO — en escala × 1000 para MXN |
| `B01-GLO-ANTES(WS-IND-SIS)` | COMP | Saldo anterior — misma escala |
| `WS-VARIACION` | numérico | Saldo convertido para presentación |

**Traza de código:**
```
PROGRAMA: P050ADSALDOS · SECCIÓN: 340-RESTO-CAMPOS · Líneas: 10482–10499

IF WS-DE-MONEDA = 1                                          [L10483]
   COMPUTE WS-VARIACION = B01-GLO-ACTUAL(WS-IND-SIS) / 1000 [L10484]
ELSE
   COMPUTE WS-VARIACION = B01-GLO-ACTUAL(WS-IND-SIS)        [L10486]
MOVE WS-VARIACION TO WS-DS-GLOB-ACT(WS-IND)

IF WS-DE-MONEDA = 1                                          [L10488]
   COMPUTE WS-VARIACION = B01-GLO-ANTES(WS-IND-SIS) / 1000  [L10489]
ELSE
   COMPUTE WS-VARIACION = B01-GLO-ANTES(WS-IND-SIS)         [L10491]

IF WS-DE-MONEDA = 1                                          [L10494]
   COMPUTE WS-VARIACION =
     (B01-GLO-ACTUAL(WS-IND-SIS) -
      B01-GLO-ANTES(WS-IND-SIS)) / 1000                     [L10495-96]
```

**Vocabulario relacionado:** `SALDO` (saldo contable GL en BD02ADSALDO), `MONEDA` (código de divisa), `BIFIN` (base de datos que contiene B01TOTPROD)

**Fórmula / pseudocódigo:**
```
IF WS-DE-MONEDA = 1
  COMPUTE WS-VARIACION = B01-GLO-ACTUAL(WS-IND-SIS) / 1000
ELSE
  COMPUTE WS-VARIACION = B01-GLO-ACTUAL(WS-IND-SIS)
MOVE WS-VARIACION TO WS-DS-GLOB-ACT(WS-IND)  [igual para GLO-ANTES y variación]
```

**Excepciones documentadas:**
- Solo MXN (MONEDA=1) se divide entre 1,000; USD y otras monedas usan el valor directo
- Factor 1,000 hardcodeado sin constante nombrada; B02-SUC-ACTUAL y B03-CTE-ACTUAL siguen el mismo patrón

**Riesgos de migración:**
- Si el nuevo sistema almacena saldos en pesos (no en escala × 1000), la división causará pérdida de precisión
- Factor 1,000 debe documentarse como constante nombrada en el nuevo sistema
- Otros campos de saldo (B02-SUC-ACTUAL, B03-CTE-ACTUAL) tienen el mismo patrón de división — verificar cobertura completa

**Estado validación:** pendiente HITL

| **Programa ejecutor** | P178 |
| **Evidencia código** | Análisis fuente (dt-mainframe-analyst): elevar Traza de código a archivo:línea exacta |
| **Dataset DMSII** | Análisis interno: derivar de Campos COBOL / DASDL |

**Descripción:** P178 no puede ejecutarse hasta que el paso P025 haya completado su ciclo. La condición de espera se evalúa sobre el campo `WKS-B03-STABDSAL` del módulo LIB-CONTROL (BD99CONTROL). Mientras `STABDSAL < 3`, P178 emite mensaje de espera y duerme 900 segundos (15 minutos). Si `STABDSAL = 99`, finaliza el proceso (estado de error). Nunca arranca el procesamiento de saldos hasta recibir la señal correcta del predecesor.

**Trigger:** Inicio del párrafo `1001105-VALIDA-STABDSDO` en el loop de inicialización (`100000-INICIO`)

**Campos involucrados:**

| Campo COBOL | Tipo | Rol |
|-------------|------|-----|
| `WKS-B03-STABDSAL` | 9(02) COMP | Estado del proceso de saldos (0-4=no listo, 3=listo, 4=ok, 99=error crítico, 5=alta disponibilidad) |
| `W77-PARAM-SISTEMA` | 9(03) | Identificador del sistema origen (500, 555, 84, 87, 408, etc.) |
| `W77-STATUS` | binario | Resultado de llamada a LIB-CONTROL |

**Vocabulario relacionado (vocab-s151.md):**

| Término | Categoría | Alcance | Significado |
|---------|-----------|---------|-------------|
| `CONTROL` | ENTIDAD | dominio | Módulo de control del proceso GL — BD99CONTROL almacena el estado de cada paso del lote batch: fechas, parámetros y estados. Gestionado por LIBCONTROL |
| `LIBCONTROL` | ENTIDAD | dominio | Librería de control de proceso GL — gestiona el registro y validación de cada paso del WFL LOTE. La librería de control más referenciada del sistema S151 |
| `LOTE` | ENTIDAD | bcop-cruzada | Lote de procesamiento batch nocturno S151 — WFL LOTE secuencia todos los programas de cierre del día contable |
| `L001` | PREFIJO | dominio | Librería de control de BD S151 (ALGOL, 3.1K LOC) — gestiona fechas y calendarios via LOCSUP. Accede BD99CONTROL |

**Fórmula / pseudocódigo:**
```
[QC-P2] UNTIL real del código fuente: STABDSAL = 3 OR 4 OR 99

PERFORM 1001105-VALIDA-STABDSDO UNTIL WKS-B03-STABDSAL = 3 OR 4 OR 99

Dentro de 1001105-VALIDA-STABDSDO (por cada iteración):
    CALL "CONSISMEN IN LIB-CONTROL" → leer WKS-B03-STABDSAL
    SI STABDSAL < 3:
        log "NO HA TERMINADO P025 DETENGO PROCESO 15 MINS"
        WAIT(900)  ← 15 minutos — loop continúa
    ELSE SI STABDSAL = 99:
        NEXT SENTENCE  ← loop sale vía UNTIL → post-loop: ABORT
    ELSE SI STABDSAL = 5 (Alta Disponibilidad):
        MOVE 99 TO WKS-B03-STABDSAL  ← convierte a 99; loop sale en siguiente UNTIL → ABORT
    ELSE SI STABDSAL > 4:
        → error "YA EJECUTADO" → terminar

FIN PERFORM (sale cuando STABDSAL = 3, 4, ó 99)
SI STABDSAL = 99 → MOVE 2 TO W77-EOF → ABORT
ELSE (STABDSAL = 3 ó 4) → iniciar procesamiento de saldos
```

**Excepciones documentadas:**
- STABDSAL = 99: P025 terminó en error — P178 aborta sin procesar ningún saldo
- STABDSAL > 4 AND ≠ 5: indica doble ejecución del ciclo — P178 genera aviso y termina para evitar doble escritura en B70
- Sin límite de retries en el código: si P025 falla permanentemente, P178 entra en bucle infinito de WAIT(900) — riesgo operativo en producción
- Alta disponibilidad (STABDSAL = 5): dentro de 1001105-VALIDA-STABDSDO el código ejecuta `MOVE 99 TO WKS-B03-STABDSAL`; la condición UNTIL se evalúa en la siguiente iteración y sale con STABDSAL=99, lo que provoca ABORT — no continúa el procesamiento de saldos [QC-P2 verificado]

**Traza de código:**
```
PROGRAMA: P178
PÁRRAFO: 1001105-VALIDA-STABDSDO (línea fuente ~081800)
  CALL "CONSISMEN IN LIB-CONTROL" USING WKS-S151B03SISMEN
  IF WKS-B03-STABDSAL < 3
     STRING "NO HA TERMINADO P025 DETENGO PROCESO 15 MINS: " WKS-B03-STABDSAL
     WAIT (900)
  ELSE IF = 99 → termina
  ELSE IF > 4 AND ≠ 5 → error ya ejecutado
```

**Riesgos de migración:**
- El mecanismo `WAIT(900)` es un primitive de Unisys MCP — en Java/cloud debe implementarse como retry con `Thread.sleep(900_000)` o job scheduling con polling
- La variable `STABDSAL` vive en BD99CONTROL (DMSII) — en target debe haber un equivalente de state store (Redis, DB relacional, tabla de control) con semántica idéntica
- Si el timeout máximo de retries no está documentado, puede producir bucle infinito en condiciones de falla de P025

**Estado validación:** pendiente HITL

**Fórmula / pseudocódigo:**
```
[QC-P1-CRITICO] El código fuente NO tiene rama ELSE para otros sistemas.
Solo S500/S555 con PRD=1 e INS=3 generan RELEASE al SORT.
Para cualquier otro sistema, ningún registro llega a A02-SORT en este INPUT PROCEDURE.

PARA cada registro leído de A01-SDOENT:
    SI A02-R00-TIPO-REG = 81:
        SI (W77-PARAM-SISTEMA = 500 OR 555) AND A02-R01-PRD = 1 AND A02-R01-INS = 3:
            PERFORM 210200-MUEVE-DATOS-APL
            MOVE CORR A02-R00-SALDOS OF A01-SDOENT TO A02-R00-SALDOS OF A02-SORT
            RELEASE A02-R00-SALDOS OF A02-SORT
        (de lo contrario: registro tipo 81 ignorado — sin RELEASE al SORT)
    PERFORM 5000000-LEE-SDOS  ← lee siguiente registro
```

**Excepciones documentadas:**
- PRD ≠ 1 OR INS ≠ 3 para S500/S555: el registro tipo 81 es ignorado silenciosamente — no se loguea, no hay contador de rechazos
- Sistema ≠ 500/555 (S84, S87, S408, etc.): [QC-P1-CRITICO] ningún registro tipo 81 se envía al SORT A02-SORT en este INPUT PROCEDURE — la tabla WKS-TAB-IMP para estos sistemas se carga por un mecanismo diferente (1520000-CARGA-REL-SALDOS), no vía SORT
- Archivo con tipo 81 antes del header (tipo 00): el programa READ secuencial puede no haber inicializado WKS-FECHA-PROCESO antes de procesar el primer registro de saldos
- PRD=1 INS=3 son valores hardcoded; si S500 modifica el catálogo de producto/instrumento, P178 requiere recompilación

**Traza de código:**
```
PROGRAMA: P178
PÁRRAFO: 210100-PROCESA (línea fuente ~110800)
  IF A02-R00-TIPO-REG OF A01-SDOENT = 81
     IF (W77-PARAM-SISTEMA = 500 OR 555) AND
        A02-R01-PRD OF A01-SDOENT = 1 AND
        A02-R01-INS OF A01-SDOENT = 3
        PERFORM 210200-MUEVE-DATOS-APL
        RELEASE A02-R00-SALDOS OF A02-SORT
  PERFORM 5000000-LEE-SDOS
```

**Riesgos de migración:**
- El valor hardcoded `PRD=1, INS=3` identifica un producto/instrumento específico de S500 que no está parametrizable — cualquier cambio de catálogo en S500 requiere recompilación de P178 o parametrización nueva
- La lectura secuencial skip-a-81 supone que el archivo está ordenado con el header al frente — romper este orden haría que el filtro no funcione

### RN-S151-394 — Creación automática de contrato faltante en BD S151 (no fatal)

| **Identificador** | RN-S151-394 |
| **Nombre** | Creación automática de contrato faltante en BD S151 (no fatal) |
| **Versión** | v2 |
| **Estado ciclo** | En validación |
| **Fecha actualización** | 2026-07-27 |
| **BC-ID** | BC-11 |
| **bian_ref** | 6.7.1 |
| **Tipo regla** | Consulta análisis SBVR (dt-mainframe-analyst) |
| **Tipo técnico** | [AUTO-CORRECCIÓN] [GESTIÓN-CONTRATOS] |
| **Confianza** | alta |
| **Veredicto** | PENDIENTE SME |
| **Regulador** | Política interna de alta automática en GL para contratos de sistema origen |
| **Programa ejecutor** | P178 |
| **Evidencia código** | Análisis fuente (dt-mainframe-analyst): elevar Traza de código a archivo:línea exacta |
| **Dataset DMSII** | Análisis interno: derivar de Campos COBOL / DASDL |

**Descripción:** Durante el proceso `220100-REG-INEXISTENTES`, P178 identifica contratos que existen en el sistema origen (S500/S555) pero no tienen registro en la BD de saldos S151 (`B20BXSDOMENCON`). Para estos contratos "inexistentes en S151", el programa crea el registro en DMSII vía `329000-PROCESA-BIT`. Este proceso no es fatal: la ausencia de contrato en S151 es esperada para contratos nuevos que aún no han sido procesados por el ciclo contable. El programa registra los totales en el reporte de cifras (R01-REPMES): `WKS-NUMCTO-S151`, `WKS-NUMCTO-SNNN`, `WKS-NUMDIF-SNNN`.

**Trigger:** `220100-REG-INEXISTENTES` al término del OUTPUT PROCEDURE del SORT A02 para W77-PARAM-SISTEMA IN (500, 555)

**Campos involucrados:**

| Campo COBOL | Tipo | Rol |
|-------------|------|-----|
| `B20BXSDOMENCON` | dataset DMSII | BD de saldos-contratos: registro por contrato en S151 |
| `WKS-NUMCTO-S151` | contador | Total contratos encontrados en S151 |
| `WKS-NUMCTO-SNNN` | contador | Total contratos en sistema origen (S500/S555) |
| `WKS-NUMDIF-SNNN` | contador | Total contratos con diferencia (en origen pero no en S151) |
| `WKS-IMPDIF-SNNN` | importe | Importe total de las diferencias encontradas |

**Vocabulario relacionado (vocab-s151.md):**

| Término | Categoría | Alcance | Significado |
|---------|-----------|---------|-------------|
| `A00-BIT-CONTRATO` | CAMPO-NUM | inc-p109 | Número de contrato principal asociado al movimiento en bitácora GL; numérico 16 dígitos |
| `A01-MOV-CONTRATO` | CAMPO-NUM | inc-pro | Número de contrato del cliente (9(16)). Identificador único del contrato bancario: sucursal (4d) + número secuencial (8d) |
| `A00-BIT500-CONTRATO` | CAMPO-NUM | inc-pro | Número de contrato bancario de la transacción en la bitácora S500 (16 dígitos) |
| `DMSII` | ENTIDAD | dominio | Base de datos relacional nativa de Unisys MCP. BD11SDOS151 (saldos), BD12MC001S151 (catálogo contable) |

**Fórmula / pseudocódigo:**
```
SI W77-PARAM-SISTEMA IN (500, 555):
    LOCK FIRST B20BXSDOMENCON
    PERFORM HASTA W77-EOF = 1:
        SI contrato NO existe en S151:
            PERFORM 329000-PROCESA-BIT  ← crea registro en DMSII
            WKS-NUMDIF-SNNN += 1
            WKS-IMPDIF-SNNN += importe
        WKS-NUMCTO-S151 += contratos encontrados en S151
        WKS-NUMCTO-SNNN += contratos en sistema origen
        LOCK NEXT B20BXSDOMENCON
    FIN PERFORM
SI WKS-NUMCTO-S151 > 0 OR WKS-NUMCTO-SNNN > 0 OR WKS-NUMDIF-SNNN > 0:
    WRITE R01-REPMES ← totales de diferencia al reporte cifras
```

**Excepciones documentadas:**
- LOCK FIRST falla (DMSII bloqueado por otro proceso): el código original no maneja esta condición explícitamente — potencial cuelgue del programa
- Alta automática de contrato sin notificación: la creación es silenciosa (solo cuenta en WKS-NUMDIF-SNNN) — un volumen anormal de altas automáticas no dispara alerta en producción
- Contrato creado en S151 pero eliminado en S500/S555 en el mismo ciclo: S151 queda con registro huérfano hasta siguiente corrida de limpieza

**Traza de código:**
```
PROGRAMA: P178
PÁRRAFO: 220100-REG-INEXISTENTES (línea ~112540)
```

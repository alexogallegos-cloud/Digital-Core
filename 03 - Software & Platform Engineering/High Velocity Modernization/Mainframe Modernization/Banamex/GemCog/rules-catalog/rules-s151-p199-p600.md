## Programa P199 — MIGRACIÓN SALDOS S500→S151 (cross-system bridge)

> `[RIESGO-EQUIVALENCIA]` — Puente entre sistema operativo (S500 Captación) y General Ledger (S151). En modernización, ambos sistemas se reemplazan simultáneamente; este programa no puede migrarse como está — debe rediseñarse como proceso de sincronización entre los nuevos sistemas.

**Descripción:** P199 (PROGRAM-ID CTASMIGCAP) es el único punto de integración entre S500 (Captación/operativo) y S151 (General Ledger). Lee el archivo secuencial MOVS500 generado por S500 y persiste los movimientos migrados en la tabla DMSII S151B08TDMIGCAP de la base S151BD13BIFIN. No genera asientos GL directamente — crea registros de migración que el GL utiliza para sus propios postings.

**Trigger:** Ejecución batch diaria post-cierre de S500, parámetro W77-PARAMETRO = número de sistema (ej. 151).

**Campos involucrados:**
| Campo COBOL | PIC | Rol |
|-------------|-----|-----|
| `W77-PARAMETRO` | 9(03) | Sistema origen (S500 variant) |
| `WKS-FECPRO-6D` | 9(06) | Fecha proceso (AAMMDD) de B01SISDIA |
| `WKS-AUT-MIGS500` | 9(08) | Último número de autorización S500 procesado |

**Vocabulario relacionado (vocab-s151.md):**
| Término | Categoría | Significado |
|---------|-----------|-------------|
| `B08TDMIGCAP` | ENTIDAD-DMSII | Dataset de migración de captación en S151BD13BIFIN |
| `MOVS500` | ARCHIVO | Archivo secuencial de movimientos S500 generado al cierre |
| `CVETRAN` | CAMPO-NUM | Clave de transacción de 6 dígitos; catálogo con 10,000 entradas |


**Fórmula / pseudocódigo:**
```
CTASMIGCAP recibe parámetro sistema (ej. 151)
Obtiene FECPRO de B01SISDIA vía LibControl
Lee archivo secuencial MOVS500 generado por S500 al cierre
Para cada registro: transforma y persiste en B08TDMIGCAP de S151BD13BIFIN
Al finalizar: genera reporte R01-TOTALES por BIN
```

**Excepciones documentadas:**
- Si MOVS500 no existe para la fecha, la ejecución termina sin procesar (sin rollback de datos ya migrados)
- En migración simultánea de S500 y S151, este puente debe rediseñarse completamente: no es migratable as-is

**Traza de código:**
- L2094: `400000-PROCESO` — loop principal de migración
- L2100: `OPEN INPUT A01-MOVS500` — apertura del archivo S500
- L2483: `CREATE S151B08TDMIGCAP` — alta en DMSII

**Riesgos de migración:** La arquitectura de puente desaparece en la migración (ambos sistemas se reemplazan). Toda la lógica de transformación aquí debe mapearse a una integración event-driven o API entre los sistemas modernos equivalentes.

**Estado validación:** Pendiente HITL

| Término | Categoría | Significado |
|---------|-----------|-------------|
| `S080BD01CON` | BASE-DATOS | Base de configuración cross-sistema con catálogos L710 |
| `CAT1565` | CATALOGO | Catálogo de habilitación de migración por fecha y BIN |


**Fórmula / pseudocódigo:**
```
Cargar catálogo CAT1565 de S080BD01CON vía L710_CONSUL_DETALLE
Si catálogo tiene entrada con campo2 = FECPRO-6D:
  indicador_migración = 1 (habilitado)
Si no hay entrada coincidente:
  indicador_migración = 0 → terminar sin procesar el día
```

**Excepciones documentadas:**
- Si el catálogo CAT1565 está vacío o no tiene la fecha actual, toda la migración del día se bloquea silenciosamente sin error

**Riesgos de migración:** En el sistema moderno este gate deberá implementarse como configuración dinámica (feature flag / tabla de calendarios), no hardcodeada en un catálogo propietario de Unisys.

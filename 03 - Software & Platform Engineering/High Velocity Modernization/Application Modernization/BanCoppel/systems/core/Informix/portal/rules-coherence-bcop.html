Metodología de identificación

del fragmento SPL a la intención de negocio · 8 señales
S1
Código de retorno = firma de capacidad
El código asignado declara qué puede fallar y por lo tanto qué sabe hacer el SP. Mismo código en múltiples SPs = capacidad transversal candidata a consolidación.
LET cCodRet = '101' → Optional<T>
LET cCodRet = '1001' → 447× → GlobalExceptionHandler
LET cCodRet = '207' → EntityNotFoundException
S2
Mensaje del código revela flujo previo
"No se encontró información" implica un SELECT/FOREACH anterior que puede retornar cero filas. El mensaje es la pista del flujo, no un simple label.
cCodRet='101' + "no se encontró"
→ hay FOREACH SELECT previo
→ mapear a Optional<T>, no excepción
S3
Regla compuesta — mismo SP
N sentencias LET con variables compartidas = una sola regla con sub-pasos. Unidad atómica de migración: mover uno sin los demás rompe el cálculo.
vInteres = vInteres * (DAY(vFecha)-1)
vProvision = vInteres * DAY(vAlta)
vInteres = vInteres * ((…)-1) ← un grupo CG
S4
Regla replicada — cross-SP
Mismo business_name + mismo código en múltiples SPs = copy-paste de capacidad. 42% del inventario son réplicas. Las reglas únicas son 3,507, no 6,067.
875 grupos cross-SP detectados
cCodRet='1001' → 447 SPs → 1 handler
Índice: 6,067 / 3,507 = 1.73×
S5
Constante literal = config pendiente
LET var = 0.16 (IVA MX), 10000 (umbral PLD), 0.0090 (ISR 2026). Toda constante regulatoria hardcodeada debe migrar como parámetro externalizado.
LET vValIva = 0.16 → tax.iva.rate
LET vLimPLD = 10000 → compliance.pld.threshold
LET vDiasVenc = 90 → credit.past_due.days
S6
Comentario inline = semántica principal
El desarrollador puso el significado en el comentario, no en el nombre de variable. El scorer normaliza acentos del contexto para hacer match.
LET cCodRet = '101'; -- No se encontró información
strip_accents(ctx): "encontro" + "informacion"
→ match con business_name tokens
S7
Condición IF como semántica del retorno
Para cada LET vCodRet = 'X', buscar hacia arriba el IF/ELIF que lo dispara. La condición es la semántica real del código de retorno. 1,287 reglas enriquecidas (95.5% cobertura).
IF (vestado = 'P') THEN
  LET vcodret = '600'
→ "[600] vestado = 'P'" — cheque pagado
S8
Swarm de expertos dominio
Fórmulas financieras con label regulatorio genérico se envían a agentes expertos (CNBV+GAT, LTOSF+CAT). Cada agente produce un enriched_name específico por patrón de código. 769 reglas enriquecidas.
CNBV+GAT: 232 patrones → TIR, sobretasa, interés diario, GAT
LTOSF+CAT: 99 patrones → comisión por-mil, IVA, min/max
LOW: 738 → 58 (−92.1%)

Hallazgo principal

CÓDIGO_RETORNO: 95% HIGH, 0% LOW — la extracción de condición IF (S7) resolvió el gap completo. Cada código de retorno ahora lleva la condición de negocio que lo dispara: '600' → vestado='P' (cheque pagado), '110' → parámetros nulos, '1001' → excepción sistema.

CÁLCULO_ARITMÉTICO: 76% HIGH, 2% LOW — el swarm de expertos CNBV+GAT y LTOSF+CAT (S8) redujo el LOW de 35% a 2%.
